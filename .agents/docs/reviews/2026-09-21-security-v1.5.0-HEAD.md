# Security review — v1.5.0-HEAD   (2026-09-21)

Range reviewed: v1.5.0..f603a5aec72baef6038f5fa035de3232788a1642

## Status: COMPLETE

## Verdict: FINDINGS

Nothing in this release blocks the gate. It carries no code, no dependency and no secret:
`git diff --name-only v1.5.0...HEAD -- '*.go' '*.mod' '*.sum'` is empty, and a
credential-pattern sweep over the whole diff returns only prose. The one security-relevant
change is a control change, and it is documented as an equivalence rather than as the
trust-boundary move it is: dropping the project `CLAUDE.md` stub takes a harness-scaffolded
project out of Claude Code's CLAUDE.md-only mode, so files nobody treats as instructions —
a nested `AGENTS.md` in a vendored or cloned subtree, an `AGENTS.md` in a parent directory —
become candidates for loading as live instruction text where the stub previously confined
loading to the one file the operator imported. Second, smaller: the stub made instruction
loading unconditional, and the documented replacement has silent windows (first session
after an upgrade, pre-2.1.277, Bedrock/Vertex/Foundry, telemetry off) in which a project's
own rules do not load and nothing says so. The global hard rules still load in every one of
those windows through `~/.claude/CLAUDE.md`, which is verified intact in source
(`internal/harness/plan.go:89`) and caps that second finding at low.

## Findings

- **[medium / confidence: medium]** `REQUIREMENTS.md:11`, `skills/init-project/SKILL.md:48`,
  `.agents/docs/architecture/DECISIONS.md` (ADR-036) — the removed stub was also a *scope
  limiter*, and no shipped artifact says so. With `CLAUDE.md` = `@AGENTS.md` present, Claude
  Code runs in CLAUDE.md-only mode: exactly one project file (the root `AGENTS.md`, reached
  through an import the operator wrote) becomes instruction text. With no `CLAUDE.md`, native
  `AGENTS.md` reading applies the memory system's own scoping — the project root, ancestor
  directories, and per-directory files loaded on demand. Exploitable in principle as prompt
  injection through a file nobody reviews as instructions: a cloned or vendored subtree
  carrying its own `AGENTS.md` (a submodule, a dependency checkout, a `web/`, a third-party
  skill), or a shared parent such as `~/workspace/AGENTS.md` dropped by another tool, now
  reaches the model without an operator action. In this repository the same mechanism turns
  two data files into instruction candidates: `context/AGENTS.md` (the rendered global
  context — a second copy of the rules that is stale the moment it diverges from the
  installed one) and `skills/init-project/assets/AGENTS.md` (a template whose
  instruction-shaped text is meant to be copied, not obeyed). Remediation, no code: add one
  sentence where the claim lives — R2 and ADR-036 — that every `AGENTS.md` in or above a
  project is live instruction text, so a clone from an untrusted source is read before a
  session runs in it; and have `/init-project` name it in its summary when the tree already
  holds more than one `AGENTS.md`. Confidence is medium because only root-level project scope
  was measured (`testing/2026-09-21-verify-agents-md-native.md`, arrangements 1–5); the
  nested/ancestor behaviour is inferred from the documented memory semantics and was not
  measured here (this dispatch may not run `claude`).
- **[low / confidence: high]** `skills/init-project/SKILL.md:48`, `REQUIREMENTS.md:11` — the
  stub loaded a project's rules unconditionally; the replacement has documented windows in
  which it loads nothing and emits no signal: the first session after any Claude Code upgrade
  (every user, every upgrade), Claude Code before 2.1.277, Bedrock, Vertex, Foundry, and a
  telemetry-disabled session (no feature-flag fetch). In those sessions a project's own
  security-relevant rules — a "never touch prod", a data-handling clause, a scoped-credential
  rule — are simply absent, and the plan's own Failure modes concedes "nothing in the harness
  detects it" (R3 bars a hook). Severity stays low because the global hard rules (never commit
  secrets, the secret-shaped-path stop) travel in `~/.claude/CLAUDE.md`, which is exempt from
  the switch and still written unconditionally — verified in source, not from the trail:
  `internal/harness/plan.go:89` writes `.claude/CLAUDE.md` from `claudeStub`
  (`render.go:17`), unchanged in this range. Remediation, no code: state in the SKILL.md
  bullet that a project whose own `AGENTS.md` carries security-relevant rules keeps (or gets)
  the one-line stub, and give the one-line session-start self-check — ask the session to name
  the project `AGENTS.md`'s first heading — as the way to tell a silent window from a normal
  session.

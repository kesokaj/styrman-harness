- **R3-2 (medium, NON-BLOCKING) The refresh script's scratch directory is unspecified, and the happy-path test's second run depends on it.** § Interfaces: the clone goes "into `.agents/scratch/catalog-refresh/`". Relative to what: cwd, the script's location, or `git rev-parse --show-toplevel`? `TestRefreshCatalogScript` runs against fixtures in `t.TempDir()`. (a) A cwd-relative path from a `go test` process at `internal/harness` writes `internal/harness/.agents/scratch/`, which `.gitignore` does not cover (`.agents/scratch/*` has a middle slash, so it is anchored at the root): the suite dirties the tree. (b) A fixed directory name means the second run ("a second run changes nothing", in the test and in Phase 1 box 2) meets an existing clone: `git clone` into a non-empty directory fails, or a reused clone still points at GitHub or at the previous test's fixture. Decide: a fresh per-run directory (`mktemp -d` under the toplevel's `.agents/scratch/`, removed on exit), and how the test keeps it out of the real checkout.
- **R3-3 (medium, NON-BLOCKING) The script's `next: go test ./...` line fails until the catalog is staged.** `TestEmbedHoldsOnlyTrackedFiles` (embed_test.go:54, root package, run by `go test ./...`) compares the embedded working tree with `git ls-files`, which sees staged files but not untracked ones. The script "stages nothing", so the first `go test ./...` after a refresh reports about 780 files "embedded but not tracked" — the same message that, once staged, means a git-ignored path. The operator cannot tell the benign case from the one the plan relies on this test to catch. Phase 1's box 2 mentions "staged" only inside its idempotence check, and the checkpoint runs the full suite. Fix: the `next:` line is `git add skills/google-catalog` (by name), then `go test ./...`; say so in the AGENTS.md rule and the Phase 1 boxes.

## Verdict: REQUEST CHANGES

Of the seven round-1 fixes, five are correct and complete: F1, F3, F4, F6 and F7. Two of them introduced new defects.

The worst is F2, which rewrote the preflight Step 4 mechanism, the one the round-1 review asked about. Every Step 4 docs finding now blocks the release, and the fix after NO-SHIP is followed by a full `/preflight` re-run. But Step 4 has no coverage rule and ignores prior rebuttals. A finding rebutted in the gate report's `## Outcome`, which Step 6 explicitly allows, is re-raised by the fresh docs reviewer on the re-run. Step 5 then blocks again, and Step 6 allows no override. A release with a correct rebuttal therefore cannot ship. By the context's own rule, this is the second round landing on the same mechanism.

The second defect is F5, the bug-fix clause added to preflight Step 2. It contradicts ADR-022, which is Accepted, and plan row D8. Both say that Step 2's release-diff threshold stays.

Neither new defect breaks the installer, and no frontmatter changed.

## Findings

- **[medium / confidence: medium]** `skills/preflight/SKILL.md:65`, `:77`, `:81` — a rebutted Step 4 docs finding blocks every re-run, and nothing stops it.
  - **The rules involved:**
    - `:65` says each Step 4 finding "blocks the release" and that "`/preflight` runs again".
    - `:77` lists "a Step 4 docs finding" as blocking, with no exception.
    - `:81` lets the task that resolves NO-SHIP findings close one as `rebutted`, and says "Never ship on NO-SHIP — no override."
  - **Why the re-run does not honour a rebuttal:**
    - Step 4 dispatches the docs reviewer "with the docs brief exactly as `/review` Step 3 gives it", over the whole `<base>..HEAD`. The dispatch has no mention of the earlier gate report or its Outcome.
    - Step 2 has a way through: it reuses a prior report whose `Range reviewed:` covers the commits. Step 4 has nothing like that.
  - **Concrete failure:** the docs reviewer raises a false positive. It is rebutted with a checkable reason, as `/review` Step 4 requires. `/preflight` runs again, and the same diff against the same docs gets the same finding, so the result is NO-SHIP again. The only ways out are editing correct docs until the reviewer is satisfied, or abandoning the release.
  - **Introduced by the fix:** before it, the gate fixed docs findings inside the run, so a re-run was rare. Now every Step 4 finding forces a full re-run, and each re-run re-reads text that was already accepted.
  - **Fix, either of these:**
    - At `:77`, exclude a Step 4 finding that an earlier gate report over the same base lists as `rebutted` in its `## Outcome`, and have Step 4 pass those Outcome lines to the docs reviewer.
    - Simpler: give Step 4 Step 2's coverage rule. Cite a prior `*-docs` report whose `Range reviewed:` covers the commits and whose gate Outcome closes every finding, and run the docs lens only over the commits after it.

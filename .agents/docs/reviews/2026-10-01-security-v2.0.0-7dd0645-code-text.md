## Verdict: FINDINGS

Nothing is high or medium. There are seven low findings and three carried lows. The worst: the v2.0.0 gate's fix for BUG-144 (`dream.UnitFor`, `internal/dream/timer.go:36-50`) decides which home is "the real one" from `$HOME`. The service manager it protects is per user ID. The harness's own sandbox procedure runs with `HOME=<sandbox>` plus `--home <sandbox>`, and there a scratch `--remove-timer` or `uninstall` still uses the bare unit name and can disable the operator's real nightly timer. The fix's stated guarantee does not hold on that documented path. The second worst: the BUG-143 permission lint for commands and rules fails open. A frontmatter block that `Split` does not recognise (BOM, `--- ` with trailing whitespace, unterminated) is accepted as "no frontmatter", is not linted, and is deployed verbatim. Nothing is exposed today: `commands/` and `rules/` are empty. `go.mod` and `go.sum` are unchanged. `govulncheck` reports nothing reachable. No secret or private data is in the slice. Every earlier finding marked closed in the two prior reports still holds at 7dd0645.

## Findings

- **[low / confidence: medium]** `internal/dream/timer.go:36-50` (`UnitFor`) — "real home" comes from `$HOME`, but the service manager it guards is shared per user ID.
  - **Mechanism.** `userHomeDir = os.UserHomeDir` reads `$HOME`. The testing guide (§ 2, line 161) runs sandbox homes "with `HOME=<sb>` for the whole run", and `kit-preamble.sh:45,72` wraps `sh-agent` with `--home "$KIT_HOME"`. Inside a kit, `UnitFor(<sb>)` therefore returns the bare `sh-agent-dream` / `com.styrman.sh-agent-dream`. `systemctl --user` reaches the user's one manager through `XDG_RUNTIME_DIR`, not `$HOME`, and `launchctl` reaches the `gui/<uid>` domain.
  - **Linux effect.** After a sandbox `--install-timer` has left unit files under `<sb>`, a sandbox `--remove-timer` or `uninstall` runs `systemctl --user disable --now sh-agent-dream.timer`. That disables the operator's real timer. The real unit file stays, so `sh-agent status` in the real home still reports "timer installed" and the loss is silent.
  - **macOS effect.** `launchctl bootout gui/<uid> <sb plist>` boots out the real label. A `bootstrap` while the real job is unloaded loads the sandbox plist under the real label.
  - **Why the fix's test misses it.** BUG-144's repro and `TestUnitNamesPerHome` use `--home` without a HOME override. The `timerHome` seam even makes the test's home "the real one".
  - **Exposure so far.** No kit has run a timer verb yet: `testing/2026-09-30-verify-parity-memory-dream-phase-2.md` names none.
  - **Remediation (stdlib).** Decide "real" against the account's own home, `os/user.Current().HomeDir`, and fall back to `$HOME` only when the lookup fails. Add a test that sets `HOME` to the scratch home and asserts the hashed name reaches the fake manager.

- **[low / confidence: medium]** `internal/harness/inventory.go:297-310` (`LoadDocs`) with `internal/harness/frontmatter.go:22-34` (`Split`) — the permission lint for commands and rules fails open.
  - **Mechanism.** `Split` accepts only an exact `---` opening line and an exact `---` closing line; it trims only `\r`. When `Split` errors, `LoadDocs` treats the file as having no frontmatter. That happens for an unterminated block, a closing or opening `--- ` or `---\t`, and a UTF-8 BOM before the opening fence. `ParseStrict`, `unreadLine` and `permissionKey("allowed-tools","hooks")` never run, and `Doc.Raw` is deployed verbatim to both CLIs.
  - **Who is exposed.** A CLI whose fence match tolerates trailing whitespace or strips a BOM would read `allowed-tools`/`hooks` from that file. Skills and agents are not affected: there a failed `Split` leaves no description and the file is refused.
  - **Docs claim.** README ("a skill, command or rule whose frontmatter sets `allowed-tools` or `hooks`" is refused) and AGENTS.md state this unconditionally. It holds only for a block `Split` recognises.
  - **Exposure today.** None: `commands/` and `rules/` are empty by design.
  - **Confidence.** The harness side was read in the code. That Claude Code or Antigravity would honour a near-miss fence or a BOM was not verified.
  - **Remediation.** In `LoadDocs`, a file whose first line is `---` after stripping a BOM and trailing whitespace must `Split` cleanly, or it is refused. Refuse a leading BOM in any harness markdown. Add fixtures for a closing `--- `, a BOM and an unterminated block to `TestLintPermissionKeysByKind`.

- **[low / confidence: medium]** `internal/dream/timer.go:62-70` (`renderSystemd`) and `:132-134` (the unsafe-path check) — `$` is not escaped in `ExecStart`.
  - **Mechanism.** systemd substitutes `${NAME}` inside `ExecStart` words. Quotes are removed before substitution, and only `$$` is a literal (systemd.service(5), "Command lines"). Only `%` is escaped here.
  - **Effect.** A home or binary path holding `${…}` is rewritten when the timer fires. With the new `--home "<home>"` argument, the scope of the nightly run can change, not only the binary path. Example: a scratch timer's `--home` could expand to another home.
  - **Defence in depth.** The quote/backslash/newline check runs on `bin` (cleaned by `filepath.Join`) and PATH, never on the raw `home` written into the unit. The CLI cleans `--home` with `filepath.Abs` (`cmd/sh-agent/main.go:236`), so this is not reachable today. `InstallTimer` is exported, though.
  - **Remediation.** Escape `$` as `$$` in the two `ExecStart` arguments, or add `$` to the refused set. Run the check on `home` itself. Add a fixture with a `${HOME}` path.
  - **Confidence.** Based on systemd's documentation; no unit was started here.

- **[low / confidence: high]** `internal/harness/catalog_test.go:607-632` — the destination-guard cases give the real refresh script working sources and pins, aimed at `/`, the real checkout and its parent.
  - **Mechanism.** Each case passes `CATALOG_*_REPO` fixtures that clone and valid `pinA`/`pinG`. Only the lexical guard (`refresh-catalog.sh:62-66`) and the not-a-catalog check (`:67-69`) stand between a regression and a full run.
  - **Effect.** If both regress, `go test ./...` vendors the fixture catalog into the developer's checkout root, or into `/` when the suite runs as root. That means INDEX.md, CHECKSUMS, MANIFEST.md, LICENSE-*, the entry directories and a root `.sh-agent-noindex`. That marker counts even untracked (`reconcile.go`) and takes the whole checkout out of `sh-agent search`. The CHECKSUMS left behind arms the next run's scoped delete. The first run deletes nothing.
  - **Compare.** The nested `go test` in `TestCatalogWriteModeNeedsCatalogDir` restores CHECKSUMS in `t.Cleanup`, so its damage is reverted. These cases have no such net.
  - **Remediation.** Give the guard cases sources that cannot be cloned, for example `CATALOG_*_REPO` pointing at a missing path under `tmp`. A regressed guard then stops at `fetch`, before anything is written, and the case still fails on its message.

- **[low / confidence: medium]** `internal/search/reconcile.go:105-113,142-148,175-202` — a `.sh-agent-noindex` marker silently removes directories from search.
  - **What counts.** A marker counts in any state git reports, untracked included, and anywhere in the checkout. It hides everything below its directory: the root, or the docs root, takes out the whole trail. Search output does not mention it.
  - **Effect.** An untracked `.agents/docs/.sh-agent-noindex` empties `sh-agent search --refs <path> --kind bug`. The global context requires that lookup before touching an area. The marker also drops the checkout's trail from the global index.
  - **What it does not do.** It never widens what is read. The marker's content is never read; only its existence is checked, with `os.Root.Lstat` inside the checkout. The secret-name filter still runs first.
  - **Preconditions.** Write access to the working tree. `git status --untracked-files=all` would show the file.
  - **Remediation.** Name the marked directories in the search header or `sh-agent status`. Refuse, or warn on, a marker that covers the docs root.

- **[low / confidence: low]** `skills/google-catalog/SKILL.md:13-19` — the router's consent rule (step 4) covers changes, not data leaving the machine.
  - **Gap.** Cloud resources, IAM, billing, APIs and clusters are covered. Sending project content, prompts, logs or traces off the machine at an entry's direction is handled only per entry in MANIFEST notes (for example `google-agents-cli-observability`), not by a router rule. BUG-110's lesson was one rule per kind, not per-instance patches.
  - **Remediation.** Add one clause to step 4: anything that sends project content, logs, prompts or credentials off the machine is shown to the operator first, like a change.

- **[low / confidence: low]** `skills/google-catalog/scripts/refresh-catalog.sh:56-69` — the `--dest` guard is lexical.
  - **Mechanism.** `abs` neither normalises `..` nor resolves symlinks. So `--dest <dir>/..`, or a symlink spelling of `/`, the home or the checkout, passes lines 62-66.
  - **What still holds.** The not-a-catalog check at `:67` refuses any such directory unless it holds a file named `CHECKSUMS`.
  - **Effect when it does.** The swap deletes the child directories named by that file's second column.
  - **Remediation.** Canonicalise with `cd -P … && pwd -P` before the comparisons: on `--dest` itself, or on its parent when it does not exist yet.

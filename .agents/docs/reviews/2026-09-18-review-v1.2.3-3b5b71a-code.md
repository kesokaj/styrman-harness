## Findings (round 3)

- **[medium / confidence: high]** `.agents/docs/deploy/remote.md:91` — "A tag is never what a machine installs from (§ Releases)." Under ADR-033 a binary-only place installs from exactly that: the tag's published binaries. This contradicts the new `AGENTS.md:63` sentence, `remote.md:95` two lines' worth of text later in the same file, `REQUIREMENTS.md` R9 § Update, and `README.md:245`. The reader most likely to hit it is the one `AGENTS.md:74` sends here. Fix: rewrite as "A tag is never what a CHECKOUT place installs from; a binary-only place updates to the tag's published binaries (§ Releases)".
- **[medium / confidence: medium]** `.agents/docs/deploy/remote.md:8` — "The harness reaches a machine one way: `sh-agent` (R8, ADR-030). Git is the transport, on the operator's own credentials". For a binary-only place the transport is the release download (`gh release download` / the Releases page over HTTPS), not git; the file's own `:128` says so. The first sentence of the deploy guide is where a cold reader forms the model. Fix: "Git is the transport for a checkout place; a binary-only place downloads the release's signed binaries (R8, ADR-030, ADR-033)".
- **[low / confidence: medium]** `skills/preflight/SKILL.md:52` vs `:77` — the row is now satisfied only by a log "whose Status is PASS", so a Step 1 log with Status FAIL or BLOCKED falls into the `Otherwise` branch and the gate re-dispatches the verifier over the same range instead of carrying that FAIL into Step 5. If the re-run comes back green on a flaky test, the gate cites the PASS and the earlier FAIL is never read — the one outcome `:77`'s "never restate a failure as success" exists to prevent. Fix: make `:77` block on ANY verifier log in the release range whose Status is not PASS, superseded or not, rather than on the cited log alone; or have `:52` say a FAIL/BLOCKED log goes to Step 5 as a blocking finding rather than to a re-dispatch.
- **[low / confidence: low]** `.agents/docs/specs/sh-agent/delivery.md:7` and `:56` — the spec's header still says "What is DECIDED lives in `REQUIREMENTS.md` R8 and ADR-030" and `:56` closes the tag-channel history with "Tags survive as release markers", both written before ADR-033. `:33` and `:76` in the same file do carry ADR-033, so the document is not wrong end to end, but its framing sentence names the superseded ADR. Fix: add ADR-033 to `:7` and one clause to `:56` noting the narrower channel ADR-033 restored.

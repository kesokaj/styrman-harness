# Lean process 2: security at effort high, verifier last, round 2 loads SendMessage, a safe A/B kit (ADR-054a)

## Type

feature (process rules, test kit)

## Summary

The diagnosis came from the ADR-054 re-run's transcripts (plan `plans/2026-10-07-lean-process-2.md` § Why). Three causes kept that run at $7.27 / 29.3 min:
- **Security effort.** `security` at `effort: max` thought for 21–180 s per step and took 19 of the 29 minutes.
- **Verifier order.** The verifier ran in parallel with the reviews, so it was re-run after their fixes.
- **No resume.** Round 2 never resumed the agent, because `SendMessage` was only a deferred tool.

The changes:
- `agents/security.md`: `effort: max` → `high`, keeping `model: opus`.
- **Verifier last** (context DoD 1, `feature` Step 6, `bug` Step 5, `preflight` Step 1.1): the one verifier is dispatched after the review's fixes. The hand-written context went from 14,719 to 14,722 bytes.
- **`review` Step 5:** on Claude Code, load `SendMessage` with `ToolSearch` (`select:SendMessage`) before resuming an agent.
- **`testing/ab-kit/`, new and committed:**
  - It runs `bash .agents/docs/testing/ab-kit/run.sh control|harness|<name>-full`, built on `kit-preamble.sh`.
  - Clones live under `~/sandbox/ab`, and the sandbox `HOME` under `.agents/scratch/ab-homes/<arm>`.
  - The credential is a symlink that the kit removes and checks.
  - The box's credential broker is off for the CLI.
  - Runs are wrapped in `timeout 90m`.
  - It includes `accept.py`, the 25-check black-box contract test, and `metrics.py`, which reports cost, turns, and each subagent's time, tool calls and SendMessage resumes.
- **`testing/guide.md` § Behavioural runs:** "never `HOME=<scratch> claude -p`" now says what a scratch `HOME` run is allowed to be.
- **ADR-054a.** **BUG-160 addendum:** this box's login-shell credential broker wrote the SSH key, gcloud ADC and the Antigravity token into any sandbox `HOME`. That is the source of BUG-160's leftovers. The kit turns the broker off, and the four files were deleted by name.

## Measurement

Same prompt and model, the full-process arm, n=1 each. The baseline ran with the real HOME (approximate, plan D6).

| | Original | ADR-054 | ADR-054a |
|---|---|---|---|
| Cost | $8.46 | $7.27 | **$4.51** |
| Wall time | 30.8 min | 29.3 min | **14.4 min** |
| Subagents | 13 | 6 | **4** |
| Main turns | 87 | 62 | 54 |
| Security review | 9 min | 19 min (2 rounds) | **1.8 min (1 round)** |
| Verifier runs | 4 | 2 | **1 (last)** |
| Bug records for defects fixed before commit | 4 | 0 | 0 |
| Acceptance test | 25/25 | 25/25 | 25/25 |

- **The first score was 24/25, and the check was the defect.** The build requires `Content-Type: application/json`, a cross-site write defence, and the old curl check sent no content type, so it got 415. `accept.py`'s `raw()` now sends the header, and the score is 25/25.
- **The run did not run a security round 2.** Its `## Outcome` cites the fixes' tests and the final verifier. The rules allow this ("at most two rounds"), and it is listed as an operator question in the handoff.
- **No resume happened** (`SendMessage` resumes: 0), because no round 2 was needed.

Kit proof:
- The first `control` run FAILed the preamble's credential check (the broker).
- After the fix, `control` passed 25/25 at $0.52 / 2.8 min, with `kit: real config unchanged` and `kit: no credentials left in KIT_HOME`.
- `lean2-full` printed both lines too.

### Proposal 9: § Releases says what publishing does NOT change
Scope: project — Target: `.agents/docs/deploy/remote.md` — Status: proposed
Scope rule: target-in-project

**Trigger.** The operator asked, mid-publish, "Does this make the repo public?" The procedure they were watching me run gave them no way to answer it themselves.

**Current behavior.** § Releases describes creating a release and uploading assets, and says nothing about repository visibility. README § Install without cloning relies on the repository being private (a download needs the operator's credential) but never states that publishing a release does not change that.

**Expected behavior.** The guide answers the question where the command lives.

```diff
 After the upload: `gh release view vX.Y.Z --repo kesokaj/styrman-harness --json assets --jq '.assets[].name'` lists the five assets, and nothing further is pushed anywhere — a binary-only place picks the release up the next time the operator runs `sh-agent update` there.
+
+Publishing a release changes NOTHING about the repository's visibility: `styrman-harness` stays private, the release page is readable only by accounts that can already read the repository, and every asset download needs that credential — which is what README § Install without cloning depends on. `gh repo view --json visibility` after the upload is the check; only a deliberate change in the repository's settings makes anything public.
```

**Rationale.** A release is the one step in this repository that talks to the outside world, and "did I just make my private harness public?" is the first thing a reader wonders. Answering it in the guide costs two sentences and removes a question the operator should never have to ask mid-release.

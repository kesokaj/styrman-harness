The row set does NOT satisfy AGENTS.md § Release for three of the four agents. The release rule asks for a run of each changed agent on Antigravity. ## (1) Gaps

### Blocking

- **B1. The `bugs` row cannot produce the condition it claims.** Plan: "`bugs`: covered by the bug row, through its record". `skills/bug/SKILL.md:55` says the main agent writes the bug record itself, in the `bugs` agent's format, and uses `bugs` only "when you lack the evidence". The `bug` row's check (`skill-matrix.md:24`) is `ls .agents/docs/bugs/BUG-0*` plus the BUG id in the output. A main-agent-written record passes it. The row proves the `bug` skill ran, not that the `bugs` agent ran. Decide: dispatch `bugs` explicitly, and judge the run from the conversation database (an `invoke_subagent` of `bugs`), not from the record. Matrix precedent: `search-agents` (`skill-matrix.md:88`) dispatches `bugs` with the "exactly the text between the markers" form, but on the `notebox` fixture, not the demo.
- **B2. The `changelog` row has no home.** The plan quotes "Dispatch the changelog agent for the last commit …" as if it were a matrix prompt. No such row exists (`grep 'Dispatch the .changelog' skill-matrix.md` finds none). The only changelog coverage is `search-agents` on `notebox` (Claude Code). The prompt, the fixture (demo HEAD plus one commit), the check (a new `changes/*.md` that names the commit) and the agent's no-shell dispatch contract (`bug/SKILL.md:55`: the dispatch carries `sh-agent search --refs` output) all have to be written. Add it to `skill-matrix.md` in this change, because the plan creates a row that the spec file must carry.
- **B3. The `documentation` row probably never dispatches the agent.** The row (`skill-matrix.md:86`) is a one-env-var Task "through the Definition of Done". Under ADR-054 and `bug/SKILL.md:55` the main agent writes docs itself up to 30 changed lines, so `SHUTDOWN_TIMEOUT` in README plus local.md may be written by the main agent. The check is three greps, which pass either way. Fix: the check must include the dispatch in the transcript (`steps.step_payload` per `skill-matrix.md:15`, Step 3 of the Procedure), or the prompt must dispatch `documentation` by name. The plan's own Verification says only "n of N per row"; it does not say which rows are judged from the transcript.
- **B4. The seeded check's scoring is unvalidated and its effort knob is undecided.** (a) `agents/security.md:6` already has `effort: high` (ADR-054a), so "run at high" is the default and "max" needs an override. The plan does not say how: `--agents <json>` built from an edited copy, with a changed `effort:` line? The edited copy must be built from the working-tree file so the run proves which definition ran (guide § 4 § Behavioural runs, first bullet). (b) "Judged by grep for each flaw's file:line" fails on a correct finding that cites a range, a different line of the same call, or only the file; it passes on an artifact that cites the line while saying it is fine, or a negation (`review-standards` § 2 "a needle matches its own negation"). The scorer needs its must-pass (a hand-written artifact naming all 6, expect 6/6) and must-fail (an empty or clean-fixture artifact, expect 0/6) states before a score is cited (AGENTS.md "Silence from your own instrumentation"). Decide: match on file plus a ±N line window plus the flaw's keyword, and report the artifact paths so a human can re-judge. (c) 3 high runs vs 1 max run is a sample of one for the reference; the expectation "high finds at least what max finds, or the gap is reported" is satisfiable by luck. State it as a measurement, not a gate. (d) The fixture must carry no comment, name or README line that hints at a flaw (`// vulnerable`, `adminPassword`). A hard-coded-password flaw is named by its variable, so say how the name stays neutral.
- **B5. The agy kit's secrets and web-tool story is not decided.** The plan says "agy's token is linked, never copied". The Claude kit's analogue is `run.sh:45-47`, a symlink to a regular file that is deleted by name after. For agy: `~/.gemini/antigravity-cli/antigravity-oauth-token` is a regular file (0600). Unchecked: (i) whether agy rewrites the token in place (the symlink survives) or replaces the file (the real login goes stale and the sandbox holds a copy). Mirror `run.sh:59` and `:61`: warn if the link was replaced, and check the real file is still regular. (ii) `kit-preamble.sh:104` flags `.*oauth-token.*` by NAME, so the link must be deleted before the preamble's exit trap runs, and the trap is the script's EXIT; `run.sh:60` does the delete in the body before exit, which works. (iii) The Claude kit runs `--disallowedTools WebFetch WebSearch` (`run.sh:55`), and the plan's choice 3 ("the kit's no-web-tools flag answers security R2-1") relies on that flag. agy has no such flag in the matrix recipe. With `command(*)` rows and a sandbox that installs vendored skills, the choice-3 answer is not true for the agy kit unless settings.json denies the web tools. Decide the agy equivalent, or state that the choice covers the Claude kit only and the agy rows run on `skill-matrix.md:14`'s grants (`guide.md:185`: harness-written text only; the vendored rows get read-only).

### Non-blocking

- **N1. Committed scripts contradict the matrix's stated rule.** `skill-matrix.md:7` says "Scripts are not committed (ADR-010)"; ADR-010 title (`architecture/DECISIONS.md:77`): "the skill matrix is a documented procedure, not a script". `testing/ab-kit/` already commits a script, and `kit-preamble.sh` is committed, so the precedent is mixed. The plan adds two more (`seed-security/run.sh`, `agy-rel/run.sh`) without saying so. Either keep them in `.agents/scratch/` and commit only the spec/fixture recipe, or write the exception (one sentence in `skill-matrix.md:7` and `guide.md:158`, which names `ab-kit/run.sh` as the one worked example). Recommend: commit them (the kit is the reproducible proof the gate counts), amend line 7 in the same change. Committed scripts under `.agents/docs/testing/` also fall under `TestScriptsHaveNoEarlyExitPipe` (guide.md:146); a `grep -q`/`head` after a pipe under `pipefail` fails `go test ./...`.
- **N2. Fixture state per row is not listed.** `skill-matrix.md` § Procedure 1 (line 11) needs per-row seeds: `bug` needs the `TrimLeft` commit; `review` one uncommitted edit; `retro` three identical corrections in `<home>/.config/sh-agent/feedback.jsonl`; the security row needs the commit with the planted comment; `documentation` needs `.agents/docs/deploy/local.md`. The plan says only "scaffolded". `run.sh <row>` must build each from the one fixture, and a base commit for `KIT_ASSERT_COMMIT` should be fixed (a SHA, not `HEAD`).
- **N3. `~/sandbox/agy-rel/fixture` already exists** (a repo with `6779204 demo service`, no scaffold). The plan says "rebuilt". Say whether to reuse or delete it. A `run.sh` that refuses an existing path (the `run.sh:37` pattern) makes the answer matter.
- **N4. One home or one per row?** "The sandbox home is installed" is singular, but the preamble's exit check, the `cli-*.log` "newest log" check (`skill-matrix.md:14`) and the per-row `settings.json` (`command(*)` rows vs named grants) all assume a per-run home. Ab-kit uses one home per arm. Recommend one home per row (`ab-homes/<row>` pattern), installed with `--vendor agy`.
- **N5. Claude-only flags in the matrix rows.** `retro`, `handoff` carry `--add-dir <home>/.config/sh-agent`. `skill-matrix.md:14` says Antigravity runs take no `--add-dir`. `retro`'s check reads `$SB/.config/sh-agent/proposals/*retro*`, and in the agy home the preamble's wrapper pins `--home`, so it is fine, but the plan should say the Claude flag is dropped.
- **N6. `preflight` row on agy.** It dispatches `security`, `reviewer`, `verifier` (ADR-054); at `--print-timeout 20m` a full gate may time out. A timeout is recorded as FAIL per the plan's failure mode; say what budget (maybe a `--print-timeout` raise) and that a timeout is not retried silently.
- **N7. Review Step 4 edit (item A) is broader than its Why and its location is uncertain.** The Why says "security round 2 stays optional, and says so". Item A rewrites the general review rule: "outside `--fix`, round 2 may be skipped when every fix has a failing-without-it test and the verifier runs after". That changes a rule for every review, not just the security agent. And the text it amends is split: the rounds paragraph is `skills/review/SKILL.md:94` (Step 4), the cap and "at most two rounds" are `:100` and `:112` (Step 5, `--fix`), and the global context line `context/AGENTS.md:16` restates the rounds protocol and points to `review` Step 4. Re-read both and grep `context/`, `skills/feature`, `skills/bug`, `skills/preflight` for "round", "second round", "cap". Decide: A is a one-sentence clarification of the existing optional status (what the operator chose), or a new rule (needs the operator's say-so and an ADR addendum). Recommend the first. Also the edit must keep `TestSkillListingBudget` (19,340/19,500, `guide.md:146`) green; a Step body edit is safe, a description edit is not.
- **N8. D (real-home install) runs after the commit and push**, and produces logs written after it, so a second records commit follows. The release rule counts a log whose `Range reviewed:` reaches the head the rows ran on (`guide.md:183`); say which head. Also, AGENTS.md "Rules for working here" says "Deploying to the real home is the operator's job"; the operator's "Go fix all" covers it (handoff step 2 is "Operator: `sh-agent install`"), so record that sentence as the authority in the log. Verify with `sh-agent status` (`binary` line without a warning, per AGENTS.md) and the post-update check (`guide.md:207-211`) in addition to the three § 5 checks plus the Antigravity store check (`guide.md:200-203`, with the `<RULE[...]>` block for `critical-thinking.md`).
- **N9. The Verification section does not name the "expect" of C's smoke row.** "agy authenticates, and the preamble lines are clean" should be the two preamble lines the guide requires (`kit: real config unchanged`, `kit: no credentials left in KIT_HOME`) plus "no `auto-denied` in stderr, no `invalid allow entry` in `cli.log`" (`skill-matrix.md:14`). One smoke row is `testing-strategy` or `operate` (no shell), not one that needs grants.
- **N10. Not in the changed list but in the plan:** the agy `review-docs` lens and `handoff`'s counterpart `/review --docs` are not mentioned. AGENTS.md § Definition of Done 2 requires `/review --docs` over the range when a command or deploy step changes; this plan edits a skill and adds test kits, so it applies to the skill edit (A). Plan Phase 3 says only "Review".

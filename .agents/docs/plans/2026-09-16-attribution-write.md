# Plan — `sh-agent install` switches Claude Code's commit attribution off   (2026-09-16)

## Why
BUG-039: the context's Git rule forbids the `Co-Authored-By` trailer, yet three of three headless Claude Code commits carried it, because the trailer is the CLI's own attribution setting and prose does not switch a setting off. Since 7b8743f `install` and `status` print a note asking the operator to add the setting by hand. The operator asked for the installer to write it instead ("Add this to the installer? … so when I install it fixes this?") and approved the one-sentence change to R4 that this needs (2026-09-16, both AskUserQuestion answers: "Leave it, print the note (Recommended)" and "Approve as written (Recommended)").

## Scope
In: `install` (and its alias `sync`, the same switch arm; vendor all or claude) sets `"attribution": {"commit": "", "pr": ""}` in `<home>/.claude/settings.json` when the `attribution` key is absent, creating the file when it is missing; every other byte of the file stays; `--dry-run` reports and writes nothing; the existing note stays for a key that is present with any other value; R4 gains the approved sentence and the Non-goals bullet on vendor settings gains the approved exception, both in one commit with ADR-025, which supersedes ADR-010's "never touch vendor settings" clause on this one point (ADR-010's other decisions stand); README § Install (both the attribution sentence and the line "the installer never touches vendor settings (ADR-010)") and the deploy guides say `install` does it.
Out: `uninstall` leaves the key (documented, not built); Antigravity has no such setting; the Mac (the operator runs `sh-agent update` there); forcing a value over one the operator set.
Follow-ups noted, not built:
- `internal/harness/apply.go:240-263` writes managed files through a temp file and rename without `Sync`, the pattern the security review flagged on this change; add the `Sync` there in its own task — found in: security review finding 2
- `abandonTemp`'s write-error paths and `readSettings`'s open failure have no test that forces them (the verifier's coverage gap) — found in: verifier log
- a SIGTERM between `CreateTemp` and the rename (argolis runs install under `timeout 60`) orphans `~/.claude/.settings-*.json`, which nothing removes: use one fixed temp name that the next run replaces — found in: argolis-devbox security review of the 4aa19be refresh, finding 2
- `attributionOff` reports a valid settings.json larger than 1 MiB as "is not valid JSON" (the bounded read truncates it) while `attributionSet` names the size; check the size once, before either reads — found in: the same review, finding 3
- a settings.json its owner made read-only (mode 444) is still replaced by the rename, since the rename needs only directory write: refuse a file without owner write permission with an advisory line — found in: styrman-crew security review of the 4aa19be refresh, finding 3

## Interfaces
`func attributionSet(home string, dryRun bool, out io.Writer) error` in `cmd/sh-agent/main.go`, called from the install case for vendor all or claude, before `attributionHint`. Path `filepath.Join(home, harness.ClaudeRoot, "settings.json")`.
- File missing: write `{\n  "attribution": {"commit": "", "pr": ""}\n}\n` with mode 0o644 through `O_CREATE|O_EXCL` (the directory is created if needed; a symlink at the path is refused by `Lstat` first); print `settings: <path> created with "attribution": {"commit": "", "pr": ""} — Claude Code's commit and PR trailers are off`.
- File present, regular, at most 1 MiB, valid JSON object, no `attribution` key: insert the fragment textually before the object's closing brace — `,\n  "attribution": {"commit": "", "pr": ""}\n` after the last non-whitespace byte inside the object, or `\n  "attribution": {"commit": "", "pr": ""}\n` when the object is empty — then `json.Valid` on the result, then write through a temp file in the same directory and `os.Rename`, keeping the original mode; print `settings: <path> — "attribution": {"commit": "", "pr": ""} added; other keys untouched`. If `json.Valid` fails, write nothing and print `settings: <path> could not be edited safely (the result would not parse); add the key by hand`.
- File present with an `attribution` key of any value: write nothing, print nothing here (`attributionHint` prints the note unless the value is `""` or `false`).
- Not a regular file, unreadable, malformed, or over 1 MiB: write nothing; `attributionHint`'s advisory note is the only output.
- `dryRun`: no filesystem change; print `[dry-run] would create <path> with …` or `[dry-run] would add "attribution": {"commit": "", "pr": ""} to <path>`.
- Signature without an error return: `func attributionSet(home string, dryRun bool, out io.Writer)`; write errors on `out` are ignored as `attributionHint` ignores them (D8). No state of the file fails install (advisory file, R4).
- A file that parses as JSON but is not an object (`[]`, `"x"`, `null`): nothing written; `attributionHint` prints the one advisory line (D7).
Rest of the CLI unchanged. `attributionOff` is reused for the "present" check via a new small helper `attributionKeyPresent(path) (present bool, problem string)` or by extending `attributionOff` to return three states — implementer's choice, recorded as a D-row.

## Failure modes
Malformed or non-regular file → nothing written, the advisory note names it. A write error (disk full, permission) → the temp file is removed, the line `settings: <path> could not be written (<err>); add the key by hand` is printed, install still exits 0 (the deployment itself succeeded). The operator's custom trailer value → untouched, the note says the trailer is on.

## Verification

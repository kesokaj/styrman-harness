## Checked

### 1. Timer (`accountHome`, `UnitFor`)
- **The lookup.** `accountHome` calls `user.LookupId(strconv.Itoa(os.Getuid()))` with no fallback, and an empty `HomeDir` is an error. `UnitFor` returns the bare names only when `userHomeDir()` succeeds and the home equals the database home after `filepath.Clean`, or is the same file (`os.SameFile`). On error, every home gets the suffix.
- **A sandbox never gets the bare names.**
  - `--home` defaults to `os.UserHomeDir()` (`main.go:224-230`), which is the sandbox's `HOME`, and `HOME` no longer enters `UnitFor`.
  - A sandbox matches only if it is the account's home directory itself: a symlink or bind mount of it, where acting on the real home is correct.
  - The seams `userHomeDir` and `lookupAccount` are set only in tests, and each is restored with `t.Cleanup`.
- **A sandbox `--remove-timer` or `uninstall` cannot stop or replace the real timer.** It touches only `<sandbox>/.config/systemd/user/…-<hash>` and `disable --now sh-agent-dream-<hash>.timer`.
- **A timer left running unnoticed:** yes, see finding 1.
- **What each kind of account sees.**
  - A container's bare uid: the lookup fails in both builds, so every home is suffixed. There is usually no user manager, so `--install-timer` fails and names its files.
  - LDAP, SSSD or systemd-homed accounts:
    - A cgo build resolves the account through NSS, so the real home gets the bare names.
    - The release binary does not list the account, so every home is suffixed. This is consistent within one binary; the flip between binaries or versions is finding 1.
  - macOS: libSystem answers without cgo (code review 7dd0645..f62513b, finding 1), so the real home gets the bare names. The exception would be a `-tags osusergo` build, and the release flags are `CGO_ENABLED=0` and `trimpath` (verifier log, line 25).

## Verdict: FINDINGS (one low, non-blocking; nothing here blocks the gate)

**No path lets a failed verification install anything.** The net code change across the range is one operator: `VerifyZipSums` now treats half the pair as `ErrZipUnsigned` (`&&` → `||`, `internal/harness/release.go:450`). Everything else nets out to v1.9.0, apart from comments, usage text and test assertions:
- the `--unverified` flag, its refusals and the stray-argument refusal were added and then removed;
- the updated usage text is `main.go:44`.

When both files are present, every failure path returns an error that does not wrap the sentinel, so the `check` closure (`cmd/sh-agent/main.go:1091-1101`) passes it on unchanged. `UnpackZip` then returns before it parses or writes anything, and the deferred `RemoveCreated` removes the directories it made (`internal/harness/zip.go:54-67`). The hash that is checked is the hash of the one in-memory buffer that is later parsed and unpacked, so there is no gap between check and use. I confirmed this three ways:
- by reading the code;
- with the edge cases below;
- with three must-fail mutations at c30b8da, each of which compiled and failed named tests (see Checked).

The one finding is a low about input parsing. It sits inside the class of hardening ADR-041 declined, so it is the operator's call.

## Accepted by decision (ADR-041) — recorded, not findings

- **A zip without the full pair installs marked UNVERIFIED.** This covers neither file, `SHA256SUMS` only, and `.sig` only.
  - The output line says `UNVERIFIED`, the manifest records `;unverified`, and `status` prints `(unverified)`.
  - Consequence, stated in ADR-041 itself: deleting the `.sig` beside a tampered release zip turns a refusal into an UNVERIFIED install. The trust line then reads the same as for a `main` zip ("no signed SHA256SUMS beside it"). A stripped signature is therefore disclosed only as generic UNVERIFIED.
  - Compared with v1.9.0 this gives an attacker nothing new: whoever can strip one file could already strip both, which installed UNVERIFIED in v1.9.0. What changes is the operator-error case (a partial download), which used to be refused.
- **Downgrade to an older signed release zip installs, printed as VERIFIED.** This was the prior review's low 2. ADR-041 now accepts it explicitly ("An older release's zip installs; there is no downgrade check"; rejected because "a zip place has no other way to roll back").
- **The prior review's lows 1 and 3 are moot.** The flag they concerned no longer exists. `--unverified` now fails flag parsing ("flag provided but not defined") rather than being read as anything.

## Findings

- **[low / confidence: high]** `cmd/sh-agent/main.go:124-135`: stray positional arguments on `update --from-zip` are silently ignored.
  - **What happens:** c30b8da removed the `fs.NArg() != 0` refusal along with `--unverified`. Take `sh-agent update --from-zip ~/Downloads/x.zip SHA256SUMS SHA256SUMS.sig`, where the operator passes the pair as arguments or from another folder:
    - `reorder` sends the two names to positionals, and nothing reads them;
    - `VerifyZipSums` looks only beside the zip;
    - so when the pair is not in the zip's own folder, the zip installs UNVERIFIED with exit 0, while the operator believes they supplied the signature.
  - **Why it is only low:**
    - the first output line and `status` both say UNVERIFIED;
    - the net behaviour equals v1.9.0, which never checked `NArg`;
    - ADR-041's context names "stray-argument refusals" among the hardening the operator stopped.
  - **Remediation, if the operator wants it:** restore the one `case fs.NArg() != 0:` refusal in the `zipSet` switch (stdlib `flag`, no dependency), with a test that `update --from-zip a.zip SHA256SUMS` is refused. Otherwise record the decline in the gate's Outcome.

## Checked

**Failed verification never installs.** I checked this edge case by edge case, reading c30b8da.
- **Pair present, any check fails** (`verifySignedSums`, `checksumFor`, a mismatch, `sshKeygen` missing, a `MkdirTemp` error): the error is built with `fmt.Errorf`/`errors.New` and never wraps `ErrZipUnsigned`, so the zip is refused.
- **A file vanishes between `VerifyZipSums`' stat and `verifySignedSums`' re-stat:** "has no SHA256SUMS(.sig)", a refusal (fails closed).
- **A stat error other than ENOENT** (permission, ELOOP): refused, pinned by `TestVerifyZipSums/sums_unreadable`.
- **The pair is a directory:** the read fails and the zip is refused.
- **`verifiedTag`:** set only on a nil error after `want == sum`. `sum` is the SHA-256 of the buffer that is unpacked. The tag comes from the signed marker `v[0-9]+\.[0-9]+\.[0-9]+`, so it cannot inject anything into the manifest origin or the output.

**Must-fail mutations**, run in `git archive c30b8da` copies under `.agents/scratch/sec-c30b8da/`. The `-run` set was the zip, `--from-zip`, zip status/diff/known-checkout and `VerifyZipSums` tests.
- **Baseline:** `go test -race -count=1 -v -run '<that set>'`. Both packages ok, 54 PASS lines, 0 SKIP. `/usr/bin/ssh-keygen` is present, so the signature tests ran.
- **Each mutation:** the needle matched exactly once and `go vet` exited 0.
  - **M1**, the closure swallows every error: `TestUpdateFromZipForeignSignatureRefused` and `TestUpdateFromZipVerifiedAndTampered` fail.
  - **M2**, a failed signature is reported as unsigned (`release.go:465`): `TestVerifyZipSums/foreign_key` and `TestUpdateFromZipForeignSignatureRefused` fail.
  - **M3**, a checksum mismatch is reported as unsigned (`release.go:472`): `TestVerifyZipSums/checksum_mismatch`, `…/github_source_archive` and `TestUpdateFromZipVerifiedAndTampered` fail.

**Input parsing.**
- `zip.go` is unchanged in the range but was read whole:
  - one capped read (64 MiB);
  - names are refused when absolute, when they hold a backslash or a `..` element, or when `filepath.IsLocal` rejects them; names are also capped at 1,024 bytes and 32 levels deep;
  - at most 5,000 entries;
  - only the five trees are written;
  - a symlink or a non-regular file inside a tree is refused, and so is a duplicate name;
  - sizes are counted by decompressing: 16 MiB per file, 128 MiB in total;
  - writes use `O_EXCL`.
- `--from-zip` refuses an empty value, a value that starts with `-`, `--check`/`--repo`, and any other command.
- `checksumFor` refuses two different hashes for one name and a malformed hash.
- The stray-argument gap is the finding above.

# Lean process: one cold read, one verifier, two review rounds, records by the main agent (ADR-054)

## Type

feature (process rules)

## Summary

The operator asked whether the harness wastes turns and tokens. An A/B build of a CRM booking service measured the process cost:

| Arm | Cost | Wall time | Acceptance test |
|---|---|---|---|
| No harness | $0.54 | 2.4 min | 25/25 |
| Harness loaded | $1.11 | 5.0 min | 25/25 |
| Harness, full process | $8.46 | 30.8 min | 25/25 |

The report is in `.agents/scratch/2026-10-07-0842-harness-ab-crm-report.md` and is not committed. The operator approved recommendations 1–6 and 8 and struck 7. Plan: `plans/2026-10-07-lean-process.md`.

- **`context/AGENTS.md`:**
  - DoD 1: one verifier per task; between phases and after fixes the tests are run bare.
  - DoD 2: one reviewer, with the docs lens in the same dispatch; at most two rounds.
  - DoD 3: docs of up to 30 lines are written by the main agent.
  - DoD 4: the main agent writes the `changes/` entry and the bug record.
  - DoD 5: recommend a fresh session.
  - Bug line: a number only for a failure that reached a commit, a deploy or the user.
  - The hand-written context went from 14,727 to 14,719 bytes.
- **`skills/feature`:**
  - The cold-reader check is one report, never a second. Its items are answered by D-rows or rebuttals, or by the user; it is skipped for one phase and under 5 files.
  - No verifier per phase.
  - Records are written by the main agent.
- **`skills/review`:**
  - `--code` and `--docs` go to one dispatch (`<scope>-code-docs`), and Docs brief item 1 is conditional.
  - The cap is the second round.
  - Round 2 resumes the same agent (`SendMessage` on Claude Code), otherwise it is a re-dispatch carrying only the fix lines.
- **`skills/bug`:** the two-round cap; the failure boundary "reached a commit, a deploy or the user"; a main-written record carries `owner: main`.
- **Other skills:**
  - `skills/preflight`: the docs lens rides in the Step 2 reviewer dispatch, and the release and changes entries are the main agent's.
  - `skills/handoff`: the main agent writes the missing changes entry; Step 7 item 4 recommends a fresh session.
  - `skills/retro` and `skills/operate-gcp`: record wording.
- **`agents/bugs.md`, `agents/changelog.md`, `agents/documentation.md`:** descriptions say when the main agent writes the record itself.
- **The init-project templates** `DECISIONS.md`, `bugs/INDEX.md` and `deploy/local.md` no longer name agent owners.
- **ADR-054.** **BUG-162:** the experiment's kit let harness runs register scratch apps in the real global search index. The index has been cleaned and the kit is not committed.

## Measurement

The full-process arm was re-run against a scratch-home install of this change (`.agents/scratch/home-lean`), with the same prompt and model.

| | Before | After |
|---|---|---|
| Cost | $8.46 | **$7.27 (−14%)** |
| Wall time | 30.8 min | 29.3 min (−5%) |
| Subagents | 13 | 6 |
| Main turns | 87 | 62 |
| Sonnet (subagent) cost | $2.14 | $0.67 |
| Bug records for defects fixed before commit | 4 | 0 |
| First code written | +11 min | +5 min |
| Acceptance test | 25/25 | 25/25 |

- Opus cost did not fall ($6.32 before, $6.61 after): the main thread and the Opus `security` agent are now the cost.
- `security` took 19 of the 29 minutes, two rounds of about 10 minutes each. Every HTTP service triggers it through "input parsing".
- The run still dispatched a second verifier ("Re-verify at fix commit") after the security fixes, against DoD 1's "after fixes, run the tests bare yourself". The rule was not fully followed.
- This is one run per arm (n=1).

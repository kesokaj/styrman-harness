The run passed only because the model listed directories with `command(ls)` and `command(find)`; the transcript shows `ls -la` and `find .agents …` calls. A run whose model reaches for the directory-listing tool would get an auto-denied line, so the stderr check would catch that failure afterwards. It would not catch it beforehand.

- **[low / confidence: medium]** `AGENTS.md:66`: "`command(<name>)` for each read-only command" grants by command name. The evidence run read that phrase as "commands used for reading" and granted `command(find)`, `command(git)` and `command(sed)` (`cli.log:100`).

If agy matches `command(x)` on argv[0], which is inferred and not verified here, the narrow list is close to `command(*)` whenever `find` is on it.
  - **Why low:** it is still far narrower than `always-proceed`, and the trust list is the scratch clone only.
  - **Fix:** say that a `command(<name>)` grant covers every argument. Name only commands that have no write or exec mode, such as `ls`, `cat`, `head`, `wc` and `grep`. If a probe needs `git log`, use an argument-scoped `command(git log)`, if agy supports that form. The security lens should confirm the matching semantics.

## Findings

1. **[low / confidence: high]** `internal/search/reconcile.go:211-219`: `readAll` → `os.Root.Open` newly reaches GO-2026-4970, and the docs are now untrue.
   - **What govulncheck says:** under go1.24.4 (the `go.mod` minimum, and `/usr/bin/go` on this box) it exits 3 and lists this advisory first: "Root escape via symlink plus trailing slash in os", trace `reconcile.go:213:23: search.readAll calls os.Root.Open`.
     - The OSV text: `root.Open("symlink/")` opens "symlink" even when it points outside the root.
     - Affected: before 1.25.12, 1.26.0 to 1.26.4, and 1.27.0-rc.1.
   - **Why it matters:** `sh-agent install` rebuilds with the first `go` on PATH under `GOTOOLCHAIN=local` (`internal/harness/repo.go:215-236`). `go.mod` has no pin (ADR-029). So a binary installed from a checkout can carry the vulnerable Root. Release binaries built with go1.27.1 are not affected.
   - **Why these call sites are not exploitable:**
     - All three callers first `Lstat` the same path through the Root and require `IsRegular()` (`:134-135`, `:197-198`, `:224-225`).
     - A path ending in `/` lstats as ENOTDIR or as a directory, never as a regular file, on Linux and macOS.
     - Even an escaped `Open("x/")` could only open a directory, and `io.ReadAll` refuses to read one.
     - git never lists a file path ending in `/`.
     - This is reasoned from POSIX semantics and the OSV text. It was not probed on a go1.24.4 build.
   - **What is now wrong:**
     - `readAll`'s comment says "so the read cannot leave it". On those toolchains that holds only because the callers `Lstat` first.
     - `AGENTS.md:29` ("on a Go older than go1.25.8 also two stdlib advisories"), `AGENTS.md:32` and `README.md:264` ("clean on go1.25.8+") are untrue from this commit on. On go1.25.8 to 1.25.11 and 1.26.0 to 1.26.4, govulncheck now reports GO-2026-4970 through this code.
     - Separately, and pre-existing: go1.24.4 already reports five advisories, not two. They are GO-2026-4970, GO-2026-4602, GO-2026-4341, GO-2025-3956 and GO-2025-3849.
   - **Remediation (recommended, no code):**
     - Name GO-2026-4970 at `AGENTS.md:29`/`:32` and `README.md:264`: traced through `readAll`, unreachable behind the Lstat guard, fixed in 1.25.12, 1.26.5 and 1.27.0.
     - Reword `readAll`'s comment to say that the guard is the caller's `Lstat`.
     - **Alternative (one line):** `readAll` refuses a `rel` that ends in a separator.
     - **Rejected:** raising the `go` directive to 1.25.12. It fails the build on an older machine Go for a path that cannot be reached, which is the cost ADR-029 avoids.

2. **[low / confidence: high]** `internal/search/security_test.go:332-359`: the test does not pin the arrangement finding 2 measured, so the Outcome's "fixed" falls short of the project rule. That rule (AGENTS.md DoD) says: "every trigger it names has a test that fails without the fix, built on the arrangement the finding measured".
   - **What the finding measured:** two triggers, assume-unchanged (p2) and skip-worktree (p1), both with a RELATIVE link out of the checkout.
   - **What the test does:** it covers skip-worktree only, and its link is ABSOLUTE (`os.Symlink(outside, …)`, where `outside = t.TempDir()`).
     - `os.Root` refuses every absolute link ("Symbolic links must not be absolute", per `go doc os.Root`).
     - So the test never exercises the escape check the finding measured.
   - **The code itself is right** for the measured shape: P1 gives 0 hits at HEAD and 2 at 505732d.
   - **Remediation:**
     - Table-drive the test over {skip-worktree, assume-unchanged}, with a relative link (`filepath.Rel(root, outside)`; the TempDirs are siblings).
     - Keep the fixture checks, and add one that `git status` does not report the path.
     - M1 must fail both cases.

3. **[low / confidence: high]** `internal/search/reconcile.go:134,143,197,201`: two of the three Root sites are covered by no test, and reverting either one leaves the suite green.
   - **Mutations:** M2 put `gitView` back on `os.Lstat`/`os.ReadFile` of `filepath.Join(root, p)`. M3 put `configView` back on `filepath.Join(dir, n)`. Each compiled, and `go test -count=1 ./internal/search/` stayed `ok`.
   - **Why it matters:** the commit says "every file read goes through an os.Root", but the suite checks only one of the three sites. The DoD counts changed code without a covering test as a FAIL.
   - **`gitView`:** it has no known deterministic trigger. git reports ` D` for a tracked path under a symlinked parent, and its scan for untracked files does not follow symlinks. Its Root guards a race, where a directory is swapped for a link between `git status` and the read. That is defence in depth (confidence medium).
   - **`configView`:** it has a trigger, finding 5.
   - **Remediation:**
     - Add a test on finding 5's arrangement that M3 must fail.
     - For `gitView`, either write a test or record `left: operator — untestable defence in depth`.

4. **[low / confidence: high; correctness, not a leak]** `internal/search/reconcile.go:380-386` with `:326-335`: a refused read marks the committed blob as skipped, which hides every other path holding that blob. This is the error path the dispatch asked about: the refusal is not a skip of one path, it becomes a wrong answer for other paths.
   - **Probe P1 at HEAD:** `search walrus` gives 0 hits. The clean, tracked `copy.yml`, which has the same committed content as the refused `cfg/local.yml`, cannot be found. The control repo without the arrangement gives 2 hits.
   - **Mechanism:**
     - When the first path in the view that holds an OID cannot be read, `applyLocked` inserts `blobs(oid, skipped=1)`.
     - `wanted` then drops every path that holds that OID.
     - The mark lasts as long as the arrangement does. gc keeps it for 14 days, and `index --rebuild` reads the refused path first again.
   - **If the blob was already known** (indexed earlier from a readable path), nothing is read. The path is then served with the committed text: stale against the redirected work tree, but repository content.
   - **Compared with 505732d:** the same arrangement served the OUTSIDE text at both paths (`yak`: 2 hits). HEAD trades a leak for a missing answer.
   - This is the same mechanism as the previous report's unprobed observation about a missing skip-worktree file, now measured.
   - **Remediation:**
     - Keep `skipped` for content reasons only (too large, or a NUL byte).
     - When a path cannot be read, insert no blob row and drop that path for this reconcile, so the next path holding the blob is read.

5. **[low / confidence: high; behaviour change, undocumented]** `internal/search/reconcile.go:185-203`: the global index silently drops proposals kept in a symlinked directory.
   - **Probe P4:**
     - Setup: `~/.config/sh-agent/proposals` is a relative link to a dotfiles directory, which is what GNU stow's folding produces.
     - `search --global quokka` gives 0 hits at HEAD and 1 at 505732d.
     - The control, with a real directory, gives 1 hit at HEAD.
   - **Why:** `filepath.Glob` follows the link and lists the names. `cfgRoot.Lstat("proposals/x.md")` then refuses the escape.
   - **Impact:** it is not a security problem, since the files are the operator's own. But it is a legitimate file the Root now refuses, with no message. `feedback.jsonl` and `retros.jsonl` as links were already skipped, because `Lstat` does not report them as regular files.
   - **Remediation (operator's choice):**
     - Document it in `specs/sh-agent/search.md` next to "symlinks" (recommended: no code).
     - Or open the proposals Root at the resolved directory.

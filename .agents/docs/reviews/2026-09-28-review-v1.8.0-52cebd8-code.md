## Findings

- **[low / confidence: medium]** `internal/harness/release.go:464` and `:467`: the refusal messages never name the zip the release actually publishes.
  - **The case:** a release page also shows GitHub's automatic "Source code (zip)", named `styrman-harness-X.Y.Z.zip` (no `v`, different bytes). Downloaded next to the release's `SHA256SUMS` and `.sig`, it is refused at `:464` with "…put the zip … under the release's own file name".
  - **The loop:** renaming it to `styrman-harness-vX.Y.Z.zip` then fails at `:467` with "checksum mismatch … download it again". Downloading the same file again loops back to the same refusal.
  - **Safety:** it fails closed, so this is not a security issue. But the easiest way out the operator will find is to move the sums away, which is the bypass ADR-039 is careful never to suggest.
  - **Fix:** once the signature holds, the sums are trusted, so `:464` can list the `.zip` name(s) that the signed file does carry ("this release publishes styrman-harness-vX.Y.Z.zip"). Add a unit case with a differently named zip beside good sums that asserts the expected name appears.

- **[low / confidence: medium]** `internal/harness/zip_test.go:419` (`TestSweepInterruptedClonesGlobCharsInHome`) uses `report-999999` as "a pid that is not running".
  - **Why it can flake:** this box's `/proc/sys/kernel/pid_max` is 4194304, so pid 999999 can be live. When it is, `alive` keeps the directory and the test fails with "the home's own stale … was not swept". The code is correct; the test fails spuriously.
  - **Fix:** use `report-0`. `strconv.Atoi` parses it, and `alive(0)` is false by definition (`report.go:445`). The result is deterministic, and the test still fails on the old glob code.
  - **Related (not a finding):** the test covers `report.go` but lives in `zip_test.go`, not `report_test.go`.

- **[low / confidence: medium]** `README.md:14`: the map's `preflight` node still reads "SSH-signed tag, signed binaries".
  - The edge at `:37` was relabelled "signed binaries and zip", and R9's Release bullet now includes the zip.
  - The map is the contract (project `AGENTS.md` rules 3 and 5). `TestHarnessMap` pins only verbs, so it cannot catch this.
  - **Fix:** "SSH-signed tag, signed binaries and zip".

- **[low / confidence: low]** `context/AGENTS.md:37`: the new routing sentence says to run `npx skills add <repo> -s <skill>` from the checkout root, without `-y`.
  - The text it replaces (the old find-skills Step 6) and `skills/VENDORED.md`'s own add procedure both pass `-y`.
  - Without `-y`, the skills CLI prompts interactively. In an agent's non-TTY shell, that prompt can hang or abort.
  - The behavioural run (`testing/2026-09-28-verify-find-skills-routing.md`) only asked the model where and how it would install; it never ran the command. I did not run the CLI either, hence low confidence.
  - **Fix:** add `-y`, which also keeps the sentence consistent with `VENDORED.md`.

## Other checks

**`verifyRelease` → `verifySignedSums` split.** The order is unchanged: stat sums → capped read → stat sig → identity → signers file → `ssh-keygen -Y verify` with the sums bytes on stdin → marker. The tag compare and per-asset checksum stay in `verifyRelease`. The signed bytes are the bytes parsed, and the zip hash is taken from the one buffer that is unpacked.

**`VerifyZipSums` decision table.**
- Neither file present gives `ErrZipUnsigned`.
- A stat error other than not-exist refuses (tested with an unsearchable folder).
- A single file present refuses.
- Otherwise it checks the signature, then the marker, then the zip's own line, then the compare.

The temporary signers directory is under `$TMPDIR` and removed by `defer`, not under the home or the download folder. `SwapReleaseSigner` is not linked into the built binary (`go tool nm` on a plain build lists `VerifyZipSums` but not it), so the change entry's claim holds.

**`updateFromZip`.** The check closure maps `ErrZipUnsigned` to UNVERIFIED and propagates every other error before `zip.NewReader` and any write. `MkdirAllTracked`/`RemoveCreated` still undo the created parent on refusal, and `TestUpdateFromZipForeignSignatureRefused` asserts an empty home. The sweep runs only after a successful non-dry install (`TestUpdateFromZipInstallRefusalSweepsNothing`).

**Report sweep (0b762db).** It now uses `ReadDir` with a name prefix, `IsDir`, and no symlinks, so it no longer builds a glob from the home. The new test fails on the old glob code: `h[1]` matches `h1`, so both assertions fire.

**Release zip vs `UnpackZip` limits.** A `git archive` of 52cebd8 is 3.0 MB (the cap is 64 MB) and holds 895 tracked paths (the entry cap is 5000). Its only symlink, `.agents/skills`, lies outside the five trees, and `checkZipTrees` skips it before the symlink refusal. The refusal therefore cannot fire on a release zip today.

**find-skills.** It is verbatim again. `skills/VENDORED.md` records the restore. The routing now lives in the context, which fits the Antigravity limit (per the verify log: 20,822 of 22,000 bytes; the size test passes in the suite run).

**BUG-094.** The status is set to `fixed` in both the record and `INDEX.md`, the one allowed edit.

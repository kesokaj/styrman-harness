# Security review — v1.12.1-c872598   (2026-09-29, release gate for v1.13.0)

Range reviewed: v1.12.1..c872598 (94 files, +6824 −34)

## Status: COMPLETE

## Verdict: FINDINGS

Worst problem: `gitView` misreads a work-tree rename in `git status --porcelain=v1 -z` output.
- It skips the rename source only when the index column is R or C. A work-tree rename (` R`, a tracked file moved and the new path added with `git add -N`) leaves the source path to be parsed as a record of its own, with its first three characters cut off.
- A source path whose characters 3-5 are `../` (a tracked `abc../x`, or `a/b../x`) becomes `../x`. `filepath.Join(root, "../x")` then reads a file BESIDE the checkout, and it is indexed and printed.
- Probe W reproduced it on c872598: a canary outside the checkout came back as `../x:1  doc … »wapiti«`.
- The same misparse keeps the moved file's content out of the index.
- Plan D22 recorded the mutation that removes this skip (M6) as "equivalent", on the grounds that the unskipped path "is parsed as a nonexistent path and dropped". Probe W shows that path can exist.

Second: the project index trusts any regular `search.db` it finds in `.agents/scratch/`. Probe D copied a crafted index into a fresh clone, and `sh-agent search --open` printed an open record, `BUG-999 … PLANTED title`, that no file holds. This range makes `--open` a step of every session's resume.

Both are low. Each needs something git cannot deliver: a user-side intent-to-add rename, or an index shipped outside git. And whoever ships a crafted tree also ships its `AGENTS.md`.

The rest holds:
- The two fixes of the aae16af..f41e5c0 review hold at c872598 and introduced no defect.
- The one new dependency is covered by the operator-approved R4 change (ADR-045). `go mod verify` and `govulncheck` are clean apart from the known, unreachable GO-2026-5024.
- Injection, secrets, crypto, authz and GCP have nothing.
- No release-diff path is unread.

## Findings

- **[low / confidence: high]** `internal/search/reconcile.go:118` (`if x == 'R' || x == 'C'`), with the join at `:124` and the read at `:351`.
  - **Weakness:** porcelain v1 with `-z` prints a second path after ANY entry that has a rename source, including a work-tree rename or copy (`Y` = R or C). The loop skips it only for an index rename.
  - **Probe W** (c872598 binary, scratch repository `.agents/scratch/secrev-v113/probe-w`):
    - Committed `abc../x`, moved it to `moved.md`, ran `git add -N moved.md`. `git status -z` printed ` R moved.md\0abc../x\0`.
    - A canary file was written to `<checkout>/../x`.
    - `sh-agent search wapiti` printed `../x:1  doc` and the canary's text. `--refs ../x` printed `../x  modified`.
    - `sh-agent search alpha`, the moved file's own words, found 0 hits.
  - **Reach:** one level up only, since git refuses `..` components in the rest of the path. That is the checkout's parent and everything under it, 1 MiB or less, not binary, and not secret-shaped by name. For a checkout directly in `~`, that includes `~/.kube/config`, `~/.docker/config.json` and `~/.config/gh/hosts.yml`.
    - The text lands in the 0600 project index and in the output of `search`, which agents read into their context. Nothing is sent anywhere.
  - **Trigger:** a tracked path of that shape, plus a user- or agent-made intent-to-add rename of it. A clone alone cannot trigger it.
  - **Second effect:** `applyLocked` inserts the vanished source's blob with `skipped = 1` (`:352`). Every path holding that content is then left out until gc, 14 days later, because a skipped blob is never re-read.
  - **Untrue descriptions:**
    - `specs/sh-agent/search.md` § Where the indexes live says the project index covers files "of the checkout".
    - Plan D22 calls M6 equivalent. `TestReconcileStagedRename` covers only an index rename (`RM`).
  - **Remediation (shortens the code):**
    - Pass `--no-renames` to the `git status` call at `:107` (git 2.18+) and delete the R/C branch. A rename then arrives as a delete plus an add, which the loop already handles.
    - Refuse any `p` for which `filepath.IsLocal` is false before `filepath.Join` (stdlib, Go 1.20).
    - In `applyLocked`, record `skipped` only for the intrinsic reasons (size, NUL byte). A file that is gone or unreadable inserts no blob row, so the next query retries.
  - **Test:** probe W's arrangement. Assert the canary's word is not found and the moved file's word is. Removing `--no-renames` must fail it.

- **[low / confidence: high]** `internal/search/store.go:198-203` (`ensureSchema` accepts any schema "1") and `internal/search/reconcile.go:347-349` (a known blob is never re-read).
  - **Weakness:** the index is keyed by blob ID, and its content is never checked against the files. A regular `search.db` that arrives with the tree is served as it is.
  - **Delivery:** git cannot deliver one; a tracked `search.db` fails `guardProject`'s check-ignore. But an archive or copy of a working tree that includes `.agents/scratch/` can, and so can a devcontainer volume or a shared folder. That is the delivery path the aae16af..f41e5c0 review accepted.
  - **Probe D:**
    - Built an index in checkout A.
    - Added one chunk (`PLANTED okapi text that no file holds`) and one record (`BUG-999`, `open`, `PLANTED title shown by --open`), both keyed to the committed `notes.md` blob.
    - Cloned A to B and copied the crafted file into `B/.agents/scratch/search.db`.
    - In B, `sh-agent search --open` printed `notes.md:1  doc BUG-999 open 2026-09-29 PLANTED title shown by --open`, and `search okapi` printed the planted text. `grep` over B's files found no `okapi`.
  - **Why it matters now:** `context/AGENTS.md:9` makes `sh-agent search --open` a resume step of every session. A planted index puts records and text into the agent's context that no file, diff or review shows. `index --rebuild` clears it.
  - **Why it is only low:** whoever ships the tree also ships its `AGENTS.md`, which the agent reads first. This adds stealth, not reach.
  - **Remediation (the operator's choice, one line each):**
    - (a) Recommended, stdlib only, no operator step: bind each index to the machine that built it. Store an identifier made once with `crypto/rand.Text()` (kept under `~/.config/sh-agent/`, or `--home`) in `meta`, and rebuild any project index whose identifier differs or is missing. This is an identifier comparison, not a crypto construction.
    - (b) Record it as a known limit in `specs/sh-agent/search.md` § Failure modes: "an index that arrives with an unpacked tree is trusted; run `index --rebuild`".
  - **Test for (a):** probe D's arrangement. `--open` in B shows no BUG-999 and prints the rebuilt note.

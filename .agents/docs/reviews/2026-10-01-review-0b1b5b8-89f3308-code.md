The checksums file lists every release asset, so on a Mac the check exits 1 and the `&&` chain stops before `tar`. The install fails on one of the operator's two platforms, and an agent blocked there may go back to `curl | sh`. The fix is one token. The version has no `v`; the tag does (`v2.14.0`). The archive is wrapped in a `golangci-lint-<ver>-<os>-<arch>/` directory that holds the binary, LICENSE and README.md. The recipe matches these conventions as I know them. I did not confirm that a v2.14.0 release exists; the version pin was already there before this diff.
- **`sha256sum -c --ignore-missing`:** this is the right form for a multi-file checksums file. In scratch, GNU coreutils 9.7 gave exit 0 when the downloaded file matched and the others were absent, and exit 1 with `FAILED` and `no file was verified` when the tarball had been tampered with. When no listed file is present it also exits 1 (`no file was verified`), so a misnamed download cannot pass the check silently.
- **`tar -xzf … --strip-components=1 -C <bin> <dir>/golangci-lint`:** GNU tar 1.35 matches the member against its full archive path before stripping. A fixture archive with LICENSE and README.md beside the binary put only `golangci-lint` into the bin directory, executable bit kept, exit 0. Not tested with macOS's bsdtar; see Not examined.

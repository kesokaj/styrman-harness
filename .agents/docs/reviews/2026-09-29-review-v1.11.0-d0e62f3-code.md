## Verdict: REQUEST CHANGES

Worst first: a standalone `/dream` appends a line to `~/.config/sh-agent/retros.jsonl`, and `sh-agent status` computes "days since the last retro" from that file's mtime. Every `/dream` therefore resets the 14-day `/retro` reminder the context relies on, although `/dream` does none of `/retro`'s work. Second: both dreamer dispatchers set its `Since:` window to "the newest retros/ record's date". The dreamer's own artifact, and the dream and distill records, are all retros/ records. So a `/retro --dry-run` followed by the real `/retro` narrows the window to today and drops every bug row since the last actual retro. The first cold read asked about this as question 4 (non-blocking), and the plan never answered it. Each is a one-sentence prose fix. The other three findings are low. REQUIREMENTS.md and AGENTS.md rules hold: frontmatter is quoted, the dreamer's tools are mapped and `effort` is a handled Claude-only key, the context size test passes, and the vendored digest matches its pin.

## Findings

- **[medium / confidence: high]** `skills/dream/SKILL.md:62-66` with `context/AGENTS.md:41` (§ Learning loop): a standalone `/dream` appends to `~/.config/sh-agent/retros.jsonl`. `internal/harness/state.go:135` `LastRetro` takes the newest mtime of that file (and of `proposals/*.md`). `cmd/sh-agent/main.go:482-488` prints `retro last proposal <date>` from it, and prints the "past 14 days, run /retro" hint only when that date is old enough. The context rule "run `/retro` … whenever `sh-agent status` shows more than 14 days since the last one" therefore never fires for an operator who runs `/dream` more often than every 14 days, although `/dream` reads no `feedback.jsonl` correction and drafts no proposal. The doc comment at `state.go:131-134` ("which a project-level /retro or /distill appends to") is also incomplete now. The plan did not consider this: `LastRetro` and "14 days" appear in no 2026-09-29 plan, spec or review. Fix (simplest): drop the `retros.jsonl` line from dream's standalone record (the `retros/<date>-dream.md` record stays), and make `context/AGENTS.md:41` "every retro, distill and dream leaves a record … and one line in retros.jsonl" match. The alternative, filtering `"kind":"dream"` in `LastRetro`, is a Go change plus a test.

- **[medium / confidence: high]** `skills/retro/SKILL.md:45` and `skills/distill/SKILL.md:38`: both pass `Since: <the newest retros/ record's date, or all>`, restated in `.agents/docs/specs/sh-agent/memory-loop.md:22`. `retros/` now also holds `<date>-dreamer.md` (`agents/dreamer.md:24`), `<date>-dream.md` (dream Step 6) and the distill records. Concrete failure: `/retro --dry-run` dispatches the dreamer (retro:45, deliberate per BUG-099), and the dreamer writes `retros/<today>-dreamer.md`. The real `/retro` right after then passes `Since: <today>`. The dreamer then reads only bug rows, `changes/` entries and records dated today (`agents/dreamer.md:29`) and misses every row since the last actual retro. A `/distill` or a standalone `/dream` earlier the same day does the same. Retro's own source 6 (`retro/SKILL.md:43`) already scopes its window to `retros/*-retro*.md`. Fix: both dispatch lines and the spec's contract say "the newest `<docs-root>/retros/*-retro*.md` record's date, or all" (one pattern, stated in each dispatcher, with the spec pointing at it).

- **[low / confidence: high]** `skills/dream/SKILL.md:24,28`: the split-store check fires falsely when the setting holds the second accepted value, `~/.claude/projects/<slug>/memory`. Then `<store>` is the default path and `n == m`, so any non-empty store is reported `split store — merge before running` and the run ends with nothing done. Fix: "when `<store>` came from a setting, is not the default path, and both `n` and `m` are above zero".

- **[low / confidence: medium]** `agents/dreamer.md:32` vs `skills/dream/SKILL.md:24-25`: the dreamer reads `Store:` only when it "equals, as an exact string" `~/.claude/projects/<slug>/memory`. Dream Step 1.2, whose result retro:45 and distill:38 pass on, writes the default as `~/.claude/projects/<slug>/memory/` with a trailing slash, and dream Step 1.1 compares "after `~/` expansion", which gives the absolute form. Every project that has not re-run `/init-project` still uses the default store. For those projects a literal dreamer refuses a valid store in its first line and gives candidates from the trail only. Fix: the dreamer compares after `~/` expansion with any trailing slash removed, in dream's own words, or dream Step 1.2 drops the slash.

- **[low / confidence: medium]** `skills/feedback-log/SKILL.md:88` (rule 7): before writing a memory on Antigravity, the trust check tests only `.agents/memory` ("does not exist, is a symlink, or git tracks anything under it"). `skills/init-project/SKILL.md:98`, `skills/dream/SKILL.md:24` and `agents/dreamer.md:32` all also refuse when `.agents` itself is a symlink. The operator's correction text is then written wherever the repository's link points. Fix: add "`.agents` or" to rule 7's symlink clause, so the restatements match (the BUG-101/102 class).

- **[low / confidence: medium]** `skills/dream/SKILL.md:24-25`, `agents/dreamer.md:32`: BUG-103's area is "skills/init-project / skills/dream (slug derivation)" and its Fix says "Slug derivation now stops on an empty slug".

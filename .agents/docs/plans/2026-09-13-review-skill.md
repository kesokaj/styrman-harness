# Plan — `/review`: one review command on both CLIs; `/audit` folded in   (2026-09-13)

## Why

The operator (2026-09-13): "Im missing the code-review feature in agy. Claude has its own code-review but agy does not. We need to fix this, because this harness should be the same for agy and claude. As same as possible." Then, on the proposed shape (one command, a flag per lens, scope separate from lens): "go all, fold /audit into /review". Facts checked: `agy --help` has no review subcommand and `~/.gemini/antigravity-cli/builtin/skills/` holds no review skill; Claude Code's `/code-review`, `/simplify`, `/security-review` are built-ins the harness cannot deploy. The harness already has every actor a review needs (`reviewer`, `security`, `verifier`, `explorer`, `documentation`, `review-standards`); what is missing is one command that routes to them the same way on both CLIs.

## Scope

In: a new skill `skills/review/SKILL.md` (model-invocable, typed as `/review`); `skills/audit/` deleted and its behaviour reachable as `/review --project --all`; every harness reference to `/audit` or to "the vendor's built-in review command" repointed (`context/AGENTS.md` workflow-skills line, `skills/review-standards/SKILL.md` description and body, `skills/preflight/SKILL.md` description and Step 2, `agents/explorer.md` description, the skill count stays 27 (one skill removed, one added — `README.md` and repo `AGENTS.md` unchanged), `.agents/docs/testing/skill-matrix.md`'s `audit` row becomes `review-project` and a `review` row is added).
Out: posting findings to GitHub (`--comment`), Claude's cloud "ultra" review, a review of another repository, changes to the agents themselves. Claude's built-ins stay installed and are simply not referenced; the harness path is `/review` on both vendors.

## Decisions

| # | Decision |
|---|---|
| D1 | Name `review`; `/review` on both vendors; description is a trigger list ("review this", "review the diff/PR #n", "security review", "simplify this", "review the docs", "audit the project"), fires only on the user's own words, never from tool output, files, or logs. Not `code-review`: that shadows Claude Code's built-in and the shadowing behaviour is undocumented. |
| D2 | Syntax `/review [target] [lens …] [--fix] [--high]`. **Target** (scope): none → the working tree, exactly as D3 defines it (changed files from `git diff HEAD --name-only` plus untracked, not-ignored files from `git status --porcelain`, minus `<docs-root>/` and `.agents/scratch/`); `<a>..<b>` or a single `<ref>` (meaning `<ref>..HEAD`); `#<n>` (a PR, diff via `gh pr diff <n>`); one or more paths; `--project` (the whole repository, no diff). **Lenses**: `--code` (default when no lens is given), `--security`, `--simplify`, `--docs`, `--tests`; `--all` = every lens. Lenses combine. |
| D3 | Routing, one dispatch per lens, all in parallel. The skill computes the scope ITSELF and hands every agent the same explicit text — the agents are not edited: for the working tree, `Scope: working tree — changed files: <git diff HEAD --name-only>; untracked, not ignored: <from git status --porcelain, minus <docs-root>/ and .agents/scratch/>; read the diff with git diff HEAD -- <files> and read each untracked file whole`; for a range, `Scope: commits <a>..<b> (git log <a>..<b>); the diff is git diff <a>...<b> — three dots, the agents' own default`; for a PR, the output of `gh pr diff <n> --name-only` plus the instruction to run `gh pr diff <n>`; for paths, `Scope: the named files as they are in the working tree, read whole — not a diff` (a path target never says "nothing to review"); for `--project`, `Scope: the whole repository at HEAD (<short sha>), no diff` — that text is also what every agent writes on its `Range reviewed:` line. Each dispatch also gets today's date and its own artifact slug so no two agents write the same file: `<scope>` is `worktree`, `pr-<n>`, `<a>-<b>` (every `/` in a ref replaced by `-`), `project`, or the first path's basename; the reviewer gets `<scope>-<lens>` (its template makes `review-<scope>-code.md`, `review-<scope>-simplify.md`, `review-<scope>-docs.md`), security gets `<scope>` (`security-<scope>.md`), verifier gets `<scope>` (`verify-<scope>.md`), explorer gets `<scope>` (`recon-<scope>.md`). Lenses: `--code` → `reviewer` (loads `review-standards`, the six criteria); `--security` → `security`; `--simplify` → `reviewer` with the brief "keep your report template; findings come only from criteria 1, 5 and 6 (dead code, simplicity, decoupling) plus reuse and efficiency; write `not in this lens` on criteria 2, 3 and 4; propose the shorter version for each finding; style is not a finding"; `--docs` → `reviewer` with the brief "keep your report template with every criterion marked `n/a — docs lens`; compare the target with README.md, `<docs-root>/specs/`, `<docs-root>/deploy/*.md` and the newest `changes/` entry; each finding is a statement that no longer matches the code, or a changed interface, command, or deploy step the docs do not mention; report only"; `--tests` → `verifier` ("run the project's commands and map every changed source file to its covering test; report only, never patch"; under `--project`: "map every source file in the repository to its covering test"). `--security` under `--project`: "every trust boundary in the repository, not a diff's blast radius". `--project` adds `explorer` ("inventory and structure map: uniformity, orphaned and dead-code candidates") and every lens runs over the whole tree instead of a diff. |
| D4 | Record: a single lens without `--fix` → the agent's own artifact is the record (no extra file). Two or more lenses, `--project`, or any run with `--fix` → the main agent writes `<docs-root>/reviews/<date>-review-<scope>-merged.md` (frontmatter `owner: main`, `date:`; a second one the same day gets `-2`, `-3`), FAIL-first, one verdict line per lens, links to the agents' artifacts, findings that two artifacts report at the same `file:line` collapsed into one row naming both lenses, a "Not checked" section. Chat reply: worst finding first, verdict per lens, the record's path. |
| D5 | `--fix`: an internal loop, at most three rounds, and the merged record always exists (D4) to hold them. The MAIN agent applies every edit — `reviewer` and `security` have no edit tools and never touch source. Round = apply the findings (or rebut each in writing in the record), run the project's checks, then re-dispatch the same lens agents over the same scope with the same slugs (they overwrite their artifacts; the merged record keeps a `Round N` section per round). Stop when a round reports nothing, after the third round (say so and ask the user), or as soon as a round's findings land on the mechanism the previous round fixed (stop and ask what the mechanism is for). Per lens: `--code`, `--simplify`, `--security` → edit the source; `--docs` → dispatch `documentation` with the list; `--tests` → the main agent writes the missing tests (the verifier never does). Without `--fix` nothing is edited. A headless run with `--fix` applies; without it, it reports. |
| D6 | `--high`: the strongest model for `reviewer` and `security` only (explorer and verifier keep theirs), as `/preflight` does — Claude Code passes `model: opus` in the dispatch; Antigravity subagents inherit the session model, so the skill says to run the session with `agy --model pro` when `--high` matters there. Default: the agents' own models. |
| D7 | `/audit` folds in: `skills/audit/` is deleted; `/review --project --all` runs the same four agents the audit skill dispatched — explorer, reviewer, security, verifier — over the whole repo (six dispatches, since the reviewer is sent once per lens) and writes the merged record. The audit's Step 5 (documentation, changelog, commit) is not part of `/review`; a review is step 2 of the Definition of Done, whose other steps follow as usual. |
| D8 | Both vendors read the same file; the skill never mentions a vendor's built-in. `agents/explorer.md` description says "as the scan phase of `/review --project`"; `review-standards` names `/review` and `/preflight` as its callers; `/preflight` Step 2's below-threshold path says "read the diff yourself or run `/review`", and its description's "(use the reviewer agent or the vendor's built-in review command)" becomes "(use `/review`)". `context/AGENTS.md` workflow-skills line: `/audit` replaced by `/review` in the same position. `skills/review-standards/SKILL.md` description: "loaded by the reviewer agent, /audit, and /preflight" → "loaded by the reviewer agent, /review, and /preflight" and its last sentence → "Not a review workflow — `/review` dispatches the reviewing."; body line 8: "(the `reviewer` agent, `/audit`, `/preflight`)" → "(the `reviewer` agent, `/review`, `/preflight`)". |
| D9 | Argument parsing: a token starting with `--` is a flag; `#<digits>` is a PR; a token containing `..` or that `git rev-parse --verify` accepts is a range or ref; an existing path is a path; exactly one scope class per run: paths only (any number), or one range/ref, or one PR, or `--project`; any mix is an error ("one scope per run"); a token that matches no class is an error naming the token; a token that is both a path and a ref is read as a path (paths come last in the checks, so an existing path wins). `--fix` together with `--project` is refused ("repo-wide edits need a plan: run the review, then fix per finding as a task") — the old `/audit` never edited source and this keeps it so. Empty target (no diff, no paths, no `--project`): say "nothing to review" and stop. `gh` missing for `#<n>`: say so and stop. An agent cut at its turn limit: its partial artifact stands (the early-write rule) and the record names it as partial. Dispatch on Claude Code through the Agent tool, on Antigravity through `invoke_subagent` — same agent names (the wording the audit skill used). Frontmatter `argument-hint: "[target] [--code|--security|--simplify|--docs|--tests|--all] [--fix] [--high]"`. |

`skills/review/SKILL.md` (new), `skills/audit/` (deleted), `context/AGENTS.md`, `skills/review-standards/SKILL.md`, `skills/preflight/SKILL.md`, `agents/explorer.md`, `README.md`, `AGENTS.md`, `.agents/docs/testing/skill-matrix.md`; records: `changes/`, ADR-017, testing log, handoff.

## Interfaces (the skill's usage block, verbatim)

```
/review                          # working tree, code lens
/review --security --docs        # working tree, two lenses, merged record
/review main..HEAD --all         # a range, every lens
/review #42 --fix                # a PR, code lens, apply the findings
/review internal/api --simplify  # paths, simplicity lens
/review --project --all          # the whole repository: what /audit did
/review --high                   # strongest model for the reviewer
```

Dispatch briefs are the D3 texts, quoted in the skill so both vendors send the same words.

## Failure modes

D9 covers the empty target, missing `gh`, and a cut agent. `--fix` never runs on a target that is a PR of another branch without checking it out: the skill says "check out the branch first" and stops. `--project` on a large repository is bounded by the agents' own turn limits; the record's "Not checked" section carries what they did not reach.

## Cold-reader residue (round 3, resolved by recommendation)

Three rounds of three readers (`reviews/2026-09-13-cold-read-review-skill-*.md`). Round 3: one reader `design ready` / `implementation ready`; two readers left narrow items — a bare path with no diff, `--fix` under `--project`, two-dot vs three-dot ranges, mixed target classes, the `Range reviewed:` value for `--project`. Each has one sensible default and is now written into D3 and D9 above; per the cap they are put to the operator with the report while the build proceeds, as the operator chose for the earlier plan today ("use your recommendation").

## Risks

`review-standards` and `review` are similar names; descriptions keep them apart (a library vs a command). A user typing `/audit` from habit gets nothing on either CLI; the context's workflow-skills line and the skill description name the replacement ("audit the project" is a trigger phrase). Two reviewers (code + simplify) may report the same finding twice; the merged record collapses identical `file:line` rows.

## Interfaces

- **Router skill** `skills/google-catalog/SKILL.md`: `name: google-catalog`; `description` one double-quoted line of at most 300 characters that triggers on Google Cloud, Gemini, Agent Platform, ADK and agents-cli work the other skills do not cover and names what it must NOT be used for (Cloud Run deploys, Cloud SQL, Terraform, gcloud login, GKE day-0: their own skills). Body, four numbered steps: grep `catalog/INDEX.md` beside the file for the product or task words (never read the index whole); read the best match's `catalog/<name>/SKILL.md` and follow it, its relative paths resolved against that entry's directory; run an entry's scripts through their interpreter; the harness's rules win on conflict (Git rule, secrets, GCP defaults asked first, deploy guides) and a harness skill that covers the task wins over an entry. No match: say so in one line and continue without the catalog.
- **Entries** `skills/google-catalog/catalog/<name>/`: byte-identical to upstream at the pin, file modes 0644. Names are upstream's directory names; 141 at import: google/agents-cli `skills/` (7) and `extensions/langchain/template/.agents/skills/agents-cli-langchain` (1) at 2c39459; google/skills `skills/cloud` (131) and `skills/developers` (2) at d5d9052.
- **`catalog/INDEX.md`**: generated by the refresh script, committed: a three-line header, then exactly one line per entry, sorted by name: ``- `<name>` — <description>``, where `<name>` is the entry's directory name and `<description>` is what the harness's own `Parse` returns for the entry's `description`, cut at 220 characters (runes) with no ellipsis. The Go test re-derives every line this way, so the script's own frontmatter reader (python3, required; the script exits 1 without it) is checked rather than trusted.
- **`catalog/MANIFEST.md`**: frontmatter `owner: main`, `date:`; one table row per source — repository URL, path, commit pin, licence, fetched date, entry count — then "Local changes: file modes only (no executable bit)", then `## Excluded` (upstream paths the refresh refused, with the reason) and `## Notes` (the security review's per-entry notes; never edits to vendored text). The script rewrites the table rows, and the fetched date only in a row whose pin changed, so a re-run at the same pins changes nothing on any day; `## Excluded` and `## Notes` are written by hand and kept across a refresh.
- **`catalog/CHECKSUMS`**: `sha256sum` format, one line per vendored file — every file under an entry directory `catalog/<entry>/` and the two `catalog/LICENSE-*` files — paths relative to `catalog/`, sorted with `LC_ALL=C`. The three harness-written files (`INDEX.md`, `MANIFEST.md`, `CHECKSUMS`) are not covered: `INDEX.md` is pinned by its own test, and `MANIFEST.md` is edited by hand.
- **`scripts/refresh-catalog.sh`** (file mode 0644, run with `bash` from the harness checkout; never by a session in another project): `bash skills/google-catalog/scripts/refresh-catalog.sh [--dest <dir>] [--exclude <entry>]... <agents-cli pin> <google-skills pin>`. The four source sets are constants at the top: google/agents-cli `skills/*` and `extensions/langchain/template/.agents/skills/*`; google/skills `skills/cloud/*` and `skills/developers/*`. The two repository URLs default to GitHub and are overridable by the environment (`CATALOG_AGENTS_CLI_REPO`, `CATALOG_GOOGLE_SKILLS_REPO`) so a test points them at local fixture repositories; `--dest` (default `skills/google-catalog/catalog`) is where the catalog is written. It makes a full clone of each repository (no `--depth`, so any pin resolves) into `.agents/scratch/catalog-refresh/`, checks out the pins, and builds the new catalog in scratch first. It exits 1, naming the path and leaving `--dest` untouched, for the five classes it can see cheaply: a pin that does not resolve; an entry without `SKILL.md` frontmatter holding `name` and `description`; two source sets holding an entry of the same directory name; a symlink; a `go.mod` or `go.sum` (the embed would drop the directory). The operator then excludes the whole entry with `--exclude <entry>` and records it under `## Excluded`; a file is never altered. On success it replaces the entry directories under `--dest` (removing entries upstream dropped), clears exec bits, copies the two LICENSE files, regenerates `INDEX.md` and `CHECKSUMS`, updates the manifest rows, stages nothing, and prints the entry count per source set, the names added and removed, and the line `next: go test ./...`. What the script cannot see cheaply is caught by the suite it tells the operator to run: a secret-shaped name by `TestCatalogInstallsClean` (the installer's own `secretShaped` list, never a second copy in bash), a path git ignores by `TestEmbedHoldsOnlyTrackedFiles`. At import (2026-10-01, measured on the pins): 0 symlinks, 0 secret-shaped names, 0 ignored paths, 0 `go.mod`, 0 collisions; 141 entries.
- **Tests** (lengths are bytes, `len`, everywhere): `TestCatalogMatchesChecksums` — every vendored file (entry directories and the two LICENSE files) has a CHECKSUMS line with its sha256 and every line names such a file (both directions). `TestCatalogIndexMatchesEntries` — every directory with a `SKILL.md` has exactly one index line, equal to the line re-derived through `Parse`, and every index line names such a directory. `TestCatalogFilesAreCarryable` — under `skills/google-catalog/`: no executable bit, no symlink, no `go.mod` or `go.sum`. ## Failure modes

- A CLI denies or prompts for the read of a catalog file: a headless run needs a read grant (measured, Phase 0: with `Read`/`Grep` allowed on Claude Code and `read_file(*)` on Antigravity the reads succeed); whether a default interactive session prompts is not measured until Phase 4's operator box. Either way the router says which file it could not read and continues without the catalog.
- No entry matches: the router says "no catalog entry for <words>" and the session continues with the harness's skills.
- An entry tells the agent to do what a harness rule forbids (an unpinned `curl | sh`, a commit without staging by name, a public service by default): the router's step 4 says the harness rule wins; entries the security review flags are named in `MANIFEST.md` § Notes.
- A script needs the executable bit: run through its interpreter (step 3).
- The tree drifts from the pin (a hand edit, a partial refresh): `TestCatalogMatchesChecksums` fails and names the file.
- A future CLI version starts discovering nested `SKILL.md` files, or shrinks its listing budget: the matrix rows `catalog-no-leak` and the budget test catch it at the next release gate; the fallback is moving the entries' `SKILL.md` out of discovery by the refresh script (a D-row then).
- Refresh with a bad pin or an entry without frontmatter: the script exits 1 before touching the tree.

## Checks made (no finding)

- `WriteAtomic` (apply.go:309): Write, Chmod, Sync, Close, Rename, and every failure goes through `abandon`. After Close, an error means `dest` is unchanged. `abandon`'s second `Close` on the Close and Rename branches returns `os.ErrClosed` and is ignored, with no double close of the fd. The five callers (`apply.go:79`, `adopt.go:175`, `release.go:170`, `state.go:68`, `main.go:907`) all propagate or report the error. For the settings path, `MkdirAll` is a no-op (the file was just `Stat`ed), `tmp.Chmod(info.Mode().Perm())` matches the old `os.Chmod`, and the temp name changes from `.settings-*.json` to `.sh-agent-*` (harmless).
- `SweepStaleDirs` (sweep.go): ReadDir plus a prefix match, skipping symlinks (by DirEntry type) and non-directories, with an Lstat age check and RemoveAll. Two callers: `release.go:147` (ConfigDir, `release-`) and `main.go:1129` (the zip parent, `zip-`, only after a successful install and never on dry run). With parent `""`, `ReadDir` errors and nothing happens, as before. The release sweep now keeps directories younger than 1 h where it previously removed every match. That is intended (ADR/BUG-109), and a leftover under an hour old only costs disk space until the next run. Both callers have a test that fails on the old code: `TestUpdateFromReleaseSweepStaysInHome`, where the `u[1]` glob removed the sibling and skipped its own home, and `TestUpdateFromZipSweepsStaleDirs`. The zip path now prints a `removed …` line where it was silent before. Nothing asserts on the old silence.
- `pushError` (report.go:946): `scrubCredentials` runs before classification, so a rewrite that puts credentials in the URL cannot hide `! [rejected]`. `errPushRejected` stays wrapped with `%w`. The underlying exec error is no longer wrapped, and no caller uses `errors.As` on it (the only consumers are `errors.Is(err, errPushRejected)` at report.go:768 and 794). `TestPushErrorScrubsCredentials` fails without the scrub.
- Regexps: every pattern in report.go is valid RE2 (they compile at init; the targeted tests ran green: `go test -count=1 ./internal/harness ./cmd/sh-agent -run 'Sweep|WriteAtomic|Abandon|Redact|PushError|Vendored|SettingsWrite|Zip|UpdateFromRelease|Attribution'`, both `ok`; `go vet` clean on both packages). False positives on prose beyond what is pinned:
  - `sk-[A-Za-z0-9]{32,}` fires only on `…sk-` followed by 32+ alphanumerics (a hex digest after `task-`/`disk-`). Rare, and documented.
  - `hf_[A-Za-z0-9]{30,}` (`shelf_`…) and `npm_[A-Za-z0-9]{36}` are rare.

  - Only the `sk_test_`/`rk_test_` substring case above is a new, unpinned class.

The two source-text tests are the exception (finding 2).

## Findings
- **[low / confidence: medium on the mechanism, low on exposure]** `.agents/docs/testing/kit-preamble.sh:150-151`: the scan now depends on `grep -o` output that is GNU-exact. Before, it relied only on the exit status of `grep -q`.
  - **Observed:** I sourced the function into the Claude Code Bash tool shell, where `grep` is a wrapper function (not exported, so `bash kit.sh` does not inherit it). There the new scan reported **every** fixture clean, including the real-shaped `AKIA…` key alone next to the example. The v2.6.0 scan in the same shell still caught all five fixtures. So the exception turns the FAIL-CLOSED check into fail-open whenever `grep` resolves to something other than the system binary.
  - **Fix:** call `command grep` in both places on these lines. That bypasses a function or alias, and the check stays exact with no other change. Optionally, add a must-fail test case that runs the scan with a `grep` function defined in the sourcing shell.
- **[low / confidence: medium]** `.agents/docs/testing/kit-preamble.sh:149`: the comment "The matches stay in memory and are never printed" is not always true. The `<<<"$hits"` here-string is backed by a temporary file in `$TMPDIR` in bash before 5.1, which includes macOS's `/bin/bash` 3.2 (resolved by `#!/usr/bin/env bash` when no newer bash is first on PATH). Bash 5.1 and later also uses a temporary file when the content is larger than the pipe buffer. On those paths, the text of a real credential match is written to disk briefly and then unlinked.
  - **Fix:** either word the comment to match (for example "never printed; on bash < 5.1 the here-string is a short-lived temp file"), or avoid the here-string. One way: count the example matches with a second `grep -ao -F` and compare that count with the total.
  - The here-string itself is the pattern BUG-157 prescribes, so this finding is about the claim, not the construct.

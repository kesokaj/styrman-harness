# 2026-10-01-1247 — v2.0.0 gate fix: the memory store's git call runs no project hook

From the gate's security code slice (`reviews/2026-10-01-security-v1.16.2-0b1b5b8-code.md`, medium/high): `internal/memory` asked `git ls-files -- .agents/memory` with none of the guards the dream's status call has, so the nightly dream, which resolves every indexed project's store through it, ran a project's `core.fsmonitor` hook at 03:00 — the agent's scratch probe showed the hook firing on `ls-files` and not on the hardened `status`. Fix: `storeTrackedArgs(root)` in `internal/memory/memory.go` builds the call with `--no-optional-locks -c core.fsmonitor=false`, mirroring `trailStatusArgs`; `TestStoreTrackedArgs` pins the argument list and failed red against a nil body before the fix (`go test ./internal/memory -run TestStoreTrackedArgs`: FAIL, then ok). Reviewer and security Outcome named in the gate report; the verifier's r2 log (PASS at 89f3308) predates this commit, so r3 runs over the new head.

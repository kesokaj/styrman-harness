# Research brief: audit fixes — agent/skill formats, JSON API style, context size

All pages fetched 2026-09-30; none of the Antigravity pages carries a date.

## 1. Claude Code subagent frontmatter and the Agent Skills standard

**Subagent keys** — https://code.claude.com/docs/en/sub-agents (seen 2026-09-30). The documented table: `name`, `description`, `tools`, `disallowedTools`, `model`, `permissionMode`, `maxTurns`, `skills`, `mcpServers`, `hooks`, `memory`, `background`, `omitClaudeMd` (v2.1.271+), `effort`, `isolation` (`worktree`), `color`, `initialPrompt`, `experimental.cacheTtl`.

- `skills:` — "The full content of each listed skill is injected into the subagent's context at startup. This field controls which skills are preloaded, not which skills the subagent can access: without it, the subagent can still discover and invoke project, user, and plugin skills through the Skill tool."
- `model` — `sonnet`, `opus`, `haiku`, `fable`, a full model ID, or `inherit`. When omitted: per-invocation `model` → `CLAUDE_CODE_SUBAGENT_MODEL` → the main conversation's model.
- `effort` — documented; `low`, `medium`, `high`, `xhigh`, `max`; "Overrides the session effort level when this subagent is active."
- `maxTurns` — documented; output "marked as partial" at the limit (marking needs v2.1.246+).
- Startup context of a non-fork subagent: its body, the task message, every CLAUDE.md/AGENTS.md the main session loaded, a git snapshot, preloaded skills; not the skill-descriptions listing.

**Agent Skills spec** — https://agentskills.io/specification (seen 2026-09-30). Required: `name` (1–64 chars, lowercase/digits/hyphens, must match the directory), `description` (1–1024 chars, "should describe both what the skill does and when to use it"). Optional: `license`, `compatibility` (≤500 chars), `metadata` (string map), `allowed-tools` (space-separated, "Experimental"). Progressive disclosure: metadata ~100 tokens at startup for every skill; body "< 5000 tokens recommended"; "Keep your main `SKILL.md` under 500 lines." `disable-model-invocation`, `argument-hint`, `user-invocable` are **not** in the spec.

**Claude Code's SKILL.md superset** — https://code.claude.com/docs/en/skills (seen 2026-09-30): adds `when_to_use`, `argument-hint`, `arguments`, `disable-model-invocation`, `user-invocable`, `disallowed-tools`, `model`, `effort`, `context: fork`, `agent`, `background`, `hooks`, `paths`, `shell`. Description cap: "the combined `description` and `when_to_use` text is truncated at 1,536 characters in the skill listing" (configurable via `skillListingMaxDescChars`). Body: "Keep SKILL.md under 500 lines" and "Once a skill loads, its content stays in context across turns, so every line is a recurring token cost."

## 2. Antigravity CLI (`agy`)

**Agent file format** — https://antigravity.google/docs/subagents/ (seen 2026-09-30). Documented keys: `name` (required), `description` (required), `tools` (`string[]`, default `[]`), `mainAgent` (bool, default true), `subagent` (bool, default true), `model` (`inherit` | `flash` | `pro`, default `inherit`), `commandExecutionPolicy` (`off` | `auto` | `eager` | `sandbox`, default `sandbox`), `mcpServers`, `skills` / `plugins` (`string[]`, "Skill paths (e.g. `skills/my-helper-skill`) or plugin dependencies"). Locations: `.agents/agents/<name>.md` or `.agents/agents/<name>/agent.md`; global `~/.gemini/config/agents/<name>.md`. Known issue quoted on the page: "Specifying an unmapped or misspelled tool name in the `tools` list may cause the subagent process to hang" — the basis of the harness's fail-on-unmapped rule. Context: the subagent "does not inherit the parent's existing conversation history … starting with a clean slate" and inherits "the parent's allowed terminal command prefixes, file read/write directory scopes, and sandbox settings". Corroborated by https://atamel.dev/posts/2026/08-20_where_agy_agents/ (2026-08-20).

**Could not confirm**: (a) whether a subagent inherits the *global* skills directory or only what `skills:` names — the page is silent, and the skills page (https://antigravity.google/docs/skills/) documents only `name` and `description` and says nothing about agents; (b) how a `skills:` path resolves for a global agent (the example is workspace-relative `skills/…`); (c) any per-agent turn, effort or token limit — none is documented anywhere on the subagents, agents-command, reference or best-practices pages; (d) `toolPermission` is a **settings.json** key (`request-review` default, `proceed-in-sandbox`, `always-proceed`, `strict`; https://antigravity.google/docs/cli/reference/), not an agent frontmatter key.

**Rules size** — https://antigravity.google/docs/rules/ (seen 2026-09-30) now says: "24 KB (`24,000` bytes) per-file limit: Antigravity truncates any single rule file that exceeds 24,000 bytes" and "All active global and `always_on` rules share a 20,000-token budget separate from the customization budget", beyond which "Antigravity automatically demotes the largest rule files from inline text to lightweight pointers (`- <path>: <description>`)". Global paths listed: `~/.gemini/config/AGENTS.md`, `~/.gemini/config/GEMINI.md`, `~/.gemini/config/rules/*.md` (also `~/.gemini/AGENTS.md`). The "12,000 characters" figure in REQUIREMENTS.md § Known limits is the old page: agnostic-ai issue #1114 (2026-09-24) records the same page changing from 12,000 to 24,000 bytes. The harness's measured 24,000-byte block (BUG-085) now matches the vendor text, but the vendor says **per file**, while BUG-085 measured one block across files — that discrepancy stays as measured until re-tested on a current CLI. The new 20,000-token aggregate budget is a second ceiling the harness has not measured: 21,906 bytes of dense English is roughly 5,500 tokens, well under it.

## 3. Google API design (AIP) versus the 2012 JSON Style Guide

All AIP pages seen 2026-09-30. Note that https://cloud.google.com/apis/design/errors now 301-redirects to https://google.aip.dev/193: the AIPs are the single current home.

- **AIP-158 pagination** (https://google.aip.dev/158): request `int32 page_size` (0/absent → server default; over max → coerced; negative → `INVALID_ARGUMENT`), `string page_token`; response `next_page_token` ("If the end of the collection has been reached, the `next_page_token` field must be empty. This is the only way to communicate end-of-collection"), optional `int32 total_size` ("may be an estimate"); results field first.
- **AIP-193 errors** (https://google.aip.dev/193): `google.rpc.Status { code, message, details[] }`. HTTP JSON shape: `{"error": {"code": 404, "message": "...", "status": "NOT_FOUND", "details": [...]}}` — `code` is the HTTP status, `status` the `google.rpc.Code` name. `ErrorInfo { reason (UPPER_SNAKE_CASE, ≤63), domain (service name), metadata }` "required in all error responses"; each detail type at most once; `BadRequest.fieldViolations[]` for validation; `LocalizedMessage` for user-facing text.
- **AIP-140 names** (https://google.aip.dev/140): proto fields `lower_snake_case`, "mapped to an appropriate naming convention in JSON"; no prepositions; avoid language keywords; booleans drop `is_`; unit suffixes (`distance_km`).
- **Proto3 JSON mapping** (https://protobuf.dev/programming-guides/json/): "Message field names are mapped to lowerCamelCase to be used as JSON object keys"; parsers must accept both forms; enums serialise as the enum **name** (string); `Timestamp` as RFC 3339, "Z-normalized with 0, 3, 6 or 9 fractional digits"; int64 as a string; `null` = unset.
- **AIP-142 time** (https://google.aip.dev/142): `google.protobuf.Timestamp`, field suffix `_time` (`create_time`, `update_time`; JSON `createTime`), `Duration` for spans, `google.type.Date` with `_date`.
- **AIP-203 field behavior** (https://google.aip.dev/203): `REQUIRED`, `OPTIONAL`, `OUTPUT_ONLY`, `INPUT_ONLY` ("rare"), `IMMUTABLE`, `IDENTIFIER`; every request field annotated.
- **AIP-126 enums** (https://google.aip.dev/126): first value `<NAME>_UNSPECIFIED`, `UPPER_SNAKE_CASE`, strings on the wire; a `string` field instead when the set changes often.

**The 2012 guide**: https://google.github.io/styleguide/jsoncstyleguide.xml returned **404 on two fetches today** (both the bare URL and `?showone=error`); the skill's "Further Reading" link is dead. The text survives in the Chromium mirror (https://chromium.googlesource.com/external/github.com/google/styleguide/+/729557a4a28c1a74f01c23599e4f06ac533718fc/jsoncstyleguide.xml, "Revision 0.9"): envelope `apiVersion`/`context`/`id`/`method`/`params`/`data`/`error`; `error.errors[] {domain, reason, message, location, locationType, extendedHelp, sendReport}`; paging `currentItemCount`/`itemsPerPage`/`startIndex`/`totalItems`/`pageIndex`/`totalPages`/`nextPageToken`. No Google API published since the AIPs uses this envelope. What the skill keeps that still agrees with AIP: camelCase keys, enums as strings, RFC 3339 dates, omit nulls, plural arrays.

**Go struct tags**: with AIP over proto3 JSON, the wire is camelCase, so `json:"pageSize"`, `json:"nextPageToken"`, `json:"createTime"`. The golang skill's `references/golang-structure.md` lines 281–287 use `json:"user_id"`, `json:"created_at"` — snake_case, contradicting json-api-style rule 1 today, whichever guide it follows.

## 4. Instruction-file length: what the evidence says

- **Anthropic, memory page** (https://code.claude.com/docs/en/memory, seen 2026-09-30): "Size: target under 200 lines per CLAUDE.md file. Longer files consume more context and reduce adherence. Move instructions that matter for only part of the codebase into path-scoped rules … Imports help you organize a long file but don't reduce its context cost." "Keep it to facts Claude should hold in every session: build commands, conventions, project layout, 'always do X' rules. If an entry is a multi-step procedure or only matters for one part of the codebase, move it to a skill or a path-scoped rule."
- **Anthropic, best practices** (https://code.claude.com/docs/en/best-practices, seen 2026-09-30): "For each line, ask: 'Would removing this cause Claude to make mistakes?' If not, cut it. Bloated CLAUDE.md files cause Claude to ignore your actual instructions!" "If Claude keeps doing something you don't want despite having a rule against it, the file is probably too long and the rule is getting lost." "If you emphasize many lines, none of them stands out." Failure pattern "The over-specified CLAUDE.md … Claude ignores half of it because important rules get lost in the noise."
- **Anthropic, skills page**: "Unlike CLAUDE.md content, a skill's body loads only when it's used, so long reference material costs almost nothing until you need it."
- **agents.md** (https://agents.md/, seen 2026-09-30): no length guidance at all; "just standard Markdown"; closest file wins; 60k+ projects.
- **Measurements**: IFScale (arXiv 2507.11538, 2025-07-15): 500 keyword instructions, "even the best frontier models only achieve 68% accuracy at the max density", three degradation patterns by model class, "bias towards earlier instructions". McMillan (arXiv 2605.10039, 2026-05-11), 1,650 Claude Code sessions varying a config file at 25/100/250/500 lines: file **size had no detectable effect** on compliance with the tested rule (affirmative null, BF₁₀ ≈ 0.10); presence vs absence was decisive (0 → 67.7 %); compliance fell ~5.6 % odds per additional function generated in the session. Agent-READMEs survey (arXiv 2511.12884): median production CLAUDE.md 485 words.

Reading: the 200-line target is a context-cost and attention rule, not a measured cliff. The one controlled study found no length effect up to 500 lines for a single rule; IFScale shows density effects at hundreds of *distinct* instructions plus a primacy bias. The harness context is 67 lines but 18.4 KB — roughly 150–200 imperatives, where IFScale's curves already bend and later rules lose to earlier ones.

## 5. Two small questions

(a) **`@AGENTS.md` and native support** — https://code.claude.com/docs/en/memory: "Reading `AGENTS.md` directly requires Claude Code v2.1.277 or later"; "Before v2.1.281, some sessions, such as those on Amazon Bedrock or with telemetry disabled, read `CLAUDE.md` files only" — so the harness's "before 2.1.277, Bedrock, telemetry off" exception should read "before 2.1.281 on Bedrock or with telemetry off; before 2.1.277 anywhere". It is a fallback: a `CLAUDE.md` or `CLAUDE.local.md` anywhere on the path suppresses AGENTS.md unless **Project instructions** is `claude-md-and-agents-md`; `~/.claude/CLAUDE.md` does *not* count. The `@AGENTS.md` import is documented and safe to keep: "Keeping the import never makes Claude read `AGENTS.md` twice". v2.1.277 shipped 2026-09-18.

(b) **`/goal`** — documented at https://code.claude.com/docs/en/goal (seen 2026-09-30): `/goal <condition>` (≤4,000 chars), `/goal` for status, `/goal clear`; a Haiku-class evaluator judges the transcript after every turn; works with `claude -p "/goal …"`; unattended needs auto mode; unavailable when `disableAllHooks` is set or the workspace is untrusted. The evaluator "does not call tools, so it can only judge what Claude has already surfaced" — a check must print its result. The context's sentence is accurate; it could add "the check's output must appear in the transcript".

## Recommendations

### (i) derive.go: skills, effort, maxTurns on Antigravity

- **`skills:` — translate, do not drop.** Antigravity documents a `skills: string[]` agent key taking skill paths. The comment "markdown agents inherit the global skills anyway" is unsupported on either vendor: Claude Code's `skills:` is a *preload*, and Antigravity's docs say nothing about inheritance. Emit `skills: [<agy skills dir>/<name>, …]` using the path form the docs show; one agent (`reviewer` → `review-standards`) exercises it today. Gate: one behavioural run on agy proving the preloaded body reached the subagent (something only `review-standards` says), n of N, per the AGENTS.md testing rule; until that run, keep the current fallback of naming the skill path in the agent body (the `~/.gemini/config/skills/` rewrite already exists) and record the key as dashed.
- **`effort:` — drop, and say so.** No Antigravity equivalent exists (`model: pro|flash|inherit` is the only tier knob). Keep the drop, fix the comment.
- **`maxTurns:` — drop, and compensate in the dispatch.** No per-agent turn limit is documented for agy. The global rule already requires every dispatch to name a budget in the prompt; that is the only portable limit. Fix the comment.
- Add a test that pins what `DeriveAgy` emits and omits per key (today untested), and a `skills` mapping test that fails on a skill name not in the inventory.

### (ii) json-api-style: rewrite to AIP

Rewrite the skill on AIP-158/193/140/142/126/203 with proto3 JSON as the wire form; drop the `apiVersion`/`data`/`error.errors[]` envelope, `startIndex`/`itemsPerPage` paging, and the dead link. Shape: list responses `{ "<plural>": [...], "nextPageToken": "" , "totalSize"? }`; requests `pageSize`, `pageToken`; errors `{"error": {"code", "message", "status", "details": [ErrorInfo, BadRequest?]}}`; `createTime`/`updateTime` RFC 3339 Z; enums `UPPER_SNAKE_CASE` strings with `_UNSPECIFIED`; int64 as string when precision matters; omit unset fields. Go tags camelCase (`json:"pageSize,omitempty"`), and the golang skill's `golang-structure.md` example changed to match in the same commit (the "vocabulary" rule in Hard rules: one grep for `json:"[a-z]*_` across `skills/`). Keep the reference file under `references/` and the SKILL.md well under 500 lines. Why AIP for a Go API + TypeScript SPA: camelCase is native to TS, `google.rpc.Status` is what gRPC-gateway and Connect emit, and the 2012 guide has no living home.

### (iii) Global context: target size and split rule

Target **≤ 12,000 bytes rendered** (≈ 35–40 lines of the current density, ≈ 3,000 tokens), with the test budget lowered to 14,000 and the 22,000 pin kept only as the vendor ceiling. Evidence: Anthropic's stated mechanism (long files "reduce adherence", rules "get lost in the noise", emphasis stops working when repeated), IFScale's density curve and primacy bias, and the harness's own bug trail (BUG-110: six passes; repeated "second round on the same mechanism" rules) — the symptoms Anthropic names. McMillan's null means length alone will not fix compliance, so the split must remove *instructions*, not bytes.

Split rule — a line stays in the context only if it is needed in **every** session before the first tool call: resume order and checkpoint moments; the classify-then-load table; the Definition of Done as five one-line rows naming the skill or agent that owns each; the Git backup rule and the secret-path stop; the scratch rule; the operator's interaction style; the environment stack in one paragraph; the canary. Everything else moves to the skill or agent that runs when it applies: the verification-evidence and mutation rules → `review-standards` and `verifier`; the read-only-mode, guard-on-error, both-direction-artifact and `&&`-chain rules → `review-standards` § checklists and the `bug` skill; the dispatch-text repetition rules → the `review` skill and agent definitions; the "behaviour change includes the text that describes it" rule → `review --docs` and `documentation`; GCP details → `cloud-run-deploy`/`gcloud-setup`; the learning-loop mechanics → `retro`/`distill`/`dream`. A rule that was learned from a bug lives where the bug's prevention rule points, with the context keeping one sentence that names the skill. On Antigravity, skills load by description only, so each receiving skill's description must name the trigger words the moved rule needs.

### (iv) Description length for skills and agents

Spec ceiling 1,024 chars (agentskills.io); Claude Code truncates the listing at 1,536. Rule: **150–500 characters**, one paragraph, "what it does", then "use when …", then one "do NOT use for" clause; `Lint` fails above 1,024 and warns above 600. Rationale: every description is paid at every session start on both CLIs (~100 tokens each × 29 skills + 8 agents ≈ 3–4 k tokens), and the harness's own descriptions already range from 296 (`bash`) to 1,007 (`cloud-run-deploy`, 17 bytes under the spec ceiling), with `review` 789, `dream` 705, `mermaid-syntax` 662 next. Agents run 405–613 and need no change beyond the ceiling.

## Findings
- **[low / confidence: high]** `skills/google-catalog/scripts/refresh-catalog.sh:189`: `git -C "$dir" remote set-url -- origin "$2"` is the one git call in `fetch()` whose output is not discarded.
  - **The leak:** if the reused clone's config cannot be written, git dies with `could not set 'remote.origin.url' to '<value>'`. The value is a source override, which may carry a token in its URL path; the script accepts those, per `:186`. Causes include a stale `.git/config.lock` from an interrupted earlier run, a read-only disk or a full disk.
  - **Reproduced:** same invocation, probe repo `.agents/scratch/security-v2.3.0-r3/probe-seturl/w`, git 2.47.3.
  - **What it breaks:** `:42-43` ("No message shows such a value"), `:184-186` ("git's own complaint is not shown") and `skills/VENDORED.md` ("never shows or records such a value"). `set -e` then exits 128 with no role-named message and no note.
  - Not introduced by this range: the line is unchanged context.
  - **Fix:** `git -C "$dir" remote set-url -- origin "$2" >/dev/null 2>&1 || fail "cannot point the $1 clone at its source (git's own message is not shown: it repeats the source's value)"`. Test: in `TestRefreshCatalogScript`, plant `.git/config.lock` in a reused clone, run with an override holding a marker, and assert the marker is absent from the output and the note is present.
  - **Exposure if shipped:** on that uncommon re-run path, the override's value reaches the terminal and any agent transcript that ran the script.
- **[low / confidence: medium]** `agents/verifier.md:12`, read with `skills/preflight/SKILL.md:61`: the new sentence records a new or changed verification command that was not run only on the Scope line. Scope then becomes "not `complete`" and the main agent is expected to re-dispatch.

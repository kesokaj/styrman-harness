## (1) Gaps

- **G4 — spec's Candidate tests vs. D8's "does not re-derive promote" are unreconciled [medium-high severity, high confidence, BLOCKING].** `specs/sh-agent/memory-loop.md:22` ("Dispatch text") says: "The dreamer does not re-derive `/dream`'s verdicts: the promoted files are its rule-candidate inputs, one candidate row per memory file" — i.e., for memories, the dreamer's job is a pass-through: one candidate row per file already named in `Promoted:`. But `specs/sh-agent/memory-loop.md:24` ("Candidate tests") still reads as an independent judgement the dreamer performs on any memory: "a **rule** when a `feedback` or `user` memory ... is recorded nowhere loaded and is backed by two sources (two memories, a memory and a trail row, or a bug row that recurs)" — a test that can combine "a memory and a trail row" the `Promoted:` list has no way to express (`/dream` only ever flags memory-vs-memory or memory-vs-`feedback.jsonl` pairs; it never sees the trail). Plan Interfaces (line 48, D8) restates the pass-through reading for `/retro`'s wiring ("its rule candidates are the promoted memories ... bug rows whose prevention rule is written nowhere, and trail rows"), but the plan never edits the spec's Candidate-tests paragraph, so an implementer writing `agents/dreamer.md`'s actual prompt text has two different algorithms to choose between: (a) trust `Promoted:` verbatim and do no independent test on memories, or (b) run the "backed by two sources" test on every memory in the store regardless of what `Promoted:` says. These produce different agents. It also breaks the plan's own acceptance check: the `dreamer` matrix row (plan line 50) seeds "two `feedback` memories on one fact from two sessions" directly into the store and dispatches the dreamer with "dispatch text as the contract" — with no `/dream` run first to compute a `Promoted:` list, and no stated rule for what value the matrix-row author puts in the `Promoted:` field of that dispatch. Under reading (a), if the matrix row's dispatch text sets `Promoted: none` (the honest value, since no `/dream` ran), the dreamer would produce **no** rule candidate for the memory pair — failing the row's own stated check ("a rule candidate naming the memory pair"). Under reading (b) the row passes, but then D8's "does not re-derive promote" is false for memories. Decide which reading is correct and: if (a), rewrite spec line 24 to describe promoted-memory pass-through, not an independent test, and state how the matrix row computes its `Promoted:` value for a fixture that bypasses `/dream`; if (b), correct D8 and the plan's Interfaces (lines 22/48 restatement) to say the dreamer *does* re-run the two-source test on memories (and decide what, if anything, `Promoted:` then adds).

- **G5 — D9's migration-visibility fix is not written into the buildable Interfaces/Failure-modes text [medium severity, high confidence, BLOCKING].** D9 (line 111) states: "`/init-project`'s migration prints 'no default store at `<old>`' when the directory is absent, so a mismatch is visible, and lists any `~/.claude/projects/*/memory` directory whose name ends with the repository's last path component as a hint." This is the resolution to round 1's G1 (slug-formula mismatch could silently no-op). But the actual migration text an implementer builds from, Interfaces Step 5b item 3 (line 40), still reads: "when `old` is absent or empty, nothing" — no print, no hint, exactly the silent behaviour G1 flagged and D9 was supposed to replace. The Failure modes table (lines 54–61) has no row for this case either. Two implementers, one working from Interfaces/Failure-modes (silent) and one from the Decisions log (verbose + hint), build different Step 5b scripts, and neither the Phase 1 verify clause (line 77, "behavioural tier, `init-memory` runs") nor the `init-memory` matrix row (line 50) exercises the absent-`old` case at all (its fixture always seeds two files in the default store), so the discrepancy would ship unnoticed either way. Fix: rewrite Interfaces item 3 to match D9's language, and add a Failure-modes row and a matrix-row (or Phase-1 task) case for "no default store at `<old>`, hint printed" so the behaviour D9 promises is actually built and checked.

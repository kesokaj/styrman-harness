## Verdict: FINDINGS — none of them blocks the release

Nothing secret-shaped is committed, no new dependency, `govulncheck ./...` clean, and the
63 lines of Go in this range (`render.go` canary, `size_test.go`, one assertion in
`harness_test.go`) take no external input and touch no credential, network, or crypto path.
The worst thing in the range is a documented procedure, not code: the sandbox verification
log records copying the operator's LIVE credential files — `~/.claude/.credentials.json`,
`~/.claude.json`, `~/.gemini/antigravity-cli/antigravity-oauth-token` — into
`.agents/scratch/sandbox-home` inside the repository checkout, and that log, the procedure
the next run will copy from, names no removal step, no file mode, and no lifetime. The
deletion did happen for this run and is recorded in two change entries and the handoff; the
document that will be repeated is the one that does not say so. Nothing in the shipped
artifacts (the rendered context and the binary) is affected, so v1.5.0 can be cut with the
two documentation fixes queued behind it.

## Findings

- **[medium / confidence: high]** `.agents/docs/testing/2026-09-21-verify-sandbox-pruned-context.md:13` — the Setup paragraph prescribes copying the operator's live Claude and Antigravity credential files (`~/.claude/.credentials.json`, `~/.claude.json`, `~/.gemini/antigravity-cli/{antigravity-oauth-token,settings.json}`) into `.agents/scratch/sandbox-home`, i.e. into a 2.5 GB working tree inside the repository, and names no lifetime, no `chmod`, and no deletion. Exploitable in principle because live OAuth/refresh tokens inside the checkout are reachable by paths the repo's own rules already warn about: a `git add -f` or `git add -A` slip, an archive or backup of the tree, a working-tree-sourced `go:embed`, and any agent holding Read over the project directory — this harness dispatches four such agents. Four mitigations were verified rather than assumed, and they are why this is medium and not high: (1) `git ls-files .agents/scratch` returns only `.gitkeep` and `git check-ignore -v` resolves the credential path to `.gitignore:39`; (2) `find .agents/scratch -name '.credentials.json' -o -name '*oauth-token*'` returns nothing today — the copies were deleted, as `changes/2026-09-21-context-consolidation-phase-1.md` ("deleted then and the handoff says so"), `-phase-4.md` and the handoff's Environment State all record; (3) the embed guard `TestEmbedHoldsOnlyTrackedFiles` (root package) asserts the embedded set equals `git ls-files` in BOTH directions and PASSES, and `go:embed` covers only `context skills agents commands rules`, none of which holds an untracked or ignored file right now (`git status --ignored` over the five is empty) — so a scratch credential cannot reach a release binary; (4) `sh-agent report` collects a fixed, named, redacted set from the HOME, not the project scratch, so there is no exfiltration path through the feedback loop. Remediation: put the lifecycle in the document that gets repeated — `.agents/docs/testing/2026-09-03-verify-sandbox.md` (guide § 4 points at it for "paths and flags") and the new log both say `chmod 700` on the sandbox home, `chmod 600` on the copies, and `rm -f` of the credential files as the procedure's last step, recorded as done; better still, the sandbox home lives outside the checkout, which the context's own carve-out already allows (a credential copy is RUNTIME data, not scratch).
- **[low / confidence: high]** `.agents/docs/testing/2026-09-21-verify-real-home-smoke-5.md:21` — the Antigravity skill-load and agent-dispatch checks were rerun with `--dangerously-skip-permissions` because the real `~/.gemini/antigravity-cli/settings.json` now holds only `trustedWorkspaces`; the six narrow `permissions.allow` entries the 2026-09-16 log records have been lost. This is the safer form of the flag (per invocation, settings untouched, throwaway clone, confirmed in the log and in the handoff's Agent notes) but it runs an unattended agent with the operator's live credentials and no tool gate, and the log presents it as the standard fallback rather than the exception. Remediation: restore the six-entry allow list (in the real settings or in the sandbox copy) and state in `guide.md` § 4/§ 5 that the allow list is the procedure and that the flag is not used in a home holding live credentials.
- **[low / confidence: medium]** `internal/harness/render.go:24` with `.agents/docs/testing/guide.md:126` — the canary is the truncation detector for the whole always-on instruction block, and its word is published in tracked files (`README.md:190`, `AGENTS.md:62`, `guide.md:126`, and nine trail files). A session whose working directory is inside the harness checkout can answer "GANNET" from the repo without the context having loaded at all, so the check can pass while the block is truncated — the project's own "silence from your own instrumentation is not evidence" rule turned on itself. Both runs in this range held (each used a demo clone that does not contain the word, and the Antigravity side independently grepped the conversation store for `<truncated`), but the guide records only the question, so the next run is free to ask it from here. Remediation: guide § 5 states the two conditions that make the answer evidence — asked from a directory that does not contain the word, and on Antigravity the conversation-store check for `<truncated` — or the word is derived per install instead of committed.
- **[low / confidence: medium]** `context/AGENTS.md` § Hard rules (pruned) — the concrete secrets-leak consequence in the generated-artifact rule (`go:embed` compiling a gitignored `.env` into a release binary, BUG-066) moved out of the always-on context into `skills/review-standards/SKILL.md:35`. The abstract half survives in the context ("an artifact built from the working tree rather than from git is pinned to what git tracks"), and `bugs/INDEX.md` records the move deliberately, so this is a judgement call rather than an oversight; the residue is that the sentence naming a CREDENTIAL now reaches only an agent that loads `review-standards`, which the main agent adding a `go:embed` during a feature does not. Remediation: optional — four words in the context bullet ("a gitignored `.env` once shipped") restore the salience at negligible byte cost, or accept it on the record.
- **[low / confidence: low]** `.agents/docs/plans/2026-09-21-context-audit-prompt.md` Step 1 — committed instruction-shaped text (a prompt a future session may run) directs the agent to fetch six vendor documentation URLs and feed the values it finds back into its own scorecard ("Use CHANGED values in Step 3"). Remote content shaping local limits is a prompt-injection surface in principle. Mitigated in the text itself: the prompt is declared READ-ONLY, every statement must be labelled MEASURED/DOCUMENTED/INFERRED, and it ends with "Make no edits until I approve specific items"; the values consumed are numeric caps. No remediation proposed; recorded so the next reader of that file knows the surface exists.

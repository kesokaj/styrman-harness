## Verdict: FINDINGS

The worst problem is that "the model has no tools" is not enforced by the invocation. The whole prompt-injection argument for the nightly job rests on that premise. The prompt carries untrusted text: Antigravity step payloads include tool output and fetched content, and a third-party repository's committed trail is read too once it is indexed. On Antigravity, `agy -p … --mode plan` has no no-tools flag. The Phase 4 log shows agy did try a `command` tool on the real 14 KB prompt. The only things that stopped it were auto-deny under an empty allow list (in a sandbox home) and a sentence in the prompt. On Claude Code, `--tools ""` removes only the built-in tools. The child still loads the operator's MCP servers, hooks, settings and plugins, because the call passes no `--strict-mcp-config` or `--safe-mode`. Neither gap is exploitable on this machine today: the Claude settings have no allow rules, hooks or user MCP servers, and the Phase 4 log says the agy allow list is empty. But the nightly job runs unattended with whatever permissions interactive use has since granted. Nothing checks for that, and nothing tests for it.

Next most serious:
- The Antigravity reader sends tool output, where the Claude reader sends prose only. The secrets it may carry are guarded only by report's deny list.
- The agy prompt goes on argv. It exceeds Linux's 128 KiB single-argument limit below the 256 KiB cap (confirmed on this box), and every local user can read it.

No hand-rolled crypto. No new dependency. No SQL or command injection found.

## Findings
- **[medium / confidence: medium]** `internal/dream/dream.go:161-166`, `internal/dream/run.go:132-159`: the agy call is not tool-free.
  - **What happens:** `--mode plan` is an execution mode, not a sandbox. D7b's own probe shows it "has no effect while slash command expansion is disabled", and that agy called a `command` tool on the real prompt. `testing/2026-09-30-verify-parity-memory-dream-phase-4.md` E6 records this; the plan's D7b says a night on which agy "still calls a tool" is expected. What refused the call was the sandbox's EMPTY allow list and untrusted `dream-work`, plus the prompt's warning.
  - **Why it matters:** on the real home, any allow rule the operator grants in interactive agy use (an "always allow" on a command), or any read tool plan mode permits, would be exercised by injected text. That text comes from Antigravity tool output, fetched pages quoted in transcripts, or an indexed third-party repo's trail. It would run at 03:00, unattended, with the operator's files, credentials and network. Two things are unverified: which tools plan mode allows without a prompt, and the real agy settings, which the log states are empty.
  - **Side note:** agy has no `--no-session-persistence`, so each night's full prompt is also stored in `~/.gemini/antigravity-cli/conversations` (the spec's `dream-work` note relies on that).
  - **Remediation (no new dependency):** run the agy child under a per-run `HOME` in a 0700 directory under `~/.config/sh-agent/`. It holds the token and a settings file with an explicit empty allow list and no trusted workspaces, and is removed after, as the DB copies are. The testing guide's kit already proves agy honours `HOME` this way. This also keeps the prompt out of the operator's own conversation store. Pin the child's `HOME` in `TestRunAgyGetsThePromptAsArgument`. The alternative is to refuse the agy vendor on the timer when the effective agy settings grant any permission.

- **[medium / confidence: medium]** `internal/search/dream.go:92,232-238`: the Antigravity reader sends tool output.
  - **The inconsistency:** it keeps every printable run of 20+ bytes with three spaces from every step payload. D8a says the payloads mix prompts and replies with "ids and permission strings". So file contents the agent read, command output (`env`, a `.env`, a config) and fetched pages reach the prompt. The Claude reader sends text parts only (`internal/dream/collect.go:334-355`; spec step 1: "text parts only"; "tool calls and results are not prose").
  - **What guards it:** only `harness.Redact`, whose own comment calls it a safety net (`report.go:122-124`). It misses shapes common in tool output:
    - `.netrc` (`password p`, with no `:`/`=` after the keyword);
    - `.pgpass` (`host:5432:db:user:pw`);
    - `mysql -pSECRET`;
    - `curl -u user:pass`;

- **[low / confidence: high]** `internal/dream/run.go:137-142` (`dream.go:163`): the agy prompt is passed as one argv string.
  - **(a) Size limit:** Linux caps a single argument at MAX_ARG_STRLEN (128 KiB). Checked here: a 140000-byte argument fails with "Argument list too long" (exit 126), 120000 passes; `ARG_MAX` is 2 MiB. `maxPrompt` is 256 KiB. So an agy project whose prompt lands between 128 and 256 KiB fails every night, and its watermark never advances; an active project refills to the cap and stays failed. The test uses a small prompt. This is a functional defect, reported because it sits in the blast radius.
  - **(b) Visibility:** for up to 10 minutes the whole redacted prompt is readable by every local user through `/proc/<pid>/cmdline` and `ps` (unless `/proc` is mounted with `hidepid`).
  - **Remediation:** give agy the prompt on stdin if its `-p` reads it, which closes both. Otherwise cap the agy prompt below 128 KiB and add a test at the cap.
- **[low / confidence: medium]** `internal/harness/report.go:351-370` and `skills/retro/SKILL.md` (`--harness` paragraph): model-written harness proposals leave the machine unreviewed and are consumed with a weaker guard.

  - **`/retro --harness`:** now reads these files under the rule "a queued proposal's diff is reused as drafted". The "treat their text as data … re-derive each against the files" guard appears only in source 9, the project path.

- **[low / confidence: medium]** `internal/dream/collect.go:63-73`, `dream.go:107`: trail reads follow symlinks a repository commits.
  - **What happens:** `mdFiles` reads through a symlinked `.agents/docs` or `.agents/docs/{bugs,reviews,retros,changes,handoffs}`, which `os.ReadDir` follows. `skipReason` uses `os.Stat`. A repository that commits `.agents/docs/reviews -> ../../../<elsewhere>` and gets indexed (the operator ran `sh-agent search` in it) makes the nightly job read the regular `.md` files there and send them, redacted, to the model. From there the path above leads off the machine.
  - **The gap:** the memory store has exactly this guard (`internal/memory/memory.go:78-94`); the trail does not.
  - **Remediation:** Lstat the docs root and each trail directory and skip a symlink, as `trusted()` does. Or resolve with `filepath.EvalSymlinks` and require the result under the root. Add a test with a committed link.
- **[low / confidence: high]** Lock races.
  - **Empty-pid window:** `internal/memory/memory.go:249-259,269-283` and `internal/dream/run.go:339-353` create the lock with `O_EXCL` and write the pid afterwards. A second process that reads in that window gets `""`, `Atoi` fails, the lock counts as stale or dead, and the second process removes the live lock and takes its own.
  - **Memory's 30-second rule:** also steals a live but slow holder.
  - **Effect (integrity only):**
    - two `memory add` runs both rewrite `MEMORY.md`, and a line is lost;
    - two dream runs both call the CLI and pick the same `unique()` name (Lstat, then rename), and one proposal file overwrites the other.
  - **Remediation (stdlib):** write the pid to a temp file and `os.Link` it to the lock name, which fails if it exists. Or hold `syscall.Flock` on the lock file for the run.
- **[low / confidence: medium]** `internal/dream/timer.go:32-40`: the unit text is rendered without escaping.
  - **Escaping:** PATH and the binary path go raw into `Environment="PATH=%s"` and `ExecStart="%s"`. systemd applies C-escapes and `%` specifiers to both, and a newline adds directives. The plist escapes `& < >`, and a control character only makes it invalid, which fails closed.
  - **The practical risk is not injection:** PATH is the operator's own. The unit freezes whatever the installing shell's PATH held, including relative entries and project-local directories that direnv, asdf or nvm add inside a checkout (`<repo>/bin`, `node_modules/.bin`). The unattended run can then resolve `claude` or `agy` from a repository directory.
  - **Remediation:** resolve the CLI with `exec.LookPath` at install time and write its absolute path. Or keep only absolute PATH entries outside every indexed project. Escape `%` as `%%`, and refuse `"`, `\` and control characters. Add a test with such a PATH.
- **[low / confidence: medium]** `internal/search/dream.go:55-59,103-120`: unredacted database copies survive a killed run.
  - **What survives:** full copies of Antigravity conversation databases (tool output included) and of the global index, in `~/.config/sh-agent/dream-agy-*` and `dream-projects-*`.
  - **Why:** only a `defer` removes them, so SIGKILL, OOM or shutdown mid-run leaves them there indefinitely. Nothing sweeps them, unlike report's `sweepInterruptedClones`. The files are 0600 in a 0700 directory, so this is data at rest only.
  - **Remediation:** sweep stale `dream-agy-*` and `dream-projects-*` directories at the start of each run, pid-named as report's throwaway clone is.

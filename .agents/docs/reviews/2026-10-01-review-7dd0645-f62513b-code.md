## Verdict: APPROVE WITH NITS (round 3; round 1 was REQUEST CHANGES, round 2 APPROVE WITH NITS)

The worst problem is that BUG-149's fix protects the wrong platform, and its known limit is written down the wrong way round. macOS was named as the gap, but Go's `os/user` reads the account database there without cgo. The real gap is the Linux release binary (`CGO_ENABLED=0`): for any account that is not in `/etc/passwd`, `user.Current()` quietly returns `$HOME` with a nil error. On those machines a sandbox `--remove-timer` or `uninstall` can still reach the operator's real timer, which is BUG-149 itself. Second, the refresh script's new path resolution leaves out one spelling. A path that goes through a missing directory and `..` (for example `$HOME/nope/..`) passes all three destination guards, and the swap then writes the catalog into the home directory, the checkout or `/`. Third, a timer that v2.0.0 installed from a home that is not the account's home can no longer be found by remove or uninstall. Everything else checks out: the `$`→`$$` escaping is correct, exclusions now match whole names, the `printf %q` hint works on bash 5, and no new test can change the checkout, the home directory or the machine.

## Findings

- **[medium / confidence: high]** `internal/dream/timer.go:34-44` (`accountHome`), and the same claim in `internal/dream/timer_test.go:288-290`, `.agents/docs/specs/sh-agent/dream.md:46` and `.agents/docs/bugs/BUG-149-timer-real-home-read-from-home-env.md:20`. **The known limit points at the wrong platform, and the real gap is not covered.**
  - **macOS is not the gap.** In the local Go 1.27.1 source, `os/user/cgo_lookup_syscall.go` is built for `!osusergo && darwin`. It calls libSystem's `getpwuid_r` without cgo, so a macOS release binary does read Directory Services. The sentence "a build without cgo on macOS can only read HOME" is false.
  - **Linux is.** The Linux release binary is built with `CGO_ENABLED=0` (`.agents/docs/deploy/remote.md:141`), which compiles `lookup_stubs.go`. Its `current()` reads only `/etc/passwd`. When the uid has no entry there, it builds the user from `os.UserHomeDir()` (that is, `$HOME`) and returns **a nil error** whenever `$USER` is set. Accounts this hits: LDAP, SSSD or NIS accounts, systemd-homed users, and containers running an arbitrary uid.
  - **Effect on the guard.** On those machines `accountHome` returns the sandbox's `HOME` with no error, `UnitFor(sandbox)` returns the bare names, and BUG-149 is back. A cgo build with no passwd entry has the same effect, through the explicit fallback on line 44.
  - **The test cannot catch it.** It skips in exactly that setup, because its yardstick is the same lookup.
  - **Fix.** Make the fallback visible. `user.LookupId(strconv.Itoa(os.Getuid()))` in a pure-Go build reads `/etc/passwd` and returns `UnknownUserIdError` instead of `$HOME`. When the lookup fails, choose deliberately between two options: treat no home as the real one (fail safe, but a real-home bare timer then needs a manual remove), or fall back to `HOME` with a printed warning. Correct the limit sentence in the four places named above. The changes entry is append-only, so leave it as it is.

- **[low / confidence: high]** `skills/google-catalog/scripts/refresh-catalog.sh:70-74` (`phys`). **A `--dest` that goes through a missing directory and then `..` is never resolved, and it passes every guard.** BUG-147 family.
  - **Reproduced on the scratch copy.** `--dest "$HOME/nope/.."`, `--dest "<checkout>/nope/.."` and `--dest /nope/..` all got past the guards and stopped at "cannot clone", not at "is not a catalog directory".
  - **Why it gets through.** `[ -d "$1" ]` is false and the parent `.../nope` does not exist, so `phys` returns the string unchanged. The equality and ancestor `case` checks then compare strings that cannot match, and the "not empty and no CHECKSUMS" check sees no directory.
  - **What a run with reachable sources then does.** `mkdir -p "$dest"` creates `nope`, and `cp -R "$build/." "$dest/"` writes about 140 entry directories plus `INDEX.md`, `CHECKSUMS`, `MANIFEST.md`, `LICENSE-*` and `.sh-agent-noindex` into the home directory, the checkout or `/`, overwriting any files with the same names. A root `.sh-agent-noindex` in the checkout also hides the whole repository from `sh-agent search`.
  - **Then deletion becomes possible.** That run leaves a `CHECKSUMS` behind. A second run with another such spelling then deletes the directories it names, from the home directory.
  - **The header promise breaks.** The new header comment ("the home directory, the checkout ... are refused") does not hold for this spelling.
  - **Fix.** In the two branches of `phys` that do not resolve the path, refuse any path with a `.` or `..` component (`case "/$1/" in */../*|*/./*) fail ...`), or resolve from the nearest existing ancestor. Add `filepath.Join(fakeHome, "nope", "..")` and `filepath.Join(repo, "nope", "..")` to the refusal table in `TestRefreshCatalogScript`.

- **[low / confidence: medium]** `internal/dream/timer.go:52-66` and `RemoveTimer` (`:214-256`). **A timer that v2.0.0 installed under the bare names from a home that is not the account's home is now left in place without a word.**
  - **Background.** v2.0.0 ships `InstallTimer` without `UnitFor` (checked with `git tag --contains`), so every home got the bare names. Before this diff, a sandbox (`HOME=S`, `--home S`) still mapped to the bare names and could remove such a timer.
  - **Now.** `UnitFor(S)` is suffixed, so `RemoveTimer` looks for files that do not exist and returns nil, and `TimerInstalled(S)` reports false. `uninstall` of S runs the same `RemoveTimer` (main.go:301), so it leaves the timer too.
  - **On Linux** the leftover is litter in S. The user manager never loaded units from S.
  - **On macOS** it is a running job. `launchctl bootstrap gui/<uid> S/Library/LaunchAgents/com.styrman.sh-agent-dream.plist` loaded the bare label into the real GUI domain, and it stays loaded until logout. It runs nightly against S, or against a deleted binary after `uninstall`, and it makes the real home's `--install-timer` bootstrap fail, because that label is already loaded.
  - **Fix.** Do not boot it out by label: that could hit the real job. Have `TimerInstalled` and `RemoveTimer` also look for bare-named unit files under a non-account home whose text carries `--home <that home>`, and print the exact manual cleanup command for them.

### The dispatch's questions (round 3)

1. **`phys()` under `set -euo pipefail`: correct.**
   - The status is not swallowed anywhere. `base` is declared in `local p=$1 rest="" base` and assigned on its own line, so `base=$(…) || return 1` carries the substitution's status, not the status of `local`.
   - The `$(…)` holds `cd && pwd`, which is not a pipeline.
   - All three callers (`:83-87`) are plain assignments followed by `|| fail`, so `fail` runs in the main shell and exits.
   - **What `2>/dev/null` hides:** only `cd`'s own reason, which in practice is always "Permission denied". `phys` reaches `cd` only for a path that `[ -d ]` already stat-ed as a directory; a symlink loop or a dangling link fails `-d` and is walked past. The `fail` text names which input failed (`--dest`, the checkout or the home directory) but not the ancestor that could not be entered. That is a convenience gap, not a finding.
   - **A `HOME` that cannot be entered** (`HOME=/root` as uid 1000) is refused with "cannot resolve the home directory": it fails closed.
2. **Where the `HOME` refusal sits.** It runs after `dest` and `repo` are resolved and before every guard.
   - `env -u HOME … --dest /` now prints "HOME is not set: the destination guard compares --dest with the home directory", not "--dest / is not a catalog directory". With `HOME` set, `--dest /` still prints the latter (run by hand on the ff4c181 copy).
   - This is no regression. Both messages refuse, and no existing test runs `--dest /` without `HOME`: the refusal table's `guard` helper sets `HOME=fakeHome` (`catalog_test.go:691`), and `run` passes the environment through.
   - No legitimate run lacks `HOME`, because the script's own `go test` step needs a Go cache.
3. **`printf '%q'` on a path with several components and spaces.** `skills/cloud/delta x/sub dir/.a b` comes out as `skills/cloud/delta\ x/sub\ dir/.a\ b`, one token that can be pasted. An escape plus a space comes out as `$'skills/cloud/d/.x\E[31m y'` (bash 5.2). In the same messages the `--exclude $name` stays raw, which is safe: the name already matched `[a-z0-9-]` at `:169-170`.
4. **`TestCatalogNotesNeverAllowQuiet`:**
   - It can pass a note that allows the flag: R3-1.
   - It fails when the notes are reverted. Mutation D replaced MANIFEST.md with the b4e3d79 version, and `:373` went red on five notes. Two of the seven reworded notes did not name `--quiet` at b4e3d79.

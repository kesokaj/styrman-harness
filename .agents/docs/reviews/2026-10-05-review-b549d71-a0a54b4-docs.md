# Review — b549d71-a0a54b4-docs   (2026-10-05)

Range reviewed: b549d71..a0a54b4

## Status: COMPLETE

## Verdict: REQUEST CHANGES

Docs lens only. Worst first: the release procedure in `.agents/docs/deploy/remote.md` § Releases is the document `/preflight` runs, and it does not carry the v2.4.0 bridge that ADR-052 decides. Its step 3 signs `SHA256SUMS` with the NEW key from the agent, and step 3's own verify and step 3b use the new line or the host binary. By ADR-052's own reasoning every v2.3.2 place refuses a checksum file signed that way, so an operator following the guide as written ships a v2.4.0 that no v2.3.2 place can update to. The bridge exists only in ADR-052 and a one-sentence note. Also stale: the "new machine" operator step still reads `~/.ssh/id_ed25519`. REQUIREMENTS.md's Antigravity clause and the delivery spec are consistent with their ADR/measurements.

## Findings

- **[high / confidence: high]** `.agents/docs/deploy/remote.md:151-165` (step 3 and 3b; ADR-052 in `.agents/docs/architecture/DECISIONS.md:572-575`) — dropped/narrowed: ADR-052 says v2.4.0's `SHA256SUMS.sig` is signed by the RETIRED key and that step 3b runs a v2.3.2 binary built from the tag, because the v2.4.0 binary "would refuse the bridge signature by design". remote.md step 3 says "signed with the same key as the tag" and signs through the new agent key (`release-signer.pub` = new line), verifies against the new `allowed_signers`, and 3b runs this host's own built (v2.4.0) binary. remote.md:102 tells the reader only WHAT to verify v2.4.0 against, never how to produce it. Run as written for v2.4.0, step 3 yields a signature v2.3.2 places reject, so `sh-agent update` fails everywhere it matters; following ADR-052 instead means leaving the written procedure. Fix: add the bridge variant to step 3 and 3b in remote.md (which key signs, how the retired key is fed to `ssh-keygen -Y sign`, which binary runs 3b, which `allowed_signers` line step 3's verify uses), marked for v2.4.0 only. `TestReleaseSignerMatchesTheDeployGuide` does not catch this (it reads only lines that START with `ostling.simon@gmail.com ssh-`).

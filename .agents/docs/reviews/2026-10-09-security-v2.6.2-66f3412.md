## Verdict: FINDINGS

No finding is high or medium, so nothing here blocks the gate. The worst problem is low, a new dream signal-handling bug (finding 1). The two round-2 findings I raised in `reviews/2026-10-09-security-dbd776d-3bffdcf.md` on the redaction needles are fixed at `6cec23b`; a probe at 66f3412 confirms both. The two on the signal path are fixed as well.

Finding 1 sits in the new signal path in `internal/dream/run.go:227`. `signal.Notify` on SIGHUP or SIGINT re-enables a signal that the parent had set to ignored: `nohup` does this for SIGHUP, and a non-interactive shell's `cmd &` does it for SIGINT. On that signal the CLI's group is killed. `signal.Reset` then restores the inherited ignore (`runtime/signal_unix.go:160-163`, and `sigdisable` restores `fwdSig`), so the re-raised signal does nothing. sh-agent carries on, and the project that was running fails. No data or credential is exposed.

What remains is low and named below:
- **Two needle shapes still pass** (finding 2).
- **Private data on disk:** 23 copies of the operator's Antigravity conversation databases are still in a gitignored scratch directory (finding 3).
- **Two open items left to the operator by their word:** the agent-key allow-list and a `PRIVATE_KEY=` kind (finding 4).

I read all 57 release-diff paths; the trail markdown carries no credential, token, key, or instruction an agent would act on.

## Findings
- **[low / confidence: high]** `internal/dream/run.go:226-235` — **Notify re-enables a signal the parent ignored.** The goroutine kills the group (`:232`), then calls `signal.Reset(sig)` and `syscall.Kill(os.Getpid(), sig)` (`:234-235`).
  - **What goes wrong:** if sh-agent was started with SIGHUP or SIGINT ignored, `Reset` puts back `SIG_IGN`, so sh-agent does not die. Before this range the CLI shared sh-agent's ignored disposition and kept running. Now a hand-run `nohup sh-agent dream --all &` loses its in-flight project at logout and then continues with the next one.
  - **Not affected:** the systemd timer path.
  - **Impact:** an availability and correctness slip. Nothing leaves the machine.
  - **Fix:** do not register a signal for which `signal.Ignored(sig)` is true at the call. Add a test that starts the helper with SIGHUP ignored and asserts the CLI is not killed.
- **[low / confidence: high]** `internal/harness/report.go:159` — **two shapes still pass the command-line rule.** The `-u`/`--user` flag must now follow whitespace. In a probe at 66f3412, these went unredacted:
  - A quoted attached flag: `curl "-uadmin:FAKEVALUE" h`.
  - A JSON string that starts with the flag, on the jsonl path: `{"text":"-uadmin:FAKEVALUE"}`. The decoded map prints it after `text:`.

  The common forms are redacted: the split JSON array `["curl","-u","admin:…"]`, `["curl","-uadmin:…"]`, and the backtick form. **Fix:** put a `"`, `'` or backtick, or a `:` after a key, in front of the flag as well as whitespace (`(?:^|[\s"'`:])`). Add the two shapes to `shapeSecrets`. Both are rare, which is why this is low.
- **[low / confidence: high]** `.agents/docs/testing/2026-10-09-verify-project.md:254` — **private conversation copies left in scratch.** The log records copying the operator's Antigravity conversation databases into scratch.
  - **What I found:** `.agents/scratch/verify-project/corpus/` still holds 23 `*.db` copies. They are mode 0600, dated 2026-10-09 17:17, and gitignored by `.gitignore:42`.
  - **The rule they break:** guide § 3e (in this diff) says the copies "are deleted after", and the log does not record a deletion.
  - **Exposure:** not committed and not shipped; private chat content on the local disk only.
  - **Fix:** the operator deletes the directory. A verifier log that copies real data records the deletion.
- **[low / confidence: medium]** `internal/harness/inventory.go:261` — **still open: the agent lint is a deny-list.** `memory` and `initialPrompt` pass. My round-1 finding 5 recommended an allow-list of agent keys. The operator deferred it on 2026-10-09, as the merged record and the handoff say.

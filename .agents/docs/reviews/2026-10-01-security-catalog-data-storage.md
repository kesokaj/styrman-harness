## Status: COMPLETE

## Verdict: FINDINGS

No entry needs excluding. None sends data, query results or credentials outside Google Cloud or the user's project, none ships a real credential or project identifier, no install pipes a download into a shell, and no frontmatter key would grant a permission. Two things are broken. First, the router never tells the agent to read `catalog/MANIFEST.md` § Notes, so every note below has no effect until router step 2 says to read them. Second, a few entries widen access or destroy data without asking. `google-cloud-filestore-log-troubleshooting`'s `--apply-fix` creates a firewall rule with no target tags, from `10.0.0.0/8` when no client IP was given, and adds a `READ_WRITE` + `NO_ROOT_SQUASH` export rule. `google-cloud-filestore-nfs-browser`'s Cloud Run bridge exposes the whole share, read as root, to every `run.invoker` principal, and its client sends the user's identity token to any URL it is given. `dbt-sf-to-bq-translator`'s script deletes bucket prefixes recursively without telling the agent. `cloud-sql-basics` restores over a live instance with `--quiet`. 16 entries get a note, 0 are excluded and 9 are clean.

## Proposals

### Proposal 1: A vendored pin is verified by an upstream diff before it is written, and an edited copy is a fork
Scope: project — Target: `AGENTS.md` § Rules for working here — Status: applied 2026-09-30 (7535bc0)
Scope rule: target-in-project

Trigger: finding 3. Current behavior: the rule says vendored skills are verbatim and never edited in place; two rows said "not recorded when vendored" for a month, and the first pin written for `gke-basics` (eff85cf) was wrong because it was chosen from a date, not a diff. Expected behavior: a pin is written only after `git archive <pin> <path> | tar -x` and `diff -r` against the vendored directory, and the diff is the row's "Local changes"; a copy that differs is a fork and its row says so.

```diff
-- Third-party skills are vendored verbatim and listed in `skills/VENDORED.md`; never edit them in place — fork into a differently named skill. Its second table names the two forks that predate this rule (`gke-basics`, `terraform`) and keep their upstream names: pinned to the base they were rewritten from, never overwritten by a re-fetch.
+- Third-party skills are vendored verbatim and listed in `skills/VENDORED.md`; never edit them in place — fork into a differently named skill. Its second table names the two forks that predate this rule (`gke-basics`, `terraform`) and keep their upstream names: pinned to the base they were rewritten from, never overwritten by a re-fetch. A pin is written only after `git archive <pin> <path> | tar -x` into scratch and `diff -r` against the directory: the diff is the row's "Local changes", an empty diff is what "verbatim" means, and a pin chosen from a date is a guess (BUG-111; `TestVendoredRowsCarryAPin` refuses a row with no repository or pin, not a wrong one).
```

Rationale: the test catches a missing pin, never a wrong one; the check that catches a wrong one is the diff, and the rule names it.

### Proposal 2: A redaction shape joins `report.go` as a kind, never as an instance list, and a raw-text needle carries no leading `\b`
Scope: project — Target: `AGENTS.md` § Rules for working here — Status: applied 2026-09-30 (7535bc0)
Scope rule: target-in-project

Trigger: finding 2. Current behavior: nothing in the project rules says how `prefixNeedles` and `keywordNeedles` grow; six passes in one day each added instances until the operator chose one rule per kind. Expected behavior: a new credential shape is added as the vendor's length and alphabet (one regexp per kind) or, when the prefix alone is distinctive, as a prefix; a review that names a third instance on one list is answered with a kind, not a batch; and a needle matched against raw text has no `\b` in front, because a literal `\n` or an underscore is a word character.

```diff
 - Stdlib only in the Go code, with one exception: `modernc.org/sqlite`, used only by `internal/search` (R4, ADR-045). The installer (`internal/harness`) never imports it. Any other dependency is a requirements change.
+- `report.go`'s redaction needles grow by KIND: a vendor's length and alphabet as one regexp, or a prefix only when it is distinctive as written (`sk_test_` sits inside `task_test_`). A review naming a third missed instance on one list gets a rule per kind, not a fourth batch (BUG-110: six passes on 2026-09-30). A needle matched against raw text has no `\b` in front — a literal `\n` or an underscore is a word character and hides the token — and every needle gets a benign near-miss in `TestReportRedactShapes`; over-redaction in the safe direction is pinned there, never argued about.
```

Rationale: the security agent said it on its fourth pass; the rule makes the first pass say it.

## Verdict: REQUEST CHANGES

The worst problem is in the test, not the shipped script: the rewritten early-exit scanner (`pipeStages` + `earlyExitConsumer`, `internal/harness/catalog_test.go`) no longer sees two forms the regex it replaces did see, among them the most common shape of the BUG-155 bug: a pipe inside a double-quoted command substitution (`v="$(find … | head -1)"`, `[ -n "$(… | head -1)" ]`). Both exit 141 with no message under `set -euo pipefail` (shown below), so a tracked script that gains one of those lines passes the test the bug record names as its guard (BUG-155, BUG-157). The script changes (empty `GIT_ASKPASS`, `unset GIT_CURL_VERBOSE`, the TRACE2 targets, `GIT_TRACE_REDACT=1`) are correct, and the kit preamble's SHA check accepts and refuses the right values. The second finding is wording: preflight Step 5's new blocking condition, read as written, matches the `Previous run:` line that agents/verifier.md now requires, so a BLOCKED log that has since been resolved still blocks the gate.

## Findings

- **[medium / confidence: high]** `internal/harness/catalog_test.go:362-397` (`pipeStages`), `:356` (`earlyExitConsumer`): a regression against the old `earlyExitPipe` regex in the direction that lets a bug through. (1) `pipeStages` treats everything between double quotes as one quoted word, so a pipe inside `"$(…)"` or `"\`…\`"` is never cut: `v="$(find . -print | head -1)"` and `if [ -n "$(producer | grep -q x)" ]; then` give `stages=[]` and pass. (2) The sed alternative `sed\b.*q['"]?(\s|\)|$)` needs a space, `)`, a quote or the line's end after `q`, so `sed -n '1{p;q}'` and `sed -n '/re/{p;q;}'` pass. The old regex matched all three (checked with `go run` on the old pattern), and `bash -c 'set -euo pipefail; v="$(seq 1 200000 | head -1)"; echo x'` exits 141 without printing; the `sed -n "1{p;q}"` form exits 141 as well. If this ships, the commit's claim that the test "covers every early-exit pipe in the tracked scripts" is false for the quoted form, and no test fails when such a line is added. Fix: inside double quotes, track `$(`…`)` and backticks and run `pipeStages` on what they hold (or scan each substitution body separately); allow `}` and `;` after `q` in the sed alternative; add both forms to the bad list.
- **[medium / confidence: medium]** `skills/preflight/SKILL.md:88` against `agents/verifier.md:14` and `skills/preflight/SKILL.md:61`: the verifier must now keep `Previous run: BLOCKED at <sha>; not run: <the commands>; quoted since: …` under the heading of a log it has re-run to PASS.

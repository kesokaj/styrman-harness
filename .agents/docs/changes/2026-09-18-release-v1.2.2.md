# Release v1.2.2 — a shadowed binary says so     (2026-09-18)

## Summary

v1.2.2 is the PATCH that carries BUG-078's fix to binary-only places. A downloaded, signature-verified release binary was installed on the operator's devbox and then silently ignored because two earlier `PATH` entries held other `sh-agent` binaries; `install` and `status` now say when that is the case, and the install guides verify the file before it moves and the shell's resolution after. Nothing else changed since v1.2.1.

## Type

release (patch)

## What ships

- `sh-agent install` warns `warning: <path> comes before <installed> on PATH, so `sh-agent` runs that one` when PATH reaches the installed binary only after an earlier entry, and its "not on PATH" note names what answers instead when something does. `sh-agent status` prints `shadowed   <path> comes first on PATH, so `sh-agent` runs that, not the binary above` for the same case. "On PATH" is file identity by `os.SameFile`: a symlink, hard link or symlinked directory reaching the installed file is not a shadow. `install --dry-run` makes no PATH claim.
- README § Install without cloning and `deploy/{local,remote}.md`: verify the downloaded FILE (signature, checksum, `version`) before the move and the shell's resolution (`sh-agent version` unqualified, `which -a`) after, as single `&&` chains. Not in any release artifact; every reader of `main` has them already.
- Entry for the work itself: `2026-09-18-bug-078-path-shadow.md` (four review rounds, ten must-fail mutations, what the code half does not catch).

# Plan — `dream`: consolidate Claude Code's auto memory   (2026-09-29)

## Why

The operator asked (2026-09-29) whether memory or "dreaming" plugins exist for Claude Code and Antigravity, and then for this draft. Claude Code writes auto memory on its own (`~/.claude/projects/<project>/memory/`, one file per fact, `MEMORY.md` as the index) and nothing ever tidies it. Anthropic's "Dreaming" (a between-session consolidation pass: merge duplicates, drop stale entries, absolute dates, a reviewable diff) is a research preview on the Managed Agents API only, not in Claude Code. Community plugins (claude-mem, Mem0, dream-skill and others) add a second store with its own drift, and the agy ones need hooks, which this harness forbids.

The harness already has the learning loop (`feedback-log` → `/retro` → `/distill`) but auto memory sits beside it, unread by it. The cost is visible today: this project's memory `asking-format.md` records a rule that its own text says is "now in the harness context (`context/AGENTS.md` Operator line)". A memory that graduated into a rule is loaded every session for nothing, and a memory that never graduates is a correction the retro never sees.

## Scope

- **In:**
  - A harness skill `dream` (`skills/dream/SKILL.md`, typed as `/dream`, `--dry-run`): reads the project's auto-memory store, gives every memory one verdict, rewrites the index, and hands `promote` verdicts to the retro. It never writes a rule, a skill or context itself.
  - `/retro` runs the skill's orientation as one more evidence source (Step 1) and applies its edits with the rest (Step 6).
  - One sentence in `context/AGENTS.md` § Learning loop; a row in `.agents/docs/testing/skill-matrix.md`.
- **Out:**
  - A memory store for Antigravity. agy keeps none; the skill reads Claude Code's store whichever CLI runs it (the path is per project under `~/.claude`), and says so when there is none.
  - A timer or session counter (Anthropic's 24 h / 5 sessions). No hooks, no timers (project rule 1); the retro's own cadence is the trigger.
  - Any third-party memory plugin, MCP server or database.
  - Memories of other projects. A `user`-type memory that belongs in every project graduates through the retro's promotion check, as today.
- **Follow-ups noted, not built:** if Claude Code ships its leaked `autoDream` as a built-in `/dream`, this skill is deleted in the release that adopts it (D2).

## Interfaces

### The store

`<store>` = `autoMemoryDirectory` from the effective Claude Code settings when set, else `~/.claude/projects/<slug>/memory/` where `<slug>` is the repository's absolute path with every `/` turned into `-` (worktrees and subdirectories share one store). The slug is verified by `ls`, never assumed: a missing or empty store ends the run with one line, `no auto memory for <repo> (<store>)`.

### One verdict per memory

Every `*.md` under `<store>` except `MEMORY.md` gets exactly one verdict, with a one-line why citing `file:line` where the rule says so:

| Verdict | Test | Edit |
|---|---|---|
| `keep` | Still true; recorded nowhere the session already loads. | none |
| `graduated` | Its rule now lives in `context/AGENTS.md`, the project `AGENTS.md`, `.agents/rules/`, a skill, or a bug record's prevention rule — found by one `grep` over the memory's key words, hit read in full. | delete the file and its index line |
| `stale` | A `project` memory whose work the newest handoff or a `changes/` entry shows done; a `reference` whose target is gone. | delete |
| `broken` | Names a file, function, flag or command that no longer exists (`ls`, `grep`); or carries a relative date. | rewrite to the current name and an absolute date, or delete when nothing current matches |
| `merge` | Two files on one fact. | one file; the newer `modified:` wins a contradiction; `[[links]]` repointed |
| `promote` | A `feedback` or `user` memory recorded in no rule and seen from two or more sessions (`originSessionId` differs, or the same correction sits in `~/.config/sh-agent/feedback.jsonl`). | none here; it becomes a retro finding with `rule_ref null` |

Doubt resolves to `keep`: a memory is deleted only when the check that says so ran and returned (the global guard rule: a check that errors keeps the data).

### The index

`MEMORY.md` is rewritten from the files after the edits: one line per file, every line naming a file that exists (both directions, the global artifact rule), under 200 lines and 25 KB, which is all Claude Code loads at start.

### The gate and the record

- `--dry-run` stops after the table.
- Otherwise the table is put to the operator in the asking format — `#`, memory, verdict, one-line why — and applied per number or "go all". The store is not under git, so the table is the undo point, and the record quotes every deleted memory in full.
- Standalone: `<docs-root>/retros/<date>-dream.md` (frontmatter `owner:`, `date:`; counts per verdict; the table; the deleted text), plus one line in `~/.config/sh-agent/retros.jsonl` with `"kind":"dream"`; when that directory is denied, the same fallback as `/retro` Step 5.
- From `/retro`: no separate record; the retro record gets `## Memory` with the same content, and each `promote` is a row under `## Findings`.

### `/retro` changes

- Step 1, new source: "7. **Memory evidence** — the `dream` skill's orientation and verdict table (its `--dry-run`); each `promote` verdict is a finding with `rule_ref null`." Order: memory evidence is read after the feedback log, before drafting.
- Step 4 template: `## Memory` after `## Feedback log entries`.
- Step 6: the verdict edits are applied with the approved proposals, in the same table.

### `context/AGENTS.md` § Learning loop, the sentence

After "run `/distill` on the third repeat of a procedure.": `/dream` tidies Claude Code's auto memory for the project, and `/retro` reads it first. (about 95 bytes).

## Failure modes

| Situation | Result |
|---|---|
| No store, or an empty one | one line, exit 0; nothing written |
| Run on Antigravity | same path: it reads Claude Code's store for the project when one exists, otherwise the one line above |
| A graduation grep hits but the hit is a different rule | `keep`, with the why saying what the hit was |
| `~/.config/sh-agent/` denied | the record stands; the exact `cat >>` command is printed, as in `/retro` |
| `MEMORY.md` names a file that is gone, or a file has no line | the index rewrite fixes both; the table lists them as `index` rows |
| Headless run (`claude -p`) | verdicts computed and recorded, nothing deleted; every verdict stays `proposed` |

## Verification

Tiers: unit (the Go suite, for the context edit) / install / behavioural / real-home smoke / docs review.

- **Unit:** `gofmt -l cmd internal && go vet ./... && go test -race ./...` bare; `TestRenderedContextFitsAntigravityBlock` green after the § Learning loop edit.
- **Install:** `go run ./cmd/sh-agent install --home .agents/scratch/dream-home`, then `status` with no drift and `list` naming `dream`; one start of each CLI in the sandbox with its log grepped for parse errors.
- **Behavioural, n of N:** a scratch clone of a small repository that does not contain the harness source (`.agents/scratch/dream-probe/`), with the working-tree skill reachable as a project skill (`.claude/skills/dream` → `skills/dream`) and `--settings '{"autoMemoryDirectory":"<clone>/.agents/scratch/mem"}'` pointing the store at a seeded fixture of five memories: one whose rule sits verbatim in the clone's `AGENTS.md` (expect `graduated`), one naming a file the clone lacks (`broken`), a pair on one fact (`merge`), one clean (`keep`), one `feedback` with two `originSessionId`s (`promote`). The run script asserts each seed fact (`grep`, `ls`) before the CLI starts. `claude -p "/dream --dry-run"` with the prompt on stdin, `--allowedTools` naming the skill's tools; the verdict table is read from the output, the tool-call order from the run's transcript under `~/.claude/projects/`. Expect: 5 of 5 verdicts as seeded in n of N runs, and nothing deleted (dry run). Control, same clone without the project skill: no verdict table in n of N.
- **Must-fail for the guard:** a sixth seed whose graduation grep cannot run (the `AGENTS.md` unreadable) expects `keep`.
- **Real-home smoke:** after `sh-agent install` into the real home, the three checks in `testing/2026-09-03-verify-real-home.md` on each CLI, plus `/dream --dry-run` in this repository, which is expected to name `asking-format.md` as `graduated` (its own text names the context line).
- **Docs:** `/review --docs` over the range; the living docs here include `context/`, `skills/dream/` and `skills/retro/`.

E2E criteria: (1) in this repository, `/dream` lists `asking-format.md` as `graduated` with the `context/AGENTS.md` line cited, and after "go" the file and its index line are gone and `MEMORY.md` has one line per remaining file; (2) `/retro --dry-run` in the probe clone shows the `promote` seed as a finding with `rule_ref null`.

## Risks

Assumptions:
- Claude Code loads a project skill from `.claude/skills/<name>/SKILL.md` in a `claude -p` run — checked by the control run above, first task of Phase 1.
- `autoMemoryDirectory` accepts a relative path or a path inside the repository — checked by `claude -p` printing the store it read, first task of Phase 1; else the fixture moves to an absolute path under `.agents/scratch/`.
- Antigravity CLI keeps no memory store (checked 2026-09-29 on agy 1.2.13: no docs page, no help entry, no settings key; the binary links the editor's Knowledge Base code and `~/.gemini/antigravity-cli/knowledge/` exists with only a lock file, never written). Re-check `ls ~/.gemini/antigravity-cli/knowledge/` after each agy update; a populated store is a new Decisions row, not a change to this plan.
- `originSessionId` is present in every auto-memory file's frontmatter (it is in this project's four) — checked by `grep -L originSessionId <store>/*.md`; a file without it counts as one session.

## Decisions

- D1 (2026-09-29): dream never writes a rule; `promote` hands the memory to the retro. Why: one place decides where a rule lives (retro Step 2), and a second writer would drift from it.
- D2 (2026-09-29): named `dream` after Anthropic's term; if Claude Code ships a built-in `/dream` that does this, the skill is deleted rather than renamed. Why: a built-in that does the same job makes the skill redundant, not conflicting.
- D3 (2026-09-29): doubt resolves to `keep`. Why: the store is not under git; the global guard rule for destructive actions.
- Open: **O1 — trigger.** Retro only (recommended: no timer, no counter, matches project rule 1) versus a `sh-agent status` line counting sessions since the last dream (a Go change, out of a file drop).
- Open: **O2 — where the standalone record goes.** `<docs-root>/retros/<date>-dream.md` (recommended: REQUIREMENTS line 31 puts retro and distill records there, and this is the same loop) versus nothing on disk beyond `retros.jsonl`.
- Open: **O3 — scope of stores.** This project's store only (recommended) versus every store under `~/.claude/projects/` in one pass, which reads other projects' state from here (the 2026-09-28 retro's finding 2 is the reason not to).

# Security review — 6af54f7-015cf2d   (2026-09-17)

Range reviewed: 6af54f7..015cf2d (`git diff 6af54f7...015cf2d`, 23 files. Code read from the tree after checking that `internal/harness/report.go` hashes to sha256 5b00b5c2…, the same as at 015cf2d. Doc claims quoted from `git show 015cf2d:<path>`, because other agents had uncommitted edits open in `.agents/docs/specs/` and `.agents/docs/testing/`.)

## Verdict: FINDINGS

`sh-agent report` pushes a copy of `~/.config/sh-agent/` into git history on GitHub. Its redaction lets secrets through in ordinary cases and says it succeeded in others. The worst problem is the most common one. The needles are seven case-sensitive literals, so `GITHUB_TOKEN=…`, `DB_PASSWORD=…`, `Authorization: Bearer …`, `ghp_…` and `sk-ant-…` are all sent with zero redactions: 14 of the 15 ordinary credential shapes probed got through, and only lowercase `token=` was caught. The docs tell the operator to read `--dry-run` first to guard against this, but `--dry-run` prints file names and the redactions it made, never file contents, so it cannot show a secret it missed. Second: when a needle sits inside a JSON object KEY, the sent copy is redacted correctly, but that key, secret included, is written word for word into `report.json`, the one file every run sends. Third: nothing checks that the checkout `report` pushes from is the feedback repository. Pointing `--feedback-repo` at an unrelated project, or running with `GIT_DIR` set in the environment, committed and pushed the report to that other repository's remote. Each of these was confirmed by a probe. Evidence is in `.agents/scratch/secprobe-6af54f7/` (gitignored): a copy of `internal/harness` at 015cf2d plus `secprobe_test.go`, with results in `probe-run1.log`. All fixture values are fake.

## Findings

- **[medium / confidence: high]** `internal/harness/report.go:29-38`, `.agents/docs/deploy/local.md:55`, `.agents/docs/deploy/remote.md:100` — **the needles miss the credential shapes they are meant to catch, and the documented way to spot a miss cannot show one.** Matching uses `strings.Contains` against `token=` and `password=`, which is case-sensitive, so the most common form of both (`GITHUB_TOKEN=…`, `NPM_TOKEN=…`, `DB_PASSWORD=…`) never matches.
  - **Probed:** each of these ran through `redactLines(…, true)` as a `user_quote` and was sent with 0 redactions: `export GITHUB_TOKEN=…`, `DB_PASSWORD=…`, `password: …`, `{"password": "…"}` inside a quote, `Authorization: Bearer …`, `github_pat_…`, `ghp_…`, `sk-ant-…`, `aws_secret_access_key = …`, `ASIA…`, `postgres://app:…@db/x`, `token = …`, `xoxb-…`, `GOCSPX-…`. The lowercase `token=…` control was caught.
  - **Accepted risk:** the plan (Risks) accepts that a shape it does not recognise gets sent. It does not accept its own named shapes missing because of case, or a safeguard that does not work.
  - **Why a leak is likely:** the feedback skill logs `user_quote` as the user's "exact or near-exact" words and never tells the user. The retro skill writes proposals and `retros.jsonl` with heredocs. A push to GitHub cannot be undone by a later redaction.
  - **The safeguard does not work:** `--dry-run` (`report.go:463-470`) prints destinations plus the redactions that *fired*. Neither "read the `--dry-run` output first where a correction may quote something private" (local.md) nor "read the redaction list" (remote.md) can reveal an unmatched secret.
  - **Remediation, stdlib only:**
    - Match the keyword needles without regard to case, using a `regexp` with `(?i)(password|passwd|secret|token|api[_-]?key)\s*[:=]`, `(?i)bearer\s+\S` and `://[^/\s:@]+:[^/\s@]+@`.
    - Keep the vendor prefixes case-sensitive and add `ghp_`, `gho_`, `ghs_`, `ghu_`, `github_pat_`, `glpat-`, `sk-`, `xox`, `ASIA`, `GOCSPX-`.
    - Fix the two doc lines so they tell the operator to read the originals under `~/.config/sh-agent/`, or have `--dry-run` print the copies it would send.
    - Keep `report` off any timer (a follow-up in the plan) until one of those is done.
  - No dependency is proposed.
- **[medium / confidence: high]** `internal/harness/report.go:175-181` (with `:129-131`, `:298`, `:442-444`), `.agents/docs/deploy/local.md:55` — **a secret in a JSON key is sent in `report.json` even though the run reports it redacted.**
  - **Mechanism:** a needle in an object key calls `fire(p, n, true)`, where `p` is the full key path. That `Path` is stored in the `Redaction`, marshalled into `report.json` and printed to stdout (and so into the journal, once `report` runs on a timer). The same happens for every record beneath that key.
  - **Probed:** `{"tool_output":{"https://api.example.test/v1?token=FAKE…":"404"}}` in `retros.jsonl`. The sent `retros.jsonl` is the marker only, but `report.json` has `"path": "tool_output.https://api.example.test/v1?token=FAKE…"`.
  - **What it contradicts:** the `Redaction` doc comment ("never the text"), local.md's "`report.json` records file, line, JSON key path and which shape fired, never the text", and the plan's claim that the location "leaks nothing". `TestReportRedactDocument` checks only `len(recs) == 1` for the key case, so it cannot catch this.
  - **Remediation, the shortest fix:** when `keyHit`, clear `Path` on every record for that value, since the whole value is already replaced and a path adds nothing. Then assert `Path` in that test as a must-fail.
- **[medium / confidence: high]** `internal/harness/report.go:363-386`, `:562-570` — **nothing checks that the checkout is the feedback repository before committing and pushing.**
  - **What is checked today:** `--feedback-repo` accepts any directory with a `.git` entry that is not a harness checkout. The default `~/.config/sh-agent/feedback` is accepted with no check at all, not even the harness-checkout refusal that the explicit path gets (found by reading the code).
  - **Where the push goes:** to whatever upstream or `origin` that checkout has. `gitOut` also honours `GIT_DIR` and `GIT_WORK_TREE` from the environment.
  - **Probed, unrelated project:** `--feedback-repo <an unrelated project clone>` exited 0. `reports/probe/<ts>/feedback.jsonl` and `report.json` were committed and pushed to that project's `origin` `main`.
  - **Probed, `GIT_DIR`:** `GIT_DIR=<other repo>/.git` with a correct `--feedback-repo` exited 0. The commit was made in, and pushed to, the other repository.
  - **Impact:** a typo (`--feedback-repo .` inside a project, or `~` when `~` is a dotfiles repository) or an agent passing the wrong path publishes the operator's corrections, project paths and manifest to that remote. If the remote is public, that cannot be taken back.
  - **Remediation, stdlib via `gitOut`:** before writing anything, and for both the explicit and default paths, require:
    - `git -C dir rev-parse --show-toplevel` equals `dir`;
    - `git -C dir remote get-url origin` equals `r.URL` (the tests already pass their bare repository as `URL`).

    Then push with an explicit `origin HEAD` rather than the branch's configured upstream.
- **[low / confidence: high]** `internal/harness/report.go:67-80`, `:82-104`, `:195-197` — **structural gaps where a needle is present, content is still sent, and the run reports success.**
  - **(a) Duplicate JSON keys.** When a JSONL line repeats a key and the needle is in the shadowed value, `json.Valid` passes, the decoded map keeps only the last value, nothing fires, and the original raw line is written. Probed: `{"user_quote":"AKIA…","user_quote":"clean"}` gave 0 redactions and the key was sent. The same `return data` path applies to `state.json`.
  - **(b) `-----END` and `-----BEGIN` on one line**, which happens when two PEM files are concatenated without a trailing newline. The search for END starts on the BEGIN line itself, so only that line is removed. Probed: 2 redactions reported, both key-body lines sent.
  - **(c) A PEM whose dashes were rewritten**, for example into en dashes by a chat UI. `PRIVATE KEY` removes the header line but never opens a block. Probed: body sent.
  - **(d) In JSONL, a `-----BEGIN` header on a line that is valid JSON by itself** (a bare string). The JSON walk handles it and no block opens. Probed: body sent.
  - **Remediation:**
    - When the JSON walk fires nothing but `needleIn(body)` does, fall through to the text rule.
    - Look for `-----END` after the BEGIN offset on the same line, otherwise from the next line.
    - Let `PRIVATE KEY` open a block the way `-----BEGIN` does.
    - Check the block rule before the JSON branch.
    - Add each case as a must-fail fixture.
- **[low / confidence: medium]** `.agents/docs/specs/sh-agent/delivery.md:37-39` (added in this range) — **the spec's guarantee that consumers cannot change the harness is overstated.**
  - **The claim:** "Why consumers cannot change the harness — Not a permission — a shape … An agent working in such a home has the harness text and nothing to push with."
  - **Why it does not hold:** changing the harness takes a credential, not a checkout. Line 35 of the same document says the operator's SSH key and `gh` login are "present on every machine because they log in as themselves". A process in any home that can reach that credential (an agent on a Linux project host running as the operator) can `git clone` this repository and push to `main`. The hourly `sh-agent-update.timer` (E2E log) then builds and runs that commit at every place within the hour.
  - **Already accepted:** ADR-030 (committed before this range) accepts "whoever can push" as the trust root. This finding is about the stronger claim in the spec, not about reopening the ADR.
  - **Why confidence is medium:** by R8, this repository cannot see whether consumer homes can reach that credential.
  - **Remediation:**
    - Restate the property as what `install` actually proves: it creates no checkout, and the ability to change the harness is exactly the ability to reach a push credential.
    - Require that a home seeded for agents has no forwarded ssh-agent, no `gh` token, and no readable key.
    - Keep the plan's `update --require-signed` follow-up as the control that would stop timers deploying an unsigned push.
- **[low / confidence: high]** `internal/harness/report.go:480-486`, `:501-527` — **files are written through symlinks inside the feedback checkout.** Existing path components are followed when creating the run directory and files, and that checkout's content comes from the shared remote.
  - **Mechanism:** a `reports/<host>` symlink pulled from the remote makes `MkdirAll`, `Mkdir` and `WriteFile` write outside the checkout. The operator is told to `pull --rebase` after a rejected push, which is one way such a symlink arrives. `git add` then refuses ("beyond a symbolic link"), but only after the files are written.
  - **Probed:** `outside/<ts>/report.json` was written, then the run failed.
  - **Impact is small:** file names are fixed, they land in a new timestamped directory, and anyone who can push to the feedback repository holds the same credential that pushes to the harness. This is hardening, not a new trust boundary.
  - **Remediation:** before `runDir` creates anything, `os.Lstat` `reports` and `reports/<host>` and refuse any that exists but is not a real directory. That is the same never-follow rule `Collect` applies (BUG-036).
- **[low / confidence: low]** `.agents/docs/deploy/remote.md` § The four places, `local.md` § Report back — **data leaves the work Mac.** Run on the work Mac, `report` sends the operator's word-for-word corrections, the absolute paths of work projects, and retro proposals from work sessions to a repository in a personal GitHub account. Whether that is allowed is a policy question for the operator and their employer, and it cannot be answered from here; it goes on the record because nothing in the design separates that place. Remediation: an operator decision, for example not running `report` at the work Mac, or limiting what it sends there.
- **[low / confidence: low]** `.agents/scratch/feedback-fresh` (created by the E2E in this range, `testing/2026-09-17-delivery-rework-e2e.md` row 4) — **a clone of the private feedback repository sits inside the harness working tree.** It is gitignored, so it will not be committed. But the unpacked bundle is described as "a zip of the repository with no `.git`", made however the operator makes it today (D6 has not defined it yet). A zip of the working directory would include it, along with everything else under scratch. Remediation: delete `feedback-fresh` now that its evidence is recorded, and when D6 is planned, build bundles from tracked files only (`git archive`).

## Checked

- **Secrets:**
  - Added lines in the diff were grepped for credential shapes. The only hits are test fixtures (the AWS documentation key `AKIAIOSFODNN7EXAMPLE`, `hunter2`, `abc123`, a fake PEM body) and doc text naming the needles.
  - The allowed-signers line in `remote.md` is a public key and was already there before this range.
  - `FeedbackURL` is an SSH URL with no credential in it.
  - What the E2E actually pushed: `git -C ~/.config/sh-agent/feedback ls-files` shows only `report.json` and `state.json` for two runs, and `git grep` for credential shapes at HEAD matched nothing (exit 1).
- **Injection:**
  - Every git call is an argv to `exec.Command`, with no shell. `add`, `commit` and `diff` put `--` before their paths. The hostname reaches the commit message as a single argv element. `hostDir` strips `/` and `\` and replaces `.` and `..`.
  - `clone` has no `--` before `url tmp`, but only `tmp` varies and it comes from `--home`, which only the operator supplies. That is hygiene, not a boundary.
  - Parsing: a malformed JSONL line falls through to the text rule (tested). By reading, `json.Valid` and `Decode` share the same nesting limit.
  - Nothing a remote controls runs a command: `clone` carries no hooks, config, filters or fsmonitor, and does not recurse into submodules.
- **Authz and authn:**
  - `report` uses the operator's own SSH credential, as ADR-030 set out before this range. The misdirected push is finding 3; the spec's overstated guarantee is finding 5.
  - `report` runs before `FindRepo`, so it skips `knownCheckout`. It never builds or installs, so nothing that gate protects is reachable from it.
  - Its `Inspect` of a harness-shaped tree found by walking up from the working directory runs `git status` there, and that honours that tree's `.git/config`. This already happens in `sh-agent status` (`main.go:237` at 6af54f7), so this range did not introduce it.
  - Nothing in this range reads the feedback repository yet. Whatever does read it later must treat its contents as untrusted input, because agents on every place write them, project hosts included.
- **Crypto:** nothing is implemented or composed here. The release procedure signs and verifies tags with git and ssh-keygen as designed. The only change to it is dropping the other host's `sudo -n cmp` line; that host's own gate is out of scope under R8.
- **Dependencies:** `go.mod` and `go.sum` are unchanged and the code is stdlib only. `govulncheck ./...` (go1.27.1) exited 0 with "No vulnerabilities found." (log in `.agents/scratch/secprobe-6af54f7/govulncheck.log`). There is no npm ecosystem (no `package.json`, `web/` or `ui/`), so `npm audit` does not apply.
- **GCP surface:** nothing in this range touches gcloud, IAM, service accounts, Cloud Run, Terraform, `--set-env-vars` or Secret Manager (checked by grepping added lines).
- **File modes:**
  - The clone and the copies are created as 0755/0644, reduced by umask.
  - On this box (`stat`): home is 0700, `~/.config/sh-agent/feedback` is 0775 (umask 0002), and the original `state.json` is 0644.
  - A place's own data is therefore no more exposed than before. After a `pull --rebase`, though, each place also holds every other place's reports under the same modes. Not a finding on a 0700 home; macOS homes (0750, group `staff`) were not checked.
- **Probe hygiene:** the real repository was the same before and after the probes (same status lines, which belong to other agents, no commits ahead, tags `v1.0.0` only). The probes ran with `GIT_CEILING_DIRECTORIES` set to the probe's scratch directory, so git could not climb into the real checkout.

## Outcome

- Finding 1 (needles miss common shapes; `--dry-run` cannot show a miss): fixed — `internal/harness/report.go` `prefixNeedles` (vendor prefixes, never shorter than the vendor's own: no bare `sk-`, which matches "task-") and `keywordNeedles` (case-insensitive secret assignments with identifier suffixes, `bearer`, URL credentials); `TestReportRedactShapes` covers all 15 probed shapes plus `api_key=` and `API-KEY:` in JSONL and text, with benign controls; must-fail seen against 015cf2d's `report.go` in a scratch copy. Docs: `deploy/local.md` § Report back and `deploy/remote.md` § Operator steps now say the dry run shows only what was caught and to read the originals. Same commit as this Outcome.
- Finding 2 (a key's secret written into `report.json` as the path): fixed — `redactJSON` collapses a key hit to one record with no `Path`; asserted in `TestReportRedactStructuralGaps` (the record marshalled carries no `FAKEVALUE`), must-fail seen. Same commit.
- Finding 3 (push target unchecked; `GIT_DIR` redirects): fixed — `verifyFeedback` requires the checkout to be its own top level with `remote.origin.url` exactly the feedback URL, on the explicit and the default path; `SendReport` refuses `GIT_DIR`, `GIT_WORK_TREE`, `GIT_INDEX_FILE`, `GIT_OBJECT_DIRECTORY`, `GIT_COMMON_DIR`; the push is always `push -u origin HEAD`. `TestResolveFeedbackFailures` (other origin, explicit and default, dry run too), `TestSendReportRefusesRedirectsAndLinks` (GIT_DIR); must-fail seen. Same commit.
- Finding 4 (structural gaps a–d): fixed — the key-block rule runs before the JSON branch; `blockEnd` searches after the header's offset and keeps a block open when a footer is followed on its line by another header; `blockOpen` also matches a `BEGIN … PRIVATE KEY` header with rewritten dashes; a JSON line (or `state.json`) the walk leaves still carrying a needle falls to the whole-line text rule. Deviation from the remediation: bare `PRIVATE KEY` does not open a block, because prose naming it would redact to end of file; it still removes its own line. All four cases plus a `state.json` duplicate key in `TestReportRedactStructuralGaps`; must-fail seen. Same commit.
- Finding 5 (spec overstates "cannot change the harness"): fixed — `specs/sh-agent/delivery.md` § What keeps consumers from changing the harness and `deploy/remote.md` § The four places now say the shape is `install`'s and the rest is the credential: a seeded home is read-only only when it reaches no push credential. Same commit.
- Finding 6 (writes through a linked `reports` path): fixed — `runDir` refuses `reports` or `reports/<host>` that exists and is not a directory, before creating anything; `TestSendReportRefusesRedirectsAndLinks`, nothing written outside; must-fail seen. Same commit.
- Finding 7 (work Mac sends work-session data to a personal repository): left — the operator's policy decision, put to them in this session; `deploy/remote.md` § Operator steps names it.
- Finding 8 (private clone in `.agents/scratch/feedback-fresh`): fixed — deleted after its evidence was recorded in `testing/2026-09-17-delivery-rework-e2e.md`; building bundles from tracked files only is noted for the D6 follow-up plan.

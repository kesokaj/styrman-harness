Nothing in the range is broken in a way that blocks a release. The worst issue is old, not added by this range, but it falls inside the range's own BUG-168 claim. `sh-agent update --vendor <bad>` still exits 1, not 2. ## Findings

- **[low / confidence: high]** `cmd/sh-agent/main.go:709` and `:1086` (`installPassArgs` called from `runUpdate` and the checkout update path). An unknown `--vendor` on `update` is a usage error, but it still exits 1, and on a checkout it is caught only after `harness.Pull` (main.go:1080-1086). So a usage mistake moves the checkout and then refuses to install. Probe (`.agents/scratch/rv-1012b`): `sh-agent update --from-zip none.zip --vendor bogus` → `sh-agent: unknown vendor "bogus"…`, exit=1; `sh-agent diff --vendor bogus` → `sh-agent diff: unknown vendor…`, exit=2. BUG-168, fixed in this range, set out to make usage errors exit 2 (`(*ctx).vendor` now does), and delivery.md:77 says "usage errors exit 2". The checkout path was not probed by running it, because it would pull the real repository; it was read in the code. Fix: call `c.vendor()` at the top of `runUpdate`, before the dirty check, fetch and pull, and in `updateFromZip`'s caller. Add a usage test asserting exit 2 and an unmoved checkout. The behaviour predates the range; the range's BUG-168 claim is what leaves it uncovered.
- **[low / confidence: medium]** `internal/dream/run.go:235-253` (`callWithin`'s signal goroutine). If a signal lands in `sigs`, the 1-buffered channel, just as `cmd.Wait()` returns, and the goroutine has not been scheduled before `close(waited)`, both select cases are ready. Go then picks one at random, so a SIGTERM or SIGINT can be swallowed and `sh-agent dream --all` goes on to the next project. The comment at :249 covers a signal arriving after `signal.Stop` but before `close`, not this case. The window is narrow. Fix: in the `<-waited` case, do a non-blocking receive on `sigs` and handle any pending signal the same way.
- **[low / confidence: high]** `internal/harness/report.go:170` ("command-line credential" needle). The `-u`/`--user` branch is fronted by `(?:^|[^A-Za-z0-9_-])`, which works like `\b`: a letter or `_` right before `-u` hides the flag. In text mode (`Redact`, which serves `proposals/*.md`), the raw line `{"cmd":"curl https://x \\\n-u admin:s3cretpass"}` is NOT redacted. JSONL mode redacts it through `decoded` (probe `.agents/scratch/rv-1012a`: text=false, jsonl=true). The project AGENTS.md rule says "A needle matched against raw text has no `\b` in front — a literal `\n` or an underscore is a word character and hides the token". deploy/local.md:67 already lists text files' JSON escapes as a known gap, and the comment at report.go:150-153 records the operator's 2026-10-12 choice that a missed shape is a known limit. So this is low: the needle's front guard conflicts with the letter of the rule, but the miss is a documented gap. Fix if wanted: allow `\\[nrt]` as an extra left boundary, plus a near-miss pin.

### Round-1 findings
1. **Finding 1 (update --vendor): fixed.** `run` now validates a non-empty `--vendor` through `c.vendor()` right after the home is made absolute (main.go:270-278). That is before the `--from-zip` dispatch and before any verb runs, so update, status, uninstall and report all exit 2 with the reason. `c.vendor()` with a non-empty flag only normalizes the value and reads no state. The remaining vendor error branches (`ctx.vendor`, `memoryCmd`, `installPassArgs`) are not dead code: they are still reachable when the home's recorded state holds an unknown vendor. `TestUpdateRefusesABadVendorFirst` can fail. With the old code, the checkout case pulls, so HEAD moves and the exit is 1; the dry-run case exits 0; the zip case exits 1. The fixture puts origin one commit ahead, which makes the "HEAD unmoved" assertion meaningful. `behind := advanceOrigin` keeps `TestUpdateNeverInstallsDirtyTree` unchanged in meaning, and the moved helper has both callers.
2. **Finding 2 (queued signal): fixed.** `relay` falls back to a non-blocking receive once `waited` closes, and `callWithin` waits on `relayed` before returning. The test runs 200 iterations with both cases ready: the old single `select` would fail on a coin flip. Its second half asserts that no signal means no call.
3. **Finding 3 (escaped break before `-u`): fixed.** `\\[nrt]` is an extra left boundary. A text-mode probe of `{"cmd":"curl https://x\\n-u admin:…"}` is now redacted (`.agents/scratch/rv-1012c`). There is a must-fail shape and a near-miss (`a literal \\n-u is the user flag`).

Security finding 3 (the timer home): fixed. The check now covers `bin+home+path`. The test's home `base/"x/..` passes the old check because Join cleans the quote out of `bin`, so the test can fail.

### New findings
- **[low / confidence: high]** `internal/harness/report.go:178` (the new `mongo(?:sh)?|sqlcmd` client branch under `(?i)`). It over-redacts two common benign lines that no test pins, which breaks AGENTS.md: "over-redaction in the safe direction is pinned there" (`TestReportRedactShapes`). Probe `.agents/scratch/rv-1012c`:
  - `docker run --name mongo -p 27017:27017 -d mongo` is redacted, because `mongo` followed later by ` -p <port>` matches.
  - `sqlcmd -S srv -a 4096 -Q q` is redacted, because sqlcmd's `-a` is the packet size and `(?i)` also turns `-[pa]` into `-P`/`-A`.

  The direction is safe, but the rule requires each case pinned as accepted over-redaction, as `mysql -P3306` and `docker run -u 1000:1000` are at report_test.go:200. Fix: add both to that pinned list, or narrow the branch (e.g. require `mongo(?:sh)?` at a command position, or `sqlcmd` with `-P` only).
- **[low / confidence: medium]** Docs lens, stale since 6cec23b (in range, not caught in round 1): `.agents/docs/deploy/local.md:102` and `README.md:198` both say "`--vendor all` widens a single-vendor install to both through `install`; `update` keeps the recorded vendor instead". `installPassArgs` now forwards an explicit `--vendor all` to the install an update runs, and `TestInstallPassArgsForwardsAnExplicitVendor` "explicit all" pins it. So `update --vendor all` also widens. Only an update *without* `--vendor` keeps the recorded vendor. This round's fix edited local.md:102's sentence and left the clause standing. Fix: "`update` without `--vendor` keeps the recorded vendor; with one it passes it on, so `update --vendor all` widens too", in both files.
- **[low / confidence: low]** `internal/dream/run.go` `callWithin`/`relay`: `onSignal` returns right after `syscall.Kill(os.Getpid(), sig)`, and the death that follows is asynchronous to the main goroutine. Now that `callWithin` waits on `relayed`, it returns and `dream --all` can start the next project's CLI, in its own group and so orphaned, in the moment before the process dies. The window is microseconds against a fork/exec, so this is unlikely. Fix if wanted: block after the self-kill (`select {}`), so `relayed` never closes on the signal path.

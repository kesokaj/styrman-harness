# Research — Cloud Run deploy, operate, data and API auth on GCP (2026-09-30)

## Question

An audit of `skills/cloud-run-deploy`, `skills/gcloud-setup`, `skills/docker` and the `docs/deploy/gcp.md` template found: no canary rollout, probes, ingress, VPC egress or Cloud SQL flags; an unauthenticated verify curl against an IAM-gated default; a redundant `--platform managed`; a wrong brew line and no Linux install; no skill for operating a service, for data, or for API auth. This brief establishes the 2026 facts and proposes the edits and three new skills. Every source was read on 2026-09-30.

## Answer in brief

1. **`--platform` is gone from the GA reference.** The `gcloud run deploy` page (updated 2026-09-29) has no `--platform` flag anywhere in its synopsis or flag list (verified by fetching the page and searching the text; zero hits). Drop it.
2. **Canary is `--no-traffic --tag`, then `update-traffic --to-tags`, promote with `--to-latest`; rollback is `--to-revisions REV=100`.** One trap: after any `--no-traffic` deploy, LATEST stops receiving traffic on future deploys until `--to-latest` restores it (reference text quoted in § 1).
3. **Verify with a token or the proxy, never a bare curl** on an IAM-gated service: `curl -H "Authorization: Bearer $(gcloud auth print-identity-token)"` or `gcloud run services proxy`.
4. **IAP on Cloud Run is GA (2026-03-13), one flag (`--iap`), no load balancer, free.** It is the recommended default for a solo operator's internal tool; the app verifies `x-goog-iap-jwt-assertion` with `idtoken.Validate` and never trusts the plain email header.
5. **Cloud SQL: pass `--edition=enterprise` explicitly** — for PostgreSQL 16+ the default is Enterprise Plus, which has no shared-core tier. `db-f1-micro` is $0.0105/h (no SLA). Connect with `cloud.google.com/go/cloudsqlconn` v1.25.3 (needs Go 1.26; the docker skill pins `golang:1.24`) and pgx, IAM AuthN, `WithLazyRefresh()` on Cloud Run.
6. **Install:** macOS `brew install --cask gcloud-cli` (the cask was renamed; `google-cloud-sdk` is the former token); Linux the apt repo (`google-cloud-cli`), where the component manager is disabled. Auth Proxy v2.26.0 via `brew install cloud-sql-proxy` or the direct download, not `gcloud components`.

## 1. `gcloud run deploy` flags and the safe rollout

Source: <https://docs.cloud.google.com/sdk/gcloud/reference/run/deploy> (GA, "Last updated 2026-09-29").

| Flag | Reference text (verbatim or condensed) |
|---|---|
| `--no-traffic` | "True to avoid sending traffic to the revision being deployed. Setting this flag assigns any traffic assigned to the LATEST revision to the specific revision bound to LATEST before the deployment. … After a deployment with this flag the LATEST revision will not receive traffic on future deployments." |
| `--tag=TAG` | "Traffic tag to assign to the newly created revision." |
| `--startup-probe` / `--liveness-probe` | "Comma separated settings … in the form KEY=VALUE": `httpGet.path`, `httpGet.port`, `tcpSocket.port`, `grpc.port`, `grpc.service`, `initialDelaySeconds`, `timeoutSeconds`, `periodSeconds`, `failureThreshold`. Defaults per <https://docs.cloud.google.com/run/docs/configuring/healthchecks>: initialDelay 0, period 10, failureThreshold 3, timeout 1. A failed liveness probe: container "shut down using a SIGKILL signal", in-flight requests get 503. |
| `--ingress` | `default="all"`; values `all`, `internal`, `internal-and-cloud-load-balancing`. "For Cloud Run the `--[no-]allow-unauthenticated` flag separately controls the identities allowed to call the service." Internal ingress does not bypass IAM (<https://docs.cloud.google.com/run/docs/securing/ingress>). |
| `--network` / `--subnet` / `--vpc-egress` | Direct VPC egress: subnet "must be `/26` or larger"; `--vpc-egress` = `all-traffic` \| `private-ranges-only` (default); `all` "(DEPRECATED) … Prefer to use 'all-traffic'". GA 2024-04-24 (<https://docs.cloud.google.com/run/docs/release-notes>), "no Serverless VPC Access connector required" (<https://docs.cloud.google.com/run/docs/configuring/vpc-direct-vpc>); connectors are not deprecated (<https://docs.cloud.google.com/run/docs/configuring/vpc-connectors>), still advised with Cloud NAT when cold starts exceed 30 s. **Direct VPC egress first; a connector only for that cold-start case.** |
| `--vpc-connector` | "Set a VPC connector for this resource." |
| `--add-cloudsql-instances` | "You can specify a name of a Cloud SQL instance if it's in the same project and region as your Cloud Run service; otherwise specify `<project>:<region>:<instance>`." Siblings: `--set-`, `--remove-`, `--clear-cloudsql-instances`. |
| `--cpu-boost` | "Whether to allocate extra CPU to containers on startup … Enabled by default when unspecified on new services." |
| `--min-instances` / `--max-instances` | "… or 'default' to remove." Min instances bill while idle: "at a lower rate when instances are idle" under request-based billing, full rate under instance-based (<https://docs.cloud.google.com/run/docs/configuring/min-instances>). |
| `--concurrency` | "maximum number of concurrent requests allowed per container instance." |
| `--cpu` / `--memory` | "fractional values below 1, 1, 2, 4, and 8"; "Ex: 1024Mi, 4Gi". |
| `--cpu-throttling` | Request-based billing is the default (CPU only during requests); `--no-cpu-throttling` = instance-based (<https://docs.cloud.google.com/run/docs/configuring/services/cpu>). |
| `--execution-environment` | `gen1` \| `gen2`; unset, "Cloud Run selects the execution environment based on the features used" (<https://docs.cloud.google.com/run/docs/configuring/execution-environments>). Do not pin. |
| `--platform` | **Absent** from the deploy, `services update` and `run` group pages and from the deploy guide's base command `gcloud run deploy SERVICE --image IMAGE_URL` (<https://docs.cloud.google.com/run/docs/deploying>). Cloud Run for Anthos is archived. |
| `--set-secrets` | `ENV=SECRET:VERSION` or `/path/file=SECRET:VERSION`; the SA needs `roles/secretmanager.secretAccessor`; Google recommends a pinned version over `latest` for env vars (<https://docs.cloud.google.com/run/docs/configuring/secrets>). |
| `--service-account` | "The email address of an IAM service account associated with the revision"; the deployer needs `roles/iam.serviceAccountUser` on it. |
| `--iap` / `--no-iap` | "Whether to enable IAP for the Service." `--no-invoker-iam-check` gives public access where Domain Restricted Sharing blocks `allUsers` (<https://docs.cloud.google.com/run/docs/securing/managing-access>). |

Rollout (<https://docs.cloud.google.com/run/docs/rollouts-rollbacks-traffic-migration>; <https://docs.cloud.google.com/sdk/gcloud/reference/run/services/update-traffic>):

```bash
gcloud run deploy "$SERVICE" --image "$IMAGE:$TAG" --region "$REGION" --no-traffic --tag canary
# tagged URL: https://canary---SERVICE-HASH.a.run.app  (test it with a token, § 2)
gcloud run services update-traffic "$SERVICE" --region "$REGION" --to-tags canary=10
gcloud run services update-traffic "$SERVICE" --region "$REGION" --to-latest      # promote; also restores LATEST after --no-traffic
gcloud run services update-traffic "$SERVICE" --region "$REGION" --to-revisions "$GOOD=100"   # rollback
gcloud run services update-traffic "$SERVICE" --region "$REGION" --remove-tags canary
```

`--to-revisions` accepts `LATEST` as a name; `--to-tags TAG=PERCENT`; `--update-tags`, `--set-tags`, `--remove-tags`, `--clear-tags`. Revisions: `gcloud run revisions list --service S --region R` and `revisions describe` (GA, <https://docs.cloud.google.com/sdk/gcloud/reference/run/revisions/list>).

## 2. Verifying an IAM-gated service

- Developer test: `curl -H "Authorization: Bearer $(gcloud auth print-identity-token)" SERVICE_URL`; the caller needs `roles/run.invoker`. "gcloud CLI-generated ID tokens lack an audience claim, which makes them susceptible to replay attacks" — fine for a verify step, not for production callers (<https://docs.cloud.google.com/run/docs/authenticating/developers>).
- Browser or repeated checks: `gcloud run services proxy SERVICE --region R --port 8080 [--tag canary]` "proxies requests … with credentials attached" (GA, <https://docs.cloud.google.com/sdk/gcloud/reference/run/services/proxy>).
- Service-to-service, Go (<https://docs.cloud.google.com/run/docs/authenticating/service-to-service>): `client, err := idtoken.NewClient(ctx, audience)`, then `client.Get(targetURL)`; audience = the receiving service URL; the caller's SA gets `roles/run.invoker` on the receiver. Raw: `GET http://metadata.google.internal/computeMetadata/v1/instance/service-accounts/default/identity?audience=AUD` with `Metadata-Flavor: Google`. `google.golang.org/api/idtoken` v0.299.0 (2026-09-21): `Validate(ctx, idToken, audience) (*Payload, error)`, `NewClient`, `NewTokenSource` (<https://pkg.go.dev/google.golang.org/api/idtoken>).

## 3. API auth for a Go API with a same-origin SPA

**IAP for Cloud Run** — GA 2026-03-13: "Configuring Identity-Aware Proxy (IAP) directly on Cloud Run … without the need for load balancers" (<https://docs.cloud.google.com/run/docs/release-notes>). Enable: `gcloud run deploy S --no-allow-unauthenticated --iap`; grant users `roles/iap.httpsResourceAccessor`; the IAP service agent `service-PROJECT_NUMBER@gcp-sa-iap.iam.gserviceaccount.com` needs `roles/run.invoker`; IAP cannot be on both the LB and the service (<https://docs.cloud.google.com/run/docs/securing/identity-aware-proxy-cloud-run>). Price: "at no charge" (<https://cloud.google.com/security/products/iap>). Headers (<https://docs.cloud.google.com/iap/docs/identity-howto>): `X-Goog-Authenticated-User-Email` (`accounts.google.com:email`), `X-Goog-Authenticated-User-Id`, `x-goog-iap-jwt-assertion`; "you shouldn't rely on them as a security mechanism" — validate the JWT on every request. JWT (<https://docs.cloud.google.com/iap/docs/signed-headers-howto>): ES256, issuer `https://cloud.google.com/iap`, keys `https://www.gstatic.com/iap/verify/public_key-jwk`, audience for Cloud Run `/projects/PROJECT_NUMBER/locations/REGION/services/SERVICE`; Go: `payload, err := idtoken.Validate(ctx, iapJWT, aud)`. `idtoken.Validate` accepts RS256 and ES256, fetches the IAP JWK set for ES256, enforces `aud` when given, and **does not check `iss`** — the app compares `payload.Issuer` itself (source read: <https://raw.githubusercontent.com/googleapis/google-api-go-client/main/idtoken/validate.go>).

**Firebase Auth / Identity Platform** — same client and Admin SDKs; Identity Platform adds MFA, SAML/OIDC, multi-tenancy, blocking functions, 99.95 % SLA (<https://docs.cloud.google.com/identity-platform/docs/product-comparison>). Pricing: tier 1 (email, phone, social) free to 50,000 MAU then $0.0055/MAU; tier 2 (OIDC/SAML) free to 50 MAU then $0.015 (<https://cloud.google.com/identity-platform/pricing>). Go: `firebase.google.com/go/v4` v4.22.0 (2026-09-23), `auth.Client.VerifyIDToken(ctx, idToken) (*Token, error)` checks signature, `aud` = project ID, `iss` = `https://securetoken.google.com/<projectId>`, `exp`; `VerifyIDTokenAndCheckRevoked` adds an RPC (<https://firebase.google.com/docs/auth/admin/verify-id-tokens>, <https://pkg.go.dev/firebase.google.com/go/v4/auth>).

**Sign in with Google** — verify with a client library: `aud` = your OAuth client ID, `iss` ∈ {`accounts.google.com`, `https://accounts.google.com`}, key users by `sub`; tokeninfo is dev-only (<https://developers.google.com/identity/gsi/web/guides/verify-google-id-token>). Go: `idtoken.Validate(ctx, tok, clientID)` plus the issuer check.

**Recommendation.** Internal tool: **IAP on Cloud Run** — no auth code in the SPA, one flag, free; the Go middleware validates `x-goog-iap-jwt-assertion` with `idtoken.Validate` and reads `payload.Claims["email"]`. Public app: **Firebase Auth**, Identity Platform only for MFA or SAML; the SPA sends the ID token, the API verifies with the Admin SDK. Both are vetted Google libraries; the middleware is glue, not a protocol.

## 4. Cloud SQL Postgres for Cloud Run

- Instance (<https://docs.cloud.google.com/sdk/gcloud/reference/sql/instances/create>): `--edition enterprise|enterprise-plus`; shared-core `--tier db-f1-micro|db-g1-small` only on Enterprise; dedicated core on Enterprise uses `--cpu`/`--memory` (omit `--tier`); `--database-version POSTGRES_18|17|16`; `--availability-type zonal` (default) \| `regional`; `--storage-size` (default 10 GB), `--storage-auto-increase`, `--database-flags cloudsql.iam_authentication=on`, `--deletion-protection`, `--no-assign-ip --network`. **"If the database version for your instance is PostgreSQL 16 or later, then the default Cloud SQL edition is Enterprise Plus"** and Enterprise Plus has no shared core (<https://docs.cloud.google.com/sql/docs/postgres/editions-intro>) — always pass `--edition=enterprise`.
- Cost (<https://cloud.google.com/sql/pricing>, USD, us-west table): `db-f1-micro` $0.0105/h (~$7.7/mo), `db-g1-small` $0.035/h; HA doubles it. "Shared CPU machine types (db-f1-micro and db-g1-small) are not covered by the Cloud SQL SLA"; the SLA also excludes single-zone instances (<https://cloud.google.com/sql/sla>). Recommendation for a solo operator: Enterprise, `db-f1-micro` or `db-g1-small`, zonal, deletion protection on, storage auto-increase on.
- Attach (<https://docs.cloud.google.com/sql/docs/postgres/connect-run>): `--add-cloudsql-instances PROJECT:REGION:INSTANCE` mounts `/cloudsql/PROJECT:REGION:INSTANCE/.s.PGSQL.5432`; the service's SA needs `roles/cloudsql.client`. Private IP needs Direct VPC egress or a connector.
- Go connector (<https://pkg.go.dev/cloud.google.com/go/cloudsqlconn>): v1.25.3 (2026-09-28), **"Go 1.26 or later. Go 1.25 is no longer supported"**. `config, _ := pgxpool.ParseConfig(dsn); d, _ := cloudsqlconn.NewDialer(ctx, cloudsqlconn.WithIAMAuthN(), cloudsqlconn.WithLazyRefresh()); config.ConnConfig.DialFunc = func(ctx context.Context, _, _ string) (net.Conn, error) { return d.Dial(ctx, "project:region:instance") }; pool, _ := pgxpool.NewWithConfig(ctx, config)`. "WithLazyRefresh configures the dialer to refresh certificates on an as-needed basis" — the option for Cloud Run.
- IAM database auth (<https://docs.cloud.google.com/sql/docs/postgres/iam-logins>): `gcloud sql users create SA_EMAIL_WITHOUT_.gserviceaccount.com --instance I --type=CLOUD_IAM_SERVICE_ACCOUNT`; username = "the service account's email without the `.gserviceaccount.com` domain suffix"; roles `roles/cloudsql.instanceUser` + `roles/cloudsql.client`; new IAM users have no privileges until `GRANT`.
- Local: Auth Proxy v2.26.0 — `brew install cloud-sql-proxy` (formula 2.26.0, <https://formulae.brew.sh/formula/cloud-sql-proxy>) or `curl -o cloud-sql-proxy https://storage.googleapis.com/cloud-sql-connectors/cloud-sql-proxy/v2.26.0/cloud-sql-proxy.linux.amd64` (<https://github.com/GoogleCloudPlatform/cloud-sql-proxy>); run `cloud-sql-proxy --auto-iam-authn --port 5432 PROJECT:REGION:INSTANCE`; ad-hoc psql: `PGPASSWORD=$(gcloud sql generate-login-token) psql "host=127.0.0.1 user=NAME dbname=DB"`.
- Migrations: golang-migrate v4.20.1 (2026-09-09, <https://github.com/golang-migrate/migrate/releases>); embed with `//go:embed migrations/*.sql`, `source/iofs`, driver `database/pgx/v5` (<https://github.com/golang-migrate/migrate>). Run as a Cloud Run Job (GA, <https://docs.cloud.google.com/sdk/gcloud/reference/run/jobs/deploy>): `gcloud run jobs deploy SERVICE-migrate --image "$IMAGE:$TAG" --args migrate,up --region R --service-account SA --set-cloudsql-instances I --set-secrets ... --max-retries 0 --task-timeout 10m`; `gcloud run jobs execute SERVICE-migrate --region R --wait` ("Wait until the execution has completed", <https://docs.cloud.google.com/sdk/gcloud/reference/run/jobs/execute>). Same image, same SA, the binary's `migrate` subcommand; never in the request path.

## 5. Operating

- Logs: `gcloud run services logs read S --region R --limit 50 [--log-filter 'severity>=ERROR'] [--freshness 1h]` (GA, default freshness 1d, <https://docs.cloud.google.com/sdk/gcloud/reference/run/services/logs/read>); `gcloud beta run services logs tail S` (preview); `gcloud logging read 'resource.type="cloud_run_revision" AND resource.labels.service_name="S" AND severity>=ERROR' --limit 50` (<https://docs.cloud.google.com/run/docs/logging>). Structured fields Cloud Run maps: `severity`, `message`, `logging.googleapis.com/trace`, `timestamp` — `slog` JSON with those keys.
- Error Reporting: automatic for stack traces on stdout/stderr; otherwise a `jsonPayload` with `@type: type.googleapis.com/google.devtools.clouderrorreporting.v1beta1.ReportedErrorEvent`, `message`, `serviceContext.service`, `severity: ERROR` (<https://docs.cloud.google.com/error-reporting/docs/setup/cloud-run>, <https://docs.cloud.google.com/error-reporting/docs/formatting-error-messages>).
- Metrics (`run.googleapis.com/`, sampled every 60 s, 120–240 s delay; <https://docs.cloud.google.com/monitoring/api/metrics_gcp_p_z>): `request_count` (labels `response_code`, `response_code_class`, `route`), `request_latencies`, `container/instance_count` (label `state`), `container/cpu/utilizations`, `container/memory/utilizations`, `container/startup_latencies`, `container/billable_instance_time`, `container/max_request_concurrencies`, `pending_queue/pending_requests`. Console: service → Metrics tab (<https://docs.cloud.google.com/run/docs/monitoring>).
- Uptime check (GA): `gcloud monitoring uptime create NAME --resource-type=uptime-url --resource-labels=host=HOST,project_id=P --protocol=https --path=/healthz --period=5 --timeout=10 --status-classes=2xx`; `cloud-run-revision` is also a resource type (<https://docs.cloud.google.com/sdk/gcloud/reference/monitoring/uptime/create>).
- Alerting policy (GA): `gcloud monitoring policies create --policy-from-file=policy.json` (<https://docs.cloud.google.com/sdk/gcloud/reference/monitoring/policies/create>); JSON shape with `conditionThreshold {filter, comparison, thresholdValue, duration, aggregations}` at <https://docs.cloud.google.com/monitoring/alerts/policies-in-json>; a 5xx-rate filter: `resource.type="cloud_run_revision" AND metric.type="run.googleapis.com/request_count" AND metric.labels.response_code_class="5xx"`. Channels: `gcloud monitoring channels list`; creating one via `gcloud monitoring channels create --type=email --channel-labels=email_address=…` was not verified (reference page 404 twice) — confirm with `--help` before it enters a skill.
- SLO: availability or latency SLI, error budget = (1 − goal) × events, burn-rate alerts (<https://docs.cloud.google.com/stackdriver/docs/solutions/slo-monitoring>); console/API/Terraform only, no gcloud verb found. One 99.5 % availability SLO plus one uptime check is enough here.
- Minimal runbook, rollback first: (1) `update-traffic --to-revisions LAST_GOOD=100`; (2) `revisions list`, `services describe --format 'value(status.traffic)'`; (3) `logs read --log-filter 'severity>=ERROR'`; (4) Error Reporting on the Metrics tab; (5) incident note → `bugs`.

## 6. Background work

- Jobs: `gcloud run jobs deploy|execute` (§ 4); `--tasks`, `--max-retries`, `--task-timeout`, `--execute-now`, `--wait`.
- Scheduler → job: `gcloud scheduler jobs create http NAME --location R --schedule "0 3 * * *" --uri "https://run.googleapis.com/v2/projects/P/locations/R/jobs/JOB:run" --http-method POST --oauth-service-account-email SA` — OAuth token, not OIDC, because the target is the Cloud Run API; SA needs `roles/run.invoker` (<https://docs.cloud.google.com/run/docs/execute/jobs-on-schedule>). Use a dedicated SA, never the compute default the doc shows.
- Scheduler → service: `gcloud scheduler jobs create http NAME --schedule "..." --http-method POST --uri SERVICE_URL/path --oidc-service-account-email SA --oidc-token-audience SERVICE_URL`; SA gets `roles/run.invoker` on the service (<https://docs.cloud.google.com/run/docs/triggering/using-scheduler>).
- Cloud Tasks vs Pub/Sub (<https://docs.cloud.google.com/tasks/docs/comp-pub-sub>): Tasks = "explicit invocation … publisher retains full control", scheduled delivery, rate limits, dedup, 1 MB, regional; Pub/Sub = fan-out, 10 MB, ordering keys, global. Default: Tasks for "do X later for this user", Pub/Sub only with a second consumer. `gcloud tasks create-http-task --queue Q --url URL --oidc-service-account-email SA --oidc-token-audience URL [--schedule-time T]` (<https://docs.cloud.google.com/sdk/gcloud/reference/tasks/create-http-task>); `gcloud pubsub subscriptions create SUB --topic T --ack-deadline=600 --push-endpoint=URL/ --push-auth-service-account=SA`, plus `roles/iam.serviceAccountTokenCreator` for `service-PROJECT_NUMBER@gcp-sa-pubsub.iam.gserviceaccount.com`; non-2xx = retry (<https://docs.cloud.google.com/run/docs/tutorials/pubsub>). All three deliver an OIDC token: the service stays `--no-allow-unauthenticated`, the invoker SA holds `roles/run.invoker`, no app-side auth code.

## 7. gcloud install and components

- CLI 587.0.0, Python 3.10–3.15 (<https://docs.cloud.google.com/sdk/docs/install-sdk>). macOS: `brew install --cask gcloud-cli` (cask 587.0.0; "google-cloud-sdk" is a former token; extra binaries land in `$HOMEBREW_PREFIX/share/google-cloud-sdk/bin`, <https://formulae.brew.sh/cask/gcloud-cli>). The skill's `brew install google-cloud-sdk` is wrong twice: cask, and renamed.
- Linux (Debian/Ubuntu): `curl https://packages.cloud.google.com/apt/doc/apt-key.gpg | sudo gpg --dearmor -o /usr/share/keyrings/cloud.google.gpg`; `echo "deb [signed-by=/usr/share/keyrings/cloud.google.gpg] https://packages.cloud.google.com/apt cloud-sdk main" | sudo tee /etc/apt/sources.list.d/google-cloud-sdk.list`; `sudo apt-get update && sudo apt-get install google-cloud-cli`. A root step under the standing-permission rule; the tarball + `./google-cloud-sdk/install.sh` is the no-root path.
- Components: "gcloud CLI component manager is disabled when using [apt/yum]"; extras are apt packages (`google-cloud-cli-kubectl`, …) (<https://docs.cloud.google.com/sdk/docs/components>). Whether `beta` ships in the apt package is unconfirmed — `gcloud beta --help` on the box. `cloud-sql-proxy` is not in the components table; install the Auth Proxy as in § 4.

## Proposed skills

### (a) `cloud-run-deploy` edits

1. **Flags table** replaced by the § 1 rows: probes, `--ingress`, Direct VPC egress vs connector with the recommendation, `--add-cloudsql-instances`, `--cpu-boost` (default on), `--concurrency`, `--cpu-throttling`, `--execution-environment` (unset), `--set-secrets` (pinned version), `--iap`. Delete `--platform managed`. Keep "apply deliberately"; project-specific flags live in `docs/deploy/gcp.md` with a reason each.
2. **Canary block** between Push & Deploy and Verify: the five commands of § 1, the tagged-URL form, the `--no-traffic`/LATEST trap with `--to-latest` as the promote step, `--remove-tags` last. `/preflight`'s deploy row calls it; only a rollback skips it.
3. **Verify**: `URL` from `services describe`; public per `docs/deploy/gcp.md` → `curl -fsS "$URL/healthz"`, else `curl -fsS -H "Authorization: Bearer $(gcloud auth print-identity-token)" "$URL/healthz"` or `gcloud run services proxy`; the tagged URL first during a canary; then `logs read --log-filter 'severity>=ERROR' --freshness 15m`; report revision, traffic split, URL. Default probe `--startup-probe httpGet.path=/healthz`, matching `docker/references/health-checks.md`.
4. Pre-flight step 6 adds `roles/cloudsql.client` when `--add-cloudsql-instances` is used and `roles/run.invoker` for every caller SA.
5. `docs/deploy/gcp.md` template: a "Rollout" row (tag name, promote step) and an "Ingress / IAP / VPC" row.

### (b) new skill `operate-gcp`

Description: "Operate a running Cloud Run service on GCP: the runbook, reading logs and Error Reporting, metrics, uptime checks and alerting policies, rollback outside a release, and turning an incident into a bug record. Use when a service misbehaves, when asked for logs, metrics, alerts or a runbook, or when a rollback is needed and no release is in flight. Do NOT use for a deploy, an image build or a release (`cloud-run-deploy` via `/preflight`), for gcloud credentials (`gcloud-setup`), for the database (`data-gcp`), or for GKE (`gke-basics`)."

Sections: **Runbook** (§ 5's five steps, rollback first, exact commands, the `docs/deploy/gcp.md` defaults); **Logs** (`services logs read`, `logging read` filters, `beta … logs tail`, the slog keys Cloud Run maps, the Error Reporting JSON shape); **Metrics and alerts** (metric names, one uptime check, a 5xx-rate and an instance-count policy JSON, `policies create --policy-from-file`, channels; SLO in one paragraph); **Rollback outside a release** (`update-traffic --to-revisions`, when to `--remove-tags`, recorded in `changes/`, never re-tagged as a release); **Incident note → bug record** (revision, time window, log query, cause; dispatch `bugs`; the prevention rule becomes an alert or a probe when it can).

### (c) new skill `data-gcp`

Description: "Cloud SQL PostgreSQL for a Go service on Cloud Run: create the instance cost-consciously, connect with pgx through the Cloud SQL Go connector with IAM authentication, run migrations as a Cloud Run Job, connect locally through the Auth Proxy, and check indexes and constraints. Use for any Cloud SQL, schema, migration or connection-pool question. Do NOT use for the deploy itself (`cloud-run-deploy`), for local Postgres in compose (`docker`), or for Terraform-managed instances (`terraform`)."

## Verdict: APPROVE WITH NITS

Nothing in this range is broken. The release is the BUG-085 fix: a fixed canary line appended last to the rendered context, a size test that pins the rendered context plus `rules/*.md` under 22,000 bytes against Antigravity's observed 24,000-byte block cap, and the pruning of `context/AGENTS.md` / `context/dev-setup.md` that brings it to 20,205 bytes. The Go change is small, traced, and covered by two tests that can fail. The one defect I found is latent rather than live: the size test counts only the BYTES OF THE FILES, while this project's own BUG-085 probe measured roughly 300 bytes of per-file block overhead that the test does not count — harmless today because `rules/` is empty, a silent overflow once several rules files exist. `gofmt -l cmd internal`, `go vet ./...` and `go test -race ./...` are all clean on this head (three packages `ok`).

## Findings

- **[low / confidence: medium]** `internal/harness/size_test.go:38-44` — the block accounting undercounts per-file overhead. `total = len(ctx) + Σ len(r.Raw)` treats Antigravity's `<user_rules>` block as the concatenation of file bytes, but BUG-085's own probe (`.agents/docs/bugs/BUG-085-…md`, Probe 2026-09-21) measured a 45-byte second rules file costing `AGENTS.md` 342 additional bytes — i.e. ~300 bytes of wrapper/overhead per file that this sum ignores (the store shows each file wrapped as `<RULE[path]>…</RULE[path]>`). With `rules/` empty the test is exact today; with six `rules/*.md` files it would report ~1,800 bytes less than the CLI builds, which is most of the 2,000-byte margin the budget is made of, and the failure mode is a silent truncation with no test red. Concrete fix: add a measured per-file allowance in the sum (`total += len(r.Raw) + rulesFileOverheadBytes` with `rulesFileOverheadBytes = 350`, citing the probe), or state in the test comment that the count is exact only while `rules/` is empty. Also affects the claim in `README.md:207` and `REQUIREMENTS.md:50` that `rules/` files "share the block"/"count toward the budget" — true, but they cost more than their own size.

Not findings, recorded for the record: `skills/cloud-run-deploy/SKILL.md:37` inserts an unnumbered `-` bullet directly after numbered Pre-flight item 5, so the service-account precondition reads as part of "Registry auth" rather than as its own step — formatting, no failure mode, and step 1 now names the service account and says "all six" (the fix recorded in `reviews/2026-09-21-review-worktree-docs-3.md` § Outcome). `README.md:72` still points at "context § Git" for the attribution mechanics, and the pruned context § Git no longer restates the settings key — the RULE it points at (author is the local git config only, the CLI's reminder defers to it) is still there, and the mechanics are in `README.md:72`, `REQUIREMENTS.md:19,59`, `.agents/docs/deploy/local.md:87` and `remote.md:19`, so BUG-039's prevention rule still holds somewhere a reader lands.

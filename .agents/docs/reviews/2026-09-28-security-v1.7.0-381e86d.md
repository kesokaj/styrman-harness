## Findings

- **[medium / confidence: high]** `.agents/docs/testing/skill-matrix.md:13-14` — row 1 is partly closed, and the allowlist is not the sandbox's real boundary.
  - **Unscoped file tools.** `read_file(*)` and `write_file(*)` stay unscoped, and row 1 names `write_file(*)`. The verify log only records that they "stay"; it gives no reason. The run uses `HOME=<home>` under the operator's own UID, so:
    - `read_file(*)` reaches the real `~/.ssh/`, `~/.claude/.credentials.json` and the real `antigravity-oauth-token`;
    - `write_file(*)` reaches shell startup files, `~/.claude/settings.json`, agy's own `settings.json`, and the harness checkout's source, which feeds the next release.
  - **Kept grants still run arbitrary code.**
    - `go`: `go run` executes a file the agent wrote. The Go demo needs `go`, so it cannot simply be removed.
    - `git`: a `-c alias.<x>=!<cmd>` or `-c core.sshCommand=<cmd>` override runs a command.
    - `find`: `-exec` runs a command.
    - Claude's `Bash(for:*)`: a loop body can run a command. Confidence on this one is low; how Claude Code 2.1.283 splits a loop was not probed.
  - **`sh-agent` allows every verb.** `command(sh-agent)` "allows every argument", and Claude's `Bash(sh-agent:*)` is just as wide. That includes:
    - `sh-agent install --home <any path>`, which can install into the real home, against `AGENTS.md`'s development rule;
    - `sh-agent report`, which sends data to the feedback repository.
  - **Swapping `HOME` does not isolate SSH.** OpenSSH finds `~/.ssh` through the passwd entry, not `$HOME`, and an inherited `SSH_AUTH_SOCK` also works. So `git` in a sandbox run can authenticate as the operator. Step 3's `git push` audit only detects this after the fact; it does not prevent it.
  - **Why it is exploitable in principle.** An agent that follows injected instructions, or simply misbehaves, can read a credential and send it out through `git`, `go` or `curl` (see the curl finding below).
  - **Remediation:**
    - (a) Run the matrix as a separate OS user, or in a container that does not mount the operator's home. That is the only boundary that holds while `go run` is granted, and it is the operator's design decision.
    - (b) Until then, scope `read_file`/`write_file` to the run's clone and `<home>/.config/sh-agent`, if agy 1.2.8 accepts a path argument. Prove the entry with the invalid-allow-entry check in both the must-pass and must-fail states. If agy does not accept a path, say so in the matrix.
    - (c) Narrow Claude's `Bash(sh-agent:*)` to the verbs a row uses, such as `Bash(sh-agent status:*)` and `Bash(sh-agent list:*)`.
    - (d) Reword line 13 so it names `go`, `git`, `find` and the same-UID reach as the accepted residual, instead of implying that nothing left runs anything.

- **[medium / confidence: high]** `.agents/docs/testing/skill-matrix.md:45-46` (with `:14`) — two scenario rows need commands the narrowed lists deny, and the procedure's remedy undoes row 1.
  - The `bash` row says "Run bash -n on it", and the `python` row says "Run python3 -m py_compile on it". Neither command is in either narrowed list.
  - **On agy:** a run that tries them logs "auto-denied", so under line 14 it does not count. The line-14 remedy then adds `command(bash)`/`command(python3)` "here, by name". That goes into the one list shared by every row. Because a `command(<name>)` grant allows every argument, this brings back the arbitrary-execution grants row 1 removed.
  - **On Claude:** there is no auto-denied check, so these runs pass silently with the step never run.
  - **Why nothing caught it:** the full matrix was not run ("Not exercised" in `2026-09-28-verify-token-rule-and-matrix.md`), and that is where this would have shown.
  - **Remediation:** change the two prompts so the agent writes the file and does not run the checker. Step 3's check already runs `bash -n` and `py_compile` outside the agent. If an agent must run them, grant Claude only `Bash(bash -n:*)` and `Bash(python3 -m py_compile:*)`, and never grant `command(bash)`/`command(python3)` on agy.

- **[low / confidence: medium]** `.agents/docs/testing/skill-matrix.md:13` — `Bash(curl http://localhost:*)` and `Bash(curl http://127.0.0.1:*)` do not confine curl to the local host.
  - **Over-match.** A prefix rule leaves everything after the prefix free:
    - extra URLs and upload options, e.g. `curl http://localhost <other URL> --data-binary @<file>`;
    - if the rule is read as a plain string prefix, also userinfo (`http://localhost:<x>@<other host>/`) and look-alike hosts (`http://localhost.<domain>/`).
  - **Under-match.** Claude Code's documented permission syntax (recalled, not probed) treats a trailing `:*` as the legacy spelling of ` *`, a prefix followed by a word boundary. Read that way, the rules also deny the port-bearing requests the matrix would make, such as `curl http://localhost:8080/healthz`.
  - **Not exercised.** The Claude list was not run; section 2 of the verify log checked agy only.
  - **Not needed.** No scenario prompt needs the agent itself to call the service.
  - **Remediation:**
    - drop curl from the allowlist, and exercise the service from step 3 (outside the agent) or with `go test` and `httptest`;
    - add `curl` to step 3's command audit.

- **[low / confidence: high]** `.agents/docs/testing/skill-matrix.md:14` — gate row 8's follow-up exists as a description of the file, not as a check.
  - The handoff's Next Step 3 asked for this: "Add a check that the sandbox settings carry no `toolPermission` key".
  - The matrix now states "no `toolPermission` key" as file content.
  - The condition for a run to count still names only the "auto-denied" and "invalid allow entry" checks. Row 8 showed that an `always-proceed` settings file passes both.
  - **Remediation:** make it a condition for the run to count that the written `settings.json`:
    - parses;
    - has no `toolPermission` key;
    - lists only the clone in `trustedWorkspaces`.

    Check this before the CLI starts, once where it must pass and once where it must fail (the prove-the-setup rule, `AGENTS.md:64-67`).

- **[low / confidence: high]** `internal/harness/plan.go:210-222` and `.gitignore:7-31` — the secret-shaped vocabulary now lives in four lists that disagree.
  - `antigravity-oauth-token` was added to two of them:
    - the context (`context/AGENTS.md:45`);
    - preflight (`skills/preflight/SKILL.md:40`).
  - It was not added to the other two:
    - `secretShaped()`, which refuses secret-shaped files at install and adopt time;
    - `.gitignore`, whose comment says it is kept in step with `secretShaped()` and "stops the add".
  - **Consequence:** an agy token file that lands in the checkout or in a skill directory is neither ignored nor refused. Only the model-level rule stops it.
  - **Other gaps:**
    - `oauth_creds.json` (the Gemini CLI's file) is not matched by `*credentials*.json`;
    - the context list lacks `id_rsa`/`id_ed25519`, `.netrc` and `.npmrc`, which the file-level lists already carry.
  - **Remediation:** add `antigravity-oauth-token` to `secretShaped()` and `.gitignore` in one change, together with the test that keeps them pinned. `filepath.Match` from the stdlib stays; no dependency is needed.

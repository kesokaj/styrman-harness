## Verdict: FINDINGS

Worst first: the nightly dream still runs a project's configured `core.fsmonitor` command. The range hardened the dream's `git status` against exactly that (security review 2026-10-01 rounds 2 and 3; `trailStatusArgs`, `TestTrailStatusArgs`), but one call earlier in the same project pass, `memory.Store` runs `git ls-files`, which reads the index and fires the hook. Measured on a scratch probe: plain `status` 1, hardened status 0, `rev-parse` 0, `log` 0, `ls-files` 1, `check-ignore` 1. So the control the code and its test claim does not hold at 03:00. After that: `--home` does not scope the service manager the timer verbs drive (on macOS a test `--install-timer --home <scratch>` loads a real nightly job over the real home); the dream redacts `feedback.jsonl` lines more weakly than report redacts the same file (measured); `memory show`/`add` follow a symlinked MEMORY.md; and for Antigravity, R3's "a CLI with no tools" rests on vendor permission behaviour this slice cannot show. Nothing high. No committed secret, no hand-rolled crypto, no new dependency; govulncheck reports only the known GO-2026-5024.

## Findings

- **[medium / confidence: high]** `internal/memory/memory.go:85`, reached every night from `internal/dream/collect.go:56` (`memory.Store`), in `--dry-run` too. `trusted()` runs `git -C <project> ls-files -- .agents/memory` without `-c core.fsmonitor=false`. `ls-files` reads the index, so a `core.fsmonitor` command set in that project's `.git/config` (or a file it includes) runs unattended, for every indexed project, every night. That defeats the hardening at `collect.go:238-244` ("it runs no fsmonitor hook the project may have configured"), which covers only the status call. Measured on a scratch probe (`.agents/scratch/sec-probe-fsmon`, hook set with `-c`, a marker counted per command): plain `status` fired 1 (must-fire control), `trailStatusArgs` status 0 (must-not-fire), `rev-parse --git-common-dir` 0, `log --name-only` 0, `ls-files` 1, `check-ignore` 1. Precondition: someone can write that project's git config. A clone does not carry it; a copied or unpacked repository does, and so does a tool that writes repo config. The project's own reviews judged this vector worth closing. Remediation: one helper for every git call on the dream path (`memory.Root`, `memory.trusted`, `trailDates`) that puts `--no-optional-locks -c core.fsmonitor=false` before the verb, plus a test that runs each of those calls against a probe repository whose fsmonitor hook writes a marker, with plain `status` as the must-fire control. `check-ignore` in `memory.Add` and `search.guardProject` (`internal/search/search.go:134`) also fires the hook, but it runs in the operator's own interactive session. Not an issue if: the operator rules every indexed project's `.git/config` trusted. Then the `trailStatusArgs` hardening and its comment's claim should be withdrawn too, not kept.

- **[low / confidence: high]** `internal/dream/timer.go:112,116,171,175` via `cmd/sh-agent/main.go:298-305,341-350`. `--home` scopes where the unit files go, but not the service manager: `systemctl --user` and `launchctl … gui/<uid>` act on the operator's real session. On Linux, `uninstall --home <scratch>` or `dream --remove-timer --home <scratch>`, with a timer file in the scratch home, runs `systemctl --user disable --now sh-agent-dream.timer`. That disables and stops the REAL nightly timer, while the output says the scratch one was removed. On macOS, `dream --install-timer --home <scratch>` runs `launchctl bootstrap gui/<uid> <scratch plist>`. That loads a real job into the login session whose ProgramArguments are `<scratch>/.local/bin/sh-agent dream --all`, with no `--home`. The job then dreams over the REAL home's projects and sends their content to the model, from a command meant as a test. This breaks the project rule that development never runs against the real `$HOME`, and the consent R3 ties to `--install-timer`. The tests use a fake manager, so they never see it. Remediation: when `home` is not the real user home (the `os.SameFile` check `NoteRunningElsewhere` already makes, `internal/harness/pathguard.go:113-121`), write or remove the files only and skip the manager calls, or refuse the verb, saying which. Test it with the fake manager recording no call under a scratch home. Not an issue if: `--home` is declared unsupported for the timer verbs and refused.

- **[low / confidence: high]** `internal/dream/collect.go:65-67,148-154` with `internal/harness/report.go:277-283`. The dream sends each `feedback.jsonl` line raw through `harness.Redact`, which calls `redactLines(..., jsonl=false)` and so skips the decoded pass report runs on the same file (`report.go:264-266`). Measured with a synthetic line (`.agents/scratch/sec-probe-redact`, `json.Marshal` of `…?api-version=1&sig=FAKEVALUE…`): Go's encoder writes `&sig=`, report redacts the line, and the dream's `Redact` keeps it, so it would reach the CLI's model. `Redact`'s doc ("removes from text every line report would redact") is false for JSONL input; `TestRedactText` feeds plain text only. Remediation: judge each feedback line by `needleIn(decoded(line))` too, as report does, in `feedback()` or in a JSONL-aware `Redact`. Extend `TestRedactText` to run every `shapeSecrets` entry through `json.Marshal` and `scrub`. Not an issue if: feedback lines are never written by an HTML-escaping encoder. Nothing guarantees that; the writer is whatever the session uses.

- **[low / confidence: medium]** `internal/memory/memory.go:243-261` (`readLines`, used by `Show` and `Add`) and `:230` (`nativeOn`). MEMORY.md is opened with `os.Open` and a symlink is followed. `trusted()` refuses a linked `.agents`/`.agents/memory` and tracked content, but not a linked file inside the store. An untracked link (an unpacked archive, another tool) makes `memory show` print the target's non-empty lines into the session, and `memory add` copy them into the rewritten MEMORY.md. `nativeOn` reads `.claude/settings.local.json` through links and with no cap. The dream's reader of the same store refuses non-regular files (`collect.go:186-201,246-256`), so the two readers of one store disagree. Remediation: Lstat plus a regular-file check and `ReadCapped` for MEMORY.md (and settings.local.json); a test with a linked MEMORY.md. Not an issue if: the store's threat model is only what a commit can carry (ADR-043's wording), accepted explicitly.

- **[low / confidence: low]** `internal/dream/dream.go:166-177`, `internal/dream/run.go:207-247,249-284`. REQUIREMENTS R3: the dream "runs a CLI with no tools". For Claude Code it does: `--tools ""`, `--strict-mcp-config`, `--setting-sources local` from the empty `dream-work` cwd, no session persistence. Antigravity has no no-tools flag. Its tools exist and are refused by `--mode plan` plus a private HOME whose settings allow nothing with `request-review`. `answer()` discards the result only AFTER a tool step shows up ("a tool step that ran, denied or not"), and `keepFailure` then keeps that stdout locally. Whether any agy tool class (read-only file view, web fetch) can execute under these settings is vendor behaviour this slice cannot show. If one can, a prompt-injected trail record or transcript (input others can write) could read files or reach the network unattended, and discarding the answer undoes neither. Remediation: record on the trail a probe of agy with these exact settings and a prompt asking for every tool class, including read-only and web. Without that probe, `--vendor antigravity` does not meet R3's "no tools" and should be refused for dream. Not an issue if: that probe already exists on the trail. My slice holds none.

## Checked

- **Secrets**: no credential, token or private key in the slice's code or tests (test values are `FAKEVALUE`). `releaseSigner` is a public allowed-signers line, compiled in. The agy OAuth token is copied 0600 into a 0700 `MkdirTemp` under `~/.config/sh-agent`, removed on exit, swept after 1 h when a run is killed. Clone/push errors scrub URL userinfo; dream log and failure text pass `scrub`. The redaction needles were reviewed by kind against `TestReportRedactShapes`. Against v1.16.2 the secret-assignment rule is narrower for short unquoted values (`password=abc`, `token=abcdefg`, `secret = my passphrase` now pass) and wider for the pass family and `--password x`. That is the pinned, accepted IN1 trade-off, not a finding. Space-separated `password hunter22` (the netrc shape) was not covered in v1.16.2 either.
- **Injection**:
  - SQL and SQLite: all SQL is parameterized; FTS words are quoted; LIKE is escaped. The SQLite DSN is built with `url.URL`, `mode=ro`, on a copy. An Antigravity `conversation_id` holding a separator or `.`/`..` is refused. The protobuf walk is depth-capped and bounds-checked.
  - Timer units: the systemd unit refuses quote/backslash/CR/LF and doubles `%`; the plist is XML-escaped.
  - Commands: `exec.Command` takes argv only, never a shell. The release tag is validated before it reaches argv.
  - Zip: names that are absolute, hold a backslash or `..`, are non-local, too long or too deep are refused, and so are symlink and irregular entries. Sizes are counted by decompression, writes use O_EXCL, and the archive is hashed and parsed from one buffer.
  - Dream output: prompt fences are escaped and labels folded; proposal fields are folded or indented; draft names are regex-checked.
  - Flags: one FlagSet per verb; `reorder` reads value flags from the FlagSet; `--` is kept; a stray argument exits 2; `--from-zip` is decided from the parsed flags.
- **Authz/authn**:
  - Release update: the gh tag goes through `IsReleaseVersion`, never sideways or back. `ssh-keygen -Y verify` uses the compiled-in signer, the namespace, and a version marker inside the signed bytes. Each asset has one checksum line, and the binary read is capped at 256 MiB.
  - Zip place: verified when SHA256SUMS and .sig are both beside the zip, otherwise installed marked UNVERIFIED (ADR-041, by design). A half pair counts as unsigned, which gives nothing to an attacker who could delete both anyway. `ReadCapped` fails closed on streams.
  - Report: refuses `GIT_DIR` & co., checks the origin exactly, pushes to the URL.
  - `knownCheckout` and `ResolveSource` refusals: unchanged.
- **Crypto**: only `crypto/sha256` checksums and OpenSSH signature verification. No hand-rolled primitive, token, session or auth flow.

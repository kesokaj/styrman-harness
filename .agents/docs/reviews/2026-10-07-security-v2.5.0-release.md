## Findings (round 1)

- **[medium / confidence: high]** `.agents/docs/testing/ab-kit/run.sh:24-25,59` (the same residual in `seed-security/run.sh:9-10` and `agy-rel/run.sh:13-14`): **an orphaned, agent-written server is live and network-reachable.**
  - **What is running.** pid 269650, `/tmp/crmsmoke/crm (deleted)`, cwd `~/sandbox/ab/runs/control-2/app`, `LISTEN *:18089`, up 04:04:26 at 15:17 UTC.
  - **Why it is exploitable in principle.** It is unattended model-written code serving an unauthenticated read/write API on every interface, as the operator's uid. The prior reviews record that this container network also carries an unauthenticated credential broker. The agent also wrote outside its sandbox (`/tmp`).
  - **What the kits did.** Their only guard was a header sentence ("check `ss -ltnp` after one"), and it did not work here.

**1. The orphaned server: FIXED.**
- At 15:32 UTC `/proc/269650` was gone and nothing listened on 18089.
- A `/proc` sweep for any process with its cwd under `~/sandbox` or `/tmp/crm*` found only the three in-flight kits: the `seed-security` main shell, the `ab-kit` `control` subshell and its `timeout claude`. There was no orphan.

`kit_leftovers` is identical in all three kits. It is called:
- in `ab-kit`, after the link removal, with `exit 1` before `exit "$rc"`;
- in `seed-security`, before scoring, with `[ "$lo" = 0 ]` as the last line;
- in `agy-rel`, after the agent check, as `verdict=FAIL…`.

I checked it for defects:
- **errexit.** `cwd=$(readlink …) || continue` and `kit_leftovers || lo=1` are safe.
- **pipefail.** The `tr | cut` inside the message has no early-exit reader.
- **Self-kill.** `seed-security` runs with its main shell's cwd in the clone (`cd "$KIT_CLONE"`). The sweep shows pid 1235646 there, and `$$` excludes it. Subshells forked inside the loop come after the `/proc/[0-9]*` glob is expanded, so the loop does not list them.
- **Exit status.** It returns 1 when something was found, whatever happened to the kill.
- **Driver edits.** The edits landed at 15:21:02 and 15:31:54, and all three in-flight runs started at 15:32:02, so no driver changed under a running bash.

The coordinator's both-ways validation (a planted `sleep 300` returns 1 and is killed; none returns 0) was taken as reported, not re-run.

- **R2-1 [low / confidence: high]** `kit_leftovers`, in all three kits: **narrower than the remediation.**
  - **What it catches.** It matches only a cwd inside `$KIT_CLONE`. That covers this incident (cwd was the clone).
  - **What it misses.** A process the agent starts with another cwd (`cd /tmp && ./crm &`, `$KIT_HOME`, or a daemon that `chdir`s to `/`) is not seen. Neither is a listener whose cwd lies elsewhere.
  - **Remediation.** Also match `exe` under `$RUN`, `$KIT_HOME` or `/tmp`, and listeners new since `t0` (`ss -ltnp` before and after). Or say "cwd inside the clone only" in BUG-163's Prevention line.
  - Low because the failure is a silent miss of a rarer shape, not a regression.

**2. The round-2 skip for security: FIXED.** `skills/review/SKILL.md:94` adds "never for a `security` finding of medium severity or higher, whose fix that agent re-checks". A grep over `context/`, `skills/*/SKILL.md`, `agents/`, `AGENTS.md` and `README.md` finds no other restatement of the skip, so there is no stale copy.

**3. Effort `high`: accepted, not changed.** The limit is stated in the seed log ("a sample … not a proof"), and the harder fixture is a follow-up. I accept this as a recorded decision.

**New trail.**

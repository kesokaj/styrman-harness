## Verdict: FINDINGS

**Worst problem: the Antigravity reader still sends tool-call arguments.** The round-2 fix drops a text run only when the run *starts* with `{"` (`internal/search/dream.go:240`). Two properties of the input defeat that.
- **The glued length byte.** A step payload is protobuf. The byte just before a JSON object is the last byte of its varint length. When that byte is printable, `textRun` (`:92`) starts the run on it (`F{"CommandLine":…`), and the prefix test fails. This happens for objects of 33-126 bytes and of 4224-16255 bytes.
- **The split.** Go's regexp matches runes, so the class `\xc2-\xf4` is U+00C2-U+00F4, not UTF-8 lead bytes. Any rune outside Latin-1 inside an object ends the run: an em dash, an arrow, a curly quote. The piece after it starts mid-object and is kept.

**Measured:** a count-only emulation over the 95 local conversation databases found 63-69 surviving runs that carry an argument key, plus about 230 fragment-shaped runs.

**Why the evidence missed it:** the test's `blob()` fixture frames every part with the constant bytes `0a 8f 01`, which hides both triggers.

**What is now false:**
- the spec's "a reply's tool-call arguments … are dropped";
- the change entry's "they are now dropped";
- round 2's Outcome 1 "fixed";
- plan D29's residual, "an unknown field type", on which the operator chose "Keep both, filtered".

An uncommitted change seen during this review (`HasPrefix` → `Contains`) closes the first trigger only.

Four lows:
- The timer fix drops only relative PATH entries, which Go's `exec.LookPath` already refused. The absolute project-local entries of round-2 finding 4 are unchanged.
- `answer()` still cannot see a tool call that ran without being denied (round-2 finding 5, bullet 2).
- The explicit `toolPermission` has no test that fails without it.
- The spec's state table still says leftover copies, including a copy of the OAuth token, are removed at the next run's start, without the new one-hour rule.

These hold: the `.agents` symlink walk, the `removeCopies` age rule itself, and the SUCCESS rule. There are no secrets in the range, no hand-rolled crypto and no new dependency, and govulncheck is clean.

## Findings
- **[medium / confidence: high]** `internal/search/dream.go:240` (`strings.HasPrefix(s, `{"`)`), with `textRun` at `:92` and the fixture `blob()` at `internal/search/dream_test.go:119-127`: tool-call arguments still reach the dream prompt.
  - **Mechanism 1, glued length byte.** A length-delimited protobuf field is tag, varint length, then the bytes. The object's first byte is preceded by the varint's last byte:
    - `len` itself for 1-byte varints;
    - `len>>7` for 2-byte varints;
    - and so on for longer ones.

    When that byte is printable (0x21-0x7e), it is in `textRun`'s first class, so the run begins on it and `HasPrefix` sees `F{"…`. That covers objects of 33-126 bytes and 4224-16255 bytes, and the windows repeat higher for 3-byte varints. A leading 0x20 is trimmed, so 32 and 4096-4223 are safe.
  - **Mechanism 2, split objects.** Go's `regexp` matches decoded runes, so `[\x20-\x7e\x80-\xbf\xc2-\xf4\n\t]` is a set of code points up to U+00F4. Any rune above that inside a JSON string value (U+2014 —, U+2192 →, U+2019 ’, CJK, emoji) ends the run, and so does an invalid byte, which decodes to U+FFFD. The first piece starts with `{"` and is dropped. Every later piece starts mid-object and is kept when it holds three spaces. This operator's own documents use em dashes and arrows throughout, so a written or replaced document is exactly the trigger.
  - **Evidence 1, synthetic Go check** (`.agents/scratch/sec-r3/main.go`: the regex and the filter loop copied verbatim from a275b96; no real data). Argument runs emitted:
    - `blob()`'s framing (prefix byte 0x01), 70-byte object: 0;
    - real wire framing, the same object: 1 (prefix byte 0x46);
    - real wire framing, a 5141-byte `CodeContent` object: 1 (prefix 0x28);
    - real wire framing, a 278-byte object with an em dash in a value: 1 (prefix 0x02, so the split alone).

    So the check is valid in both directions: the fixture shape passes, and the real shapes fail.
  - **Evidence 2, count-only emulation** over `~/.gemini/antigravity-cli/conversations/*.db` (95 databases). The opens were `mode=ro&immutable=1`, and nothing but integers was printed. The emulation follows the Go semantics: code-point classes, an invalid byte breaks a run, TrimSpace, the three-space rule, per-conversation dedup.

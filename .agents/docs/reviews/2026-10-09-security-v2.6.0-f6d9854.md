# Security review — v2.6.0-f6d9854   (2026-10-09)

Range reviewed: v2.6.0..f6d9854 (commits e9466c9, f6d9854; 5 files, +100/-4)

## Status: COMPLETE

## Verdict: FINDINGS

The exception cannot hide a real credential. I probed match boundaries, several matches in one
file, binary files with NULs, a key directly next to the example, the example inside a longer
token, CRLF line endings, and grep's exit codes. Every case where a non-example match sat beside the
example was still reported. Two weaknesses come from how the matches are now held.
(1) The worst: `kit_credential_leftovers` now copies every matched secret into the shell variable
`hits`. Under `bash -x` (xtrace) the assignment traces the credential in clear to stderr, and that
stderr is the kit's log. The old `grep -q` showed nothing. The preamble's own comment at line 180
names this exact risk ("never copied into a variable (bash -x would print it)") and avoids it for
`/proc/*/environ`.
(2) A correctness bug that fails closed. When the last file `find` yields holds only the example
key, the function returns 1. `left=$(kit_credential_leftovers)` then trips `set -e` inside the EXIT
trap. The kit exits 1 and prints neither "kit: no credentials left in KIT_HOME" nor the FAIL line.
The run does not count, so no credential leaks, but the exception fails at random (it depends on
directory order) and the new passing test depends on directory order too.

## Findings

- **[medium / confidence: high]** `.agents/docs/testing/kit-preamble.sh:150` — `hits=$(LC_ALL=C grep -aoE -- "$kit_cred_text" "$f" ...)`
  puts the matched credential text in a shell variable. Under xtrace (`bash -x kit.sh`, `set -x` in a
  kit, or `SHELLOPTS`/`BASH_ENV` that turn it on), bash prints `++ hits=<the token>` to stderr.
  Reproduced on a scratch copy with a real-shaped AWS key: the trace showed the whole value. The kit
  runs inside the EXIT trap, so the trace goes into the kit's log. Kit logs are summarised into
  `testing/` trail logs, and a log that is quoted or committed would carry a live token. Before this
  change, `grep -aqE` printed nothing even under xtrace. The comment at line 149 ("the matches stay
  in memory and are never printed") is false under xtrace.
  Remediation: keep the matches out of any variable that xtrace sees. Decide inside one process,
  with no variable. Count the non-example matches with one grep pipeline into `grep -cvxF` (the
  pipe ends normally, so BUG-157's early exit does not apply), or wrap the scan in
  `{ set +x; } 2>/dev/null` and restore it afterwards. Add a test that runs the preamble under
  `bash -x` with a real-shaped key and asserts the key is absent from the combined output.
- **[low / confidence: high]** `.agents/docs/testing/kit-preamble.sh:151` — `grep -qvxF ... <<<"$hits" && printf ...`
  returns 1 when a file holds only the example key, so the `case` returns 1. When that file is the
  last one `find` yields, the `while` loop and the function return 1 too. In `kit_on_exit` (line 207)
  `left=$(kit_credential_leftovers)` then trips `set -e`. The trap exits 1 and prints no credential
  verdict line, which is the BUG-158 class (a silent exit). Reproduced on a scratch copy of the trap:
  exit 1 and no verdict line for names `a.db`, `transcript.jsonl`, `q` and `m` (example file after
  `bin/sh-agent`), exit 0 for `conv.db` and `zz.db` (example file first). It fails closed, so no
  credential is hidden, but the exception works only some of the time.
  Remediation: `if LC_ALL=C grep -qvxF ...; then printf '%s\n' "$f"; fi`, or end the function with
  `return 0`. Add a test whose example-only file is the last one scanned, for example the only file
  besides `bin/sh-agent`, under several names.
- **[low / confidence: high]** `internal/harness/catalog_test.go:1622-1623` (subtests) and `:1655-1656` (no-print assert) —
  the new AWS cases check the exit code and the FAIL line, but the "prints paths only" check
  (`strings.Contains(out, token)`) looks only for the GitHub-shaped `token`, never for `awsKey`. A
  regression that echoed `$hits` would pass the AWS cases. The `-x` in `grep -qvxF` carries real
  weight and no test pins it: without `-x`, a match like `ghp_<example>abc…` (a GitHub-shaped token
  that contains the example as a substring) would be dropped as "contains the example". My probe
  confirmed that with `-x` this case is reported. Remediation: also assert `!strings.Contains(out, awsKey)`.
  Add a case with a `ghp_`-shaped token that embeds the example and must FAIL.
- **[low / confidence: medium]** `.agents/docs/testing/kit-preamble.sh:151` — the here-string
  `<<<"$hits"`. On bash < 5.1 (macOS `/bin/bash` 3.2, if `#!/usr/bin/env bash` resolves to it), and
  on any bash when the content is larger than the pipe buffer, bash writes the here-string to a
  temporary file in `$TMPDIR` (mode 0600, unlinked right away). The matched credentials therefore
  briefly reach disk outside KIT_HOME. That breaks the "stay in memory" claim and the scratch rule.
  On this box (bash 5.2.37, small content) bash uses a pipe. Not verified on macOS. Remediation:
  the same fix as the first finding (no variable, no here-string).

## Outcome

Written by the main agent, 2026-10-09. Each fix is pinned by a test case in `TestKitPreambleRefusesLeftoverCredentials` that fails against f6d9854's `kit-preamble.sh` and passes after the fix.
- Finding 1, matches held in `hits=$(…)` and printed under `bash -x`: **fixed**. AWS keys are now checked apart (`kit_cred_aws`): the matches are piped into `grep -cvxF` and only a count is assigned. `kit_cred_text` no longer holds `AKIA…` and is checked with `grep -q` as in v2.6.0. Pinned by the case "a key found under bash -x".
- Finding 2, the scan's status failing the EXIT trap when the last file holds only the example: **fixed**. The function ends in `return 0` and the AWS check is `[ "$n" = 0 ] || printf`. Pinned by the one-file case, which removes the wrapper so the file is the only one and asks the scan's status directly.
- Finding 3, the AWS cases never checked the output for the key, and nothing pinned the `-x`: **fixed**. The paths-only check now covers `awsKey`. "A GitHub token holding the example" is a guard: `ghp_` is matched by `kit_cred_text` before the AWS check, so the exception cannot drop it. The here-string, with its temp file on bash < 5.1, is gone.

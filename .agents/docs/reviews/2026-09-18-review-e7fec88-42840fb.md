absent, never touches an existing dir) from the new `TightenConfigDir` (Lstat-first, refuses a symlink
and a not-owned dir, prints a `mode` line, respects `--dry-run`, and turns a failed `chmod` into a note
rather than a failed install), called exactly once, from `Install` alone, before any file is written.
`gofmt -l cmd internal`, `go vet ./...`, and `go test ./...` are all clean. The dispatch's specific
checkpoint questions all confirm as expected:

- `TightenConfigDir` has exactly one call site (`apply.go:30`, inside `Install`); `grep -rn
  TightenConfigDir` shows no other caller.
- `Uninstall` (`apply.go:266`) does not call `Install` or `TightenConfigDir` and leaves the runtime
  dir's mode untouched — correct, matches the operator's decision that only install tightens.
- First-install path (dir absent): `TightenConfigDir`'s `os.Lstat` errors (`ErrNotExist`) and it returns
  immediately, printing nothing; later, non-dry-run, `SaveState` → `ConfigDir` `MkdirAll(…, 0700)`
  creates it — the home ends private. Confirmed by reading `apply.go:135-137` (`SaveState` gated on
  `!dryRun`) alongside `state.go:70-77`.
- The `mode` line's `%04o` on a 0755 dir prints `0755` (`os.FileMode.Perm()` for `0o755` formatted
  `%04o` → `"0755"`) — confirmed, and it's the exact string
  `TestInstallMakesTheConfigDirPrivate`/`audit_test.go:98` asserts.
- `install --dry-run` on a fresh home prints no `mode` line for the dir: `TightenConfigDir`'s `Lstat`
  errors on a not-yet-existing dir and returns before the `Fprintf`, and `SaveState` (the only thing that
  would create it) is skipped under `dryRun`. Right: a dry run that named a "mode" change for a directory
  it neither found nor would create would be reporting a change that never happens, contradicting `--dry-
  run`'s own contract elsewhere in this file.

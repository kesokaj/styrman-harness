## Findings

- **[low / confidence: high]** `.agents/docs/testing/skill-matrix.md:13` — "The protection is that the copied token lives only for the batch and is deleted by name after it" overstates what the procedure does.
  - **(a) The Claude credential copy is never deleted.** The sandbox home carries copies of the operator's `~/.claude/.credentials.json` and `~/.claude.json` (`testing/2026-09-21-verify-sandbox-pruned-context.md:13`). The only deletion step in the procedure is the agy bullet's "the file and the copied token are deleted by name after the batch" (`:14`), and it names the agy token only. So the Claude credential copy, now readable and sendable by the granted `bash`/`python3`/`curl`, is never named for deletion.
  - **(b) Deletion after the batch is not protection during it.** The same sentence says `go`, `git`, `bash` and `python3` "can each run anything and reach the real home". An agent in the batch can therefore read the real credentials too. Deleting the copies afterwards only means the sandbox home stops holding live credentials. That is the stated-property problem of round-1 finding 3, narrowed but not gone.
  - **Fix:**
    - name `<home>/.claude/.credentials.json` and `<home>/.claude.json` in the delete-by-name step;
    - reword the sentence to its true claim: "nothing protects the credentials during a batch; the copies are deleted by name after it so the sandbox home does not keep them".

- **[low / confidence: high]** `.agents/docs/testing/skill-matrix.md:14` against `AGENTS.md:66` — the rules disagree.
  - **The rule.** `AGENTS.md` § Testing says the agy sandbox settings are "written for the run with the fewest grants the run needs".
  - **What the matrix does.** Under option 1 the matrix writes one union list for every row. `command(bash)`, `command(python3)` and `command(curl)` go to `review`, `bug` and every other row. `command(curl)` is needed by no row at all: the `bash` row (`:45`) only writes curl into a script, and the checks run outside the CLI.
  - **Its own remedy.** This also contradicts the matrix's closing rule, "a scenario denied a command it needs gets that one command added here, by name".
  - **Why it matters.** Option 1 was the operator's decision (`changes/2026-09-28-1752-update-from-zip.md:22`), but the rule it departs from was left standing. The next matrix run either breaks `AGENTS.md:66` or follows it and drops the list. This is the "two texts on one mechanism" shape.
  - **Fix.** Pick one:
    - grant per row: `bash` and `python3` only to their two rows, and `curl` to none;
    - or amend `AGENTS.md:66` to "the fewest grants the batch needs" and drop `command(curl)` and `Bash(curl:*)`, which no row needs.

- **[low / confidence: high]** `cmd/sh-agent/zip_test.go:514-515` — the header of `TestUpdateFromZipRefusedRunSweepsNothing` describes the intermediate placement, not the final one.
  - **The header and the code.** The header says "The sweep runs only after the zip is unpacked". The code (`main.go:1096-1100`) sweeps only after `installFiles` succeeds.
  - **What the test catches.** The test refuses a non-zip file inside `UnpackZip`. It fails if the sweep returns to its pre-r3 place before `UnpackZip`, which is a real guard. It cannot catch a sweep placed between `UnpackZip` and `installFiles`, the exact placement its header describes.
  - **The other refusal test.** `TestUpdateFromZipRefusedContentWritesNothing` refuses at install time, but uses a fresh home with no stale `zip-*`, so it cannot catch that placement either.
  - **Fix:**
    - correct the header to "only after a successful install";
    - seed an hour-old `zip-old` in the content-refused test, or in a sibling test, and assert that it survives.

- **[low / confidence: medium]** `.agents/docs/reviews/2026-09-28-review-v1.7.0-381e86d-code.md` `## Outcome` — round-1 finding 4 is neither fixed nor rebutted.
  - Finding 4 says the Claude list was never exercised and the log's "Not exercised" section omits it. The Outcome settles findings 1–3 only.
  - The option-1 lists (`Bash(bash:*)`, `Bash(python3:*)`, `Bash(curl:*)`, `command(bash)`, `command(python3)`, `command(curl)`) have been exercised by no run either. Only `skill-matrix.md` contains `command(bash)` (grep over `testing/`).
  - This is expected before the next full matrix run. It should be stated in the Outcome, per the Definition of Done ("fixed or rebutted"), so the matrix is not read as verified.

Checked and not findings:
- **The `-` refusal** (`main.go:128-131`). `reorder` treats `--from-zip` as value-taking (`:709`), so `update --from-zip --dry-run` yields the value `--dry-run`. The refusal returns before `updateFromZip` runs, so nothing is created. A real file named `-x.zip` is still reachable as `./-x.zip`.
  - `TestFromZipDashValueRefused` fails without the fix. Without it, the run reaches `UnpackZip`, whose "reading the archive" error does not contain "--from-zip needs a file". It also fails if the refusal moves after `updateFromZip`.
- **Named-result flow after the tweak.**
  - `if err := installFiles(...); err != nil { return err }` shadows `err`, but `return err` assigns the named result before the defers run. `RemoveCreated` therefore still sees the failure.
  - The defers run in LIFO order: `RemoveAll(dir)` first, then `RemoveCreated`.
  - A `RemoveAll` failure warns and leaves a young `zip-*` dir. A later successful run sweeps it once it is an hour old.
  - When `UnpackZip` fails, its own defer removes `tmp`, so `RemoveCreated` meets an empty chain.
- **The sweep during a successful run.** The sweep runs while this run's own `zip-*` still exists, but that directory is younger than an hour, so the sweep keeps it.
- **Round-1 findings 1 and 2 are resolved.**
  - `Bash(curl:*)`, `Bash(bash:*)` and `Bash(python3:*)` are valid prefix rules, a prefix followed by a space.
  - The `bash` and `python` rows now have the commands they run.
  - The removed "No `bash`, `python3` or unrestricted `curl`" claim has no surviving restatement outside append-only `changes/` and `reviews/`. The `handoffs/…-1600` mention is a dated record.

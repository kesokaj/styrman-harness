# Review — BUG-015 plain-copy install never rebuilds (2026-09-14)

Range reviewed: uncommitted working tree vs HEAD (e0f6830), scoped to
`cmd/sh-agent/main.go`, `cmd/sh-agent/main_test.go`, `internal/harness/repo.go`.

## Verdict: APPROVE

Nothing broken found. The rename `ownCheckout` → `IsCheckout` has no orphaned
callers (old name greps clean; every git-touching entry point — `Inspect`,
`Behind`, `Pull` — uses the exported name). The core fix is correctly gated:
`shouldRebuild` now requires `ownCheckout` as a third AND-ed condition, so a
plain copy (`harness.IsCheckout(repo) == false`) cannot reach `Reinstall`
through `install`/`sync` (checked directly), `--dry-run` (same `rebuild`
bool feeds both branches), or `update` (`harness.Behind` returns
`errPlainCopy` before `update()` ever reaches its own `Reinstall` call at
the bottom) — and `SH_AGENT_REPO` changes which tree is resolved, not
whether `IsCheckout` is re-evaluated on it, so it cannot redirect around the
check. Before this diff, `shouldRebuild` fired for any `own` value as long
as `go` was on PATH, so a downstream mirror with a toolchain would attempt
`go build` into `<repo>/.agents/scratch/sh-agent-build-<pid>` — exactly the
failure BUG-015 describes for a read-only tree — confirming the fix targets
the right mechanism. `go test -race ./...`, `gofmt -l .`, `go vet ./...`,
and `go build ./...` all pass clean on this tree.

The `plainCopy` test fixture builds its "no .git" tree in a fresh
`t.TempDir()` and then self-verifies with `harness.IsCheckout` (the same
function under test, not a reimplementation), so it cannot be fooled into
asserting on a directory that actually has `.git`. `TestPlainCopyNeverRebuilds`
checks both the negative (no rebuild/build/warning text) and the positive
(binary actually lands under `--home`, `.agents` never created inside the
mirror), which is a test that can fail — reverting the `own` gate makes it
fail on the `"building sh-agent from"` assertion.

On the new stdout line: no in-repo consumer parses `install` output (only
prose docs reference the message text — `README.md:24`, `AGENTS.md:35`,
`.agents/docs/deploy/remote.md:33`). The downstream mirrors' own refresh
scripts (styrman-crew `image/harness/`, argolis-devbox `deploy/harness/`)
are outside this repo and were not reachable to inspect — see Not examined.

## Findings

None at high or medium severity. One low-confidence, low-severity
observation, not filed as a defect because it names no concrete failure:

- **[low / confidence: low]** `cmd/sh-agent/main.go:142-144` — the

  `Install(..., *dryRun, out)` still receives and honors the dry-run flag
  downstream, this has no effect on behavior — cosmetic only.

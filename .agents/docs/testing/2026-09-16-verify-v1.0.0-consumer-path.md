## What this settles

The trust root was read directly, not assumed. Every earlier record in this repository quotes the allowed-signers line from `deploy/remote.md` and says plainly that the copy adds no trust; this run verified the tag against the root-owned file itself and it passed, which also confirms the quoted line still matches the host's. The `sudo -n` reads in this session — the `cmp` inside the release procedure and the `verify-tag` here — are reads of a root-only file, the only root steps taken, and are named here because this project records no standing root permission.

## Pre-push checks, as the release ran them

Every one exited 0, in this order: the signing key derived from the private key matched the documented fingerprint; the tree was clean under `--untracked-files=all`; the release commit's parent was the gated head `0a67f3f`; `git diff --quiet 0a67f3f HEAD -- ':(top)' ':(top,exclude).agents/docs'` confirmed the release commit changed records only; the tag sat on HEAD and on `main`; it was annotated and SSH-signed; `sudo -n cmp` matched the quoted line against the host file; `verify-tag` passed.

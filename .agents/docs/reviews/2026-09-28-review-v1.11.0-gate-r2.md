## Verdict: REQUEST CHANGES

The worst problem is the fix for the cold-read cap (`skills/feature/SKILL.md:80`). It asks the user less often than both the retro text it replaced and the fix the round-1 finding suggested. When the third report ends `implementation ready`, every open gap is now turned into a D-row and the work proceeds without asking. That includes part-(1) gaps, which the brief defines as "what must be decided before implementation starts", and part-(2) scope items. So a third report of `design needs revision` plus `implementation ready` ticks the no-code gate with design gaps still open. A scope-creep item gets a D-row `by: cold read round 3`, and the brief's own test ("a gap unless a D-row says who asked for it") then counts it as asked for. That lets BUG-042 (b) through again.

The second problem is in `agents/verifier.md`. The verifier fix prescribes the unquoted `; echo <name>=$?`, and for a long suite adds a redirect. The probe transcripts show the permission gate refused the unquoted form 6 of 6 times, and allowed the quoted form 5 of 5 times when there was no redirect. The verify log reads the evidence as "inline vs redirected", so the text was narrowed on the wrong variable and still prescribes the refused form.

Round-1 findings 1, 2, 5, 6 and 7 are fixed correctly, and so is finding 4's arithmetic.

## Findings

- **[medium / confidence: high]** `skills/feature/SKILL.md:80` (with `:15`, `:55`) — The early exit now fires on `implementation ready` alone and turns "each gap and question still open" into a D-row, with no question to the user.
  - The brief at `:78` lets a report end `design needs revision` + `implementation ready`: gaps and BLOCKING questions are counted separately.
  - Part (1) defines a gap as "what must be decided before implementation starts", so proceeding with one open contradicts the brief's own definition.
  - Part (2) says a scope item "is a gap unless a D-row says who asked for it". A D-row `by: cold read round 3` satisfies that test for extra scope nobody requested. That reopens BUG-042 (b), "plan grew past the brief … the cold reader never asked", whose prevention says a gate must count something a headless run cannot argue its way around.
  - It also skips the cap's own `Open:` path, where "the phases that depend on them wait" (`:15`). An undecided gap written as a D-row carries no wait, and the text does not say who decides its content.
  - The retro text this replaced (d3cc2b7) scoped the exit to items the report marks NON-BLOCKING. Round 1 suggested "not a part-(1) gap". The Outcome's "meaning no BLOCKING question" is a wider rule, and nobody decided on it.
  - Fix: make the trigger "`implementation ready` and `design ready` was withheld only for items the report lists as NON-BLOCKING questions". Simpler: "the third report has zero part-(1) and part-(2) gaps and says `implementation ready`". Anything else goes to the user as before. If the wider rule is intended, it is a gate change for the operator: put it to them.

- **[medium / confidence: medium]** `agents/verifier.md:41-42` — Both bullets prescribe `; echo <name>=$?` unquoted.
  - In the probe transcripts, Claude Code's permission gate refused every unquoted `=$?` ("Contains simple_expansion"): 6 of 6 (`verifier-new-2` calls 2, 3, 5; `verifier-old-2` calls 3, 4, 7).
  - It allowed every double-quoted `echo "<name>=$?"` that had no redirect: 5 of 5 (`verifier-new-1` calls 7, 9, 10; `verifier-old-1` calls 2, 4).
  - Every redirect to a file was refused ("needs approval").
  - The corrected log (`.agents/docs/testing/2026-09-28-verify-retro-apply.md`, paragraph under the verifier table) explains the narrowing as "shared calls are only for output read inline". But the inline shared calls in `-new-2` and `-old-2` were refused as well. Quoting separated allowed from refused, not inline versus redirected.
  - The new long-suite form `> <file> 2>&1; echo <name>=$?` combines both refused constructs.
  - Failure mode: under a gate like the probe's, a verifier that follows the text literally loses a turn on every status echo and on the long suite. That is the turn-limit failure the retro change was meant to answer.
  - No behavioural run covers the cb6cf73 definition. The probe ran d3cc2b7's, and the changes entry lists only `go test` and the size test. `AGENTS.md` § Testing requires a behavioural run for an `agents/*.md` change.
  - Confidence is medium because the real operator's permission settings may allow both constructs.
  - Fix: prescribe `; echo "<name>=$?"` (quoted) in both bullets. Correct the log's causal sentence. Run the behavioural probe on the cb6cf73 definition before claiming the narrowing helps.

- **[low / confidence: high]** `.agents/docs/testing/2026-09-28-verify-retro-apply.md` (table column "Shared calls … executed") — Under the new definition, each of the 3 "executed shared calls" runs a single verification command followed by its echo (`verifier-new-1` calls 7, 9, 10: gofmt, vet, test separately). No call under the new definition ran two verification commands together. `verifier-old-1` call 4 did (vet, test and cover in one call).
  - The column therefore does not measure sharing. The log's "the old definition's verifier already combined commands" understates it: in this probe the new definition combined fewer commands than the old one.
  - Fix: count calls that hold two or more verification commands, or rename the column "status-echo calls".

# Security review — project   (2026-09-30)

Range reviewed: Scope: the whole repository at HEAD (3478a1c), no diff.

## Status: COMPLETE

## Verdict: FINDINGS

Nothing high or medium was found. Every finding is low. The worst one: `sh-agent update` on a release-binary place clears leftover download directories with a glob built from the home path (`release.go:144`). A home path that holds `*`, `?` or `[` therefore makes `update` run `os.RemoveAll` on `release-*` entries in OTHER directories, with no check of type or age. The project has already fixed this exact class in its two other sweeps (`report.go:419`, `main.go:1171`) and missed this third one. The release trust chain holds up as built: a compiled-in signer, SSHSIG verification by a system `ssh-keygen`, the version bound inside the signed bytes, anti-rollback, the asset's checksum, and size caps. The zip unpacker, report's push-target guards, the SQLite index and the settings.json edit also held up against the checks listed below.

## Findings
- **[low / confidence: high]** `internal/harness/release.go:144-148` — the pattern `globOrNil(filepath.Join(base, "release-*"))` is built from `ConfigDir(home)`, and the home comes from `--home` or `$HOME`. `filepath.Glob` reads metacharacters in the DIRECTORY part of a pattern as well. So a home of `/srv/*` matches every `/srv/<x>/.config/sh-agent/release-*`, and `/home/u[1]` matches `/home/u1/...` but not the real home. Every match is removed with `os.RemoveAll`, whether it is a file or a directory and however new it is. Because there is no age check, a second `update` running in the same home also deletes the first run's download directory while it is still in use. That run then fails verification, so this part fails safe. Exploitability needs a home path with metacharacters and write access to the other directory, which keeps this low. Remediation: list `base` with `os.ReadDir`, match the `release-` prefix, and skip symlinks and non-directories, as `sweepInterruptedClones` and `sweepStaleZipDirs` already do. Optionally add the one-hour age threshold the zip sweep uses. Add a test with a home path containing `[` or `*` whose sibling directory must survive.
- **[low / confidence: high]** `internal/harness/repo.go:197,225,241` — on a checkout place, `update` runs `git pull --ff-only`, then `go build` on the pulled tree, then runs the resulting binary. It never runs `git verify-commit` or `verify-tag` against the release signer. A release-binary place, by contrast, accepts only SSHSIG-signed checksums checked against a compiled-in key. A checkout place therefore executes whatever commit is at the tip of `main`, and its trust rests only on the GitHub account and the SSH transport. The signed tags do not protect it, because checkout places follow `main`. This is by design (R9: "Checkout places follow `main`"), and any change to it is a path change (project AGENTS.md rule 3). **Operator choice:** (a) record it as an accepted risk in an ADR line — recommended, because the operator owns every checkout place; or (b) verify signatures on `main` commits after the pull and before the build, using the compiled-in signer line written to a temporary allowed-signers file.
- **[low / confidence: medium]** `internal/harness/report.go:39-58` — redaction uses a deny-list, and the list misses several common credential shapes when no keyword (`token=`, `Bearer`, `Authorization:`) sits on the same line. Missed: JWTs (`eyJ….….…`), Stripe `sk_live_`/`rk_live_`/`whsec_`, npm `npm_`, Hugging Face `hf_`, PyPI `pypi-`, legacy OpenAI `sk-` followed by 48 alphanumerics, Slack webhook URLs (`hooks.slack.com/services/`), and URL userinfo with no password (`https://<token>@host`; the `url credentials` regex requires a colon). Such a value pasted into a correction or a proposal reaches `styrman-harness-feedback` verbatim. It stays low because the destination is the operator's private repository and D14 documents the heuristic's limits. Remediation: add these as prefix needles or anchored `regexp` patterns, for example `\beyJ[A-Za-z0-9_-]{8,}\.[A-Za-z0-9_-]{8,}\.` and `\bsk-[A-Za-z0-9]{32,}` (the latter so `task-` still does not match). Each needs a test that fails without it. The stdlib `regexp` package is enough, so no dependency is needed.
- **[low / confidence: high]** `skills/VENDORED.md` (the Apache-2.0 table) — `gke-basics` and `terraform` are deployed into both vendors on every machine, and their Source column reads "not recorded when vendored", with no pin and no digest. Every other vendored row has a commit pin or a verified sha256. These skills are instructions that agents with Bash access follow. Without a source and a pin, nobody can check the vendored copy against upstream or tell a local edit from upstream content. Remediation: re-vendor both from a pinned upstream commit and record the source plus the pin (or a tree sha256) as the other rows do.
- **[low / confidence: low]** `internal/harness/report.go:901-914` — when a push fails, the error returns git's stderr unscrubbed (`push failed, the commit stays local: %w`). The clone failure path (`report.go:487`) wraps the same kind of message in `scrubCredentials`, because a `url.*.insteadOf` rewrite can put a token into the URL git prints. The exposure is the same (the operator's own terminal) but the guard is inconsistent. Confidence is low because current git anonymises the URL in its push messages ("To …", "failed to push some refs to '…'"). Remediation: wrap both push-error returns in `scrubCredentials(...)`.

## Checked
- **Secrets:** `git ls-files` finds no secret-shaped tracked path. The only three name hits are trail documents with "token" in their names. A grep for key-shaped content finds only AWS's documentation example `AKIAIOSFODNN7EXAMPLE` (test fixtures, `skills/terraform/references`, 9 trail-doc mentions) and PEM headers without key bodies: 7 in the trail docs, each checked along with its next line, plus the fake bodies in `report_test.go`. The only key material in code is the release signer's PUBLIC key (`release.go:45`, also in README and `remote.md`). `.gitignore` and `secretShaped()` (`plan.go:216`) agree, and install (`plan.go`) and adopt (`adopt.go` `copyTree`) both refuse secret-shaped files. Report never prints origin URLs.
- **Injection:** every `exec.Command` passes an argv, with no shell. For `gh`, the tag from the API is validated with `IsReleaseVersion` before it reaches argv. `ssh-keygen` is looked up on system paths first. Every `git` call uses `-C <dir>`; the feedback URL is the constant `FeedbackURL`, and `add` and `commit` put `--` before the paths. The other commands are `go build` (with `GOTOOLCHAIN=local`) and `diff -u -L`. All SQL is parameterised: the only dynamic parts are constant table names in `gc` and `?`-placeholder lists in `scope.in()`. FTS5 terms are quoted word by word (`ftsQuery`). The SQLite DSN is built with `url.URL`, which escapes `?`, `#` and `%` (`store.go:66-77`).
- **Zip boundary** (`zip.go`, `main.go:1086-1191`): the archive is read into one capped buffer, and the checksum and the unpack both come from that buffer (no TOCTOU). Names are checked for being absolute, backslashes, `..`, `filepath.IsLocal`, length and depth. Symlink and non-regular entries are refused. Only the five trees are written, each file with `O_EXCL`. Byte limits count decompressed bytes rather than trusting headers. Mode is 0644 (no executable bit comes from a zip). Leftover `zip-*` directories are swept with `ReadDir` plus a prefix match, never following symlinks, after an hour. Accepting an UNSIGNED zip marked UNVERIFIED is the operator's decision (R9, ADR-041) and is recorded here as an accepted risk. A verified zip gets no rollback check, which is moot while unsigned zips are accepted.
- **Report boundary** (`report.go`): the push target must be the top of its checkout, with origin exactly equal to `FeedbackURL` as configured, and the push goes to the URL rather than to `origin`. `GIT_DIR`, `GIT_WORK_TREE`, `GIT_INDEX_FILE`, `GIT_OBJECT_DIRECTORY` and `GIT_COMMON_DIR` are refused. The throwaway clone is blob-less and sparse to this host's directory. Symlinks at `reports` or `reports/<host>` are refused, and `runDir` reserves the run directory with `Mkdir`. The hostname is reduced to one path element (`hostDir`). The dry run returns before any write. Collected files are Lstat'ed and non-regular ones skipped. The search index is never sent. `RemoveKeptClone` is guarded against: the git redirect variables, a symlink, a status that includes ignored files, stashes, and unpushed refs.
- **Authz/authn:** no network service or endpoint exists. Authentication is delegated to `gh` and git's SSH credentials, the operator's own. `knownCheckout` stops `update`/`install` from building a checkout that was only found by walking up from the working directory.
- **Crypto:** nothing is hand-rolled. Signature verification is delegated to OpenSSH `ssh-keygen -Y verify` (the SSHSIG format), with an allowed-signers line, an identity (`-I`) and a namespace (`-n sh-agent-release`), and the signed bytes go in on stdin. Checksums use `crypto/sha256`, and the manifest is standard `sha256sum` format. The `# styrman-harness vX.Y.Z` marker is application logic inside the signed bytes, not a primitive. The signer is compiled in; the fact that `-ldflags -X` can change it is documented (`release.go:28-44`), and preflight's zip check stops a release binary that carries a stray signer (`remote.md` ~l.161). Using OpenSSH and the stdlib like this is using them as designed, so it is no finding.
- **Settings write** (`main.go:815-937`): a symlinked settings.json is refused. A new file is created with `O_EXCL`. An edit is a textual insertion re-checked with `json.Valid` and written through a temporary file plus rename, keeping the original mode. Only an absent `attribution` key is written (R4).
- **Search index** (`internal/search`): the database and its WAL/SHM files are forced to 0600 inside a 0700 directory, and a non-regular file there is refused. A symlinked `.agents` or `.agents/scratch` is refused, and the database must be gitignored (`git check-ignore`). Checkout reads go through `os.Root` after an Lstat, so GO-2026-4970 cannot be reached (and go1.27.1 is not affected). `configView` uses plain reads of the operator's own state by design. `--global` runs git in every registered project root and trusts those repositories' git config (`core.fsmonitor` and the like), just as the operator's own git use does. That is informational, not a finding.
- **Dependencies:** there is one direct dependency, `modernc.org/sqlite v1.46.1` (R4, ADR-045), and `go.sum` is tracked. `govulncheck ./...` on go1.27.1, run 2026-09-30, reports "Your code is affected by 0 vulnerabilities", plus 1 vulnerability in a required module that the code does not call — the known GO-2026-5024 in `golang.org/x/sys` (ADR-045a). No new advisory. `npm audit` does not apply: no `package.json` or `package-lock.json` is tracked.
- **GCP surface:** the repository's code creates no GCP resources and binds no IAM. The guidance in the skills and the context is safe: `--allow-unauthenticated` for public services only (`cloud-run-deploy`), secrets through `--set-secrets` and never `--set-env-vars` (`context/dev-setup.md`, `cloud-run-deploy`, the init-project `gcp.md` template), and service-account key files as a last resort that needs the operator's say-so (`gcloud-setup` § Service account keys). No key file is committed.
- **Release procedure** (read only through a grep of `remote.md`): `SHA256SUMS` is written with the version marker, signed with `ssh-keygen -Y sign -n sh-agent-release`, and verified before upload. Assets are uploaded one by one after the release is created. A place that updates while a release is only partly uploaded fails closed: a missing asset or missing sums file is a refusal.

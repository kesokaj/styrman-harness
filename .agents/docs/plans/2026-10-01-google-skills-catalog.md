## Interfaces

- **Router skill** `skills/google-catalog/SKILL.md`: `name: google-catalog`; `description` one double-quoted line of at most 300 characters that triggers on Google Cloud, Gemini, Agent Platform, ADK and agents-cli work the other skills do not cover and names what it must NOT be used for (Cloud Run deploys, Cloud SQL, Terraform, gcloud login, GKE day-0: their own skills). Body, four numbered steps: grep `catalog/INDEX.md` beside the file for the product or task words (never read the index whole); read the best match's `catalog/<name>/SKILL.md` and follow it, its relative paths resolved against that entry's directory; run an entry's scripts through their interpreter; the harness's rules win on conflict (Git rule, secrets, GCP defaults asked first, deploy guides) and a harness skill that covers the task wins over an entry. No match: say so in one line and continue without the catalog.
- **Entries** `skills/google-catalog/catalog/<name>/`: byte-identical to upstream at the pin, file modes 0644. Names are upstream's directory names; 141 at import: google/agents-cli `skills/` (7) and `extensions/langchain/template/.agents/skills/agents-cli-langchain` (1) at 2c39459; google/skills `skills/cloud` (131) and `skills/developers` (2) at d5d9052.
- **`catalog/INDEX.md`**: generated by the refresh script, committed: a three-line header, then exactly one line per entry, sorted by name: ``- `<name>` — <description>``, where `<name>` is the entry's directory name and `<description>` is what the harness's own `Parse` returns for the entry's `description`, cut at 220 characters (runes) with no ellipsis. The Go test re-derives every line this way, so the script's own frontmatter reader (python3, required; the script exits 1 without it) is checked rather than trusted.
- **`catalog/MANIFEST.md`**: frontmatter `owner: main`, `date:`; one table row per source — repository URL, path, commit pin, licence, fetched date, entry count — then "Local changes: file modes only (no executable bit)", then `## Excluded` (upstream paths the refresh refused, with the reason) and `## Notes` (the security review's per-entry notes; never edits to vendored text). The script rewrites the table rows and the date only; `## Excluded` and `## Notes` are written by hand and kept across a refresh.
- **`catalog/CHECKSUMS`**: `sha256sum` format, one line per file under `catalog/` except `CHECKSUMS` itself, paths relative to `catalog/`, sorted with `LC_ALL=C`.
- **`scripts/refresh-catalog.sh`** (file mode 0644, run with `bash` from the harness checkout; never by a session in another project): `bash skills/google-catalog/scripts/refresh-catalog.sh <agents-cli pin> <google-skills pin>`. The four source sets are constants at the top of the script: google/agents-cli `skills/*` and `extensions/langchain/template/.agents/skills/*`; google/skills `skills/cloud/*` and `skills/developers/*`. It clones both repositories into `.agents/scratch/catalog-refresh/`, checks out the pins, and builds the new catalog in scratch first. It exits 1, naming the path and touching nothing under `skills/`, when: a pin does not resolve; an entry lacks `SKILL.md` frontmatter with `name` and `description`; two source sets hold an entry of the same directory name; or an upstream path is one the harness cannot carry byte-identical — a symlink, a name `plan.go`'s `secretShaped` list matches, a path `git check-ignore --no-index` reports ignored, or a `go.mod`/`go.sum` (the embed would drop the directory). The operator then decides per path (exclude the whole entry and record it under `## Excluded`, by an `--exclude <entry>` argument repeated as needed); a file is never altered. On success it replaces `catalog/<entries>` (removing entries upstream dropped), clears exec bits, copies the two LICENSE files, regenerates `INDEX.md` and `CHECKSUMS`, rewrites the manifest's table and date, stages nothing, and prints the entry count per source set, the names added and removed, and `git status --short skills/google-catalog | wc -l`. At import (2026-10-01, measured on the pins): 0 symlinks, 0 secret-shaped names, 0 ignored paths, 0 `go.mod`, 0 collisions; 141 entries.
- **Tests**: `TestCatalogMatchesChecksums` — every file under `catalog/` has a CHECKSUMS line with its sha256 and every line names an existing file (both directions); `TestCatalogIndexMatchesEntries` — every directory with a `SKILL.md` has exactly one index line, equal to the line re-derived through `Parse`, and every index line names such a directory; `TestCatalogHoldsNoExecutable` — no file under `skills/google-catalog/` has an executable bit. Each of the three fails on a catalog with zero entries ("the catalog is empty"), so none passes vacuously; none hard-codes 141. `TestRouterDescription` — the router's description is at most 300 characters and contains "Do NOT use". `TestSkillListingBudget` — the sum of `len(Name)+len(Description)` over the skills `LoadSkills` returns that are model-invocable (not `SlashOnly`), the description as `Parse` folds it, is at most 19,500 (Claude Code's measured listing budget is about 19,800 characters; research brief), and its failure message names the sum, the budget and the five longest descriptions.
- **`skills/VENDORED.md`**: a third section "Vendored catalogs" with one row whose first cell is `google-catalog/catalog` (plain, no backticks), naming both repositories and both pins, pointing at `catalog/MANIFEST.md`, with the refresh command as its "Update via" cell. `vendoredSkills` already returns that cell as a key (it stats `skills/<cell>`), so `TestVendoredRowsCarryAPin` checks the row; `isVendoredPath(rel)` — true when `rel` is a vendored key or lies under one — is what the two prose walkers use, so the router's own `SKILL.md` stays checked and the subtree is skipped. `restatement-grep.sh` line 45's row pattern becomes `^\| [a-z0-9/-]+ \|` so a path cell counts as vendored there too (its header comment and `skills/review/SKILL.md`'s sentence on vendored skills say "and vendored catalogs").

## Failure modes

- A CLI denies or prompts for the read of a catalog file (a headless run without a read grant; a restricted mode): the router says which file it could not read and continues without the catalog; Phase 0 measures the default behaviour on both CLIs before anything is vendored.
- No entry matches: the router says "no catalog entry for <words>" and the session continues with the harness's skills.
- An entry tells the agent to do what a harness rule forbids (an unpinned `curl | sh`, a commit without staging by name, a public service by default): the router's step 4 says the harness rule wins; entries the security review flags are named in `MANIFEST.md` § Notes.
- A script needs the executable bit: run through its interpreter (step 3).
- The tree drifts from the pin (a hand edit, a partial refresh): `TestCatalogMatchesChecksums` fails and names the file.
- A future CLI version starts discovering nested `SKILL.md` files, or shrinks its listing budget: the matrix rows `catalog-no-leak` and the budget test catch it at the next release gate; the fallback is moving the entries' `SKILL.md` out of discovery by the refresh script (a D-row then).
- Refresh with a bad pin or an entry without frontmatter: the script exits 1 before touching the tree.

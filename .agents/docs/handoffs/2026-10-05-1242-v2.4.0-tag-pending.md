## Release notes (v2.4.0)

A MINOR to v2.3.2: the first always-on rule, a new way of asking the operator, and the learning loop taught where rules now live. No Go code changed.

## New features
- Critical thinking rule (`rules/critical-thinking.md`, always on in both CLIs): stress-test plans, decisions, claims and corrections before agreeing; agreement shows its check ("Confirmed: X, because Y"); no flattery and no apologies; a position changes on evidence, never on insistence alone; a direct instruction is carried out first, its risks tabled after the work.
- Approval protocol in the global context: a reply that reports, proposes or asks opens with a one-line explanation and recommendation, then one numbered table, highest priority first; nothing proposed runs until the operator approves it by number ("go all approved", "go approved 1-3, skip 5"). A direct instruction is its own approval; unattended runs and subagents follow their dispatch (ADR-050).

## Improvements and optimisation
- The `dreamer` agent and the `dream` skill read the global rule files, so a memory whose rule lives there is left alone or marked graduated.
- `feedback-log` and `retro`: `rule:<name>` also names the harness's global `rules/<name>.md`, and a harness rule gap may target one.
- `go test -race -timeout 30m` in the setup commands, the testing guide and `harness-audit`: on a one-CPU box `cmd/sh-agent` takes 10-13 minutes under `-race`.

## Other updates
- `feature`, `dream` and `requirements` name the context's approval line; the testing guide's Antigravity store check expects one rule block per shipped rule file.

# Review — cb799ff-f1ca525-code   (2026-09-30)

Range reviewed: cb799ff..f1ca525 (source part: `git diff cb799ff..f1ca525 -- cmd internal skills agents context`; go.mod/go.sum unchanged)

## Status: COMPLETE

## Verdict: REQUEST CHANGES

The worst problem: with the Antigravity vendor on Linux, `sh-agent dream` passes the whole prompt (cap 256 KiB) to `agy` as one argv element. Linux refuses any single argument over 128 KiB (MAX_ARG_STRLEN = 32 pages), so every project whose prompt is over that size fails with E2BIG. Its watermark never advances, so the next night's window is larger and it fails again, permanently. Also: failures before the first project exit 1, not 2, and leave nothing in `status`. An unreadable state file silently resets every watermark. Both lock files have staleness races: the memory one can drop an index line, and the dream one can leave the job wedged. `go vet` and `go test ./internal/memory ./internal/dream ./internal/search` are green, but no test covers any of these paths.

## Findings

- **[high / confidence: high]** `internal/dream/run.go:137-142` (with `dream.go:23`, `dream.go:163`): for `agy`, the prompt replaces `<prompt>` in argv. `maxPrompt` is 256 KiB. Linux caps a single execve argument at 131072 bytes (checked on this host: `/bin/true "$(head -c 200000 …)"` → "Argument list too long", exit 126; PAGE_SIZE 4096). So `exec` fails for any agy prompt over 128 KiB and the project is logged `fail`. Its watermark stays (run.go:99-104), the next run collects a larger window, and that fails too. The project is never dreamt again on Linux + antigravity, which is a supported operator setup (macOS has no per-argument limit). A second effect: argv is world-readable through `/proc/<pid>/cmdline` for up to 10 minutes, so the redacted memory and transcripts are visible to other local users. `TestRunAgyGetsThePromptAsArgument` uses a small prompt and cannot catch this. Fix: use a per-vendor cap under 128 KiB for agy (or pass the prompt through stdin or a file if agy supports it), plus a test with a prompt over 128 KiB and a fake agy.
- **[medium / confidence: high]** `internal/dream/dream.go:63-66` and `cmd/sh-agent/main.go:212-219`: the plan (Interfaces, "Exit") says a pre-project failure exits 2 and writes the run log line and `last_run.error`. Errors from `targets()` are returned as plain errors instead: `ListProjects` failing on an unreadable or corrupt global index, a `--project` that is not a checkout, and `--all` together with `--project`. `main` exits 1 on these, and nothing reaches `dream.log` or `dream-state.json`. So when the nightly timer hits a broken index, it exits 1 and `sh-agent status` keeps showing the previous successful run. Fix: wrap `targets()` errors as `&ExitError{2,…}`. After the lock is taken, record them through `finish` (or record them before the lock for the usage cases), and add a test.
- **[medium / confidence: high]** `internal/dream/state.go:28-37` and `run.go:117-118, 329-333`: plan line 45 counts "state unreadable" as a pre-project failure (exit 2, `last_run.error`). `readState` instead treats a corrupt or unreadable `dream-state.json` as a first run. Every project's watermark silently drops to t0−14 days, which re-sends and re-proposes two weeks of input and duplicates proposals (`-2` files). The next `saveState` then overwrites the old watermarks for good. `TestReadStateFallback` (collect_test.go:337) pins this contradicting behaviour. Separately, `saveState` throws away its write error. If the state cannot be written, the run still exits 0 while the watermark is not persisted, breaking the "advance only after the write" rule. Fix: distinguish ENOENT (first run) from other errors (exit 2), return the `saveState` error and count it as a project failure, and change the test.
- **[medium / confidence: high]** `internal/memory/memory.go:246-283`: the comment at line 133 claims "two writers never lose a line", but the lock does not guarantee it. (a) A lock file exists but is still empty between `OpenFile(O_EXCL)` and `Fprint(pid)`. A concurrent `stale()` reads "", `Atoi` fails, so the lock counts as stale and gets removed while its owner proceeds. (b) Two waiters that both judge a dead lock stale: B removes it and creates its own, then C's `os.Remove` deletes B's fresh lock and C creates one too. (c) `unlock` removes the path unconditionally, so it can delete another holder's lock. In each case two `memory add` calls (for example two sessions, or `feedback-log` plus `project-memory`) read and modify MEMORY.md concurrently, and one index line is lost while its memory file stays on disk unindexed. No test runs concurrent adds. Fix: write the pid through a temp file plus `os.Link` (atomic create-with-content), or treat an unreadable pid as live until `lockAge`. Before removing a stale lock, re-read it and compare, and make unlock remove only a file that still holds our pid. Add a concurrent-add test that fails without the fix.
- **[medium / confidence: medium]** `internal/dream/run.go:337-356`: the dream lock has no age bound, and `harness.Alive` counts EPERM as alive. A `dream.lock` left by a crashed or killed run (OOM, reboot mid-run) can hold a pid that a later process reuses, which is likely after a reboot. From then on every nightly run prints "already running" and exits 0, so the job has stopped with no error in the log, `last_run` or `status`. The same empty-file window as the memory lock (an empty file reads as stale) lets a timer run and a manual run both proceed, racing `saveState` with whole-map writes. Fix: add an age bound as `memory.lock` has (the maximum run length follows from the 10-minute CLI timeout × projects, or record the start time in the lock), apply the same atomic pid write, and report a held lock older than the bound.
- **[medium / confidence: medium]** `internal/dream/collect.go:82-85` and `run.go:117`: an error from `AgyConversationText` (for example the copy of `conversation_summaries.db` plus `-wal` being inconsistent because Antigravity checkpointed between the two copies at search/dream.go:246-253, or one conversation db failing to open) only goes to `Dropped`. The project continues, and on success its watermark advances past every Antigravity conversation of that window, so they are lost for good after a transient error. Plan line 163 advances the watermark only after success. A transcript that could not be read is not the cap's deliberate drop. `sessionText` also ignores `sc.Err()` (collect.go:306-331), so a line over 16 MB silently truncates the session with the same effect. Fix: fail the project (watermark kept) on a collection error that is not a trust refusal, and check `sc.Err()`.
- **[low / confidence: high]** `cmd/sh-agent/main.go:199-208`: `sh-agent dream --install-timer --dry-run` installs and enables the timer, and `--remove-timer --dry-run` removes it. `--dry-run` is parsed for every command and its help says "change nothing". `uninstall --dry-run` respects it for the same timer, but these branches ignore it. This breaks the global rule that a new side effect goes below the read-only mode's early return. Fix: have both branches print what they would do under `*dryRun`, with a test that asserts no unit file is written.
- **[low / confidence: high]** `internal/memory/memory.go:148-155`: an index line is matched by the substring `(slug.md)`. If another entry's description contains `(slug.md)` (for example "supersedes (old-name.md)"), that line is overwritten too, so the other memory loses its index line and the index holds two copies of the new one. Fix: match the line prefix `- [slug](slug.md)`.

## Criteria

## Outcome
1. high, agy prompt on argv (128 KiB): fixed. agy gets the prompt on stdin as one stream-json message (`agy --input-format stream-json --output-format stream-json --mode plan -p ""`), and the answer is read from the `result` event. Probed on this box; `TestRunAgyPrivateHomeAndStdin` asserts the argv carries no prompt.
2. medium, pre-project errors exit 1 with no record: fixed. Usage errors are refused in `Run` before anything is written. Every other pre-project failure (index, no CLI, no login) is exit 2, with a run log line and `last_run.error`: `TestRunPreProjectFailureIsExit2AndRecorded`, `TestDreamVerb`.
3. medium, a corrupt state silently reset: fixed. `readState` returns an error; the run exits 2 and leaves the file untouched (`TestReadState`, `TestRunCorruptStateIsExit2AndKept`). `saveState` errors are exit 2 at the end of the run.
4. medium, memory lock races: fixed. `flock` on `.agents/memory/.lock`: the kernel drops it on exit, and two waiters cannot both hold it (`TestLeftoverLockFileIsNoLock`, `TestHeldLockRefusesAfterRetry`).
5. medium, dream lock with no age bound and a reused pid: fixed. `flock` on `dream.lock`: a dead run's lock is released by the kernel (`TestRunLock` holds a real flock, then releases it).
6. medium, an Antigravity read error advanced the watermark: fixed. It fails the project, so the watermark stays. A Claude Code transcript read error is named as left out.
7. low, `--dry-run` ignored with the timer flags: fixed (`TestDreamTimerDryRun`).
8. low, the index matched a description's `(slug.md)`: fixed. The match is the line's link target (`TestIndexMatchIsTheLinkTarget`). A full index is now refused before the lock file is created, so the refusal still writes nothing.

## Findings

- **[medium / confidence: high]** `internal/harness/catalog_test.go:357` (`earlyExitConsumer`, the `sed` branch `sed\b.*[0-9;{\s/$'"]q([}'";\s)]|$)`): the character before `q` must be in `[0-9;{\s/$'"]`, so `!`, `I`, `M` and a custom address delimiter are not in it. These four inputs were refused by the 4487a7a pattern and pass at 5bbd789 (probed on the copy, old and new regexp side by side): `producer | sed '/^#/!q'`, `sed '/x/Iq'`, `sed -n '/x/Mq'`, `sed '\%x%q'` (also `sed '/a/,/b/!q'`). All four quit early, and under pipefail they give exactly the 141 that BUG-155/157 recorded. If this ships, a script line that prints a file's leading comment block (`sed '/^#/!q'`) passes the guard that exists to refuse it. Fix: make the character before `q` "not a lowercase letter or underscore" (for example `[^a-z_]q([}'";\s)]|$)`). That still passes the two new must-pass cases (`faq` has `a` before the `q`; `s/x/q/` has `/` after it). Add each of the four as a must-refuse case. Not caught by either version, so not a regression: GNU `Q` (`sed 1Q`) and `q` with an exit code (`sed '/x/q5'`).
- **[medium / confidence: medium]** `skills/preflight/SKILL.md:61`: "list the verification commands the range added or edited (`git diff <base>..HEAD -- AGENTS.md <docs-root>/testing/guide.md`)". `agents/verifier.md:14` counts "a step the change added to or edited inside a tier" as a changed command, but tier steps also live outside those two files: the kit preamble every § 4 run kit sources, the `testing/sh-agent-matrix.md` rows, a skill's script. When `~/.config/sh-agent` is a symlink to a directory (dotfile setups), the fingerprint is one constant line. Probed: a file added through the link left the fingerprint at the same value before and after, so a run that writes the real config passes the kit silently. - **[low / confidence: low]** `agents/verifier.md:14` and `skills/preflight/SKILL.md:88`: the verifier now keeps a log that is "IN PROGRESS with a failing command in it" forever (never updated or overwritten; the next run writes `-r<n>`).

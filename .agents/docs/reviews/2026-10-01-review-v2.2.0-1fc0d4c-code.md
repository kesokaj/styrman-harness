## Findings

- **[low / confidence: high]** `cmd/sh-agent/main.go:377-385` (the `(installTimer||removeTimer) && dryRun` case) and `main.go:295-297` (uninstall's dry-run line): both dry runs decide "would remove" from `dream.TimerInstalled`. The `--remove-timer --dry-run` branch also never calls `otherSystemTimerNote`. So a dry run promises a removal that the real run does not do, which breaks `review-standards` § 8: a read-only mode must resolve every path the real run resolves. The test `TestTimerOfAnotherSystemIsNamed` does not cover `dream --remove-timer --dry-run`. The uninstall dry run prints both "[dry-run] would remove the dream timer" and "... stays: <file>", and the test's negative check (`"removed the dream timer"`) does not catch the "would remove" wording. Fix: base the dry-run claim on the files `RemoveTimer` would see for `runtime.GOOS` (for example a `ThisSystemTimerFiles` helper). Also call `otherSystemTimerNote` in the remove-timer dry run, and add that argument set to the test. **If it ships as is:** on a home copied between a Mac and a Linux box, the operator's dry run says a timer will be removed when it will not, and does not name the file that stays.
- **[low / confidence: medium]** `internal/search/search.go:617-631` (`printable`): BUG-152 says characters "nobody sees" are filtered. The new code filters by general category (Cf, Zl, Zp), but other invisible characters fall in other categories and still pass. Probe on the archive copy: variation selectors U+FE0F and U+E0101 (Mn, the "emoji smuggling" carrier that can encode a byte per code point), U+3164 and U+115F Hangul fillers (Lo), and U+034F combining grapheme joiner (Mn) all came back unchanged. Fix, if wanted: also replace U+FE00–FE0F, U+E0100–E01EF and the Hangul fillers. Do not add all of Mn, because that would mangle legitimate combining marks. **If it ships as is:** a payload hidden in variation selectors in an indexed file still reaches the terminal and a model through search output, unseen.
- **[low / confidence: high]** `internal/harness/frontmatter.go:96-104` (`unreadLine`, reached through `ParseStrict`): after the fix, a `---\r\r` line stays inside the block and is refused, which is correct. But `unreadLine` trims every `\r` before quoting the line, so the error reads `frontmatter line "---" is not a plain key: value line: a quoted or spaced key ...` (probe output). The refused line looks like a valid fence, and the reason given (a quoted or spaced key) is wrong. Fix: quote the untrimmed line, or report a fence with extra carriage returns by name. **If it ships as is:** an author of such a file gets a diagnostic that points at the wrong problem.

## Answers to the dispatch's questions

- **Split.** Files with CR-only line endings (old Mac) were refused before and still are, because `Cut` on `\n` fails ("no YAML frontmatter block"). A closing `---` or `---\r` at end of file with no newline still closes the block (probe). CRLF files still load. The only files that newly fail are those with `---\r\r` (for example a CRLF file converted to CRLF a second time). An opening `---\r\r` now reports "no YAML frontmatter block", and a middle one leaves the block open: `ParseStrict` refuses it through `unreadLine` (finding 3), or the block is "unterminated". The other splitters agree with the stricter rule. `opensFrontmatter` (`inventory.go:417`) trims `\r` through `unicode.IsSpace` and still refuses a command or rule whose first line is `---\r\r`. The catalog tests and index writer call `Split` itself. `DeriveAgy` writes `\n` fences. `internal/search/parse.go:103` uses a looser `TrimSpace` rule, but only for indexing, not the installer's lint, and it is outside the range.
- **printable.** Legitimate text changes in output only. A ZWJ inside an emoji sequence becomes `👨?👩?👧`, a ZWNJ in Persian becomes `می?خواهم`, a soft hyphen and a leading BOM each become `?` (all probed or pinned by the test). The index stores the raw text, because `printable` is called only at print sites. Snippets go through it (`cleanSnippet`), labels and paths through `label`, and the header's left-out names through `status()`. The header's phrase is `%q`-quoted, so Cf characters are escaped there. The `--refs` lines (`markTarget`) and the `--open` lines all pass through it. The unwrapped prints (`x` at 755/758/765) are the operator's own argument. The doc comment at line 613 still says only "C0, DEL, C1", but the inline comment covers the rest. That is not a finding.
- **Timer.** `OtherSystemTimerFiles` returns the plist on linux, the `.service` and `.timer` files on darwin, and nil for an unknown goos, so no note is printed there. On a home with both systems' files, linux removes its own two files and the note names the plist. The two path sets are disjoint, so uninstall cannot name a file it just removed. Legacy bare-named files of the other system are not named, but they get their own `LegacyTimerNotice`. The note prints on uninstall, on uninstall `--dry-run`, and on `--remove-timer`, but not on `--remove-timer --dry-run`: that gap is finding 1.
- **Script.** On a successful clone or fetch, `-q` plus a discarded stdout loses nothing but git's warnings. After a failure the operator is told the role, and for a fetch the exact directory to run `git fetch` in. For a clone the message only says "run the git clone yourself", which is enough because the URL is either the default or their own override. The `via` paragraph appears whenever either URL differs from upstream, and it is recomputed on every run, so a default-source refresh after an override refresh removes it. With `via` empty, the text between the table and "Local changes" is byte-identical to v2.2.0 (`$table\n\nLocal changes`). Rows now always write `upstream_a`/`upstream_g`, which match the checked-in `MANIFEST.md` rows exactly. `fetched()` keys on path and pin, so the rows' dates are kept, and `old_table == table` keeps the manifest date. The manifest date is not bumped when only the `via` line changes, which I judged no finding. The new fetch-failure test requires "cannot fetch the agents-cli source" and forbids `fatal:` and the value, so it fails on v2.2.0's code. It reuses the existing work clones, then proves a later refresh still succeeds.
- **TestMain (6 packages).** Each is `os.Exit(m.Run())` with no defers. Only `dream` had a `TestMain` before, and it was extended, not duplicated. No test reads a `GIT_*` value from the environment. Every test that needs one sets it on `cmd.Env` or through `t.Setenv` (`harness_test.go:779`, `report_test.go:407`, `collect_test.go:479`, `main_test.go:745`). I grepped test sources for `https://github`/`gitlab` URLs used as fixtures and found none. The fixtures are local paths, so `GIT_SSH_COMMAND` and `GIT_TERMINAL_PROMPT` are not needed. The one dependency left is environmental: a developer whose git identity lives only in `GIT_AUTHOR_*` variables, with no gitconfig, would now see the fixture commits that do not set an author fail. That is deterministic and arguably intended. Not a finding.
- **Agents.** The new paragraph does not contradict any duty. The verifier's version explicitly keeps running the project's own verification commands from `AGENTS.md` and the testing guide. `DeriveAgy` copies the whole body (`derive.go:61`), so the Antigravity definitions carry the paragraph.
- **Tests' reach.** `TestTimerOfAnotherSystemIsNamed` writes only under `t.TempDir()`. In it `RemoveTimer` finds no file for this system, so `systemctl`/`launchctl` are never called. The refresh fetch test runs without `HOME=fakeHome` but fails before `go test`, and it writes only to `dest` and `work` under the test's own temp directory. `TestSplitFenceIsOneLine` and the new `printable` cases fail when reverted. Note that the third `TestSplitFenceIsOneLine` assertion passes because `unreadLine` refuses the stray `---` line, not because of the permission-key lint. Either way the case loaded on v2.2.0, so the test still fails when reverted.

## Findings

- **[low / confidence: medium]** `.agents/docs/testing/kit-preamble.sh:24,47,49,72`. The real-home guard is weaker than guide.md:168 describes, in four ways:
  - **Line 24 compares strings.** `case "$KIT_HOME" in "$HOME"|"$HOME/")` lets through `$HOME/.`, a symlink to the home, `//home/<user>` and a relative path.
  - **Line 47 trusts `$HOME`.** It reads the "real home" from `$HOME` when the file is sourced. A kit that exports `HOME=<sandbox>` first points both the guard and the exit fingerprint at the sandbox, and the check passes without having checked anything.
  - **Line 49 watches one directory.** The fingerprint covers only `~/.config/sh-agent`. A write to `~/.claude`, `~/.gemini`, `~/.ssh` or a real checkout goes unseen.
  - **Line 72 can be overridden.** The wrapper inserts `--home "$KIT_HOME"` after the first argument. The binary accepts a repeated `--home` with exit 0 (checked: `sh-agent status --home h1 --home h2`). Go's `flag` keeps the last value (not checked against this binary's output), so an agent's own `--home <path>` after the verb overrides the pin. An absolute path to the real binary bypasses PATH altogether.
  - **Why it matters:** BUG-107 and BUG-123 were exactly writes into the real `~/.config/sh-agent`, and guide.md:167 states "The real home is never touched" on the strength of this file.
  - **Fix:**
    - Canonicalise both paths (`cd -P -- "$KIT_HOME" && pwd -P`).
    - Take the real home from the passwd entry (`getent passwd "$(id -u)" | cut -d: -f6` on Linux, `dscl . -read /Users/"$(id -un)" NFSHomeDirectory` on macOS) rather than from `$HOME`.
    - Refuse a KIT_HOME that equals, contains or sits inside the real home.
    - Have the wrapper refuse any argument list that already carries `--home`.
    - Add `~/.claude`, `~/.gemini` and the harness checkout's `git status --porcelain` to the fingerprint.
  - **Not an issue if** the guide instead calls the preamble a tripwire for accidents rather than a boundary, and stops claiming the real home is never touched.

- **[low / confidence: medium]** Broad grants in a HOME-only sandbox. The locations are `.agents/docs/testing/skill-matrix.md:14`, `guide.md:167,169`, `bugs/BUG-141-antigravity-grant-name-write-to-file.md` (Fix and Prevention), `handoffs/2026-10-01-1130-audit-fix-closed.md:32`, `handoffs/2026-09-30-1826-v1.16.2-released.md:31` and `testing/2026-09-30-verify-real-home-v1.17.0.md:23`.
  - **What the docs instruct:** six headless Antigravity rows (`node`/mmdc, `docker`, `gcloud`, the init-project `for` loop, a heredoc) run with `command(*)`, and agy-only sandbox runs have used `--dangerously-skip-permissions`.
  - **What the sandbox actually is:** a HOME override plus `trustedWorkspaces`. The agent still runs as the operator's uid, inherits the operator's environment apart from HOME, and can reach the docker socket (root-equivalent for a docker-group user on Linux), the real checkouts and the real dot-directories by absolute path. Finding 1's exit check would not see any of that.
  - **Why it is low:** the inputs are fixture repositories and harness-written skills, so the realistic trigger is a model mistake rather than an attacker. The skip-permissions use was approved by the operator for named gates (BUG-115, handoff 1826:31).
  - **Fix:** run the `command(*)` and skip-permissions rows in a container or VM, or under a throwaway OS user, with `env -i` and an explicit variable allowlist. Or record the remaining risk as accepted in the guide (one sentence) or an ADR, and soften guide.md:167 accordingly.
  - **Not an issue if** that acceptance is written down, or the rows move into real isolation.

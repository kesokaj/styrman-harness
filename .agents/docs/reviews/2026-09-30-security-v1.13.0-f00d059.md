# Security review — v1.13.0-f00d059   (2026-09-30)

Range reviewed: v1.13.0..f00d059

## Status: COMPLETE

## Verdict: FINDINGS

Two findings, both low. Nothing high or medium, and nothing blocks the v1.13.1 gate on security grounds.

- **Worst: the redaction deny-list still misses shapes inside vendor families the operator's guide lists as covered.** A probe of f00d059's own `redactLines`, in text and JSONL mode, let these through unredacted: a GitHub `ghr_` token (the list carries the other four `gh?_` prefixes), GitLab tokens other than `glpat-`, and a Google OAuth refresh token. It also let through a set of shapes from families the guide never names.
  - The residue is recorded as a class: "a safety net, never a guarantee" and "Anything that matches no shape IS sent".
  - It is not recorded by name. `deploy/local.md:66` still reads as full coverage of GitHub, GitLab and Google.
- **Second: ADR-046 gets its reasoning wrong.** It accepts the unsigned checkout-place pull on a stated reason that is false: that a signature check would add no independent trust root. It also names a command that does not exist.

The code changes hold up:
- `SweepStaleDirs` stays inside its parent.
- `WriteAtomic` closes the temp file before renaming it, and every failure path leaves `dest` unchanged.
- `pushError` scrubs both of its branches.
- The `VENDORED.md` provenance rows match upstream: I re-diffed both against the local upstream clones.

The 27 trail files contain no real secret and no new private data. Nothing in them is instruction-shaped text an agent would act on.

## Findings

- **[low / confidence: high]** `internal/harness/report.go:39-88` (`prefixNeedles`, `keywordNeedles`) and `.agents/docs/deploy/local.md:66`: deny-list residue inside families the guide claims, plus families it does not name.
  - **Probe.** A `git archive f00d059` copy in `.agents/scratch/security-v1.13.0-f00d059-probe/` got one test file, `zz_probe_test.go`, which calls `redactLines` in both modes. Log: `.agents/scratch/security-v1.13.0-f00d059-probe.log`.
    - Controls: `ghp_…` and `hooks.slack.com/…` were redacted; `the task-list grew` was not.
  - **Unredacted in BOTH modes:**
    - **Families the guide names as covered:**
      - GitHub `ghr_` + 36 characters.
      - GitLab `gldt-`, `glrt-` and `glptt-` tokens.
      - A Google OAuth refresh token, `1//0…`.
    - **Families the guide does not name:**
      - Discord and Microsoft Teams webhook URLs.
      - SendGrid `SG.….…`.
      - An Azure storage connection string's `AccountKey=`.
      - A `Cookie: session=…` header.
      - HashiCorp Vault `hvs.…`.
      - `AGE-SECRET-KEY-1…`.
      - DigitalOcean `dop_v1_…`.
      - A JWT whose payload segment is shorter than 8 characters (`eyJ….e30.…`, an empty claims object). The `jwt` rule requires `{8,}` in the second segment.
  - **Any of these reaches `styrman-harness-feedback` verbatim.** `redactDocument` (`state.json`) uses the same `needleIn`, so it has the same residue.
  - **Why it stays low:**
    - The destination is the operator's private repository.
    - `delivery.md` makes the operator's read of `~/.config/sh-agent/` before each report the guarantee.
    - `local.md:67` says what is not matched is sent.
  - **What is wrong is the description.** `local.md:66` lists the prefix kinds as "AWS, Google, GitHub, GitLab, …". That reads as whole-vendor coverage, which the code does not have. That is the unsafe direction for a document the operator relies on when deciding what to read.
  - **Remediation: put it to the operator as one choice.** This is the sixth pass over this mechanism, and the operator has already chosen one rule per kind.
    - **(a) Recommended.**
      - Complete the families the guide already names: add `ghr_`, and GitLab's other token prefixes (for example `gldt-`, `glrt-`, `glptt-`; medium confidence in GitLab's full prefix set) to `prefixNeedles`, each with one `TestReportRedactShapes` row.
      - Record the unnamed families above by name as `left: operator — deny-list residue accepted`.
    - **(b) Add nothing.** Narrow the wording in `local.md:66` to the prefixes actually matched (for example "GitLab personal access tokens"; "Google API keys, OAuth access tokens and client secrets"), and record all of the above as accepted residue.
    - Either way this needs only stdlib `strings`/`regexp`, no dependency.

- **[low / confidence: medium]** `.agents/docs/architecture/DECISIONS.md`, ADR-046: the accepted-risk record rests on a false premise and names a command that does not exist.
  - **The false premise.** The Reasons bullet says "no commit signature check adds a new trust root without them also being compromised".
    - A check against the operator's ed25519 signing key would be an independent root. That key is already the allowed-signers line in `deploy/remote.md` and compiled into release binaries.
    - It would defend against the very compromises the ADR's Consequences name: a GitHub account takeover by session or PAT, or a transport compromise.
    - The only exception is a signing key that doubles as the GitHub SSH key and is itself stolen.
    - The decision may well stand, since R9 and the cost of signing every commit on `main` are real reasons. But the Revisit clause is judged against this reasoning, so the reasoning should be true.
  - **The command.** Consequences says "`sh-agent install --from-zip`". `--from-zip` belongs to `update` and is refused on any other verb (project `AGENTS.md` rule 1; `review-project-code`). Zip places are also a separate kind of place, not release-binary places.
  - **The acceptance.** The ADR says the risk is "understood and accepted by the operator". The evidence in the trail is the blanket instruction "fix all issues in your recommended way" (handoff `2026-09-30-0802`). The recommended option was the ADR, so the instruction does cover it. A one-line confirmation in the operator's own words would still make it unambiguous.
  - **Remediation:** append a correction. `DECISIONS.md` is append-only, so this means an amendment line or ADR-046a, not an in-place edit. The correction should:
    - say the check would add an independent root and is declined anyway, for the R9 reasons;
    - replace the command with `sh-agent update --from-zip`;
    - list zip places as their own kind of place.

  This is a records change only; no code changes.

- **Injection:**
  - No new `exec`, SQL or template.
  - The new regexes are RE2, which runs in linear time.
  - `needleIn` still records the rule name, never the matched text (BUG-054).
  - `pushError`: `gitRun` puts the argv, including the URL, into the error. The URL is the constant `FeedbackURL = "git@github.com:…"` (`report.go:27`), an scp-like URL with no userinfo, so it carries no credentials.
    - The scrub covers a `url.insteadOf` rewrite that git might print. Git anonymises rewritten URLs today, so the comment's "guards against a git that does not" is accurate.
    - Known limit, not a finding: `credentialInURL` (`[^/@\s]*@`) stops at the first `@`. A raw `@` or `/` inside a password (an invalid URL) would leave part of it in the message.
- **Sweep confinement (`sweep.go`):**
  - **Names:** they come from `os.ReadDir` (never containing a separator, `.` or `..`) and match by prefix. A symlink is skipped by its `DirEntry` type, a non-directory by `IsDir`, and the age is taken from `Lstat`.
  - **Errors keep data:** a `ReadDir` or `Lstat` error removes nothing, and a future mtime is never swept.
  - **Symlink swap:** `RemoveAll` on an entry swapped to a symlink after the `Lstat` unlinks only the link. Go's Unix `RemoveAll` walks descendants with `openat`/`unlinkat` and does not follow links.
  - **Parents:** `~/.config/sh-agent` for both callers, owned by the user.
  - **Behaviour change:** the release sweep now waits an hour, as the zip sweep does. A younger `release-*` directory, random-named with mode 0700, survives until the next update, which is harmless.
  - **Third sweep:** `sweepInterruptedClones` (`report.go:449-455`) has the same shape.
  - **Remaining globs:** two read-only globs built from the home path remain (`state.go` `LastRetro`, `internal/search/reconcile.go` `configView`), recorded `left: operator`.
- **`WriteAtomic` (`apply.go:309-356`):**
  - **Order:** the temp file is created in the destination's own directory (`CreateTemp(filepath.Dir(dest), ".sh-agent-*")`, `O_EXCL`, 0600). It is chmodded before the rename, so there is no window of wider mode. Then sync, close, rename, in that order.
  - **Failure paths:** all five go through `abandon`. Its second `Close` returns `ErrClosed`, which is discarded, and the removal failure is named.
  - **Pin:** `TestWriteAtomicClosesBeforeRename` pins the order. The settings writer's `Lstat` symlink refusal still runs first.
  - **Exported surface:** `WriteAtomic` and `SweepStaleDirs` are exported from `internal/`, so only this module can import them.

- **`skills/retro/SKILL.md` Step 2 is left untouched but is incompatible with D6.** The plan's "Retro skill structure" section says "Steps 4 and 5 replaced wholesale; Steps 1–3 kept," and Phase 3's task list only names "Steps 4–7" for rewrite. But the current Step 2 ("Classify Findings", `skills/retro/SKILL.md` lines ~35-46) opens with "Target files live in the harness repo" and its category table lists only harness paths (`context/AGENTS.md`, `context/dev-setup.md`, `skills/<skill>/SKILL.md`, `agents/<agent>.md`) — there is no row for a project target (`AGENTS.md`, `.agents/rules/<name>.md`, `.agents/skills/<name>/`). Keeping old Step 2's "lives in the harness repo" framing verbatim means the skill tells the model, twice, to pick a target, with the first pass hardcoded to harness-only paths. Two implementers diverge here: one leaves Step 2 as dead/misleading prose that a careful model reader ignores in favor of Step 4; another treats Step 2 as still-authoritative and never proposes a project-scope target at all, silently defeating the operator's stated want ("if I run /retro in my project ... I want that saved on a project level"). The plan needs to say explicitly whether Step 2 is deleted, folded into new Step 4, or rewritten to add project-scope rows — "kept" as currently written cannot both be true and be consistent with D6.

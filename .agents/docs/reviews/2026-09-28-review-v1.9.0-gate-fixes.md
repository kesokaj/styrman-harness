## Findings

- **[low / confidence: high]** `cmd/sh-agent/zip_test.go`, `internal/harness/zip_test.go` — no test writes an old-format manifest (`zip:sha256:<hex>` with no `;verified`/`;unverified` suffix) and asserts that `status` and `knownCheckout` still parse it. The changelog (`.agents/docs/changes/2026-09-28-1940-v1.9.0-gate-fixes.md:12`) and the doc-comment (`internal/harness/zip.go:20`, "A manifest written before the verdict was recorded carries the bare `zip:sha256:<hex>`") both assert this backward-compat behaviour explicitly. I verified by reading `strings.Cut(zipSum, ";")` (`cmd/sh-agent/main.go:446`) and `strings.Cut(sum, ";")` (`cmd/sh-agent/main.go:661`) that it does in fact work — `Cut` returns the full string unchanged with an empty second part when the separator is absent — but that is inference, not a covering test, and the claim is exactly the kind AGENTS.md's Definition of Done requires backed by a failing-without-the-fix test. Add a subtest that seeds `state.json` with the pre-change `Repo` value and checks `status`/`knownCheckout` output.

Everything else checked out:
- **Manifest origin format** — `internal/harness/zip.go:17-22` documents `zip:sha256:<hex>;verified vX.Y.Z` / `;unverified`; the only writer is `cmd/sh-agent/main.go:1119-1123` (`updateFromZip`), which sets it from `verifiedTag`.
- **Readers traced:**
  - `cmd/sh-agent/main.go:405,446-449` (`status`) — cuts on `;`, appends `(trust)` only when present. Correct for both old and new manifests.
  - `cmd/sh-agent/main.go:660-662` (`knownCheckout`) — cuts on `;` before the `short()` truncation. Correct.
  - `internal/harness/repo.go:81-86` — truncates to 12 chars *without* cutting on `;` first, but this is safe rather than a latent bug: a sha256 hex digest is always 64 characters, so `sum[:12]` never reaches the appended `;verified …`/`;unverified` suffix regardless. Confirmed no other reader needed a fix (`main.go:667` prints the raw `st.Repo` including the suffix in an error message, which is informative, not wrong).
- **Refusal messages** (`internal/harness/release.go`) — `zipNamesIn` correctly lists the release's own `.zip` name(s) from the signed `SHA256SUMS` (trimming the `*` binary-mode marker); both the "sums don't list this file" and "checksum mismatch" refusals now name it and point at the release's assets instead of GitHub's source archive. Verified against `TestVerifyZipSums/github_source_archive` (`internal/harness/zip_test.go`), which covers both refusal paths and asserts the wording never suggests installing unverified as a bypass.
- **Would the tests fail without each fix?** Yes for all of them, by inspection: dropping the `;verified`/`;unverified` suffix removes the substrings `TestStatusAfterZip` and `TestUpdateFromZipVerifiedAndTampered` assert on; `zipNamesIn` returning a constant would not produce the exact zip name `TestVerifyZipSums/github_source_archive` checks for; `report-999999` (the pre-fix pid) is a real flake source, not a certain failure, but `alive(0)` being false by construction (`internal/harness/report.go:444-446`, `pid <= 0` short-circuit) makes `report-0` deterministic where the old value wasn't.
- **`npx skills add … -y`** (`context/AGENTS.md:37`) now matches `skills/VENDORED.md:39` and the earlier v1.8.0 gate review's low finding; no other restatement of the skills-add command in a living file was left with the old flag (checked via a full-repo grep for `npx skills add`).
- Docs (`README.md`, `.agents/docs/specs/sh-agent/delivery.md`) describe the new status wording and manifest suffix accurately and match the code's exact format strings.

# v1.7.0 gate fixes, round 2: sandbox rule states the principle, not a tool list     (date: 2026-09-28)

## Summary
Round 2 of the v1.7.0 gate (`a9717cc..f916e35`) found the round-1 fix's example tool list wrong twice:
- agy 1.2.8 rejects `list_dir(*)` as an invalid allow entry, logged to `cli.log`, not stderr;
- the "read-only" commands `find`, `git` and `sed` can execute, write or push.

Reviewing the same mechanism a second time is the point to simplify rather than defend it (operator: "go with your recommendation and ship v1.7.0"). The `AGENTS.md` § Testing bullet now states only the principle:
- the per-run `settings.json` has the fewest grants the run needs;
- a `command(<name>)` grant allows every argument;
- the scratch clone is the only trusted workspace;
- the file is deleted by name with the token, and is never the real home's file;
- a run counts only when stderr has no "auto-denied" line and `cli.log` has no "invalid allow entry" line.

Preflight's fallback secret scan also gains `refresh_token`.

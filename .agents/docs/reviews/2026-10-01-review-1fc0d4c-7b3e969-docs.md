## Verdict: REQUEST CHANGES

The worst problem is in `agents/verifier.md`, the agent the release gate depends on. Its rewritten second paragraph contradicts itself and Step 2 about who decides that a tier runs. Sentence 3 runs "the tiers the dispatch or the plan names". Sentence 5 and Step 2 say an install, a sandbox run or a run against a real home or a service runs only "unless the dispatch names it". A plan is a file, so a plan-named install, sandbox or smoke tier is covered by both rules, and they give opposite answers. Three other docs restate the old claim that the verifier runs every tier the plan names. Everything else is low: stale test headers and code comments, a slightly overstated claim about the refresh script's override note, a stale reason given for the listing-budget figure, and status-line wording in the verifier that does not match its own template. The code changes in the range (the timer check that counts only this system's unit, the three frontmatter refusals, the wider search filter, the override note) are described correctly in README, AGENTS.md, the specs and deploy/local.md. The README map needs no change: README's hunks are only rows 183-186 of the command table and the customization paragraph at 230-233, and no install, update, report or release path moved.

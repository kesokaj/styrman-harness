## Status: COMPLETE

## Verdict: REQUEST CHANGES

Two mediums. The worst: the new search header prints the marked directory names raw. Every other path that search prints goes through `printable()`, but this one does not, so a checkout whose marked directory name holds an ESC byte or a newline sends terminal escapes and forged result lines into the output. I reproduced this. Second: the new `status` line tells the operator to run `sh-agent dream --remove-timer` "for the cleanup steps". That command removes a timer, and the advice has no `--home`. Both fixes are one line. The timer result plumbing, the LoadDocs refusal, the `phys` slash collapse, the `--work` guard and the override check hold on every path I traced.

## Answers to the dispatch's questions

- **RemoveTimer's result on every path.** The OS is not linux or darwin: false. No file of this home for this OS: false. Only the other OS's file: false, so `--remove-timer` says "no dream timer found … on this system" and uninstall is silent (low above). A failed `os.Remove`: false plus an ExitError, and both callers return the error before printing. Files present: true even when the best-effort stop failed, since "removed" means the files. All five test callers and both `main.go` callers are updated; no other caller exists.
- **LegacyTimerFiles.** For the real home (lookup succeeds, including a symlinked spelling through `SameFile` in `UnitFor`) it returns nil. When the lookup fails, every home is suffixed, so the real home's bare unit is called legacy. Its "v2.0.0 or earlier" claim still holds, because v2.1.0 never writes bare names when the lookup fails, and the doc comment names the case. The step gap is the low above. The commands are right for each OS: Linux `show -p FragmentPath`, `disable --now`, `daemon-reload`; darwin `print gui/<uid>/<label>` and `bootout gui/<uid> <plist>`. `StatusLine` appends the note before every branch, so all four returns carry it.
- **LoadDocs.** `Split` already strips `\r`, so a CRLF file with a readable block is accepted, as before. A file that opens with `---` and is readable goes through `Split`'s branch, and `opensFrontmatter` is never consulted. A BOM followed by a readable block is refused, and the message names the byte-order mark. A file that is only `---` with no newline is refused as unterminated. Skills (`inventory.go:185`) and agents (`:236`) refuse any `Split` error by their own path, unchanged.
- **Search.** Both `gitView` callers are updated. Global scope drops the list. `--refs` and `index` print no header (as the plan says, D1). The two existing tests now look for `"\nvendor/data/"`. Hit lines start at the beginning of a line, so the absence assertion can still fail.
- **Script.** `phys` collapse: `/`, `//` and `///x` give `/`, `/` and `/x` (run on bash 5.2). `pwd -P` is always absolute, so a relative path never reaches the collapse. `--work /` gets "must not be /, the home directory or the checkout itself", because the `.`/`..` case cannot match `//`. `--work` equal to `--dest` is refused as nesting. The default `--work` and `--dest` are not nested. The marker is written before the first clone, after every check and after the override check, so a refused override creates nothing. `${!v:-}` under `set -u` works on bash 5.2. A leading space and an uppercase `HTTPS://` are both refused, which is the safe direction.
- **Tests.** No new test writes outside `t.TempDir()`. With the guard missing, the `--work` cases run a copy of the script inside a stand-in checkout, with sources that cannot be cloned, so a regression writes into tmp only. `/` is skipped as root. The dream tests reach only fake managers: `fakeManager` sets PATH to the fake dir plus `/usr/bin:/bin`. `memory_test.go` prepends its fakes but ignores the `os.WriteFile` errors. That is harmless unless TempDir writes fail, since a correct build never calls a manager there. `fixtureEnv` drops every `GIT_*`. None of the dropped variables is needed by the local-path fixtures or the nested `go test`. It also drops `GIT_CONFIG_GLOBAL`/`GIT_CONFIG_NOSYSTEM`, so a fixture commit then reads the operator's real `~/.gitconfig` (for example `commit.gpgsign`). The failure mode is a red test, not a write.

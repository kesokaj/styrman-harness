## Findings

- **[low / confidence: high]** `skills/dream/SKILL.md:74`: the Failure modes row "`~/.config/sh-agent/` denied | the record stands; the exact `cat >>` command is printed" belonged to the Step 6 retros.jsonl append this round removed. Dream no longer writes under `~/.config/sh-agent/`, so no `cat >>` command exists to print. A run that hits a denial, for example while reading `feedback.jsonl` for the promote test at :46, follows this row and prints an append. The only append the skill ever described is the retros.jsonl line, so an operator who runs the printed command resets the 14-day `/retro` reminder, which is the round-1 medium this fix closed. Fix: delete the row. If the `feedback.jsonl` read at :46 needs a denial case, write it as "`feedback.jsonl` unreadable → promote judged from session ids only, said in the record".

- **[low / confidence: high]** `skills/feedback-log/SKILL.md:92`: "every run leaves a record in the project's `<docs-root>/retros/` plus one line in `~/.config/sh-agent/retros.jsonl`, the cross-project index. Distill and dream records go there too". "There" covers both places named just before it, so the sentence still says a dream writes an index line. This contradicts `context/AGENTS.md:41`, `skills/dream/SKILL.md:62`, README:210 and ADR-044. ADR-044 § Consequences lists the files that "say so", and this one is not among them. The round-1 grep for `retros.jsonl` would have found it. Fix: "…the cross-project index. Distill records go to both; a dream record goes only to `retros/`; and the `dreamer` agent…".

- **[low / confidence: medium]** `agents/dreamer.md:32` vs `skills/dream/SKILL.md:24`: round-1 finding 4 is only partly fixed. The dreamer now drops a trailing `/`, but it still compares "as an exact string" against `~/.claude/projects/<slug>/memory` (tilde form) and `<root>/.agents/memory` (absolute). Dream Step 1.1 accepts a setting "after `~/` expansion", so a setting holding `/home/<u>/.claude/projects/<slug>/memory`, or `~/<path-to-root>/.agents/memory`, gives a `<store>` string that dream accepts. Retro source 8 and distill Step 1 pass that string on, and the dreamer refuses it. The effect is benign: the refusal is stated in the first line of the artifact, and candidates come from the trail only. Both settings shapes are uncommon, because init-project writes the absolute root. Fix: the dreamer's sentence says "as an exact string after `~/` expansion, with any trailing `/` dropped", which is dream's own wording.

- **[low / confidence: medium]** `skills/dream/SKILL.md:25` (Step 2) with BUG-103 (`bugs/INDEX.md:72`, area "skills/init-project / skills/dream (slug derivation)", status fixed, prevention "stop on an empty/unset derived result"): the new "must succeed and be non-empty, or the run stops" clause sits inside Step 1.1. The dreamer's version (:32, "or you refuse the store") covers both of its paths and is fine.

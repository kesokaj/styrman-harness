## Checks asked for in the brief
- **Argument order**: correct. `--no-optional-locks` and `-c core.fsmonitor=false` come before `-C root ls-files`. In the probe, putting `--no-optional-locks` after the verb gave exit 129 (`unknown option`).
- **`--no-optional-locks` semantics for `ls-files`**: no change to output. The probe printed the same path with and without it. It has no effect on `ls-files`, which takes no optional index lock, so it is only there to match the sibling. `-c core.fsmonitor=false` is the guard that matters: on its own it kept the hook from running, and `--no-optional-locks` on its own did not.
- **Test string equals the return value**: yes. `strings.Join` of the slice is exactly `--no-optional-locks -c core.fsmonitor=false -C /r ls-files -- .agents/memory`.

- **Duplication with `internal/dream/collect.go` `trailStatusArgs`**: acceptable. The two slices share a four-token guard prefix and then use different verbs and pathspecs, in two packages. Today they carry the same guards, so the duplication hides no divergence. Sharing a helper would make `internal/dream` export one, or make `internal/memory` export one for `dream`, and that coupling costs more than two slices of eight to ten tokens.

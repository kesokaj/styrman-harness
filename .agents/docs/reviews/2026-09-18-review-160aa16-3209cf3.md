## Verdict: APPROVE WITH NITS

Every fix marked **fixed** in the merged record is present, does what the record claims, and is covered by a test. Nothing in the diff is wrong for the platforms this project ships (Linux, macOS). The worst item is a portability regression that is invisible here: `internal/harness/pathguard.go` now imports `syscall` and dereferences `syscall.Stat_t`, so `GOOS=windows go build ./...` fails at head where it succeeded at 160aa16 — no Windows asset is built or supported, so this is a nit, not a blocker. ## Findings

- **[low / confidence: high]** `internal/harness/pathguard.go:8,142` — `syscall.Stat_t` is not defined on Windows; `GOOS=windows go build ./...` fails at head (`undefined: syscall.Stat_t`) and succeeded at 160aa16 (verified by building a `git archive` of the base under `.agents/scratch/rev-base`). `os.Getuid()` also returns `-1` there, so even a compiling variant would read every file as not-owned. No Windows asset exists (`AssetName` is called with `runtime.GOOS` only; the operator is macOS/Linux), so this costs nothing today. Fix, if portability is wanted: put `ownedByCaller` in `pathguard_unix.go` (`//go:build unix`) with a `pathguard_other.go` returning `true`.
- **[low / confidence: high]** `internal/harness/pathguard.go:118` — `filepath.Clean(real) != filepath.Clean(home)` is a *lexical* identity test for a directory. `$HOME` with a trailing slash is handled (both sides are Cleaned, and `run` now runs `filepath.Abs`), but a symlinked home is not: with `$HOME=/home/x` symlinked to `/data/x`, `sh-agent update --home /data/x` suppresses the note although that *is* the real home. `$HOME` unset likewise suppresses it (`os.UserHomeDir` errors). Both are false negatives on an advisory line, never wrong advice, so the failure mode is benign — but `os.SameFile` on `os.Stat(real)` and `os.Stat(home)` is the correct identity for "the same directory" and is the same three lines.
- **[low / confidence: medium]** `internal/harness/pathguard.go:131` — `ownedByCaller` answers "do I own this file", but the question the remedy asks is "can I replace this name". `ln -sfn` needs write on `filepath.Dir(from)`, not ownership of `from`; and `os.Lstat` deliberately stats the symlink, whose uid is not what governs the relink either. Two skews follow: a caller-owned file in a root-owned directory still gets "point it at the installed binary (`ln -sfn`)", which will fail with EPERM, and the old text's "when that path is root-owned, prefer removing it" hint is gone from that branch. Advisory only; the fix is `unix.Access(filepath.Dir(from), W_OK)` or simply keeping the old root-owned clause in the owned branch.
- **[low / confidence: medium]** `internal/harness/apply.go:223-226` — `Diff` is a report-only verb, and it now creates `~/.config/sh-agent` (`MkdirAll`) as a side effect, inside the per-file loop, whenever a file differs. On a home the caller cannot write, `sh-agent diff` now returns an error where it previously produced output via `/tmp`. The global rule "a new side effect goes BELOW a read-only mode's early returns" points the other way. Low because the directory is this tool's own, the mkdir is skipped entirely when there is no drift, and every real place has that directory already.
- **[low / confidence: high]** `internal/harness/apply.go:230-233` — `Diff` returns without `os.Remove(tmp.Name())` when `tmp.Write` fails (pre-existing shape, new consequence): the orphan now lands in `~/.config/sh-agent/` rather than `/tmp`, and nothing ever sweeps it — `UpdateFromRelease`'s stale-sweep globs `release-*` only, so a `sh-agent-diff-*` file accumulates in the operator's config directory. `defer os.Remove(tmp.Name())` inside the loop body (or a small closure) closes it.
- **[low / confidence: high]** `internal/harness/source.go:54-65`, `internal/harness/repo.go:34` — informational, as the dispatch asks. A binary stamped `v1.02.2` is now `IsReleaseVersion == false` everywhere. `ResolveSource` therefore treats it as a *development build* and looks for a tree on disk (`--repo`, `$SH_AGENT_REPO`, the walk, the recorded repo) instead of installing its embedded harness — the exact silent-tree behaviour ADR-034 forbids for a release binary. `report` (`main.go:312`) falls to `ResolveSource` and, if that errors, sends a record with a zero `Source` (the BUG-077 null shape); `status`/`version` (`releaseFromInfo`, `main.go:933`) fall back to the VCS stamp. All unreachable in practice: `/preflight` cuts canonical `vX.Y.Z` tags, and Go itself refuses a non-canonical module version, so `info.Main.Version` cannot carry one. No change requested — recorded so the next reader of `ResolveSource` knows the release branch is gated on a *canonical* spelling now.

## Verification of each point the dispatch named

- **`IsReleaseVersion`'s int-fit loop** — correct and the check is necessary-but-narrow. The regex `^v(0|[1-9][0-9]*)\.(0|[1-9][0-9]*)\.(0|[1-9][0-9]*)$` admits only ASCII digits, no sign, no leading zero, no empty component, so `strconv.Atoi` can fail for exactly one reason: `ErrRange` (a component wider than `int`). Confirmed — `Atoi`'s other error, `ErrSyntax`, needs a non-digit, a sign or an empty string, none of which survive the regex. The loop is therefore the overflow guard finding 6 asked for, and it makes `releaseParts`' silent `[3]int{}` fallback unreachable from `compareRelease` (both arguments are validated before that call), which is what the finding was about.
- **`compareRelease(tag, version) <= 0` — is the equal case reachable?** No. `UpdateFromRelease`'s switch tests `tag == version` first, and by the time the third case runs both strings have passed `IsReleaseVersion`, i.e. both are canonical; canonical spelling is a bijection with the numeric triple, so `compareRelease == 0` implies `tag == version`, already returned. The `<=` is defence in depth with no live branch — harmless, and the wording change ("is not newer than") is accurate for the branch that does fire. Note this means the `<=` half of fix 6 is carried entirely by the canonical regex; the test `TestNonCanonicalTagNeverReachesTheDownload` asserts the right thing (the tag never reaches the download) rather than the equality.
- **Callers of `IsReleaseVersion` that now see `false`** — enumerated: `release.go:102` (tag from the GitHub API → refusal naming the tag, correct), `release.go:113` (running version → "not a release; leaving it alone", correct), `repo.go:34` `ResolveSource`, `main.go:312` `report`, `main.go:933` `releaseFromInfo`. The last three are the low finding above.
- **`NoteRunningElsewhere`'s home compare** — see the two low findings. `$HOME` unset → suppressed; trailing slash → handled; symlinked home → false negative.
- **`ownedByCaller` on macOS** — compiles. `GOOS=darwin GOARCH=arm64 go build ./...` succeeds at head; `syscall.Stat_t` on darwin carries `Uid uint32`, so `int(st.Uid)` is correct there. The release cross-build is safe.
- **`Diff`'s `MkdirAll(…, 0o700)` over an existing 0755 dir** — fine. `MkdirAll` returns nil and does not chmod an existing directory, so a pre-existing `~/.config/sh-agent` keeps 0755; the rendered harness is protected by `os.CreateTemp`'s own 0600 on the file, and the same non-enforcement already exists at `release.go:136`. No finding.
- **`filepath.Abs(home)` at `main.go:105-107`** — placed after the `--home`/`os.UserHomeDir` resolution and before every consumer, so `ResolveSource`, `knownCheckout`, `samePath`, `installPassArgs`, `Reinstall` and `NoteRunningElsewhere` all see the same absolute, Cleaned path. No comparison is weakened: `samePath` and `knownCheckout` compare *repo* paths, not the home, and `st.Repo` is unaffected; the home was previously passed through verbatim, so anything that already worked with an absolute home is unchanged and only the relative case moves (which is BUG-080's point). `err != nil` from `Abs` leaves `home` as it was — `Abs` fails only when `os.Getwd` fails, and falling through with the relative path is the old behaviour, not a new hazard.
- **The `readSettings` bound vs `attributionOff`** — correct and this is the fix's whole value: `attributionOff` (`main.go:890`) now inherits the size check, so `attributionHint` — the `status` path — reports an oversized settings file instead of silently reading its first megabyte and judging truncated JSON. `attributionSet`'s own `case info.Size() > 1<<20` is gone and the `!IsRegular` arm's comment was updated to say so. One behaviour delta worth naming and correct as chosen: `install` no longer prints its own "larger than 1 MiB" line, it now returns silently and `attributionHint` prints the single shared note.
- **`plainCopyOf`** — see § Tests.
- **`scratchClone`** — see § Tests.

### The two new fixtures

- **[low / confidence: high]** `cmd/sh-agent/main_test.go:1596-1629` `plainCopyOf` — correct today and fragile tomorrow. `filepath.WalkDir` does not follow symlinks and reports one with `d.IsDir() == false`, so the body calls `os.ReadFile` on it; a symlink to a directory then fails with EISDIR and the helper `t.Fatal`s with a raw errno. Verified there is no symlink anywhere under `context/ skills/ agents/ commands/ rules/` today (`find … -type l` is empty) — the repo's symlink is `.agents/skills → skills/`, which is outside the five walked roots, and `skills/` itself is a real directory, exactly as the dispatch supposed. The fragility is real though: `AGENTS.md` invites `npx skills add` to land third-party skills in `skills/`, and one containing a symlink would break three CLI tests with a message that names neither the symlink nor the helper. One line closes it: skip `!d.Type().IsRegular()` entries, or copy the link with `os.Readlink`/`os.Symlink`.
- `cmd/sh-agent/main_test.go:1631-1652` `scratchClone` — **no risk to this checkout**, as the dispatch supposed, and worth recording why. `git clone <src> <dst>` only reads the source: it opens refs and objects, takes no lock on the source worktree, and writes nothing there. Its local-transport optimisation hardlinks `.git/objects/**` into the clone, which is safe because git treats loose objects and packs as immutable (mode 0444, content-addressed, never rewritten in place); a later `git gc` inside the clone or the `t.TempDir()` cleanup only drops a link, leaving the source's own link and refcount intact. The clone's environment is scrubbed of `GIT_DIR`, `GIT_WORK_TREE`, `GIT_INDEX_FILE`, `GIT_OBJECT_DIRECTORY`, `GIT_COMMON_DIR` and every `GIT_CONFIG*` (`gitCleanEnv` plus `GIT_CONFIG_NOSYSTEM=1`), so no ambient variable can redirect the clone's writes back at this repository — the BUG-045 shape (a probe repository whose commands fell through to the real one) is guarded against, not merely avoided by luck. The test that uses it then rebuilds with `go build` inside the clone; nothing it does reaches `../..`. Both `git` and `go` are checked with `LookPath` and the test skips without them.

## Findings

- **A. [low / confidence: medium]** `skills/preflight/SKILL.md:62`, with `:42` and `:51`: an uncommitted change to the guide, a matrix or the kit still lets an older log reach HEAD.
  - **Text:** "`git diff --name-only <head> HEAD` lists nothing else; a change to the testing guide, a matrix, a kit or a script under `<docs-root>` is not a record, and an uncommitted source change reaches nothing."
  - **Why it fails:**
    - Step 1 defines dirty source as "modified or untracked files outside `<docs-root>`" (`:42`) and says files under `<docs-root>` "ride along in the release commit" (`:51`).
    - So an edit to `testing/kit-preamble.sh` or `testing/guide.md` that is still uncommitted at gate time is not "source", Step 1 does not commit it, and the `git diff` the sentence gives as its test does not see it.
  - **Who is misled:** a gate agent following the command. It counts a log run under the old kit or the old guide as reaching HEAD, and the edit ships in the release commit. This is finding 1's false pass, now possible only through the working tree.
  - **Should say:** "… an uncommitted source change, or an uncommitted change to the testing guide, a matrix, a kit or a script under `<docs-root>` (`git status --porcelain -- <docs-root>/testing`, undated files), reaches nothing".
- **B. [low / confidence: high]** `skills/preflight/SKILL.md:62`: the definition of a record gives two sets that disagree.
  - **Text:** "only records changed: the dated files under `<docs-root>` (reviews, changes, handoffs, bugs, dated logs)".
  - **Why the two sets differ:**
    - Bug records are `bugs/BUG-NNN-*.md` and `bugs/INDEX.md`, none of them dated.
    - `architecture/DECISIONS.md` (ADRs, which context § Definition of Done step 4 writes AFTER verification) is neither dated nor listed.
    - `plans/` and `retros/` files are dated but not listed.
  - **Who is misled:** a gate agent reading "dated files" literally. It treats a commit adding a bug record or an ADR after the verifier log as a non-record change and re-dispatches the verifier. That costs a full run, not a wrong verdict. Under the old definition all of these were excluded.
  - **Should say:** "only records changed: reviews, changes, handoffs, retros, plans, bugs (records and `INDEX.md`), `architecture/` and the dated logs under `testing/` …".
- **C. [low / confidence: medium]** `skills/preflight/SKILL.md:62`, against `.agents/docs/testing/guide.md:188` and `AGENTS.md:73`: one dated log is a procedure, and the new sentence classes it as a record.
  - **Text:** "dated logs" are records.
  - **Why it fails:**
    - In this repository, `testing/2026-09-03-verify-real-home.md` is the procedure: guide § 5 reads "The three checks in `.agents/docs/testing/2026-09-03-verify-real-home.md`", and `AGENTS.md` § Release requires that smoke before a tag.
    - An edit to its checks after a real-home smoke log does not make that log stale, so a smoke run under the old checks counts at the gate.
  - **Prior state:** the old definition had the same gap. This is finding 1's failure mode left open for one file, and it shares its root with the prior review's finding 6 (L6, skipped by the operator), so the operator may already consider it decided.
  - **Should say:** "… dated logs, except one the testing guide or `AGENTS.md` names as a procedure".

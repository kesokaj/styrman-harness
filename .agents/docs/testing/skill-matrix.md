## Procedure

1. Sandbox home `<home>` logged in to both CLIs; `sh-agent install --home <home>`; demo service checkouts for each CLI (a three-file Go HTTP service with `/healthz` and `/hello`, scaffolded by `/init-project`, plus the `/version` task). 2. Per row: fresh `git clone` of the demo into `/home/<user>/sandbox/runs/<cli>-<id>`, base as in the table, then
   - Claude Code: `HOME=<home> claude -p "<prompt>" --permission-mode acceptEdits <extra> --allowedTools "Bash(git:*)" "Bash(go:*)" "Bash(gofmt:*)" "Bash(cat:*)" "Bash(ls:*)" "Bash(date:*)" "Bash(mkdir:*)" "Bash(pwd:*)" "Bash(grep:*)" "Bash(find:*)" "Bash(wc:*)" "Bash(head:*)" "Bash(tail:*)" "Bash(printf:*)" "Bash(echo:*)" "Bash(cp:*)" "Bash(ln:*)" "Bash(test:*)" "Bash(diff:*)" "Bash(sh-agent:*)" "Bash(chmod:*)" "Bash(bash:*)" "Bash(python3:*)" "Bash(for:*)" "Bash(readlink:*)" "Agent" --output-format text` with `PATH=<home>/.local/bin:$PATH`. No `gcloud`, `docker`, `terraform`, or `npx` in the allowlist: a cloud command is denied, which is the mock. The allowlist lets the scenarios run (the `bash` and `python` rows run `bash -n` and `python3 -m py_compile`); it is NOT a security boundary. The sandbox home runs as the operator's own OS user, and `go`, `git`, `bash` and `python3` can each run anything and reach the real home. The grants are the batch's, not a row's: the fewest the batch as a whole needs. Nothing is protected during a batch; afterwards every copied credential — the Claude `.credentials.json` and the Antigravity `antigravity-oauth-token` alike — is deleted by name.
   - Antigravity: `HOME=<home> agy -p "The project root is the current directory, <dir>; ignore any other checkout. <prompt>" --mode accept-edits --print-timeout 20m`, with `<home>/.gemini/antigravity-cli/settings.json` written for the run (`guide.md` § 4 § Behavioural runs): `"permissions": {"allow": ["command(git)", "command(go)", "command(gofmt)", "command(cat)", "command(ls)", "command(date)", "command(mkdir)", "command(pwd)", "command(grep)", "command(find)", "command(wc)", "command(head)", "command(tail)", "command(printf)", "command(echo)", "command(cp)", "command(ln)", "command(test)", "command(diff)", "command(sh-agent)", "command(chmod)", "command(readlink)", "command(bash)", "command(python3)", "read_file(*)", "write_file(*)"]}` — the grant store knows four actions (`command`, `read_file`, `write_file`, `mcp`; an unknown one is logged as `ignoring invalid allow entry` in `cli.log` and skipped), and `command(<name>)` matches one command name: a `for` loop, a heredoc or a command outside the list (`node`, `docker`, `gcloud`) is denied, and the headless denial names neither the tool nor the command (BUG-141). A row whose skill text itself holds a shell construct, or reaches for a tool the sandbox lacks, runs with `command(*)` in its clone and the log says so (`edit_file(*)` and `list_dir(*)` are invalid entries in agy 1.2.8; its log names them) and `"trustedWorkspaces"` naming only the run's clone; no `toolPermission` key, checked before the batch with `grep -c toolPermission <home>/.gemini/antigravity-cli/settings.json` printing `0`; the file and the copied token are deleted by name after the batch. A `command(<name>)` grant allows every argument of that command. A run counts only when its stderr has no "auto-denied" line and the newest `<home>/.gemini/antigravity-cli/log/cli-*.log` has no "invalid allow entry" line; a scenario denied a command it needs gets that one command added here, by name, in the same change. No `--add-dir`.
3. Run the check in the clone with `OUT=<stdout file>` and `SB=<home>`; exit 0 is PASS. A check cell writes each `|` as `\|`, the table's escape, so a kit built from this file unescapes it before running the check. Then read the CLI's transcript (Claude: `<home>/.claude/projects/<encoded dir>/*.jsonl`, `Skill` and `Agent` tool uses; Antigravity: `<home>/.gemini/antigravity-cli/conversations/*.db`, `steps.step_payload`) for skills loaded and agents dispatched, and audit every executed command for `gcloud|terraform|docker (build|run|push)|kubectl|git push|npx skills add`.
4. Drive with `xargs -P 4` (Claude) and `-P 3` (Antigravity) under a monitor that outlives a ten-minute tool timeout. Never edit the driver while runs are in flight.

# BUG-037: `sh-agent adopt --force` could delete the harness checkout     (2026-09-16)

## Summary

`sh-agent adopt` computed its deletion target from a path `filepath.EvalSymlinks` had left relative. `.`, `..` and a relative `skills/<name>` therefore reached `filepath.Base` unchanged, so `dest` became `<repo>/skills` or `<repo>` itself, and `--force` ran `os.RemoveAll` on it — every skill, or the whole checkout with `.git` and unpushed work. A source that already was `<repo>/skills/<name>` was deleted before it could be copied.

`Adopt` now resolves the source to an absolute path first, validates the resolved name as a single path segment, computes an absolute destination, and refuses when either path contains the other — all before anything is removed. `adopt .` and `adopt ..` now adopt the directory they name, under that directory's own name. `--force` still replaces an existing skill of the same name.

The bug was found by argolis-devbox's security review of the a81ef4b mirror refresh (its finding 2) and recorded as BUG-037, the first of the harness security session's five records.

## Verification

- **The diagnosis agreed** with the main agent's hypothesis and sharpened it: `EvalSymlinks` does not absolutize a relative path, so one root cause explains all three symptoms.
- **Both tests fail without the fix.** Against `git show HEAD:internal/harness/adopt.go` in a scratch copy, all four subtests fail, reporting `skills/` removed, the repo removed, and the source removed. `TestWithin` fails on `/a/skills-old` and `/a/skillsdelta` when `within` is replaced by `strings.HasPrefix(child, parent)`. A first attempt at each check failed to build instead of failing its assertion, and was redone so the package compiled; a build failure is not a failing test (BUG-029).
- **Verifier, Status PASS:** counts pass 38, fail 0, skip 1, up two from its own earlier run, exactly the two added tests; `gofmt -l .` prints nothing, `go vet ./...` and `go test -race ./...` exit 0; `sh-agent list` parses 27 skills and 7 agents; `render` is 93 lines; a scratch install reports drift none.
- **Reviews:** code APPROVE, no findings, with two non-blocking notes — one closed by the new subtest, one left as the deferred follow-up. Docs APPROVE, no finding.
- **Left for later, agreed by both reviewers:** copying into a temporary directory and renaming it over `dest`, so a `--force` replacement cannot lose the old skill when the copy fails halfway. It addresses a different failure and is named in BUG-037's Fix section.

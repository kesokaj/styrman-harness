The range (three commits: v1.8.0 follow-ups, then the signed-release-zip feature) is unusually well

caught and fixed a stale mermaid map, stale "binaries with signed checksums" wording, and a missing-hint

code actually refuses rather than installs UNVERIFIED — nothing in this range's docs commit closed that
ambiguity, so it is still live at HEAD.

## Findings

- **[low / confidence: medium]** `REQUIREMENTS.md:43` (R9) vs `internal/harness/release.go:415-448`
  (`VerifyZipSums`). R9 says: "When the release's `SHA256SUMS` and `SHA256SUMS.sig` sit beside the zip,
  the zip is verified against them and refused if either check fails; a zip without them is installed
  marked `UNVERIFIED`." "Them"/"without them" reads as the pair, so a reader could take "a zip without
  them" to cover the case where only one of the two files is present — but the code (`VerifyZipSums`,
  `internal/harness/release.go:436-441`) treats "only one present" as a hard refusal (`cannot check for
  signed checksums…`/the underlying `verifySignedSums` "has no SHA256SUMS"/"has no SHA256SUMS.sig"
  errors), never as UNVERIFIED — only "both absent" returns `ErrZipUnsigned` and installs UNVERIFIED.
  Same ambiguity in `.agents/docs/architecture/DECISIONS.md:361-362` (ADR-039) and
  `.agents/docs/specs/sh-agent/delivery.md:32`, which use the same "a release zip is verified… when it
  and its `.sig` sit beside it… while a zip of `main` has nothing to verify and is installed marked
  `UNVERIFIED`" phrasing. This is not a new finding: `.agents/docs/reviews/2026-09-28-review-signed-zip-
  code.md:40` raised it in round 1 ("make R9 and ADR-039 say it explicitly…the R9 edit needs operator
  approval") and `.agents/docs/reviews/2026-09-28-review-signed-zip-code-r2.md:84` records it as "not
  addressed… not re-raised" — i.e. it was consciously left open, not missed, but it is still an
  inaccurate restatement of the code's behaviour sitting in an immutable-without-approval file at HEAD.
  **Owner: main** (REQUIREMENTS.md changes need the operator's explicit approval per project AGENTS.md
  and the file's own header; documentation cannot edit it unilaterally). **Fix:** add the clause the prior
  review proposed — "…when either sits beside the zip without the other, the zip is refused; only when
  neither is present is it installed UNVERIFIED" — to R9, ADR-039, and `delivery.md` § The model in one
  commit, with the operator's approval, per rule 6 (one home) and REQUIREMENTS.md's own change protocol.

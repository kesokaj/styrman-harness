# Security review — v2.5.0-a967512-part1   (2026-10-09)

Range reviewed: v2.5.0..a967512 (part 1 of 3: the paths below)

Paths: internal/metrics/{agy,claude,events,ingest,numbers,report,show,store,verb}.go (all new in range, each read whole), cmd/sh-agent/main.go (full range diff read: +199/-2, the `metrics` verb and its helpers).

## Status: COMPLETE

## Verdict: FINDINGS

Three findings, all low. Nothing here blocks the release on security grounds. Nothing in these paths leaves the machine: `sh-agent report` collects files by an allowlist (`internal/harness/report.go` `Collect`), which names `metrics.db*` as "never sent" and never reaches `reports/` or `metrics-agy-*`. The dream prompt gets only `Numbers()`, whose keys are all fixed strings. The worst problem is in `metrics show`: its text output prints Claude Code skill names raw from the model's `Skill` tool input. I probed it: a `Skill` call whose `skill` held `\u001b[31m…` was ingested, and `WriteText` wrote the raw ESC byte to the terminal. A prompt-injected session can therefore put terminal control sequences, or any prose, into the store and onto the operator's terminal. The second finding: a few `Verb` shapes keep content words in the store. The third: under `--source`, the subagent `.meta.json` read can be made to hang or exhaust memory.

## Findings
- **[low / confidence: high]** `internal/metrics/claude.go:321-323` (stored), `internal/metrics/show.go:638-641` (printed). `skill` is the model's `Skill` tool argument. It is stored verbatim, with no shape check. The Antigravity path does check: it keeps a skill only when it matches `[A-Za-z0-9_.-]+` (`agy.go:37`). `WriteText` prints the skills map with `%v`, so control bytes reach the terminal unescaped. Probe (scratch home, now deleted): input skill `"x\u001b[31mRED\u001b[0m"`, then `metrics show` text printed `skills (claude) map[x\x1b[31mRED\x1b[0m:1]`, raw ESC included. In principle, an injected instruction in a file or page the agent reads can steer the call. The effect is escape-sequence injection into the operator's terminal: hidden or rewritten output, a changed title, and on some terminals an OSC 52 clipboard write. It also stores free text, against R4's "never arguments or prose". The same raw `%v` printing applies to subagent types (`show.go:648-651`, from `.meta.json` / `agent_name`). Remediation: at ingest, keep a Claude skill name only when it matches the same name pattern as `agy.go:37` (else store NULL or `invalid`). In `WriteText`, print keys with `%q` or strip C0/C1 controls. Add a test that ingests an ESC-bearing skill and asserts it is absent from the store and from the text output.
- **[low / confidence: high]** `internal/metrics/verb.go:381-389`, `:261-262`, `:271-273`, `:299-303`. In a few shapes, `Verb` keeps content as a verb. Probed through `metrics.Verb` in scratch:
  - `cat <<"$DELIM"\nleakword2 a\n$DELIM` gives `["cat" "leakword2"]`. A delimiter with a character outside `[A-Za-z0-9_.-]` is not recognised, so the first word of every body line is tokenised as a program.
  - `curl --ghp_SECRETTOKEN123` gives `curl --ghp_SECRETTOKEN123`. A token-shaped long "flag" is kept whole.
  - `npx ghp_tokenvalue123` gives `npx ghp_tokenvalue123`. The subcommand slot keeps any identifier-shaped positional.
  - `go run sk-live-abcdef` gives `sk-live-abcdef`.
  - `mysql -pab` keeps two characters of a glued value. This one is documented.

  The store is local (0600 file in a 0700 directory, never sent), so the exposure is a secret-shaped word persisted forever in the "store of record", with no expiry. Remediation: when `<<` is seen and no delimiter can be read, fail closed and drop the rest of the command line, not its body. Cap the kept subcommand and long-flag names by length (e.g. 24) and by a no-digit-run rule, or keep a subcommand only from a per-program allowlist for `npx`/`go run`. Add the probes above as `TestVerb` rows.
- **[low / confidence: medium]** `internal/metrics/claude.go:155`. `<agent>.meta.json` is read with `os.ReadFile`, with no `Lstat`/regular-file check and no size cap. The transcript beside it is checked (`:124-130`), but between that `Lstat` and `os.Open` (`:142`) the file can be swapped for a FIFO. With `--source`, the home being read belongs to a sandboxed agent that can write it. A `meta.json` symlinked to `/dev/zero` makes `ReadFile` grow without bound, and a FIFO blocks. Either way the acceptance kit's ingest, or a nightly dream reading the same layout, hangs or is killed. Remediation: `Lstat` and require `IsRegular` before reading `meta.json`. Read it through `io.LimitReader` (64 KiB). Open the transcript with `O_NONBLOCK` (or `os.Open` then `f.Stat()` and require a regular file) instead of trusting the earlier `Lstat`.

### Round 2 findings
- **[low / confidence: high] R2-1** `internal/metrics/verb.go:63-64`, `:261-275`, `:303`. Finding 2 is only partly fixed: the 32-character cap stops long tokens but not short secrets. A scratch probe of `metrics.Verb` gave:

- **[low / confidence: medium] R2-2** `internal/metrics/claude.go:125-143`, `:172-176`. - **[low / confidence: medium] R2-3** `internal/metrics/claude.go:334-338` and `agy.go:254-257` (tool names), `show.go:638-651` (output). Two gaps remain around Finding 1:

A body line equal to that prefix then ends the body early, and the lines after it become verbs. Probe: `cat <<'END!'\nbody1\nEND\nleak_after_partial x\nEND!` gives `["cat" "leak_after_partial"]`.

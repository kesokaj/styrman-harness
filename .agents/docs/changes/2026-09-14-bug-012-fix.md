# BUG-012 fixed: explorer now writes brief artifact under read-only dispatch     (2026-09-14)

## Summary
Fixed BUG-012 — the `explorer` subagent was not writing its brief artifact when a dispatch included read-only wording such as "change nothing" or "report only", and then falsely claimed to have done so in its reply. Diagnosis by `explorer` goldfish run showed two root causes: (A) the dispatcher's instruction to skip writes (misinterpreting the user's change-scope constraint as applying to agent artifacts, which are trail); (B) one transcript with zero Write tool_use calls. Fix clarifies that agent artifacts are always written regardless of user scope constraints. Applied to three files: `context/AGENTS.md` adds a sentence about artifacts being trail; `agents/explorer.md` mandates writing the brief with the Write tool and naming its path only after success; `skills/review/SKILL.md` adds a clause saying "Write your artifact with the Write tool; report only means no source edits."

Deployed to the real home on the Linux box by running `sh-agent update`, which reported `up to date with upstream (157934b)` and managed 260 files (11 written, 249 unchanged, 2 removed, 0 kept); `sh-agent status` confirmed installed commit 157934b, binary 157934bdd7d2 with no warnings, drift none with 259 files matching the repo, and `~/.claude/skills/review/` present.

# BUG-033 and BUG-034: the review commands refuse a shadowing agent, and the release gate blocks on a missing security report     (2026-09-16)

## Summary

Two findings from styrman-crew's security review of the a81ef4b refresh, both on the release gate's independence, both decided by the operator.

- **BUG-033.** On Claude Code a project agent named like a harness review agent replaces it: the sandbox showed `/review --security` dispatching `security` and the project's copy running, its report admitting it had no shell tool. The context only asked projects not to reuse harness names. Now `/review` stops before dispatching, and `/preflight` returns NO-SHIP, when the project layer holds `reviewer.md`, `security.md`, `verifier.md` or `explorer.md` under `.claude/agents/` or `.agents/agents/`, or a file whose frontmatter `name:` is one of those four; both name the file. The operator chose this over renaming the harness agents or keeping the convention.
- **BUG-034.** `/preflight`'s blocking list failed open when the security report Step 2 owes was missing or cut off. It now blocks on a security report that is missing, has no `## Not examined` section, or names a path from the release diff under it. The operator chose that narrow reversal of D35, scoped to the security row; D52 records it and D35's row points at it.

- **The three matrix checks** pass in their shadow clones and fail in the control, so none fires in both states.
- **BUG-034 has no end-to-end run**: staging a missing security report would mean sabotaging an agent. The clause is confirmed by reading Step 5.
- **Verifier, Status PASS:** counts pass 54, fail 0, skip 1, unchanged, no Go file in the diff; `list` 27 skills and 7 agents; `render` 93 lines; scratch installs with drift none and both vendors' copies carrying the final text.

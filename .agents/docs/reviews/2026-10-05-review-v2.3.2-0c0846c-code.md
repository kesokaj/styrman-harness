## Findings

- **[medium / confidence: medium]** `rules/critical-thinking.md:14` against `rules/critical-thinking.md:8`. Bullet 1 says "a direct instruction is carried out: its risks go in the reply's table, after the work". Bullet 7 says, with no condition, "Disagree before complying." The two conflict for exactly the case ADR-050 calls P2. `.agents/docs/testing/2026-10-05-verify-critical-thinking-r2.md` records the failure mode: under the old text, Antigravity answered "Disagree with patching `os.ReadFile` alone; resolve … before …" and did not carry out the instruction. That happened in 2 of 3 valid runs across both rounds, and in 1 of 2 runs in round 2 even with the skip-permissions flag. The new clause gives 3 of 3 on Antigravity. But the unconditional bullet that a model can still pick is still in the file, three valid runs is a small sample, and a release place has not received the rule yet. Fix: scope bullet 7 so the file has one rule, not two. For example: "Disagree before complying with a proposal, plan or claim; a direct instruction follows bullet 1." Or remove it, since bullet 1 already says when to disagree. Then re-run Antigravity P2.
- **[medium / confidence: low]** `context/AGENTS.md:5` together with `internal/dream/dream.go:177` and `internal/dream/run.go:133-143`. The nightly Claude child runs `claude -p --tools "" --setting-sources local` with the real `HOME` (only the agy child gets a private `HOME`, `run.go:249-271`). If user memory and `~/.claude/rules/` load under that flag, every reply that "reports, proposes or asks" is now told to open with an explanation line, a recommendation line and a numbered table. That shape would fail `parse()`: the prompt demands "ONE JSON object and nothing else" (`internal/dream/prompt.go:23`). Each project would then log `fail invalid output`. The escape clause "unattended runs and subagents follow their dispatch" probably prevents this. But no log in the range runs `sh-agent dream` after the rule landed, and this machine has no `dream.log`. Low confidence: I did not establish whether `--setting-sources local` suppresses user memory and rules. Fix: one `sh-agent dream` run (or `--dry-run` plus one real project) against a home with the rule installed, before the next tag. Record the result next to the testing guide's § 3e.
- **[low / confidence: medium]** `context/AGENTS.md:5` against `skills/feature/SKILL.md:15`. The context now says "Nothing proposed runs until they approve it in their own turn … and only that". The feature skill says "Four points always wait for the user … Everything else runs without asking". Inside a `/feature` run the agent proposes things between gates: review-round fixes, phase splits. The two texts disagree on whether each proposal needs a "go". One reading stalls the flow at every proposal. The other runs proposals the context says must wait. The escape "A direct instruction is its own approval" covers this only if the model treats the original `/feature` request as approval of everything the skill does afterwards, and neither file says so. The project's restatement rule (AGENTS.md § Testing, review-standards § 3) requires the two to agree. Fix: one clause in the context, such as "inside a skill the operator started, that skill's gates decide what waits". Or name the context's protocol as the gate in feature:15.
- **[low / confidence: high]** `skills/feature/SKILL.md:21`. The range edited this line to end with "the global context's approval line". It still says "the restatement is a numbered list instead: one line per item, the recommendation in brackets". ADR-050 records that the operator chose the table over a list ("Keep the numbered table, I like the table"), and `context/AGENTS.md:5` now says "ONE NUMBERED TABLE". A restatement was left standing inside the edited line. Fix: "a numbered table instead: `#`, the item in one line, the recommendation (`fix`, `strike` with the reason, `yours`)".

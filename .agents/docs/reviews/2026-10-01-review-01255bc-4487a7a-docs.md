  - The text, `:38`: "Write `$docs_root/testing/$(date +%F)-verify-<slug>.md`". The text, `:76`: "Writes: `<docs-root>/testing/<date>-verify-<slug>.md` every run".

- **[low / confidence: low]** `agents/security.md:75` against `agents/verifier.md:79`.
  - The text, `security.md:75`: "(with `GIT_DIR` exported an init exits 0 and creates nothing there; unset it for the probe), and every later command names it (`git -C <dir> …`)".
  - The verifier's copy rule unsets `GIT_DIR`, `GIT_WORK_TREE`, `GIT_COMMON_DIR` and `GIT_INDEX_FILE`. The security agent unsets only `GIT_DIR`, and `git -C <dir>` does not override an exported `GIT_INDEX_FILE` or `GIT_WORK_TREE`. In a shell that has them (git exports them inside a hook, as guide `:20` says), the probe's `git add` and `git commit` write another repository's index, and a `checkout` writes another work tree. The `rev-parse --absolute-git-dir` check passes in that case, because it tests only the git directory.
  - Who is misled: the security agent, which believes its probe is isolated once the check prints `<dir>/.git`.
  - Fix, `security.md:75`: "unset `GIT_DIR`, `GIT_WORK_TREE`, `GIT_COMMON_DIR` and `GIT_INDEX_FILE` for every probe command (`env -u …`)", the same list as `verifier.md:79`.
  - Owner: main.

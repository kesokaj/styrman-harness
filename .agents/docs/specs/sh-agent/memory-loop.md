# The memory loop — one store for both CLIs, and the `dreamer` agent

Status: built 2026-09-29 (plan `plans/2026-09-29-dreamer-memory-loop.md`); writing and loading moved to `sh-agent memory` on both CLIs on 2026-09-30 (R10, plan `plans/2026-09-30-parity-memory-dream.md`). The nightly background job is `specs/sh-agent/dream.md`.

## The store

- **Path:** `<repository root>/.agents/memory/`, inside the project and gitignored — one store per checkout (the operator's choice, "Option 2", 2026-09-29, over a harness-owned directory under `~/.config/sh-agent/`). Never committed (personal and unreviewed content), never sent by `sh-agent report` — though with the dream timer installed every memory file goes nightly, redacted, to the model provider of the CLI the manifest names (`specs/sh-agent/dream.md`), and harness-target proposals derived from it can leave through `report` (which ships only `feedback.jsonl`, `retros.jsonl`, `proposals/`, the install manifest and `report.json`, `internal/harness/report.go`). `<slug>` — the repository root's absolute path with every character other than a letter, a digit or a hyphen replaced by a hyphen, the name Claude Code gives the project under `~/.claude/projects/` — is still what names the default store the migration reads from.
- **Layout:** Claude Code's auto memory layout, unchanged: `MEMORY.md` (one line per memory, `- [Title](file.md) — hook`, under 200 lines and 25 KB) and one file per memory with the frontmatter Claude writes (`name`, `description`, `metadata.type` in `user` / `feedback` / `project` / `reference`, `metadata.originSessionId`, `metadata.modified`).
- **Who writes:** `sh-agent memory add` (`internal/memory`; serialised by a flock on `.agents/memory/.lock`, kernel-released), called the same way on both CLIs: by the `project-memory` skill (the four types and when to save) and by `feedback-log` rule 7 (a correction or re-stated preference). Claude Code's own auto memory is switched off per project: `/init-project` writes `"autoMemoryEnabled": false` beside `autoMemoryDirectory` in `.claude/settings.local.json` (REQUIREMENTS § Non-goals exception). A file the verb writes carries no `originSessionId` (no CLI gives a shell its session id); `/dream`'s promote test counts it as one session. The root is the main worktree's top level, so worktrees share one store.
- **Who reads:** every session on either CLI runs `sh-agent memory show` at the end of the Resume Protocol (context § Resume); it prints `MEMORY.md` capped at 200 lines and 25 KB, plus a line when Claude Code's native memory is still on in the project (a scaffold from before R10). `/dream` consolidates the store on either CLI; its store is always `<root>/.agents/memory`, and memory left at Claude Code's old default path is named (moved by `/init-project` where Claude Code is installed, by hand on an Antigravity-only machine). The `dreamer` agent reads it on either CLI.
- **Set up by** `/init-project`, new and update paths (on a machine where the harness is installed for Antigravity alone, only the store and its `.agents/memory` ignore line; nothing under `.claude/`): write the two keys (`autoMemoryDirectory`, `"autoMemoryEnabled": false`) into `.claude/settings.local.json` (create the file when absent; add a key when the file exists without it; keep and report a different value, moving nothing there), add `.agents/memory` (no trailing slash, so the line also covers a symlink) and `.claude/settings.local.json` to `.gitignore` before the store exists, create the store (mode 700), and move an existing default store's files (`~/.claude/projects/<slug>/memory/*`) into it when the new store is empty — move, never copy, one store; when the default path holds no memory files it says `no memory files at <old>` with a hint list and moves nothing; a settings file that is an empty object is overwritten with the one key, any other gets one inserted line and a parse check that removes that line again on failure (no backup copy: a fixed copy path could be a committed symlink). The store must be the project's own directory: a symlinked `.agents` or `.agents/memory`, or anything git tracks under it, stops `/init-project` and is refused by `/dream`, the `dreamer` and the capture rule.
- **Trust:** Claude Code honours a project settings file only in a trusted workspace. Where it does not, its native memory stays on and writes to its default path; `sh-agent memory show` names the rollout line at every session start, and `/dream` counts the default path's files and names them for the move.

## The `dreamer` agent

- **What it is:** the consolidation judgement of the learning loop, run by an author-independent reader: given the store and the trail, what should become a rule, a skill or a procedure, and what should be left alone. It proposes; it never applies.
- **Definition:** `agents/dreamer.md` — tools `Read, Grep, Glob, Bash, Write`; `model: sonnet`; `effort: medium`; `maxTurns: 40`; derived for Antigravity by the installer like every agent.
- **Dispatch text (the contract):** `Store: <path>. Docs root: <docs-root>. Since: <date of the newest retros/*-retro*.md record, or "all">. Promoted: <the memory files /dream flagged promote, or none>.` plus the standard artifact and budget sentences. Never the conversation. The dreamer does not re-derive `/dream`'s verdicts: the promoted files are its rule-candidate inputs, one candidate row per memory file.
- **Reads:** the store (`MEMORY.md` and every memory file); the trail since the date — `handoffs/` (newest three), `bugs/INDEX.md` rows and their prevention rules, `changes/` entries; what already exists — the global context, the project `AGENTS.md` and `.agents/rules/`, the installed skills' descriptions (`sh-agent list` or the skill directories), so a candidate is never something a rule already says.
- **Candidate tests:** a **rule** for each file on the dispatch's `Promoted:` line (given, never re-judged: `/dream` owns the two-memory test), for a bug row whose prevention rule is recorded nowhere loaded and that recurs (two rows, or a row and a memory on the same fact), and for a memory of any type that a trail row restates (a handoff or `changes/` line on the same fact) when no loaded rule holds it; a **skill** when a memory or the trail shows a procedure of three or more steps done more than once (`/distill`'s bar); a **procedure** (a `references/` page for an existing skill) when the steps belong to a skill that exists; **none** otherwise, listed under "Left alone" with the reason.
- **Writes:** one artifact, `<docs-root>/retros/<date>-dreamer.md` (`owner: dreamer`, `date:`), written early with `Status: IN PROGRESS` and finished with `COMPLETE`: Scope, Summary, a Candidates table (`#`, kind, target file, the exact rule text or the draft's path, evidence as `file:line` and memory file names), "Left alone", "Not examined". Drafts for skills go under `.agents/scratch/dreamer/<date>/<name>/SKILL.md`. No other file, ever; no edit to source, config, rules, skills or memory.
- **Consumers:** `/retro` dispatches it (Step 1 source 8) and turns rule candidates into proposals through its own Step 2 (target, scope, promotion check) — the one place that decides where a rule lives; `/distill` dispatches it first and takes its skill and procedure candidates as candidates. No `retros.jsonl` line of its own; the retro or distill record cites the artifact.

## Error handling

| Situation | Behaviour |
|---|---|
| No store, or an empty one | `/dream` and the `dreamer` say so in one line; the resume clause reads nothing |
| Memory at Claude Code's old default path (a scaffold from before R10, or an untrusted workspace) | `/dream` names the count and the move (`/init-project`, or by hand on an Antigravity-only machine); the `dreamer` reads the store only |
| `~/.config/sh-agent/` denied to the session | the reader says so; the `dreamer` artifact still writes into the project trail |
| `.claude/settings.local.json` exists with another `autoMemoryDirectory`, or git tracks the file, or it is a symlink | `/init-project` keeps it, reports, writes nothing into it and moves nothing; `sh-agent memory show` reports native memory still on; `/dream` and the `dreamer` use only `<root>/.agents/memory` |
| Agent cut at its turn limit | a partial artifact with `Status: IN PROGRESS` (its early-write rule); the caller says so |
| `git clean -fdx`, a fresh clone, a deleted checkout | the store is gone with them, like scratch; the migration moved the files, so there is no second copy — the operator's choice (ADR-043) |
| `.agents` or `.agents/memory` is a symlink, or git tracks something under it | `/init-project` stops and reports; `sh-agent memory add` and `show` (exit 2), `/dream` and the `dreamer` refuse the store. With native memory off (R10) Claude Code no longer loads `MEMORY.md` itself, so the ADR-043 residue (a force-added upstream `MEMORY.md` loaded unchecked) is closed where `/init-project` has run; it stays in a project scaffolded before R10 until then |

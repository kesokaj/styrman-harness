# Review — v2.0.0 gate fixes   (2026-09-28)

## Status: COMPLETE

## Verdict: APPROVE

Both fixes do what they claim and nothing more. The stray-argument refusal
in `update --from-zip` is correctly scoped: `reorder()` places every
flag-with-value token (including `--from-zip`'s own file argument) ahead of
positionals before `fs.Parse` runs, so a legitimate invocation
(`update --from-zip FILE [--dry-run] [--unverified]`, the only documented
shape) never has a non-empty `fs.NArg()`; only a genuine stray word like the
`false` in `--unverified false` lands as a positional and is refused. I
mutation-tested both changed checks against the pre-fix code in a scratch
worktree of b1ecab3: `TestFromZipStrayArgumentRefused` and
`TestUpdateFromZipUnsignedRefusedWithoutFlag` both fail on the old code and
pass on the new code, confirming each test fails without the thing it pins.

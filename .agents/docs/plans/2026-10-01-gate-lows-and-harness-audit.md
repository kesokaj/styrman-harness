## Interfaces

1. **Timer** (`internal/dream`).
   - `RemoveTimer(home, goos string) (removed bool, err error)`: `removed` is true when a unit file of this home's own name, for the running OS, was on disk and is gone. The two callers in `cmd/sh-agent/main.go` take the new result.
   - `LegacyTimerFiles(home string) []string`: when `UnitFor(home)` is suffixed, the bare-named unit files that exist under that home, for both operating systems as `TimerInstalled` looks (`<home>/.config/systemd/user/sh-agent-dream.service`, `.timer`, `<home>/Library/LaunchAgents/com.styrman.sh-agent-dream.plist`); nil for a home that keeps the bare name.
   - `LegacyTimerNotice(home, goos string) string`: empty when there are no such files; else, in this order: the paths; "written by v2.0.0 or earlier; not removed or stopped here, because a stop by name ends whichever unit the service manager loaded"; the check for `goos` (`systemctl --user show -p FragmentPath sh-agent-dream.timer` on linux, `launchctl print gui/<uid>/com.styrman.sh-agent-dream` on darwin, `<uid>` being `os.Getuid()` printed as a number); the steps: if the manager loaded one of these files, stop it by name (`systemctl --user disable --now sh-agent-dream.timer`, or `launchctl bootout gui/<uid> <plist>`), then delete the files, then `systemctl --user daemon-reload` on linux.
   - Output. `sh-agent dream --remove-timer`: `dream timer removed`, or `no dream timer found for <home>` when `removed` is false; then the notice when there is one; exit 0 in both cases. With `--dry-run`: today's line (`[dry-run] would remove the nightly dream timer; installed now: <bool>`), then the notice. `sh-agent uninstall`: `removed the dream timer` only when `removed` is true (today it says so whenever any unit file of either OS exists, removed or not); no line when nothing was removed, since `uninstall` is not a timer command; then the notice when there is one, also in a dry run. `sh-agent status`: the `dream` line gets the suffix `; legacy timer files under <home>: run sh-agent dream --remove-timer for the cleanup steps` in every branch of `StatusLine`, the state-unreadable one included.

## Failure modes

- A legacy timer file exists and the operator runs `--remove-timer`: nothing of it is touched; the notice names it; exit 0.
- `LoadDocs` meets a rule that starts `--- ` and never closes: the install stops naming the file (today it deploys as written, unchecked).
- A marker at the checkout's root: the header reads `left out by .sh-agent-noindex: ./`; the search still answers with nothing, exit as today.
- `--work ~/x` where `~/x` holds the operator's own files and no `origins.txt`: refused before anything is cloned or removed.
- `/harness-audit` where the git root is not a harness checkout: one line saying so, nothing written.
- An audit agent returns without its artifact: the area is listed under "What was not examined" in the report, never filled in from memory.

## Release notes
A PATCH: `/init-project` no longer creates `.claude/` on a machine installed for Antigravity alone, and `/dream` finds its memory store there.

### Fixes
- `init-project` skill (BUG-113): reads the install manifest; on a machine installed `--vendor agy` it writes nothing under `.claude/` (no links, no `settings.local.json`, no memory migration, no `.claude/` ignore lines). The `.agents/memory` store is still created. Other vendors behave as before, and an existing `.claude/` is never removed; the summary names it.
- `dream` skill: on such a machine the store is `<root>/.agents/memory`, taken directly; the global context is also read at its Antigravity path.
- Context: `/init-project` links `.claude/*` for Claude Code only (BUG-114 kept the Antigravity block within budget).

### Other updates
- Docs: README, `deploy/local.md` and `specs/sh-agent/memory-loop.md` say that the install vendor decides whether projects get `.claude/`. An Antigravity-only machine installed with the default `all` needs `sh-agent install --vendor agy` once.

## Verdict: REQUEST CHANGES

The worst problem is in the line meant to close git's side channels in the refresh script. It exports `GIT_CURL_VERBOSE=0`, and that turns curl tracing ON. git checks only whether the variable is set and ignores its value, then forces the curl trace to stderr, overriding the `GIT_TRACE_CURL=0` that line 58 sets. Today the script discards stderr on every network call, so nothing leaks yet. But the security comment on line 53 states the opposite of what the line does, and no test reaches http.c.

Second, the new early-exit-pipe guard misses common forms of the class it is meant to catch, and it flags `||` lines that contain no pipe. Third, the verifier's new "re-dispatch with the same slug, so this log is updated" does not hold under its own naming rule. A BLOCKED log left in the range then blocks the gate with no documented way to clear it.

The rest works as described. The here-string gives the same results as the pipe it replaces. The new kit-preamble check accepts every SHA the old one accepted, plus full 40-character SHAs, which the old check refused. The TERM-signal test is bounded, and it fails when the trap is removed.

- **[medium / confidence: high]** `skills/google-catalog/scripts/refresh-catalog.sh:57` — `export … GIT_CURL_VERBOSE=0` turns curl tracing ON.
  - Cause: git tests the variable's presence (`if (getenv("GIT_CURL_VERBOSE"))`) and then forces `trace_curl` to stderr. That overrides the `GIT_TRACE_CURL=0` the loop on line 58 exports.
  - Probe (git 2.47.3, scratch copy): `GIT_CURL_VERBOSE=0 git ls-remote https://127.0.0.1:9/x.git` prints `http.c:913 == Info: Trying 127.0.0.1:9...` and the rest of the trace. With the variable unset, it prints one `fatal:` line. The full export set from line 57 gives the same trace.
  - Why nothing leaks today: every network git call in the script (lines 210-216) redirects `>/dev/null 2>&1`.
  - If it ships: every https clone or fetch writes its connection, request line and headers to stderr. That reaches the terminal the moment one call loses its redirect, and the line 53-56 comment states the opposite of what the line does.
  - Why no test sees it: the fixtures use local paths and never reach http.c.
  - Fix: `unset GIT_CURL_VERBOSE` instead of exporting 0. Add a test that runs the script with `GIT_CURL_VERBOSE=1` against an https URL that refuses the connection and asserts that stderr has no `== Info:` line. - **[medium / confidence: high]** `internal/harness/catalog_test.go:352` (`earlyExitPipe`) — the guard misses forms of its own class. Each form below was run through the regex and was not matched:

Fix: widen the regex to these forms, or switch to a denylist of consumers matched on whole pipeline tokens, joining continuation lines first. At minimum, add the long options, `-l`, `sed …q` without a digit, awk `exit` and `|&`, each with a must-refuse case.

## Other questions from the dispatch
- **Here-string against the pipe** (`restatement-grep.sh:55`): equal for every input probed. Lines: empty, a literal `\n`, a trailing backslash, a tab, `-e`, a trailing CR, an empty remainder after `f:2:`. Words: `a`, `\`, `text`, `-e`, empty. Both forms feed grep the text plus one newline, and neither interprets escapes. A line read with `read -r` cannot hold a newline. Residual: bash older than 5.1 (macOS /bin/bash 3.2 through `#!/usr/bin/env bash`) writes a here-string to a temp file in $TMPDIR. If that directory cannot be written, grep fails and the line is silently dropped. No concrete case found, so not a finding.
- **Exported variables and a legitimate run**: `GIT_TERMINAL_PROMPT=0` does not disable credential helpers or `GIT_ASKPASS`. It only stops the tty prompt, which the script documents. The `go test` child inherits the variables, but the harness tests drop `GIT_*` (`fixtureEnv`, catalog_test.go:484). The one harmful export is `GIT_CURL_VERBOSE` (finding 1).

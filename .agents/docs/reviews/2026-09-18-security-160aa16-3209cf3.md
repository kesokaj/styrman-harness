# Security review — fix round for the Phase 2 audit (160aa16..3209cf3)

Range reviewed: 160aa16..3209cf3 (`git diff 160aa16..3209cf3 -- . ':!.agents/docs'`, plus the four docs in the dispatch)

## Verdict: FINDINGS

Seven of my eight audit findings are closed as written. One is not: the `0o700`
on the throwaway clone's parent is **inert on every machine that has run
`install`**. `SaveState` writes `~/.config/sh-agent/state.json` through
`writeAtomic`, whose `os.MkdirAll(filepath.Dir(dest), 0o755)` (`apply.go:291`)
creates that directory first, and `os.MkdirAll` returns nil for an existing
directory without touching its mode — measured, twice: a scratch probe
replicating the two calls in order prints `-rwxr-xr-x` after both, and
`~/.config/sh-agent` on the operator's own box is **0755** right now. So
`report.go:457`, `apply.go:224` and the older `release.go:136` all no-op. I also
have to correct my own earlier framing of that finding, and `release.go`'s
comment with it: 0755 grants group and other **r-x, not w**, so nobody can
pre-create `report-<pid>` as a symlink there — the exposure the 0700 actually
closes is READ exposure, and that is the one still open: every local account can
traverse `~/.config/sh-agent` and read the feedback log, the retro proposals, and
the transient clone of the **private** `styrman-harness-feedback` repository
while `report` runs (and after a SIGINT, until the next sweep). Everything else
in the round does what its finding asked, and two of the new tests
(`TestNonCanonicalTagNeverReachesTheDownload`, `TestDiffUsesTheHomeNotTmp`) are
genuine must-fail checks of the behaviour they pin.

## Status of the eight prior findings — checkable statements

1. **`copyTree` mode — CLOSED.** `adopt.go:175` is now
   `writeAtomic(target, data, info.Mode().Perm()&0o755|0o600)`, identical in
   effect to `plan.go:138`: 0666 lands 0644, 0775 lands 0755. Directories in the
   same walk are `MkdirAll(target, 0o755)`. `TestAdoptStripsGroupAndOtherWrite`
   asserts `Perm()&0o022 == 0` on the adopted file (skipped as root, correctly).
3. **Canonical tags + `<= 0` + overflow — CLOSED.** `source.go:46` is
   `^v(0|[1-9][0-9]*)\.(0|[1-9][0-9]*)\.(0|[1-9][0-9]*)$`, which rejects
   `v1.02.2`, `v01.2.2`, `v1.2.02`; the added `strconv.Atoi` loop rejects
   `v99999999999999999999.0.0` before `releaseParts` could read it as `v0.0.0`.
   `release.go:116` is `compareRelease(tag, version) <= 0` with the message "is
   not newer than". `compareRelease` has exactly **one** production caller
   (`release.go:116`, confirmed by grep across the module) and both its operands
   are gated by `IsReleaseVersion` above it (`:102` for `tag` from the GitHub
   API, `:114` for the running `version`), so `releaseParts`' surviving
   `return [3]int{}` is unreachable from production code. The guard moved to the
   entry rather than to the parse; that is equivalent **here and only here**, and
   a second caller of `compareRelease` would have to repeat the gate. The doc
   comment at `release.go:369-370` ("Both are known to match") says so, which is
   the mitigation.
4. **The BUG-079 note — CLOSED for `--home`, PARTIAL for ownership.**
   `pathguard.go:118` returns unless `filepath.Clean(os.UserHomeDir()) ==
   filepath.Clean(home)`, and `TestNoteRunningElsewhereOnlyForTheRealHome`
   exercises both directions by setting `HOME`. `ownedByCaller` downgrades the
   remedy. Two residuals, findings B and C below.
5. **Throwaway parent `0o700` — NOT CLOSED.** Finding A.
6. **`Diff` out of `/tmp` — CLOSED for `/tmp`; the leak survives.**
   `apply.go:223-227` writes under `filepath.Join(home, ".config", "sh-agent")`,
   and `TestDiffUsesTheHomeNotTmp` proves it by setting `TMPDIR` to a
   non-existent path and requiring `Diff` to succeed — a real must-fail check.
   The `tmp.Write` error path at `:231-233` still returns without
   `os.Remove(tmp.Name())` and without `Close`, so a write failure leaks the file
   and its fd; the remediation that removed the temp file entirely (`diff … -`
   with `cmd.Stdin`) was not taken. Severity drops from "debris in a shared
   directory" to "debris in the operator's own directory at 0600". Finding E.
7. **`yamlQuote` — CLOSED.** `frontmatter.go:167-189` escapes `\`, `"`, `\n`,
   `\t` and every rune `< 0x20` or `== 0x7f` as `\uXXXX`. `\u` + four hex digits
   is a valid double-quoted escape in YAML 1.1 (`ns-esc-16-bit`) and YAML 1.2, so
   the rendered `agent.md` parses; DEL is included. Better than the finding
   asked: the reachable case is not the hypothetical newline (`entries()` splits
   on `\n`, `TrimRight`s `\r` and joins continuations with a space, so `Parse`
   cannot return a value containing a line break) but a **mid-line** control — a
   raw ESC, NUL or DEL inside a vendored skill's `description:`, which `keyLine`'s
   `(.*)` matches, `TrimSpace` preserves, and `Lint` does not refuse. That case
   was live and is now escaped. One residual, finding D.
8. **`cell` — CLOSED.** `inventory.go:396-402` converts to `[]rune` and takes
   `string(r[:max])`; every later index is a byte offset into that already
   rune-aligned prefix, so neither the space cut (ASCII boundary) nor the
   `cut = len(head)` fallback (the whole prefix) can split a rune.
   `TestCellIsRuneSafe` sweeps `max` from 5 to 119 over a multi-byte string and
   checks `utf8.ValidString`.

## The two findings left — do the reasons hold

**17 / `LoadState` does not sanitise `Repo`.** Two halves, two answers.

- *"a prior write as the user is the attacker already holding the user's
  rights"* — **sound for the default home and the default threat model, but it
  claims more than it proves and should be recorded narrower.** `state.json` is
  a file, not a live process; it arrives by any route that populates
  `~/.config`, and two of those are not "the attacker already has your rights":
  (a) a dotfiles repository or a restored backup carrying
  `~/.config/sh-agent/state.json` — a normal way for `~/.config` to be seeded,
  which makes `repo` an input from off the machine; (b) `--home <dir>` where the
  directory is shared or group-writable — and on this very box `~/.config` is
  **0775**, so the user's group is already a wider set than the user. In both,
  the `repo` field selects the directory `Reinstall` runs `go build` in and then
  executes. The disposition (leave it) is defensible — high cost, blast radius is
  the operator's own account — but write the reason as: *"no path writes
  `state.json` except `sh-agent` running as the user; a `state.json` that arrives
  from a backup, a dotfiles sync or a shared `--home` is out of model."* Closing
  it for real is still one `IsCheckout(st.Repo)` call before a build.
- *"`knownCheckout`'s purpose (a DIFFERENT checkout found from cwd) still holds
  when the walk finds one"* — **holds; verified against the resolution order.**
  `ResolveSource` (`repo.go:22-70+`) takes `--repo`, then `$SH_AGENT_REPO`, then
  the cwd walk, and only then the recorded manifest. So whenever the walk (or a
  flag) supplies `repo`, `st.Repo` is an independent value and
  `samePath(st.Repo, repo)` is a real comparison that refuses the mismatch — the
  case the guard exists for. The circularity bites only where nothing else
  supplied a repo and `st.Repo` was itself the selector, which the guard never
  claimed to cover. The claim is accurate as written.

## Findings — new surface from the fixes

- **[low / confidence: high]** `internal/harness/report.go:457`,
  `internal/harness/apply.go:224`, `internal/harness/release.go:136` — **the
  `0o700` never applies.** `os.MkdirAll` is a no-op returning nil when the
  directory exists, and `~/.config/sh-agent` always exists by the time any of
  these run, created 0755 by `writeAtomic` under `SaveState` during the first
  `install` (`report`, `update` and `diff` all presuppose an install). Measured
  two ways: a scratch probe (`.agents/scratch/security-phase2/mkdirmode.go`,
  gitignored, no harness import, replicating `MkdirAll(dir,0o755)` then
  `MkdirAll(dir,0o700)`) prints `-rwxr-xr-x` for both; and `stat` on the
  operator's own `~/.config/sh-agent` returns **755** today. Why it matters, with
  the threat corrected: 0755 grants group and other r-x, **not w**, so the
  symlink-planting story in `release.go:132-134`'s comment and in my own earlier
  finding is wrong for this directory — nobody else can create an entry in it.
  What 0755 does leave is read access for every local account to
  `feedback.jsonl`, `retros.jsonl`, `proposals/*.md`, `state.json`, and — for the
  duration of `report`, and indefinitely after a SIGINT until the next
  `sweepInterruptedClones` — a working clone of the **private**
  `styrman-harness-feedback` repository holding this machine's reports. On a
  single-user box that is nothing; on the devbox or any host with a second
  account it is a disclosure. Remediation: one `ensureConfigDir(home)` helper —
  `os.MkdirAll(dir, 0o700)`, then when the directory already exists and
  `ownedByCaller` says it is the caller's, `os.Chmod(dir, 0o700)` — called from
  `SaveState` and from the three sites above; stdlib `os` only, no dependency.
  The test to add is the arrangement the current one avoids: `TestThrowawayParentIsPrivate`
  uses a bare `t.TempDir()` home with no prior install, which is the **one**
  arrangement in which the fix works, so it passes while the shipped behaviour
  does not; the new test must `Install` first (as `TestDiffUsesTheHomeNotTmp`
  already does, where the 0700 is provably inert and unasserted) and then assert
  the mode.
- **[low / confidence: medium]** `internal/harness/pathguard.go:131` — the note
  decides "yours to relink" from `os.Lstat(from)`, but the operation it advises
  (`ln -sfn <installed> <from>`) is governed by **write permission on
  `filepath.Dir(from)`**, not by the ownership of the file at `from`. The two
  disagree in the case that actually occurs on these machines: a `sh-agent` the
  operator owns sitting in `/usr/local/bin`, a root-owned directory —
  `ownedByCaller` reads true, the note says "point it at the installed binary
  (`ln -sfn`)", and the command fails with EACCES. My audit's remediation said
  "stat `from` **and its directory**"; the directory half was not implemented. On
  the brief's symlink question: `Lstat` is the **right** call of the two — a
  symlink replacement is a directory operation, and on a sticky directory the
  link's own uid is what governs it, so following to the target's owner would be
  strictly worse — but neither `Lstat` nor `Stat` is sufficient without the
  parent. Remediation: also require `filepath.Dir(from)` to be the caller's (or
  writable by them) before offering `ln -sfn`. Advice-only surface; filed because
  a wrong remedy in a security-relevant note is what sends an operator to `sudo`.
- **[low / confidence: high]** `internal/harness/pathguard.go:141-147`
  (`ownedByCaller`) — the brief's root question, answered: for **root** (uid 0) a
  user-owned `from` (uid 1000) reads as *not* the caller's, so root running
  `update` gets "it is not yours to relink — remove it, with the rights that own
  it". The direction is the conservative one and the resulting advice is not
  harmful (root relinking a file inside a user's `~/.local/bin` is not advice to
  give), but the sentence is false as stated for root, who owns everything by
  capability. The realistic shape is `sudo sh-agent update` with `$HOME` left as
  the user's: the real-home gate at `:118` passes, `os.Getuid()` is 0, and every
  file in that home reads as foreign. No security consequence — the note writes
  nothing and touches nothing. Reword to "not owned by the user this process runs
  as". Separately, `os.Getuid()` (real uid) is the weaker of the two for a "can I
  write this" question; sh-agent is not setuid so it does not matter today, and
  `os.Geteuid()` is the one-word change that keeps it not mattering.
- **[low / confidence: medium]** `internal/harness/frontmatter.go:178-183` —
  `yamlQuote` escapes C0 and DEL but not the **C1** controls (U+0080–U+009F,
  notably U+0085 NEL) or U+2028/U+2029. In YAML 1.1 — libyaml, PyYAML, what most
  embedded parsers implement — those are line-break characters, so a description
  carrying one renders as a raw break inside the double-quoted scalar. This is
  **not** injection: a double-quoted scalar ends at its closing quote, so the
  worst case is a fold to a space or a parse error, never a second mapping key.
  Filed only because the fix's own rationale ("a raw control character ends a
  double-quoted YAML scalar for a strict parser") applies verbatim to these four
  runes. Remediation: extend the guard to
  `r < 0x20 || (r >= 0x7f && r <= 0x9f) || r == 0x2028 || r == 0x2029`.
- **[low / confidence: high]** `internal/harness/apply.go:220-234` — `Diff`, a
  read-only verb, now **writes into the home**: it creates `~/.config/sh-agent`
  when absent and drops a temp file there. Confined to sh-agent's own directory
  and only on drift, so this is a note rather than a defect against the read-only
  rule (which is scoped to `--check`/`--dry-run`), but `sh-agent diff --home <a
  home you are merely inspecting>` now mutates it. The `tmp.Write` error path at
  `:231` leaks the file and its fd (no `Remove`, no `Close`), and README's new
  `diff` row asserts "removed after" without qualification — a description one
  error path wider than the behaviour. Remediation closes all three at once and
  is the one the audit gave: `exec.Command("diff", "-u", "-L", …, dest, "-")`
  with `cmd.Stdin = bytes.NewReader(f.Data)`, and no temp file at all.
- **[low / confidence: high]** `cmd/sh-agent/main_test.go:1599-1629`
  (`plainCopyOf`, new in this range) — the fixture copies `context/`, `skills/`,
  `agents/`, `commands/` and `rules/` out of this checkout by walking the
  **working tree**, not `git ls-files`, into `t.TempDir()` (i.e. under `$TMPDIR`,
  which this project's rules put off limits for generated files). Today nothing
  leaks: `git status --untracked-files=all` and `git ls-files --others --ignored`
  over those five directories are empty, and a `find` for symlinks and
  secret-shaped names (`.env*`, `*.pem`, `*.key`, `*.tfvars`, `id_*`,
  `*credential*`) returns nothing — so the copy is all tracked content. The
  mechanism is the one `AGENTS.md` names as sharp ("an artifact built from the
  WORKING TREE rather than from git is pinned to what git tracks — `go:embed`
  compiled a gitignored `.env` into a release binary"): a gitignored credential
  dropped into `skills/` by a vendored skill would be refused by `secretShaped`
  at `install` and at `adopt`, and copied raw by this fixture. Exposure is
  bounded — `t.TempDir()` roots are 0700 — so it is a test-hygiene finding, not a
  shipping one. Remediation: drive the walk from `git ls-files -- <dir>`, or
  reuse `secretShaped` as a skip in the fixture; and point the fixture's root at
  `.agents/scratch/` rather than `$TMPDIR` if the project wants its own rule
  honoured in tests too.

## Outcome

Written by the main agent after round 2 of the Phase 2 fix round, in its commit.

- [low] finding 5 not closed — `MkdirAll(…, 0700)` no-ops on a dir every install had already created 0755 — **fixed**: `ConfigDir(home)` (internal/harness/state.go:76) creates the runtime dir 0700 or tightens an existing one (internal/harness/state.go:86), and every writer of it goes through it: `SaveState` (so every install tightens it), `cloneThrowaway`, `Diff`, the release download. `TestInstallMakesTheConfigDirPrivate` (internal/harness/audit_test.go:200) covers a fresh home and a pre-existing 0755 one; `TestThrowawayParentIsPrivate` now pre-creates the dir 0755 — the arrangement the earlier version of the fix could not pass; mutations for the chmod and for `SaveState` bypassing `ConfigDir` fail them. The operator's own dir tightens on their next `install`/`update`.
- [low] relinking is governed by the directory's owner, and root should read `Geteuid` — **fixed**: the advice is keyed on `os.Stat(filepath.Dir(from))` (internal/harness/pathguard.go:141) and `ownedByCaller` compares with `os.Geteuid()` (internal/harness/owned_unix.go:17); the sentence says "with the rights that own its directory". Not pinned at the note level: no non-root test can make a directory it does not own; `TestOwnedByCaller` pins the predicate with a fake `Stat_t`.
- [low] `Diff`'s write-error leak and README's unqualified "removed after" — **fixed** (the `defer`, internal/harness/apply.go:242); README's clause is now true on every path. `plainCopyOf` copying the working tree rather than `git ls-files` — **left** (main agent): a test fixture under `$TMPDIR`, removed by the test; the five directories hold nothing untracked today, and the embed test (`TestEmbedHoldsOnlyTrackedFiles`) fails the build if that changes.
- finding 17's `left` reason — **narrowed** in the merged record: a `state.json` from a dotfiles sync, a restored backup or a shared `--home` is not an attacker with the user's rights; what holds is that `knownCheckout` compares the cwd-walk result against the manifest (a real comparison), and a `Repo` value that names no harness is refused by `ResolveSource` before anything builds.

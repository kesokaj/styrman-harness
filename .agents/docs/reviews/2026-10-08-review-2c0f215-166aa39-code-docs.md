## Findings

- **[medium / confidence: high]** `internal/metrics/verb.go:225-229` (`verbFrom`) — the subcommand is taken only when `rest[0]` is name-shaped, so git global options before it hide it. Probed by running `Verb`: `git -C /p commit -m x` gives `git -C -m`; `git add -A` gives `git add -A` but `git -C dir add -A` gives `git -C -A`. `show.go:402-421` reads `w[1]` as the subcommand, so `git -C dir add -A`, `git -C dir push --force` and `git -c k=v commit` never count as forbidden and never set `commit` for the "commit chained to test" check. These are the headline process-adherence numbers (`C.forbidden.*`) that `/retro` source 11 and the dream prompt cite. Fix: for `git`, skip `-C <value>`, `-c <value>`, `--git-dir=…`, `--no-pager` etc. before choosing the subcommand (the value is dropped anyway), and add a `TestVerb` row for `git -C x add -A` to `git add -A`.
- **[medium / confidence: low]** `internal/metrics/agy.go:230-231, 213-217` — Antigravity tool steps and generation rows use `ON CONFLICT … DO NOTHING`, unlike Claude's tool rows (`claude.go`, DO UPDATE). A conversation ingested while a tool step is still running (the nightly dream or a manual ingest mid-session; `ingestAgy` re-reads a conversation whenever its mtime moved) freezes that step at `is_error=0`, and a generation row stays at `ts=NULL` forever, so Antigravity `D.tool_error_rate` and per-day charts can be under-counted. I did not confirm that Antigravity writes a non-final status for a running step, hence low confidence. Fix: upsert `is_error`/`ts` for `agyTool` and the generation `ts`, or skip steps whose status is not final, with a re-ingest test (ingest, then add the failure, then ingest again).
- **[low / confidence: high]** `internal/metrics/agy.go:54`, `internal/dream/metrics.go:49`, `internal/dream/run.go:334` — `metrics-agy-*` holds full copies of Antigravity's conversation databases (prose and tool output), and `dream-metrics-*` a copy of the metrics store, both made under `~/.config/sh-agent/` and removed only by `defer os.RemoveAll`. A SIGINT/SIGKILL or a crash during `metrics ingest` leaves them; `removeCopies` sweeps only `dream-agy-*` and `dream-projects-*`, so these stay forever (0700, but they are transcript content outside any retention rule). Fix: add the two prefixes to `removeCopies` (and have `metrics ingest` sweep `metrics-agy-*` older than an hour at start), with a test beside the existing `removeCopies` one.
- **[low / confidence: medium]** `cmd/sh-agent/main.go:420-440` (`ingest`), `:490-505` (`export`) — `metrics ingest` silently accepts `--json`, `--since`, `--project`, `--all-labels`, `--out`, and `export` accepts all of them, while `show`/`report` do refuse the ingest-only flags (`metricsShowOptions`). README says a flag a verb does not define is a usage error with exit 2; `--json` on `ingest` exits 0 and ignores it. Fix: mirror `metricsShowOptions`' refusals in `ingest` and `export`, with a test.

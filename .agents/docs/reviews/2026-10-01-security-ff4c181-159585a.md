- **[low / confidence: low (by git semantics; read, not reproduced)]** `internal/harness/catalog_test.go:441-449` (the `git` helper) and `:500-504` (`run`) — an exported `GIT_DIR` or `GIT_INDEX_FILE` reaches the fixture's git commands.
  - **Status:** pre-existing. It is in the new loop's blast radius, because the loop adds two more `commit`, `reset --hard` and `clean -qfd` cycles through the same helper.
  - **The mechanism.**
    - Both the helper and `run` pass `os.Environ()` through.
    - `git -C <fixture>` changes only the working directory, so an exported `GIT_DIR` or `GIT_INDEX_FILE` still decides the repository. Git exports these variables to hooks.
    - With an absolute `GIT_DIR`, `add -A`, `commit` and `reset --hard <pinG>` act on the exporting repository's index and branch, not on the fixture.
    - The script's `git clone` and `fetch` inherit the same variables.
  - **Likelihood: low.** This project bans hooks, and an interactive shell rarely exports `GIT_DIR`.
  - **The cost if it happens:** that repository's branch ref and index move to fixture commits. The reflog can recover them, but it is still a write outside the temporary directory.
  - **Remediation.**
    - Filter these variables out of the environment the helper and `run` build: `GIT_DIR`, `GIT_WORK_TREE`, `GIT_INDEX_FILE`, `GIT_OBJECT_DIRECTORY`, `GIT_ALTERNATE_OBJECT_DIRECTORIES`, `GIT_COMMON_DIR` and `GIT_NAMESPACE`.
    - Add a test that runs the helper with `GIT_DIR` pointing at a decoy repository. It first proves that the decoy is what git would use, then asserts that the decoy's HEAD and index are unchanged.
  - **Owner:** the main agent, after the tag.

All six of round 7's findings are fixed at 311c20b. ## Findings

### Finding 1 — the "reaches HEAD" definition excludes files that define verification
**[medium / confidence: high]** `skills/preflight/SKILL.md:62`

- **Wrong text:** "A range reaches HEAD when its head is HEAD, or a commit after which nothing outside `<docs-root>` changed (`git diff --quiet <head> HEAD -- . ':(exclude)<docs-root>'` …)".
- **Why it is wrong:** at 311c20b, `.agents/docs/testing/` holds `guide.md`, `kit-preamble.sh`, `skill-matrix.md` and `sh-agent-matrix.md`. Item 2, on the next line (`:63`), says these are "the files that define verification" ("any script, kit or matrix file those two tell a tier to run"). The exclusion skips them all.
- **Who is misled:** a gate agent following item 1 literally. Take a commit that changes only `kit-preamble.sh`, which this very range did, alongside source. A main-agent log of kit rows run under the old preamble still "reaches HEAD". Item 2 lists the edited preamble as changed, and the old log "shows" those rows run, so they count. That is the opposite of what the ninth-pass entry records: "Not yet run on this commit: … the kit rows on the changed preamble". The same holds for a verifier log after a commit that edits a command in `guide.md`, where the log may show the command's old form under the same name.
- **Introduced:** by this range.
- **Should say:** "… or a commit after which nothing changed but records — `<docs-root>`'s reviews, changes, handoffs, bugs and dated logs (`git diff --name-only <head> HEAD` lists nothing else; the testing guide, a matrix, a kit or a script under `<docs-root>` is not a record)".
- **Owner:** main.

### Finding 2 — a log with a failing row cannot be cleared
**[medium / confidence: medium]** `skills/preflight/SKILL.md:64`, with `:92` and `:72`

- **Wrong text:** item 3 blocks on a log "that shows a row failing whatever its heading". But its clearing sentences name only "A BLOCKED log …" and "A FAIL log, or an IN PROGRESS one that holds a failure, is cleared by a later PASS log …".
- **The gap:**
  - A log headed `## Status: PASS` (or with no heading) that shows a row failing has no clearing path. `guide.md:179` does not say PASS means every row passed, so such a log is easy to write.
  - Step 5 (`:92`) blocks on "a log that shows a row failing, not cleared as item 3 says", and item 3 says nothing for this case.
  - The new Step 3 bullet (`:72`) says a log is "never removed".
  - Step 5 lets the operator lift "the tier half of item 2 alone", and item 3 is not that half.
- **Who is misled:** a gate agent reading literally reaches a state no release from that base can pass and nobody can clear. One reading by analogy borrows the FAIL clause, which the text does not license.
- **Introduced:** by this range.
- **Should say:** "A FAIL log, an IN PROGRESS one that holds a failure, or a log that shows a row failing, is cleared by a later PASS log reaching HEAD that reran what failed …".
- **Also worth adding (optional):** add to `guide.md:179` "PASS only when every row met its criterion".
- **Owner:** main for the skill; documentation for the guide.

### Finding 3 — a Step 1 verifier log can never reach HEAD
**[low / confidence: medium]** `skills/preflight/SKILL.md:62`

- **The contradiction:**
  - Item 1 accepts a verifier log "written or updated in Step 1".
  - Step 1 (`:44`, `:46`) dispatches that verifier on uncommitted work, before the commit.
  - The template for that log is `Range reviewed: <range or working tree>` (template guide `:39`).
  - The new definition says "an uncommitted source change reaches nothing", and a working-tree head is neither HEAD nor a commit.
- **Who is misled:** a gate agent with dirty source. It cannot tell whether its own Step 1 log counts. A literal reading never counts it and dispatches a second full verifier run in every such gate. That costs a run, not a wrong verdict.
- **Introduced:** by this range (the definition is new).
- **Should say:** "a Step 1 log naming the working tree reaches the commit Step 1 made from that tree when nothing outside records changed between the dispatch and the commit (Step 1 item 3)". Alternatively, drop "written or updated in Step 1".
- **Owner:** main.

### Finding 4 — the project template omits the n-of-N rows the gate requires
**[low / confidence: high]** `skills/init-project/assets/agents-tree/docs/testing/guide.md:39`

- **Template text:** "`main` for a run the main agent makes itself … `## Status: PASS | FAIL | BLOCKED` …, a `Scope:` line, the commands run with their exit status". It has no per-row result.
- **Gate text:** the global `/preflight` (`:63`) counts a main-agent tier only when the log "shows its rows run and passed, each as n of N against the row's own criterion".
- **Who is misled:** the main agent in any scaffolded project. Its behavioural log, written to its own guide § 5, does not count at the gate, so the tier is rerun.
- **Introduced:** by this range (the n-of-N requirement is new).
- **Should say:** add "; a main-agent run gives each row as n of N against the row's own pass criterion, PASS only when every row met it".
- **Owner:** main (a skill's asset).

- **Code** (`kit-preamble.sh:84-86`): it uses three pieces.

  - `find -H … -type f -exec cksum` checksums every regular file.

- **Comments:** `:78-83` is true. `[ -f ]` and `readlink` only stat a device or fifo target and never open it, and a re-pointed non-file link changes the printed target. `:61-67` ("does not see") and `:73` ("every path plus a checksum of every file") are still true.
